## Overview

`gt-sanity` v5 removes the option alias and exported types left over from earlier plugin designs. Field-level localization is configured with one option, and stored Sanity content is unchanged.

---

## Breaking changes

### `internationalizedArray` option removed

Configure field-level localization with [`fieldLevelLocalization`](/docs/integrations/sanity/reference/plugin-configuration#field-level-localization). It takes the same `GTFieldLevelLocalizationConfig` object.

```ts title="sanity.config.ts"
gtPlugin({
  sourceLocale: 'en',
  locales: ['es', 'fr'],
  translateDocuments: [{ type: 'post' }],
  fieldLevelLocalization: { enabled: true },
  translationLevel: 'internationalizedArray',
});
```

The `internationalizedArray()` plugin re-export and the `'internationalizedArray'` value of `translationLevel` are unchanged.

### Translations Tab types removed

The `Adapter`, `ExportForTranslation`, `ImportTranslation`, and `TranslationsTabConfigOptions` type exports are removed. They described the adapter interface of the Translations Tab plugin that `gt-sanity` was originally based on, and the plugin no longer uses it. `GTPluginConfig` also drops `devApiKey`, which the plugin never used; pass `apiKey` or use the secrets document.

### Object-keyed field serialization removed

`BaseDocumentSerializer(schema).serializeDocument()` drops its `translationLevel` and `baseLang` parameters and now takes `(doc, stopTypes?, serializers?)`. `BaseDocumentMerger.fieldLevelMerge` is removed. These served the object-keyed field model (`title: { en, es }`), which the plugin no longer supports.

### Removed v3 options are no longer reported

Passing `typePrefix`, `includeCompatibilityTypes`, or `components` in the field-level config no longer logs a warning. These options have had no effect since v3.
