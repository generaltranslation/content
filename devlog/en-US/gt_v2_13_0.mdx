## Overview

The [`t()`](/docs/react/reference/functions/t-function) function now automatically derives dynamic content — no more wrapping variables in [`derive()`](/docs/react/reference/functions/derive). This is enabled by default and works out of the box with the GT CLI.

This is the latest step in a series of [`derive()`](/docs/react/reference/functions/derive) improvements. First, [gt-react@10.15.0](/devlog/gt-react_v10_15_0) brought [`derive()`](/docs/react/reference/functions/derive) support to the [`t`](/docs/react/reference/functions/t-function) tagged template literal. Then [gt@2.12.0](/devlog/gt-cli_v2_12_0) extended [`derive()`](/docs/react/reference/functions/derive) to resolve values from objects and arrays. Now, gt@2.13.0 removes the need to call [`derive()`](/docs/react/reference/functions/derive) at all when using [`t()`](/docs/react/reference/functions/t-function).

## Before & after

Previously, dynamic values in [`t()`](/docs/react/reference/functions/t-function) required an explicit [`derive()`](/docs/react/reference/functions/derive) call:

```js
const noun = cond ? "boy" : "girl"
const result = t("The " + derive(noun))
```

Now, just use the variable directly:

```js
const noun = cond ? "boy" : "girl"
const result = t("The " + noun)
```

The CLI handles derivation automatically when it parses your [`t()`](/docs/react/reference/functions/t-function) calls — it detects variables with a finite set of possible string values and derives them behind the scenes.

## Configuration

Auto-derive is enabled by default. To disable it, set `autoDerive` to `false` in your `gt.config.json`:

```json
{
  "files": {
    "gt": {
      "parsingFlags": {
        "autoDerive": false
      }
    }
  }
}
```

> **Note:** This applies only to the [`t()`](/docs/react/reference/functions/t-function) function. The [`t`](/docs/react/reference/functions/t-function) tagged template macro is unaffected — it already handles derivation through the template literal syntax introduced in [gt-react@10.15.0](/devlog/gt-react_v10_15_0).
