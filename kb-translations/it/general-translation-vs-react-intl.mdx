react-intl è la [libreria React di FormatJS](https://formatjs.github.io/docs/react-intl). Ogni messaggio si scrive inline come `defaultMessage` in ICU MessageFormat, con una `description` per i traduttori; poi si raccolgono tutti i messaggi in un catalogo JSON con `formatjs extract` e si renderizzano i cataloghi tradotti tramite `IntlProvider`. La libreria però non traduce nulla: il catalogo estratto viene affidato a te, ai tuoi traduttori o a un sistema di gestione delle traduzioni (TMS), e i file tradotti ritornano per essere compilati. Anche le librerie di General Translation renderizzano messaggi ICU, ma in più General Translation genera le traduzioni.

## Cosa fa bene react-intl

* **ICU MessageFormat ovunque.** [Plurali con `#` e corrispondenze esatte come `=0`, `select` e `selectordinal`](https://formatjs.github.io/docs/core-concepts/icu-syntax), basati sulle API `Intl` del browser.
* **Testo di origine inline.** FormatJS [consiglia di scrivere `defaultMessage` e `description` inline](https://formatjs.github.io/docs/getting-started/message-declaration) e di lasciare che siano `babel-plugin-formatjs` o `@swc/plugin-formatjs` a generare gli ID dei messaggi, così nessuno deve inventarsi le chiavi.
* **Strumenti per un flusso di lavoro basato su TMS.** [`formatjs extract`](https://formatjs.github.io/docs/tooling/cli) genera il catalogo, i formattatori integrati producono file per Crowdin, Lokalise, Smartling e Transifex, `formatjs compile` esegue il pre-parsing dei messaggi e `formatjs verify` verifica che nei cataloghi non ci siano chiavi mancanti o in eccesso.
* **TypeScript.** [La versione 12 è in grado di tipizzare gli argomenti ICU di ogni messaggio](https://formatjs.github.io/docs/react-intl/upgrade-guide-12.x).
* **Manutenzione attiva.** [La versione 12 è stata rilasciata a settembre 2026](https://github.com/formatjs/formatjs/blob/main/packages/react-intl/CHANGELOG.md), con licenza BSD-3-Clause.

## Cosa react-intl lascia a carico tuo

Ecco una piccola inbox realizzata con react-intl. Il testo in inglese rimane nel componente come `defaultMessage`:

```jsx title="Inbox.jsx"
import { FormattedMessage } from 'react-intl';

export function Inbox({ count }) {
  return (
    <section>
      <h1>
        <FormattedMessage defaultMessage="Inbox" description="Heading of the inbox page" />
      </h1>
      <p>
        <FormattedMessage
          defaultMessage="You have {count, plural, one {# unread message} other {# unread messages}}."
          description="Number of unread messages in the inbox"
          values={{ count }}
        />
      </p>
    </section>
  );
}
```

`formatjs extract` trasforma quei messaggi in un catalogo le cui chiavi sono ID generati automaticamente:

```json title="lang/en.json"
{
  "U5vJOY": {
    "defaultMessage": "You have {count, plural, one {# unread message} other {# unread messages}}.",
    "description": "Number of unread messages in the inbox"
  },
  "gBGgGs": {
    "defaultMessage": "Inbox",
    "description": "Heading of the inbox page"
  }
}
```

Ogni lingua di destinazione richiede messaggi tradotti che mantengano intatta la sintassi ICU. `IntlProvider` accetta stringhe di messaggio o messaggi precompilati; questi ultimi vengono generati da `formatjs compile`. I descrittori estratti contengono ciascun messaggio con la relativa descrizione. Per generare gli ID come in questo esempio, configura il plugin Babel o SWC nella tua build. Con l&#39;[App Router di Next.js](https://formatjs.github.io/docs/guides/nextjs-app-router), i componenti di react-intl vengono eseguiti nei componenti client, mentre il codice lato server formatta i messaggi tramite `createIntl` di `react-intl/server`.

## Mantenere i messaggi ICU e generare le traduzioni

Le librerie di General Translation svolgono lo stesso compito di react-intl: renderizzano i messaggi ICU, applicano le regole del plurale di ciascuna impostazione regionale e formattano numeri, valute e date. Le tue stringhe ICU si possono migrare quasi senza modifiche, perché [`useGT`](/docs/react/reference/hooks/use-gt) accetta la stessa sintassi:

```tsx title="Inbox.tsx"
import { useGT } from 'gt-react';

export function Inbox({ count }: { count: number }) {
  const gt = useGT();
  return (
    <section>
      <h1>{gt('Inbox', { $context: 'Heading of the inbox page' })}</h1>
      <p>
        {gt('You have {count, plural, one {# unread message} other {# unread messages}}.', {
          count,
          $context: 'Number of unread messages in the inbox',
        })}
      </p>
    </section>
  );
}
```

[`npx gt translate`](/docs/cli/reference/commands/translate) estrae queste stringhe, genera le traduzioni sfruttando le relative note di contesto e scrive i cataloghi di destinazione, tutto con un unico comando. L&#39;esempio mantiene entrambe le descrizioni FormatJS come `$context`. I [termini del Glossario e i prompt personalizzati](/docs/platform/dashboard/guides/defining-context-for-translations) condivisi orientano terminologia e tono, mentre i revisori modificano i risultati nella [dashboard](/docs/platform/dashboard/guides/reviewing-translations).

Il `#` viene formattato in base all&#39;impostazione regionale, quindi un conteggio di 12345 diventa &quot;12,345&quot; in inglese e &quot;12.345&quot; in spagnolo. Per il JSX con markup, [`<T>`](/docs/react/reference/components/t) traduce l&#39;intero blocco contrassegnato, elementi inclusi. In `gt-next` funziona direttamente nei Componenti server.

La dashboard, la landing page e l&#39;app iOS di Ramp sono disponibili in oltre 11 impostazioni regionali grazie a General Translation. (Vedi le [distribuzioni in produzione](https://generaltranslation.com/enterprise).)

## react-intl e General Translation a confronto

| Funzionalità                   | react-intl                                                                                                                 | General Translation                                                                                                             |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Come scrivi i testi            | `defaultMessage` inline in ICU, estratto in un catalogo JSON                                                               | JSX inline in [`<T>`](/docs/react/reference/components/t), oppure stringhe ICU in [`useGT`](/docs/react/reference/hooks/use-gt) |
| Traduce i tuoi contenuti       | No                                                                                                                         | Sì, con [`npx gt translate`](/docs/cli/reference/commands/translate)                                                            |
| Flusso di lavoro dei cataloghi | Estrai i messaggi, traducili con il flusso di lavoro che preferisci ed eventualmente precompilali; il plugin genera gli ID | [`npx gt translate`](/docs/cli/reference/commands/translate) estrae e traduce prima della build                                 |
| Contesto di traduzione         | Il messaggio e la sua descrizione                                                                                          | Stringhe ICU con `$context`; struttura JSX marcata con componenti inline; Glossario e prompt personalizzati condivisi           |
| Next.js App Router             | Componenti all&#39;interno dei componenti client; `createIntl` sul server                                                  | [`<T>`](/docs/react/reference/components/t) nei Server Component e nei Client Component                                         |
| Licenza                        | [BSD-3-Clause](https://github.com/formatjs/formatjs/blob/main/packages/react-intl/LICENSE.md)                              | Librerie JavaScript e CLI con licenza MIT                                                                                       |

Resta su react-intl se i tuoi cataloghi ICU e i formattatori del TMS funzionano già, se ti affidi agli argomenti tipizzati dei messaggi o a `formatjs verify`, oppure se usi FormatJS al di fuori di React. Scegli General Translation se vuoi continuare a scrivere in ICU, integrando la generazione e la revisione delle traduzioni nel tuo flusso di lavoro di sviluppo.

## Migrare da react-intl

Migra un componente o una route alla volta. Sostituisci ogni `<FormattedMessage>` con una chiamata a [`useGT`](/docs/react/reference/hooks/use-gt) che mantenga la stessa stringa ICU e ne passi la descrizione come `$context`, come mostrato sopra. Per il JSX con formattazione avanzata, usa [`<T context="…">`](/docs/react/reference/components/t#context). Continua a caricare i cataloghi react-intl esistenti per i componenti che non hai ancora migrato. Una volta migrato l&#39;ultimo componente, rimuovi il plugin FormatJS e gli script di estrazione e compilazione. (Consulta [Migrare da altre librerie i18n](/docs/react/guides/migrating-i18n-libraries).)

## Punti chiave

* react-intl formatta i messaggi ICU e fornisce strumenti per la gestione dei cataloghi, ma la generazione delle traduzioni richiede un flusso di lavoro separato.
* General Translation estrae e traduce con un solo comando della CLI, mantenendo il contesto fornito dalle descrizioni e mettendo a disposizione dei revisori un editor nella Dashboard.
* Le tue stringhe ICU passano a [`useGT`](/docs/react/reference/hooks/use-gt) quasi senza modifiche, un componente alla volta.
