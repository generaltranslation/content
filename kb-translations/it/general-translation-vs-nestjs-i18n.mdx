nestjs-i18n è un modulo i18n open source per NestJS: determina la lingua di ogni richiesta a partire dalla query string, da un&#39;intestazione, da un cookie o da `Accept-Language`, mentre `I18nContext` o `I18nService` restituiscono dai tuoi cataloghi il messaggio in quella lingua. Renderizza le traduzioni, ma non le produce: il catalogo di ogni lingua va scritto e tenuto aggiornato da te, dai tuoi traduttori o da un servizio esterno. General Translation colma questa lacuna in due modi: la sua CLI traduce i cataloghi di nestjs-i18n e la libreria `gt-node` traduce i contenuti che esistono solo a runtime.

## Cosa fa bene nestjs-i18n

* **Pensato per Nest.** Basta una sola chiamata a `I18nModule.forRoot()`, [un decoratore di parametro `@I18n()` per `I18nContext` e `I18nContext.current()` nei servizi](https://nestjs-i18n.com/quick-start). Funziona su HTTP, GraphQL, gRPC e WebSocket.
* **Resolver della lingua.** [`QueryResolver`, `HeaderResolver`, `CookieResolver` e `AcceptLanguageResolver`](https://nestjs-i18n.com/concepts/resolver) vengono eseguiti nell&#39;ordine in cui li elenchi, appositi resolver coprono i trasporti GraphQL e gRPC e puoi anche scriverne di tuoi.
* **Cataloghi semplici.** Una cartella per lingua (`src/i18n/en/`, `src/i18n/es/`) con [file JSON o YAML](https://nestjs-i18n.com/concepts/loader), in cui il nome di ciascun file diventa un namespace (`inbox.title`), più il ricaricamento a caldo durante lo sviluppo.
* **Plurali e interpolazione.** Segnaposto `{name}`, riferimenti `$t()` ad altre chiavi e [oggetti plurali le cui chiavi `zero`, `one`, `two`, `few`, `many` e `other`](https://nestjs-i18n.com/guides/plurals) vengono selezionate tramite `Intl.PluralRules`. In alternativa, l&#39;impostazione opt-in `useICU`, [aggiunta nella 10.8.0](https://github.com/toonvanstrijp/nestjs-i18n/releases/tag/v10.8.0), formatta i messaggi con ICU MessageFormat.
* **Type safety.** [`typesOutputPath` genera i tipi `I18nTranslations` e `I18nPath`](https://nestjs-i18n.com/guides/type-safety), così una chiave scritta male provoca un errore di compilazione, e il comando `nestjs-i18n check` termina con un errore se in una lingua mancano delle chiavi.
* **Messaggi di validazione.** `I18nValidationPipe`, `I18nValidationExceptionFilter` e `i18nValidationMessage()` [traducono gli errori di class-validator per i DTO](https://nestjs-i18n.com/guides/dto_validation/global-validation).

È distribuito con licenza MIT e [la versione 10.8.5 richiede Node.js 22 o successivo](https://github.com/toonvanstrijp/nestjs-i18n/blob/v10.8.5/package.json).

## Cosa nestjs-i18n lascia a carico tuo

Ecco un catalogo in inglese per una inbox, con un plurale:

```json title="src/i18n/en/inbox.json"
{
  "title": "Inbox",
  "unread": {
    "one": "You have {count} unread message.",
    "other": "You have {count} unread messages."
  }
}
```

La cartella dello spagnolo contiene una copia tradotta del file e un controller restituisce `i18n.t('inbox.unread', { args: { count } })`. Non c&#39;è alcuna cartella per il tedesco. Ecco le richieste inviate a un&#39;app Nest 11 minimale con nestjs-i18n 10.8.5:

```text title="Output"
?lang=es&count=3  "Tienes 3 mensajes sin leer."
?lang=de&count=3  "You have 3 unread messages."
```

Il tedesco ripiega sull&#39;inglese perché il suo catalogo non è stato tradotto. Il rilevamento della lingua funziona, ma non può fornire il testo mancante. Ed è proprio questo il lavoro che nestjs-i18n lascia a te: creare i cataloghi e mantenerli aggiornati ogni volta che il testo inglese cambia.

## Come General Translation si integra in un&#39;app NestJS

La CLI di General Translation traduce i cataloghi di nestjs-i18n direttamente lì dove si trovano. Fai puntare una voce `json` alle cartelle delle lingue:

```json title="gt.config.json"
{
  "defaultLocale": "en",
  "locales": [
    "es",
    "de"
  ],
  "files": {
    "json": {
      "include": [
        "src/i18n/[locale]/*.json"
      ]
    }
  }
}
```

[`npx gt translate`](/docs/cli/reference/commands/translate) legge `src/i18n/en/inbox.json` e scrive `src/i18n/es/inbox.json` e `src/i18n/de/inbox.json`, mantenendo tutte le chiavi. Eseguilo in CI: le voci invariate riutilizzano le traduzioni precedenti. nestjs-i18n carica i cataloghi generati tramite il loader già esistente.

Questo esempio usa messaggi in inglese, spagnolo e tedesco con le forme `one` e `other`. Visualizza un&#39;anteprima dei messaggi generati con conteggi pari a 1 e 3 ed esegui `nestjs-i18n check -p src/i18n` per individuare eventuali chiavi mancanti prima del rilascio.

Per i contenuti disponibili solo a runtime, come il post di un collega o un record di database, usa [`gt-node`](/docs/node/quickstart) di General Translation. Inizializzalo una sola volta, poi passa la lingua risolta da nestjs-i18n a [`withGT`](/docs/node/reference/functions/with-gt) quando chiami [`tx`](/docs/node/reference/functions/tx):

```ts title="src/main.ts"
import { NestFactory } from '@nestjs/core';
import { initializeGT } from 'gt-node';
import { AppModule } from './app.module';

// Legge dall'ambiente GT_PROJECT_ID e GT_API_KEY (una chiave di progetto con traduzione Runtime abilitata).
initializeGT({ defaultLocale: 'en', locales: ['en', 'es', 'de'] });

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  await app.listen(3000);
}
bootstrap();
```

```ts title="src/posts.controller.ts"
import { Controller, Get, Param } from '@nestjs/common';
import { I18n, I18nContext } from 'nestjs-i18n';
import { tx, withGT } from 'gt-node';
import { PostsService } from './posts.service';

@Controller('posts')
export class PostsController {
  constructor(private readonly posts: PostsService) {}

  @Get(':id')
  async findOne(@Param('id') id: string, @I18n() i18n: I18nContext) {
    return withGT(i18n.lang, async () => {
      const post = await this.posts.findOne(id);
      return { ...post, body: await tx(post.body, { $context: 'A post written by a user' }) };
    });
  }
}
```

Entrambi gli strumenti ora utilizzano la lingua selezionata dai resolver di nestjs-i18n già configurati. Se `?lang=es` ha la precedenza su `Accept-Language: de`, sia i messaggi del catalogo sia il post tradotto saranno in spagnolo. Usa i cataloghi per i testi fissi dell&#39;interfaccia e [`tx`](/docs/node/reference/functions/tx) per i contenuti creati dai tuoi utenti.

Continua a usare nestjs-i18n per le chiavi tipizzate, le ricerche nei cataloghi e i messaggi di validazione. General Translation si occupa della generazione delle traduzioni e offre un Glossario e prompt personalizzati condivisi, oltre alla [revisione nella dashboard](/docs/platform/dashboard/guides/reviewing-translations). Usa il flusso di lavoro basato sui cataloghi descritto sopra per i testi fissi e `tx` per il contenuto dinamico.

## nestjs-i18n e General Translation a confronto

| Funzionalità             | nestjs-i18n                                                                             | General Translation                                                                                              |
| ------------------------ | --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Ruolo                    | Risolve la lingua della richiesta e renderizza i messaggi dai cataloghi                 | Traduce i cataloghi e il contenuto dinamico a runtime                                                            |
| Traduce i tuoi contenuti | No                                                                                      | Sì, con [`npx gt translate`](/docs/cli/reference/commands/translate) e [`tx`](/docs/node/reference/functions/tx) |
| Rilevamento della lingua | Query, intestazione, cookie, `Accept-Language`, GraphQL, gRPC e resolver personalizzati | Usa la stessa lingua risolta tramite [`withGT`](/docs/node/reference/functions/with-gt)                          |
| Plurali                  | Chiavi di categoria specifiche per lingua, selezionate con `Intl.PluralRules`           | Traduce le chiavi plurali presenti nel tuo file sorgente                                                         |
| Type safety              | Tipi di chiave generati e controllo delle chiavi mancanti                               | Mantiene le chiavi dei cataloghi, così i tipi generati restano invariati                                         |
| Messaggi di validazione  | Integrazione con class-validator                                                        | Traduce i cataloghi da cui provengono questi messaggi                                                            |
| Costo                    | Gratuito, con licenza MIT                                                               | [In base all&#39;utilizzo](https://generaltranslation.com/pricing)                                               |

## Quando usare l&#39;uno o l&#39;altro

Continua a usare nestjs-i18n per i suoi resolver, le chiavi tipizzate e l&#39;integrazione con la validazione. Aggiungi General Translation se vuoi che i cataloghi vengano tradotti in CI man mano che il testo inglese cambia, oppure se la tua API restituisce contenuti generati dagli utenti o provenienti dal database da tradurre al volo. I tuoi controller esistenti continuano a usare le stesse chiavi; General Translation mantiene aggiornato il testo associato a quelle chiavi.

## Usare entrambi

1. Lascia nestjs-i18n e le relative cartelle così come sono.
2. Aggiungi `gt.config.json` con il percorso del tuo catalogo e imposta `GT_API_KEY` e `GT_PROJECT_ID`. (Consulta [Configurare la CLI](/docs/cli/guides/configuring#credentials).)
3. Carica le traduzioni già esistenti con [`npx gt upload`](/docs/cli/reference/commands/upload), quindi esegui [`npx gt translate`](/docs/cli/reference/commands/translate) nella CI.
4. Se in seguito modifichi le traduzioni in locale, esegui [`npx gt save-local`](/docs/cli/reference/commands/save-local) prima di rigenerarle. Aggiungi `gt-node` dove ti serve la traduzione in fase di esecuzione.

## Punti chiave

* nestjs-i18n gestisce il rilevamento della lingua, le chiavi tipizzate, i plurali e i messaggi di validazione in NestJS, ma ogni catalogo in ogni lingua spetta a te scriverlo, comprese le forme plurali di ciascuna lingua.
* La CLI di General Translation traduce in-place i cataloghi JSON di nestjs-i18n, mentre `gt-node` traduce il contenuto dinamico usando la stessa lingua della richiesta.
* Usali insieme: nestjs-i18n si occupa del rendering, General Translation della traduzione.
