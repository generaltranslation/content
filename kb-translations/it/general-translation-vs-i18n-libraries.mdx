Una libreria di internazionalizzazione (i18n) svolge due compiti mentre la tua app è in esecuzione: seleziona il messaggio corrispondente all&#39;impostazione regionale dell&#39;utente e formatta plurali, date e numeri in base a quell&#39;impostazione regionale. Le librerie open source come i18next, react-intl, next-intl, Lingui e vue-i18n si occupano di entrambi, ma nessuna di esse traduce i tuoi contenuti. Questo lavoro resta a tuo carico, prima che l&#39;app venga eseguita: inserire ogni stringa in un file di catalogo, tramite chiave o estraendo i messaggi inline, far tradurre ogni catalogo e mantenerli tutti aggiornati man mano che l&#39;interfaccia cambia. Le librerie di General Translation svolgono gli stessi compiti a runtime, ma in più General Translation si occupa della traduzione: i testi restano inline nei tuoi componenti e le traduzioni vengono generate come fase della build.

## Cosa fanno bene le librerie consolidate

Ognuna di queste librerie è matura, gratuita e molto diffusa, e ciascuna ha un punto di forza diverso:

* **i18next** è la più scaricata. Funziona in qualsiasi ambiente JavaScript e la CLI ufficiale `i18next-cli` estrae le chiavi dal codice e ne genera i tipi TypeScript.
* **react-intl** (FormatJS) si basa su ICU MessageFormat, la sintassi standard per plurali e selezioni. La sua documentazione consiglia di scrivere ogni `defaultMessage` inline insieme a una `description` per i traduttori, per poi raccoglierli in un catalogo con `formatjs extract`.
* **next-intl** è progettata per l&#39;App Router di Next.js. Le sue traduzioni funzionano nei Componenti server, i messaggi usati solo dai Componenti server possono essere esclusi dal client e le chiavi dei messaggi supportano il controllo dei tipi. La sua API per i messaggi inline, introdotta nella versione 4.5, è ancora contrassegnata come sperimentale.
* **Lingui** mantiene il testo di origine inline tramite macro come `<Trans>`, genera automaticamente gli ID dei messaggi ed estrae i messaggi in cataloghi PO.
* **vue-i18n** è il plugin i18n per Vue 3, con messaggi in JSON, YAML o in blocchi `<i18n>` all&#39;interno dei single-file component.

Tutte conservano le traduzioni in formati di catalogo, come JSON e PO, con cui traduttori e sistemi di gestione delle traduzioni (TMS) lavorano già abitualmente.

## Cosa resta a carico tuo

Nessuna di queste librerie traduce alcunché. Le traduzioni devi fornirle tu, i tuoi traduttori o un servizio esterno, come Locize del team di i18next o un TMS come Crowdin. Ecco un piccolo componente per una casella di posta realizzato con react-i18next:

```json title="locales/en/translation.json"
{
  "inbox": {
    "title": "Inbox",
    "unread_one": "You have {{count}} unread message.",
    "unread_other": "You have {{count}} unread messages."
  }
}
```

```tsx title="Inbox.tsx"
import { useTranslation } from 'react-i18next';

export function Inbox({ count }: { count: number }) {
  const { t } = useTranslation();
  return (
    <section>
      <h1>{t('inbox.title')}</h1>
      <p>{t('inbox.unread', { count })}</p>
    </section>
  );
}
```

Ogni altra lingua richiede poi un proprio file, ad esempio `locales/es/translation.json`, scritto a mano o affidato a un traduttore. Ciascun file deve inoltre includere le forme plurali della propria lingua come chiavi separate: il giapponese ne usa una, il polacco quattro e l&#39;arabo sei (`_zero`, `_one`, `_two`, `_few`, `_many` e `_other`). Una stringa aggiunta al componente resta assente da tutti gli altri file finché qualcuno non la inserisce, e chi traduce il catalogo vede `inbox.unread_other` e una frase, non la schermata in cui appare.

## General Translation fa lo stesso, e in più genera le traduzioni

Le librerie di General Translation svolgono lo stesso compito di i18next, react-intl e next-intl. Selezionano i messaggi corretti per ogni impostazione regionale, ne applicano le regole del plurale e formattano numeri, valute e date con [`<Num>`](/docs/react/reference/components/num), [`<Currency>`](/docs/react/reference/components/currency) e [`<DateTime>`](/docs/react/reference/components/datetime). Gestiscono le variabili ICU-style nelle stringhe di [`useGT`](/docs/react/reference/hooks/use-gt), i dizionari basati su chiavi tramite [`useTranslations`](/docs/react/reference/hooks/use-translations) per i team che preferiscono le chiavi e, con `gt-next`, un URL dedicato per ogni impostazione regionale. Ma General Translation va oltre e fa ciò che le altre librerie non fanno: genera le traduzioni.

Ecco la stessa casella di posta realizzata con `gt-react`. I testi restano nel componente, [`<T>`](/docs/react/reference/components/t) contrassegna il JSX da tradurre e [`<Plural>`](/docs/react/reference/components/plural) contiene le forme in inglese:

```tsx title="Inbox.tsx"
import { T, Plural, Num } from 'gt-react';

export function Inbox({ count }: { count: number }) {
  return (
    <T>
      <section>
        <h1>Inbox</h1>
        <Plural
          n={count}
          one={<p>You have <Num>{count}</Num> unread message.</p>}
          other={<p>You have <Num>{count}</Num> unread messages.</p>}
        />
      </section>
    </T>
  );
}
```

Eseguendo [`npx gt translate`](/docs/cli/reference/commands/translate) prima della build, ogni blocco [`<T>`](/docs/react/reference/components/t) viene inviato, insieme alla sua struttura di elementi, all&#39;API di General Translation, e viene scritta una traduzione per ogni impostazione regionale di destinazione. Tu scrivi le forme plurali previste dall&#39;inglese, e la traduzione genera quelle richieste da ciascuna lingua di destinazione, come `few` e `many` del polacco. [`<Plural>`](/docs/react/reference/components/plural) sceglie poi un branch tradotto in base alle regole del plurale dell&#39;impostazione regionale del lettore. [`<Num>`](/docs/react/reference/components/num) formatta il conteggio secondo l&#39;impostazione regionale del lettore al momento del rendering, mentre un valore racchiuso in [`<Var>`](/docs/react/reference/components/var) non viene mai inviato all&#39;API. Quando modifichi la frase, l&#39;esecuzione successiva la traduce di nuovo; quando elimini il componente, anche le sue traduzioni vengono rimosse.

Le librerie di General Translation supportano Next.js (`gt-next`), React (`gt-react`), Vue 3 (`gt-vue`) e Node.js (`gt-node`), con librerie sperimentali per React Native, TanStack Start e per Flask e FastAPI in Python. Sono distribuite con licenza MIT e funzionano anche senza un account General Translation: caricano le traduzioni da qualsiasi sorgente, e [`gt generate`](/docs/cli/reference/commands/generate) genera file template per i team che traducono manualmente. Sotto `gt-react` o `gt-next` non c&#39;è alcuna altra libreria i18n, perché il parsing e la formattazione dei messaggi ICU sono affidati a pacchetti sviluppati da General Translation. Per impostazione predefinita, le traduzioni vengono incluse come file nella build, ma possono anche essere caricate dalla CDN di General Translation.

## Confronto tra le librerie

| Libreria                                                          | Come scrivi i testi                                                                                                                      | Traduce i tuoi contenuti? | Da dove provengono le traduzioni                                                                                                            | Plurali                                                                                                                                   |
| ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| [i18next](/kb/general-translation-vs-i18next) con `react-i18next` | Chiavi in un file JSON per ogni impostazione regionale                                                                                   | No                        | Da te, dai traduttori o da un servizio come Locize                                                                                          | Una chiave per ogni forma plurale                                                                                                         |
| [`react-intl`](/kb/general-translation-vs-react-intl) (FormatJS)  | Testo `defaultMessage` inline, estratto in un catalogo JSON                                                                              | No                        | Da te, dai traduttori o da un TMS                                                                                                           | ICU MessageFormat                                                                                                                         |
| `next-intl`                                                       | Chiavi in un file JSON per ogni impostazione regionale                                                                                   | No                        | Da te, dai traduttori o da un TMS come Crowdin                                                                                              | ICU MessageFormat                                                                                                                         |
| [Lingui](/kb/general-translation-vs-lingui)                       | Macro inline, estratte in cataloghi PO                                                                                                   | No                        | Da te, dai traduttori o da un TMS come Crowdin                                                                                              | ICU MessageFormat                                                                                                                         |
| [`vue-i18n`](/kb/general-translation-vs-vue-i18n)                 | Chiavi in oggetti messaggio per ogni impostazione regionale                                                                              | No                        | Da te, dai traduttori o da un TMS                                                                                                           | Forme separate da una barra verticale; la versione 11 richiede una regola personalizzata per lingue come il polacco                       |
| General Translation (`gt-react`, `gt-next`, `gt-vue`)             | JSX all&#39;interno di [`<T>`](/docs/react/reference/components/t) oppure stringhe tramite [`useGT`](/docs/react/reference/hooks/use-gt) | Sì                        | Generate da [`npx gt translate`](/docs/cli/reference/commands/translate) sfruttando il contesto del tuo codice, oppure scritte dal tuo team | Branch di [`<Plural>`](/docs/react/reference/components/plural); la traduzione genera le forme richieste da ciascuna lingua di destinazione |

Continua a usare i18next, react-intl, next-intl, Lingui o vue-i18n se i tuoi cataloghi e il tuo processo di traduzione funzionano già, se i traduttori o un TMS lavorano con file di catalogo, oppure se il tuo framework non è tra quelli supportati dalle librerie di General Translation. Scegli le librerie di General Translation se vuoi che i testi restino leggibili direttamente nei componenti, che le traduzioni vengano generate tenendo conto del contesto del codice e che ogni lingua sia aggiornata a ogni build, senza dover attendere un ciclo di traduzione.

## Mantieni la tua libreria o migra una route alla volta

Cambiare libreria è facoltativo. La CLI `gt` rileva `next-intl` o `i18next` dal tuo `package.json` e ne traduce i file JSON mantenendone la sintassi dei messaggi. Sono supportati anche i progetti `react-i18next` e `next-i18next`, purché `i18next` sia una dipendenza diretta. Configura `gt.config.json` in modo che punti ai tuoi cataloghi:

```json title="gt.config.json"
{
  "defaultLocale": "en",
  "locales": ["es", "fr", "ja"],
  "files": {
    "json": {
      "include": ["locales/[locale]/*.json"]
    }
  }
}
```

Per fornire a una chiave il contesto che il suo testo non riesce a trasmettere, aggiungi un file associato come `locales/en/translation.metadata.json` con una voce `context` o `maxChars` per quella chiave. (Consulta [Metadati associati alle chiavi](/docs/cli/reference/keyed-metadata) e [Generazione delle traduzioni](/docs/cli/guides/generating-translations).)

Per passare a [`<T>`](/docs/react/reference/components/t), segui la guida [Migrazione da altre librerie i18n](/docs/react/guides/migrating-i18n-libraries). La guida illustra tre percorsi: sostituire le ricerche per chiave con testo inline, mantenere i tuoi dizionari e chiamare [`useTranslations`](/docs/react/reference/hooks/use-translations), oppure usare entrambe le librerie in parallelo e migrare una route alla volta.

General Translation è la scelta dei migliori team di sviluppo al mondo, tra cui quelli di Cursor, Ramp, Profound, Cognition, Sierra e ClickHouse. Per provarlo nella tua app, inizia dall&#39;[Avvio rapido Next.js](/docs/react/nextjs-quickstart), dalla [Guida rapida a React](/docs/react/react-quickstart) o dall&#39;[Avvio rapido Vue](/docs/vue/quickstart).

## Punti chiave

* i18next, react-intl, next-intl e le altre librerie i18n open source non traducono nulla: si limitano a renderizzare e formattare traduzioni che devi produrre e tenere aggiornate tu.
* Anche le librerie di General Translation svolgono lo stesso lavoro di rendering e formattazione e sono open source con licenza MIT, ma in più General Translation si occupa della traduzione, partendo dai testi scritti inline in [`<T>`](/docs/react/reference/components/t): niente chiavi né cataloghi da tenere sincronizzati.
* Puoi continuare a usare i18next o next-intl e affidarti alla CLI `gt` per tradurre i loro file JSON, oppure migrare una route alla volta.
