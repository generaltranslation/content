## Introduzione

Uno degli errori più comuni che vedo nell&#39;internazionalizzazione è la tendenza a
spezzare semplici espressioni ternarie in più chiamate di traduzione.
Spesso il risultato è qualcosa del genere:

```jsx
'use client'

import { T, useGT } from 'gt-react'

export default function ThemeSetting({ enabled }) {
  const gt = useGT()

  return (
    <>
      <span>
        <T>Dark Mode:</T>
      </span>
      <button>{enabled ? gt('On') : gt('Off')}</button>
    </>
  )
}
```

Nella maggior parte dei casi, funziona come previsto. Prima di implementare l&#39;i18n, il codice era probabilmente qualcosa del tipo `{ enabled ? 'On' : 'Off' }`.
Aggiungere la funzione `gt()` per l&#39;i18n è stata probabilmente solo un&#39;estensione naturale della struttura del codice esistente.

Ogni volta che vedo una cosa del genere, mi viene un brivido. Non è affatto il modo in cui la libreria è stata pensata per essere usata.
Ci sono due motivi per cui si tratta di un errore, soprattutto quando si usa la traduzione automatica: (1) il contesto e (2) la flessibilità.

### Contesto

Il significato non risiede solo nelle parole, ma anche nel modo in cui vengono presentate.
La parola &quot;back&quot; su una freccia per tornare indietro ha probabilmente un significato molto diverso dalla parola &quot;back&quot; (schiena) nel curriculum di un chiropratico.
Inoltre, senza un contesto più ampio, i traduttori (anche quelli umani) potrebbero avere difficoltà a tradurre correttamente la parola.
È famoso il caso del reparto i18n di WhatsApp che, in uno strumento di modifica delle immagini, tradusse in tedesco la parola &quot;crop&quot; (ritagliare) nel senso agricolo di &quot;raccolto&quot;.

Per aggirare questo problema di contesto, possiamo fornire informazioni sulla presentazione dei contenuti tramite i componenti [`<T>`](/docs/react/reference/components/t) e [`<Branch>`](/docs/react/reference/components/branch).
Nel nostro esempio, questo darebbe al nostro &quot;traduttore&quot; un quadro più completo del significato di &quot;on&quot; e &quot;off&quot;.

```jsx
<T>
  <span>Dark Mode:</span>
  <button>
    <Branch branch={enabled.toString()} true="On" false="Off" />
  </button>
</T>
```

### Flessibilità

Oltre al contesto, un altro modo interessante per sfruttare la traduzione tramite LLM è la sua capacità di comprendere il codice.
Vediamo un esempio in cui l&#39;ordine dei componenti può cambiare a seconda della lingua:

```jsx
<T>
  I eat lunch at <Branch branch={atHome.toString()} true="home" false="work" />.
</T>
```

Abbiamo quindi due frasi possibili:

* &quot;Pranzo **a casa**&quot;
* &quot;Pranzo **al lavoro**&quot;

In mandarino avremmo:

* &quot;我**在家**吃午餐&quot;
* &quot;我**在公司**吃午餐&quot;

Il componente [`<T>`](/docs/react/reference/components/t) riconosce che in questo caso l&#39;ordine delle parole nella frase deve cambiare e riorganizza il proprio contenuto figlio
di conseguenza, cosa difficilmente realizzabile usando gli operatori ternari con la traduzione delle stringhe.

```jsx
<T>
  我在
  <Branch branch={atHome.toString()} true="家" false="公司" />
  吃午餐。
</T>
```

### Conclusione

Se c&#39;è una cosa da ricordare di questo articolo, è che dovresti sempre cercare modi per sfruttare il contesto e la flessibilità nel tuo codice.
Il componente [`<Branch />`](/docs/react/reference/components/branch) è probabilmente uno dei modi più semplici per farlo.

Per maggiori dettagli, consulta la documentazione del [componente `<Branch />`](/docs/react/reference/components/branch).
