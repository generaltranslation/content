Paraglide JS è una libreria i18n basata sul compilatore, sviluppata da inlang. I messaggi risiedono in file JSON come `messages/en.json` e il compilatore trasforma ciascuno di essi in una funzione tipizzata da richiamare con `m.greeting({ name })`, così il bundler può escludere i messaggi che una pagina non usa mai. La traduzione, però, resta a carico tuo: ogni messaggio in ogni lingua deve arrivare da te, da un traduttore o da un comando di traduzione automatica eseguito sui file. Anche le librerie di General Translation renderizzano le traduzioni, ma General Translation in più le genera, a partire dai testi che scrivi una sola volta, inline, nei tuoi componenti.

## I punti di forza di Paraglide JS

* **Sicurezza dei tipi.** Le chiavi dei messaggi e i relativi parametri vengono generati come tipi. Con la versione 2.29.0, sia un `m.greting()` con un errore di battitura sia una chiamata a `m.greeting({})` senza il parametro `name` producono errori TypeScript.
* **Dimensione del bundle.** I messaggi vengono compilati in moduli ES, quindi quelli inutilizzati vengono eliminati tramite tree-shaking. Nel [benchmark pubblicato](https://paraglidejs.com/benchmark) da Paraglide, una pagina che utilizzava 100 messaggi su 200 in cinque impostazioni regionali trasferiva 47 KB con Paraglide e 205 KB con i18next.
* **Plurali e varianti.** Il formato dei messaggi predefinito [dichiara un selettore di plurale](https://paraglidejs.com/variants) e confronta le categorie CLDR come `one`, `few` e `many`. I [plugin](https://paraglidejs.com/file-formats) aggiungono il supporto per ICU MessageFormat 1 e per i file di i18next, mentre i formattatori gestiscono numeri, date e tempo relativo tramite `Intl`.
* **Strategie per l&#39;impostazione regionale.** Un [elenco `strategy`](https://paraglidejs.com/strategy) ordinato risolve l&#39;impostazione regionale a partire dall&#39;URL, da un cookie, da `localStorage`, dalla lingua preferita del browser, da una variabile globale, da strategie personalizzate o da `baseLocale`. Nella versione 2.29.0 il [valore predefinito](https://github.com/opral/paraglide-js/blob/main/src/compiler/compiler-options.ts) è `cookie`, poi `globalVariable` e infine `baseLocale`. Il [middleware lato server](https://paraglidejs.com/middleware) e `localizeUrl` gestiscono le route localizzate.
* **Ampio supporto ai framework.** Paraglide [funziona con qualsiasi app Vite](https://paraglidejs.com/vite) e offre guide per React, Vue, Solid, SvelteKit, TanStack Start, React Router, Astro e Next.js. È l&#39;[add-on su cui si basa `npx sv add paraglide`](https://paraglidejs.com/sveltekit) nella CLI di Svelte. La sua [guida per Next.js](https://paraglidejs.com/next-js) copre l&#39;App Router tramite un plugin webpack, da eseguire con il flag `--webpack`.
* **Strumenti gratuiti e aperti.** La libreria è distribuita con [licenza MIT](https://github.com/opral/paraglide-js/blob/main/LICENSE). La [CLI di inlang](https://inlang.com/m/2qj2w8pu/app-inlang-cli) verifica i progetti in CI, [Sherlock](https://inlang.com/m/r7kp499g/app-inlang-ideExtension) mostra le traduzioni inline in VS Code e [Fink](https://fink.inlang.com/) è un editor gratuito nel browser che esegue il commit delle modifiche dei traduttori in un repository GitHub.

## Cosa Paraglide JS lascia a carico tuo

Un progetto inlang è una cartella `project.inlang` il cui file `settings.json` elenca le impostazioni regionali, i plugin e il percorso dei file dei messaggi. Ecco una casella di posta con un messaggio semplice, un parametro e un plurale:

```json title="messages/en.json"
{
  "inbox_title": "Inbox",
  "greeting": "Hello {name}!",
  "unread_messages": [
    {
      "declarations": ["input count", "local countPlural = count: plural"],
      "selectors": ["countPlural"],
      "match": {
        "countPlural=one": "You have {count} unread message.",
        "countPlural=*": "You have {count} unread messages."
      }
    }
  ]
}
```

```tsx title="Inbox.tsx"
import { m } from './paraglide/messages.js';

export function Inbox({ name, count }: { name: string; count: number }) {
  return (
    <section>
      <h1>{m.inbox_title()}</h1>
      <p>{m.greeting({ name })}</p>
      <p>{m.unread_messages({ count })}</p>
    </section>
  );
}
```

Ogni altra impostazione regionale richiede un proprio file con le stesse chiavi e con le varianti previste da quella lingua: il polacco gestisce `one`, `few`, `many` e `*`. Se una chiave manca in `messages/pl.json`, la funzione compilata ripiega sull&#39;impostazione regionale di base senza alcun avviso. Ecco il componente renderizzato con un file polacco privo di `greeting`:

```text title="Output"
pl  <h1>Skrzynka odbiorcza</h1><p>Hello Ada!</p><p>Masz 2 nieprzeczytane wiadomości.</p>
```

`npx @inlang/cli check` l&#39;ha rilevato: ha segnalato che `greeting` non ha una traduzione in polacco ed è terminato con codice di uscita 1, così la CI può bloccare la lacuna. Colmarla, però, resta compito tuo. `inlang machine translate` traduce i messaggi mancanti usando per impostazione predefinita un servizio gratuito gestito dalla community, oppure la tua chiave di Google Cloud Translation o DeepL, un messaggio alla volta e senza il componente in cui compare. La documentazione stessa della CLI di inlang suggerisce che gli agenti di programmazione con contesto sul prodotto e sul codice possono produrre bozze migliori di una traduzione automatica generica.

## General Translation scrive le traduzioni

Le librerie di General Translation svolgono lo stesso lavoro di rendering. La differenza sta in dove si trovano i testi e in chi li traduce. Ecco la stessa inbox con `gt-react`:

```tsx title="Inbox.tsx"
import { T, Plural, Num, Var } from 'gt-react';

export function Inbox({ name, count }: { name: string; count: number }) {
  return (
    <T>
      <section>
        <h1>Inbox</h1>
        <p>Hello <Var>{name}</Var>!</p>
        <Plural
          n={count}
          singular={<p>You have <Num>{count}</Num> unread message.</p>}
          plural={<p>You have <Num>{count}</Num> unread messages.</p>}
        />
      </section>
    </T>
  );
}
```

Non c&#39;è alcun file di messaggi da tenere allineato: il testo inglese è il componente stesso. [`npx gt translate`](/docs/cli/reference/commands/translate) invia ogni blocco [`<T>`](/docs/react/reference/components/t), insieme alla sua struttura di elementi, all&#39;API di General Translation e scrive una traduzione per ogni impostazione regionale di destinazione: in questo modo una nuova frase viene tradotta prima della build, anziché ripiegare sull&#39;inglese. Un valore in [`<Var>`](/docs/react/reference/components/var) non viene mai inviato all&#39;API, e [`<Plural>`](/docs/react/reference/components/plural) sceglie un ramo in base alle regole del plurale dell&#39;impostazione regionale del lettore. [`npx gt validate`](/docs/cli/reference/commands/validate) verifica il progetto senza chiamare l&#39;API, mentre [`gt generate`](/docs/cli/reference/commands/generate) genera file template per i team che traducono manualmente.

Il titolo, il saluto e i rami del plurale all&#39;interno di questo blocco vengono inviati insieme per la traduzione. General Translation applica inoltre il [Glossario e i prompt personalizzati](/docs/platform/dashboard/guides/defining-context-for-translations) assegnati al progetto, e i revisori modificano i risultati nella dashboard. Aggiungi la CLI alla pipeline di CI, oppure configura [Locadex](/docs/platform/locadex/quickstart) per aprire pull request di traduzione a ogni modifica del codice.

Le librerie JavaScript di General Translation sono rilasciate con licenza MIT e funzionano con traduzioni fornite da te, senza bisogno di un account. Includere le traduzioni nel bundle dell&#39;app rende il rendering indipendente dal servizio ospitato; la consegna tramite CDN ti permette invece di pubblicare le modifiche alle traduzioni separatamente dai rilasci dell&#39;applicazione. Per la configurazione, consulta [archiviazione delle traduzioni](/docs/react/guides/storing-translations).

Sierra pubblica i suoi contenuti web e go-to-market in oltre 7 impostazioni regionali con General Translation. (Vedi [distribuzioni in produzione](https://generaltranslation.com/enterprise).)

## Paraglide JS e General Translation a confronto

| Funzionalità             | Paraglide JS                                                                                   | General Translation                                                                                                                                             |
| ------------------------ | ---------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Come si scrivono i testi | Chiavi in un file JSON per ogni impostazione regionale, richiamate come `m.key()`              | JSX all&#39;interno di [`<T>`](/docs/react/reference/components/t), stringhe tramite [`useGT`](/docs/react/reference/hooks/use-gt) o dizionari basati su chiavi |
| Traduce i tuoi contenuti | No; `inlang machine translate` usa un servizio della community, Google o DeepL                 | Sì, con [`npx gt translate`](/docs/cli/reference/commands/translate)                                                                                            |
| Cosa vede il traduttore  | Il contenuto del messaggio passato allo strumento di traduzione scelto                         | Il blocco JSX contrassegnato, le note dello sviluppatore, il Glossario e i prompt personalizzati assegnati                                                      |
| Sicurezza dei tipi       | Tipi generati per ogni chiave e parametro                                                      | JSX inline, senza chiavi di messaggio da digitare in modo errato                                                                                                |
| Bundle                   | Tree-shaking per singolo messaggio                                                             | Le traduzioni vengono caricate per impostazione regionale                                                                                                       |
| Traduzione mancante      | Fallback sull&#39;impostazione regionale di base; `inlang check` la segnala                    | Generata da [`npx gt translate`](/docs/cli/reference/commands/translate); il contenuto non tradotto viene renderizzato nella lingua di origine                  |
| Framework                | App Vite, React, Vue, Solid, SvelteKit, Astro, TanStack Start, React Router, Next.js (webpack) | React, Next.js, Vue, Node.js e [altri SDK](/docs/overview/get-started)                                                                                          |
| Costo                    | Gratuito e open source                                                                         | Librerie JavaScript gratuite; [traduzione fatturata in base all&#39;utilizzo](https://generaltranslation.com/pricing)                                           |

Resta su Paraglide JS se sviluppi con SvelteKit, Astro o Solid, se per te contano soprattutto il tree-shaking per singolo messaggio e le funzioni di messaggio tipizzate, oppure se il tuo team scrive o acquista già le proprie traduzioni. Scegli General Translation se vuoi testi leggibili direttamente nei componenti e ogni lingua generata a ogni build tenendo conto del contesto del tuo codice.

## Passare a General Translation un componente alla volta

È possibile migrare un componente alla volta. I messaggi di Paraglide sono semplici funzioni e non richiedono alcun provider, quindi una chiamata `m.*` e un blocco [`<T>`](/docs/react/reference/components/t) possono essere renderizzati fianco a fianco mentre converti le route. La guida [Migrazione delle librerie i18n](/docs/react/guides/migrating-i18n-libraries) illustra i passaggi, a partire dalla [Guida rapida a React](/docs/react/react-quickstart) o dall&#39;[Avvio rapido di Next.js](/docs/react/nextjs-quickstart).

## Punti chiave

* Paraglide JS compila i cataloghi in funzioni tipizzate e compatibili con il tree-shaking. Strumenti inlang separati possono generare le traduzioni per questi cataloghi.
* General Translation mantiene i testi inline in [`<T>`](/docs/react/reference/components/t) e genera le traduzioni sfruttando il contesto del codice, del Glossario e dei prompt personalizzati, con la revisione nella dashboard.
* Puoi continuare a usare i messaggi Paraglide esistenti mentre sposti i componenti su General Translation. Ogni componente migrato porta con sé, direttamente nel JSX, il testo di origine e il contesto di traduzione.
