## Pourquoi la pluralisation est importante dans React

On croise souvent des applications qui affichent des messages maladroits comme :

```text
Vous avez 1 nouveau(x) message(s)
```

C&#39;est le signe révélateur d&#39;un développeur qui n&#39;a pas vraiment réfléchi à l&#39;expérience utilisateur.

Les applications React doivent souvent gérer la pluralisation — pour le nombre de notifications, la longueur des listes ou les résultats de recherche.
**Et bien gérer la pluralisation n&#39;a rien de très compliqué, surtout si votre application n&#39;est disponible qu&#39;en anglais.**
Mais les développeurs débutants tombent souvent dans de nombreux pièges, en particulier lorsqu&#39;ils conçoivent des interfaces multilingues.

Ce guide explique comment gérer proprement les formes plurielles en anglais, formater les nombres selon les différents paramètres régionaux et mettre en place un système de pluriels entièrement multilingue avec React et Next.js.

### Le problème des formes plurielles codées en dur

De nombreux projets, y compris certains étonnamment vastes et importants, codent en dur la logique de pluralisation.

```jsx
export default function Example({ n }) {
  return (
    <p>
      Displaying {n} item{n === 1 ? '' : 's'}
    </p>
  )
}
```

Mais la pluralisation est souvent plus complexe que le simple ajout d’un &quot;s&quot; à la fin d’un mot.
Certains noms ont des formes du pluriel irrégulières, comme &quot;child&quot; et &quot;children&quot; en anglais.
Parfois, d’autres parties de la phrase doivent aussi s’accorder avec le nom, comme
&quot;is&quot; et &quot;are&quot; selon le nombre.

Le tableau ci-dessous présente quelques scénarios courants :

| Scénario               | Exemples                                                                                    | Notes                                                                                               |
| ---------------------- | ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Nombre de spectateurs  | &quot;1 person is watching&quot; <br /> &quot;2 people are watching&quot;                   | Le nom irrégulier (&quot;person&quot; → &quot;people&quot;) et le verbe doivent changer.            |
| Suppression d’éléments | &quot;Delete this message?&quot; <br /> &quot;Delete these 2 messages?&quot;                | Le démonstratif change (&quot;this&quot; ou &quot;these&quot;), en plus de la pluralisation du nom. |
| Résultats de recherche | &quot;No results&quot; <br /> &quot;1 result found&quot; <br /> &quot;2 results found&quot; | Formulation différente pour zéro, un ou plusieurs résultats.                                        |

Avec des expressions conditionnelles, le code devient vite ingérable.

Et cela tourne au cauchemar dès qu’il faut publier votre application dans d’autres langues.
Ce qui fonctionne en anglais ne fonctionne souvent plus du tout dans des langues comme le polonais ou l’arabe, dont les règles de gestion des quantités sont totalement différentes.
**Les entreprises avec lesquelles nous travaillons repoussent souvent l’internationalisation
tant il est pénible de refactoriser une UI codée en dur comme celle-ci.**

## Comment gérer les formes plurielles en anglais

En anglais, employer les bonnes formes plurielles dans votre application est généralement simple.

Pour la pluralisation simple des noms, écrivez une fonction utilitaire :

```jsx
export function pluralize(
  count: number,
  singular: string,
  plural: string = singular + 's'
) {
  return `${count === 1 ? singular : plural}`;
}
```

Désormais, une seule fonction suffit pour gérer toute votre logique de pluralisation,
et elle prend aussi en charge les formes plurielles irrégulières :

```js
pluralize(2, 'user') // "users"
pluralize(2, 'person', 'people') // "people"
pluralize(2, 'child', 'children') // "children"
```

Mais que faire si vous avez besoin d&#39;une logique plus complexe, par exemple :

```text
"No one is watching"
"1 person is watching"
"2 people are watching"
```

À ce stade, il est temps d’envisager sérieusement une bibliothèque d’internationalisation (« i18n ») nécessitant peu de maintenance.

Bien que les développeurs pensent souvent que les bibliothèques i18n ne servent qu’aux interfaces multilingues,
elles peuvent s’avérer très utiles pour le formatage des pluriels et des variables, même dans des applications monolingues.
En interne, la plupart des bibliothèques i18n s’appuient sur l’API native `Intl.PluralRules` de JavaScript pour déterminer la forme du pluriel adaptée à chaque langue.

Il existe de nombreuses bibliothèques i18n pour React, dont la nôtre, [`gt-react`](/docs/react/overview) (ou [`gt-next`](/docs/react/nextjs-quickstart) si vous utilisez Next.js).
Avec gt-react, afficher un pluriel anglais est très simple :

```jsx
import { Plural } from 'gt-react'

function Example({ count }) {
  return (
    <Plural n={count} zero={'No one is watching'} one={`${count} person is watching`}>
      {count} people are watching
    </Plural>
  )
}
```

L’UI est affichée de manière conditionnelle en fonction de la valeur de `n`.

La plupart des bibliothèques utilisent l’API [`Intl.PluralRules`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules) de JavaScript pour déterminer quelle forme du pluriel afficher.
Ainsi, en anglais, vous utiliseriez le nom `"one"` pour désigner le singulier et `"other"` pour désigner le pluriel.
Notre composant [`<Plural>`](/docs/react/reference/components/plural) vérifie d’abord la catégorie de pluriel exacte, puis les props génériques `plural` et `other`. Il ne se rabat sur ses éléments enfants que si aucune de ces props n’est disponible.

Recourir à une bibliothèque est une bonne pratique, même pour les applications uniquement en anglais, et facilite grandement une future internationalisation.

## Pluralisation dans les applications React multilingues (i18n)

Si votre application ne s’adresse qu’à des utilisateurs anglophones, l’approche ci-dessus peut suffire — mais la plupart des applications en production finissent par devoir prendre en charge plusieurs langues. C’est là que les choses se corsent.

* En arabe, les noms prennent des formes différentes selon qu’il y en a zéro, un, deux ou plusieurs
* Dans des paramètres régionaux comme `de-DE`, `es-ES` et `it-IT`, les grands nombres utilisent des points au lieu de virgules : 1,000,000 devient ainsi 1.000.000
* En hindi, les chiffres sont regroupés par paires : 1,000,000 devient ainsi 10,00,000

**Pour une application internationalisée, utilisez une bibliothèque d’i18n dédiée**, qui fournira sa propre documentation sur la gestion des formes plurielles et le formatage des nombres.

### Formatage des nombres selon les paramètres régionaux

Vous pouvez utiliser l’objet `Intl` pour [formater des nombres](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/NumberFormat) dans n’importe quel paramètre régional.
Le plus simple est d’utiliser la méthode intégrée `toLocaleString()`.

Par défaut, elle utilise le paramètre régional actuel de l&#39;environnement d&#39;exécution :

```javascript
const n = 1000000
n.toLocaleString() // affiche 1,000,000 lorsque le paramètre régional de l'environnement d'exécution est "en-US" (anglais américain)
n.toLocaleString('de') // 1.000.000, car le paramètre régional spécifié est "de" (allemand)
```

gt-react propose également un composant [`<Num>`](/docs/react/reference/components/num), qui s&#39;appuie en interne sur `Intl.NumberFormat`.

```jsx
import { Num } from 'gt-react'

// affiche 1,000,000 lorsque la langue est « en-US »
// affiche 1.000.000 lorsque la langue est « de »
// affiche 10,00,000 lorsque la langue est « hi »
export default function Example() {
  return <Num>1000000</Num>
}
```

### Comprendre les formes du pluriel selon les langues

Les six formes du pluriel prises en charge par l&#39;API `Intl.PluralRules` de JavaScript sont : `zero`, `one`, `two`, `few`, `many` et `other`.
Si l&#39;anglais n&#39;utilise que `one` (« singulier ») et `other` (« pluriel »),
des langues comme l&#39;arabe ou le polonais en comptent davantage.

Par exemple, un utilisateur anglophone s&#39;attendra à voir :

```text
"No one is watching"
"1 person is watching"
"2 people are watching"
```

Alors qu&#39;un utilisateur arabophone s&#39;attendra à des expressions différentes pour le singulier,
le duel (lorsqu&#39;il y a exactement deux éléments), ainsi que pour les formes du pluriel désignant de petites et de grandes quantités :

```text
"لا أحد يشاهد"
"1 شخص يشاهد"
"2 شخصان يشاهدان"
"3 أشخاص يشاهدون"
"11 شخصاً يشاهدون"
```

C’est là qu’une bibliothèque d’internationalisation devient indispensable.
Chaque langue a sa propre logique pour déterminer quand et comment afficher les formes plurielles :
mieux vaut donc s&#39;appuyer sur une bibliothèque dédiée pour ne pas se tromper.

Une bonne bibliothèque d’i18n remplit deux rôles :

1. Déterminer quelle forme du pluriel (`one`, `many`, `other`, etc.) utiliser en fonction du paramètre régional
2. Trouver, dans la bonne langue, la traduction correspondant à cette forme

**Si vous utilisez déjà une bibliothèque d’internationalisation,
consultez sa documentation pour en savoir plus sur le formatage des pluriels.**
Presque toutes les bibliothèques proposent une documentation dédiée à l’affichage des formes plurielles.

### Exemple complet : formes plurielles dans une application React multilingue

Si vous n&#39;utilisez pas encore de bibliothèque d&#39;internationalisation, essayez [`gt-react`](/docs/react/react-quickstart) !

Le composant [`<Plural>`](/docs/react/reference/components/plural) de gt-react :

* Offre un moyen simple et déclaratif d&#39;afficher correctement les formes plurielles dans React
* Fonctionne nativement avec le composant de formatage [`<Num>`](/docs/react/reference/components/num)
* Fonctionne nativement avec le composant de traduction [`<T>`](/docs/react/reference/components/t), qui s&#39;intègre à notre [service de traduction](https://generaltranslation.com) pour générer automatiquement les formes du pluriel

En assemblant toutes ces briques, on obtient un composant multilingue complet :

```jsx
import { T, Plural, Num } from 'gt-react'

// Fonctionne clés en main dans plus de 100 langues
function Example({ count }) {
  return (
    <T>
      <Plural
        n={count}
        zero={'No one is watching'}
        one={
          <>
            <Num>{count}</Num> person is watching
          </>
        }
      >
        <Num>{count}</Num> people are watching
      </Plural>
    </T>
  )
}
```

***

Configurez la pluralisation avec le [Démarrage rapide `gt-react`](/docs/react/react-quickstart) pour les applications React ou le [Démarrage rapide `gt-next`](/docs/react/nextjs-quickstart) pour les applications Next.js. Consultez la [référence de l’API `<Plural>`](/docs/react/reference/components/plural) pour découvrir l’API complète du composant.

La pluralisation est l’un des défis i18n les plus fréquents dans React : la gérer correctement dès le départ vous épargne une refactorisation importante par la suite.
