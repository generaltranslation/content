La [plateforme de localisation](https://crowdin.com/) de Crowdin structure la localisation autour de projets de traduction : les ingénieurs maintiennent des fichiers de ressources, les connectent à Crowdin, puis réintègrent les catalogues traduits dans l’application. Son automatisation fait avancer le contenu à chaque étape de ce workflow. General Translation, lui, intègre la traduction directement au développement : les textes restent dans vos composants et les traductions sont générées lors de la compilation.

## Les points forts de Crowdin

* **Gratuit pour démarrer.** Le [forfait Free](https://crowdin.com/pricing) inclut 60 000 mots hébergés, les traductions étant partagées dans la mémoire de traduction de Crowdin. Les projets open source qui répondent à ses [critères de licence open source](https://crowdin.com/product/for-open-source) (par exemple une licence OSI et l’absence de produit commercial associé) peuvent obtenir une licence gratuite.
* **Outils pour développeurs.** Une CLI configurée dans `crowdin.yml`, des intégrations Git pour GitHub, GitLab, Bitbucket et Azure Repos, une GitHub Action, un serveur MCP et [plus de 700 applications et intégrations](https://store.crowdin.com/).
* **IA contextualisée.** Vous pouvez [utiliser vos propres clés OpenAI, Anthropic, Gemini ou d’autres fournisseurs](https://support.crowdin.com/crowdin-ai/), ou bien un modèle géré par Crowdin. Chaque requête inclut le contexte de la chaîne de caractères, sa clé et sa longueur maximale, et les prompts peuvent intégrer votre glossaire, votre mémoire de traduction, votre guide de style, les chaînes voisines et des captures d’écran étiquetées.
* **Traduction humaine.** Une place de marché de prestataires, ainsi que les [Crowdin Language Services](https://crowdin.com/features/vendor-integrations), à commander directement depuis un projet.
* **Contexte et contrôle qualité.** Des captures d’écran associées aux chaînes, un [éditeur In-Context pour les applications web](https://support.crowdin.com/in-context-localization/), un plugin Figma et des contrôles qualité intégrés.
* **Mises à jour mobiles à distance (OTA).** Des SDK iOS, Android et Flutter ainsi qu’un client JavaScript mettent à jour les chaînes depuis le [CDN de Crowdin](https://support.crowdin.com/content-delivery/), sans publier de nouvelle livraison de l’application.

## Ce que Crowdin laisse encore à vos ingénieurs

Les ingénieurs doivent toujours mettre en place et maintenir l’aller-retour entre l’application et les projets de traduction Crowdin :

1. Mettre en place une bibliothèque d’i18n, extraire chaque chaîne de caractères anglaise dans un fichier de ressources sous une clé, puis faire référence à cette clé dans le composant.
2. Décrire les fichiers dans `crowdin.yml` et les envoyer avec [`crowdin upload sources`](https://crowdin.github.io/crowdin-cli/commands/crowdin-upload-sources), ou passer par une intégration Git ou une GitHub Action.
3. Configurer l’IA, la traduction automatique, des prestataires ou vos traducteurs pour traduire chaque langue, avec les étapes de relecture dont votre projet a besoin.
4. Réintégrer les catalogues traduits dans l’application. L’[intégration GitHub de Crowdin](https://support.crowdin.com/github-integration/) les renvoie via une branche de service `l10n_`. Par défaut, sa synchronisation automatique s’exécute toutes les heures ; l’intervalle est configurable et une synchronisation immédiate est possible.

Crowdin peut aussi collecter du contexte à partir du code : grâce à ses compétences pour agents de codage et à ses [commandes `crowdin context`](https://crowdin.github.io/crowdin-cli/commands/crowdin-context), un agent analyse la base de code et téléverse des descriptions pour les chaînes. Avec le composant [`<T>`](/docs/react/reference/components/t) de General Translation, c’est le JSX balisé lui-même qui fournit le texte, les éléments imbriqués et les espaces réservés nommés utilisés pour la traduction.

Les forfaits payants sont principalement tarifés en fonction des mots hébergés (nombre de mots source multiplié par le nombre de langues cibles), auxquels s’ajoutent les sièges de gestionnaire : chaque nouvelle langue fait donc augmenter le nombre de mots hébergés. (Voir la [tarification de Crowdin](https://crowdin.com/pricing), consultée en octobre 2026.)

| ---------------------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Emplacement des chaînes      | Fichiers de ressources à clés dans votre dépôt, synchronisés avec les projets Crowdin                      | Dans votre code, au sein de [`<T>`](/docs/react/reference/components/t), ou dans vos fichiers de ressources existants                                               |
| Connexion au code            | `crowdin.yml` avec la CLI, des intégrations Git ou une GitHub Action                                       | [`npx gt translate`](/docs/cli/reference/commands/translate) dans votre processus de compilation, ou des pull requests [Locadex](/docs/platform/locadex/quickstart) |
| Qui traduit                  | Traduction automatique ou fournisseurs d’IA, prestataires ou vos propres traducteurs                       | L’IA, avec le contexte issu de votre code, du glossaire et des instructions personnalisées, puis relecture par votre équipe dans le tableau de bord                 |
| Contexte de chaque chaîne    | Clé, longueur maximale, captures d’écran, glossaire, mémoire de traduction et contexte rédigé par un agent | JSX balisé, espaces réservés nommés, notes des développeurs, ainsi que le glossaire et les instructions personnalisées attribués au projet                          |
| Tarification                 | Offre gratuite ; offres payantes selon le nombre de mots hébergés et de sièges de gestionnaire             | À l’usage de la traduction ; voir les [tarifs](https://generaltranslation.com/pricing)                                                                              |
| Applications mobiles natives | SDK de mise à jour à distance (OTA) pour iOS, Android et Flutter                                           | La CLI traduit les fichiers de ressources iOS et Android en vue de la livraison de l’application                                                                    |
| Open source                  | Licence gratuite pour les projets open source éligibles                                                    | Bibliothèques JavaScript et CLI sous licence MIT                                                                                                                    |

## Pourquoi les équipes choisissent General Translation plutôt que Crowdin

General Translation vous évite de rédiger des catalogues pour l&#39;interface React : les textes restent dans vos composants, à l&#39;intérieur de [`<T>`](/docs/react/reference/components/t). Supprimer un composant supprime aussi ses textes intégrés, sans laisser de clés orphelines à nettoyer ailleurs.

* **Plus rapide.** Placez [`npx gt translate`](/docs/cli/reference/commands/translate) avant la compilation de votre application pour générer et télécharger les traductions dans le même workflow. La commande réutilise les traductions existantes et ne génère que le contenu nouveau ou modifié. Pour un workflow basé sur les pull requests, [Locadex](/docs/platform/locadex/quickstart) prépare les modifications de traduction à votre place.
* **Moins coûteux à l&#39;usage.** Chez Crowdin, le nombre de mots hébergés augmente avec la taille du catalogue source et le nombre de langues cibles. General Translation facture l&#39;utilisation de la traduction, et non l&#39;hébergement de ce catalogue. Conserver des traductions terminées n&#39;entraîne aucuns frais de traduction récurrents ; les tarifs d&#39;utilisation sont détaillés sur la page [tarifs](https://generaltranslation.com/pricing).
* **Meilleure qualité.** Un bloc [`<T>`](/docs/react/reference/components/t) peut regrouper un titre, une phrase, un lien et des espaces réservés dynamiques : le traducteur dispose ainsi du lien entre ces éléments plutôt que de clés isolées. Ajoutez des notes de développeur ainsi qu&#39;un [glossaire et des instructions personnalisées](/docs/platform/dashboard/guides/defining-context-for-translations) partagés pour la terminologie produit. Les relecteurs peuvent modifier le résultat dans l&#39;[Éditeur de Traduction](/docs/platform/dashboard/guides/reviewing-translations).
* **Moins de risques.** Vous pouvez conserver votre bibliothèque d’i18n existante et importer les traductions relues avant de changer la façon dont les nouvelles sont produites. Vous adoptez ainsi General Translation sans réécrire chaque composant ni perdre le travail de vos traducteurs.

Cursor publie son site web et sa documentation dans plus de 14 paramètres régionaux avec General Translation. (Voir les [déploiements en production](https://generaltranslation.com/enterprise).)

## Quand Crowdin est le meilleur choix

Optez pour Crowdin si votre projet open source est éligible à sa licence gratuite et souhaite s&#39;appuyer sur une communauté de traducteurs, si vous pilotez un programme de traduction humaine avec des prestataires et une relecture en plusieurs étapes, si vous échangez des fichiers XLIFF ou Office, ou encore si vos applications mobiles natives ont besoin de ses SDK de mise à jour OTA (over-the-air).

## Passer de Crowdin à General Translation

Pour les catalogues pris en charge, comme les fichiers JSON, YAML, PO et les fichiers de ressources iOS ou Android, configurez leurs chemins source et de paramètres régionaux dans `gt.config.json`. Suivez la [configuration initiale de la traduction de fichiers](/docs/cli/quickstart), puis exécutez [`npx gt upload`](/docs/cli/reference/commands/upload) pour importer vos traductions existantes avant d&#39;en générer de nouvelles. Importez votre glossaire dans un [groupe de contexte](/docs/platform/dashboard/guides/defining-context-for-translations) afin que les nouvelles traductions reprennent la même terminologie.

Dans une application React, vous pouvez ensuite adopter [`<T>`](/docs/react/reference/components/t) progressivement, au fil de la création de nouveaux écrans. Pour comparer les différents prestataires, consultez [Pourquoi utiliser General Translation plutôt qu&#39;un TMS ?](/kb/general-translation-vs-tms).

## General Translation est-il une alternative à Crowdin ?

Oui. General Translation associe traduction par IA, éditeur de révision humaine et bibliothèques qui conservent les textes React dans le JSX. Il traduit également les catalogues existants : vous pouvez donc remplacer Crowdin sans avoir à changer au préalable de bibliothèque d’i18n.

## Points clés

* Crowdin est un TMS solide pour les programmes de traduction open source et humaine, avec une offre gratuite et une IA qui exploite les clés, les captures d&#39;écran et les glossaires.
* Crowdin automatise la livraison des catalogues ; il revient toutefois aux ingénieurs de connecter ces catalogues à l&#39;application et de configurer le workflow de traduction.
* Choisissez General Translation pour éliminer les catalogues à clés de la rédaction React, générer des traductions au moment d&#39;une livraison et conserver vos traductions existantes déjà relues lors de la migration.
