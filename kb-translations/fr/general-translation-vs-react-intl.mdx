react-intl est la [bibliothèque React de FormatJS](https://formatjs.github.io/docs/react-intl). Vous écrivez chaque message directement dans le code sous forme de `defaultMessage` en ICU MessageFormat, ajoutez une `description` à l’intention des traducteurs, rassemblez tous les messages dans un catalogue JSON avec `formatjs extract`, puis affichez les catalogues traduits via `IntlProvider`. Elle ne traduit rien : le catalogue extrait est confié à vous-même, à vos traducteurs ou à un système de gestion de la traduction (TMS), puis les fichiers traduits vous reviennent pour être compilés. Les bibliothèques de General Translation affichent elles aussi des messages ICU, mais General Translation génère en plus les traductions.

## Les points forts de react-intl

* **ICU MessageFormat de bout en bout.** [Formes plurielles avec `#` et correspondances exactes comme `=0`, `select` et `selectordinal`](https://formatjs.github.io/docs/core-concepts/icu-syntax), le tout reposant sur les API `Intl` du navigateur.
* **Texte source intégré.** FormatJS [recommande d’écrire `defaultMessage` et `description` directement dans le code](https://formatjs.github.io/docs/getting-started/message-declaration) et de laisser `babel-plugin-formatjs` ou `@swc/plugin-formatjs` générer les ID de messages : personne n’a donc à inventer de clés.
* **Des outils pensés pour un workflow avec TMS.** [`formatjs extract`](https://formatjs.github.io/docs/tooling/cli) génère le catalogue, des formateurs intégrés produisent des fichiers pour Crowdin, Lokalise, Smartling et Transifex, `formatjs compile` pré-analyse les messages et `formatjs verify` contrôle les catalogues pour repérer les clés manquantes ou superflues.
* **TypeScript.** [La version 12 permet de typer les arguments ICU de chaque message](https://formatjs.github.io/docs/react-intl/upgrade-guide-12.x).
* **Maintenance active.** [La version 12 est sortie en septembre 2026](https://github.com/formatjs/formatjs/blob/main/packages/react-intl/CHANGELOG.md), sous licence BSD-3-Clause.

## Ce que react-intl laisse à votre charge

Voici une petite boîte de réception avec react-intl. Le texte anglais reste dans le composant, sous forme de `defaultMessage` :

```jsx title="Inbox.jsx"
import { FormattedMessage } from 'react-intl';

export function Inbox({ count }) {
  return (
    <section>
      <h1>
        <FormattedMessage defaultMessage="Inbox" description="Heading of the inbox page" />
      </h1>
      <p>
        <FormattedMessage
          defaultMessage="You have {count, plural, one {# unread message} other {# unread messages}}."
          description="Number of unread messages in the inbox"
          values={{ count }}
        />
      </p>
    </section>
  );
}
```

`formatjs extract` transforme ces messages en un catalogue dont les clés sont des identifiants générés :

```json title="lang/en.json"
{
  "U5vJOY": {
    "defaultMessage": "You have {count, plural, one {# unread message} other {# unread messages}}.",
    "description": "Number of unread messages in the inbox"
  },
  "gBGgGs": {
    "defaultMessage": "Inbox",
    "description": "Heading of the inbox page"
  }
}
```

Chaque langue cible nécessite des messages traduits dont la syntaxe ICU est préservée. `IntlProvider` accepte des chaînes de messages ou des messages précompilés ; ces derniers sont générés par `formatjs compile`. Les descripteurs extraits contiennent chaque message et sa description. Pour obtenir les ID générés utilisés dans cet exemple, configurez le plugin Babel ou SWC dans votre processus de compilation. Avec l’[App Router de Next.js](https://formatjs.github.io/docs/guides/nextjs-app-router), les composants de react-intl s’exécutent dans des composants client, tandis que le code serveur formate les messages à l’aide de `createIntl`, importé depuis `react-intl/server`.

## Conserver les messages ICU et générer les traductions

Les bibliothèques de General Translation remplissent le même rôle que react-intl : elles affichent les messages ICU, appliquent les règles de pluriel propres à chaque paramètre régional et formatent les nombres, les devises et les dates. Vos chaînes ICU se migrent presque sans modification, car [`useGT`](/docs/react/reference/hooks/use-gt) accepte la même syntaxe :

```tsx title="Inbox.tsx"
import { useGT } from 'gt-react';

export function Inbox({ count }: { count: number }) {
  const gt = useGT();
  return (
    <section>
      <h1>{gt('Inbox', { $context: 'Heading of the inbox page' })}</h1>
      <p>
        {gt('You have {count, plural, one {# unread message} other {# unread messages}}.', {
          count,
          $context: 'Number of unread messages in the inbox',
        })}
      </p>
    </section>
  );
}
```

[`npx gt translate`](/docs/cli/reference/commands/translate) extrait ces chaînes, génère les traductions à partir de leurs notes de contexte et écrit les catalogues cibles, le tout en une seule commande. L’exemple conserve les deux descriptions FormatJS en tant que `$context`. Les [termes du glossaire et les instructions personnalisées](/docs/platform/dashboard/guides/defining-context-for-translations) partagés guident la terminologie et le ton, et les relecteurs ajustent les résultats dans le [tableau de bord](/docs/platform/dashboard/guides/reviewing-translations).

Le `#` est formaté selon chaque paramètre régional : un nombre comme 12345 s’affiche « 12,345 » en anglais et « 12.345 » en espagnol. Pour du JSX contenant du balisage, [`<T>`](/docs/react/reference/components/t) traduit l’intégralité du bloc balisé, éléments compris. Dans `gt-next`, il fonctionne directement dans les Composants serveur.

Le tableau de bord, la page d’accueil et l’application iOS de Ramp sont disponibles dans plus de 11 paramètres régionaux grâce à General Translation. (Voir les [déploiements en production](https://generaltranslation.com/enterprise).)

## react-intl vs General Translation en un coup d’œil

| Fonctionnalité         | react-intl                                                                                                                         | General Translation                                                                                                                  |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Rédaction des textes   | `defaultMessage` intégré en ICU, extrait vers un catalogue JSON                                                                    | JSX intégré dans [`<T>`](/docs/react/reference/components/t), ou chaînes ICU dans [`useGT`](/docs/react/reference/hooks/use-gt)      |
| Traduit votre contenu  | Non                                                                                                                                | Oui, avec [`npx gt translate`](/docs/cli/reference/commands/translate)                                                               |
| Workflow du catalogue  | Extraction des messages, traduction via le workflow de votre choix, précompilation facultative ; le plugin génère les identifiants | [`npx gt translate`](/docs/cli/reference/commands/translate) extrait et traduit avant votre compilation                              |
| Contexte de traduction | Le message et sa description                                                                                                       | Chaînes ICU avec `$context` ; structure JSX balisée avec des composants intégrés ; glossaire et instructions personnalisées partagés |
| App Router de Next.js  | Composants utilisés dans des composants client ; `createIntl` côté serveur                                                         | [`<T>`](/docs/react/reference/components/t) dans les Server Components comme dans les composants client                              |
| Licence                | [BSD-3-Clause](https://github.com/formatjs/formatjs/blob/main/packages/react-intl/LICENSE.md)                                      | Bibliothèques JavaScript et CLI sous licence MIT                                                                                     |

Conservez react-intl si vos catalogues ICU et les formateurs de votre TMS fonctionnent déjà, si vous vous appuyez sur ses arguments de message typés ou sur `formatjs verify`, ou si vous utilisez FormatJS en dehors de React. Optez pour General Translation si vous souhaitez conserver la rédaction en ICU tout en intégrant la génération et la relecture des traductions à votre workflow de développement.

## Migrer depuis react-intl

Migrez un composant ou une route à la fois. Remplacez chaque `<FormattedMessage>` par un appel à [`useGT`](/docs/react/reference/hooks/use-gt) qui conserve sa chaîne ICU et transmet sa description via `$context`, comme illustré ci-dessus. Pour du JSX enrichi, utilisez [`<T context="…">`](/docs/react/reference/components/t#context). Continuez à charger les catalogues react-intl existants pour les composants qui n’ont pas encore été migrés. Une fois le dernier composant migré, supprimez le plugin FormatJS ainsi que les scripts d’extraction et de compilation. (Voir [Migrer des bibliothèques i18n](/docs/react/guides/migrating-i18n-libraries).)

## Points clés

* react-intl formate les messages ICU et fournit des outils de gestion de catalogues ; la génération des traductions passe par un workflow distinct.
* General Translation extrait et traduit en une seule commande CLI, en conservant le contexte fourni par les descriptions et en mettant à la disposition des relecteurs un éditeur dans le tableau de bord.
* Vos chaînes ICU migrent presque telles quelles vers [`useGT`](/docs/react/reference/hooks/use-gt), un composant à la fois.
