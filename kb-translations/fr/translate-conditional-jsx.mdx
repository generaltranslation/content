## Introduction

L&#39;une des erreurs les plus courantes que je rencontre en internationalisation consiste à
découper de simples expressions ternaires en plusieurs appels de traduction.
Cela ressemble souvent à ceci :

```jsx
'use client'

import { T, useGT } from 'gt-react'

export default function ThemeSetting({ enabled }) {
  const gt = useGT()

  return (
    <>
      <span>
        <T>Dark Mode:</T>
      </span>
      <button>{enabled ? gt('On') : gt('Off')}</button>
    </>
  )
}
```

Dans l&#39;ensemble, cela fonctionne comme prévu. Avant l&#39;implémentation de l&#39;i18n, le code ressemblait sans doute à quelque chose comme `{ enabled ? 'On' : 'Off' }`.
L&#39;ajout de la fonction `gt()` pour l&#39;i18n n&#39;était probablement qu&#39;un prolongement naturel de la structure de code existante.

Chaque fois que je vois ça, je grimace intérieurement. Ce n&#39;est pas du tout l&#39;usage pour lequel la bibliothèque a été conçue.
Deux arguments montrent pourquoi c&#39;est une erreur, en particulier dans le contexte de la traduction automatique : (1) le contexte et (2) la flexibilité.

### Contexte

Le sens ne réside pas seulement dans les mots, mais aussi dans la manière dont ils sont présentés.
Le mot &quot;back&quot; sur une flèche de retour n&#39;a probablement rien à voir avec le mot &quot;back&quot; (dos) sur le CV d&#39;un chiropracteur.
De plus, sans contexte plus large, les traducteurs (même humains) peuvent avoir du mal à traduire correctement un mot.
On cite souvent l&#39;exemple du service i18n de WhatsApp, qui aurait traduit en allemand le mot &quot;crop&quot; (recadrer) d&#39;un outil d&#39;édition d&#39;images au sens agricole de « récolte ».

Pour contourner ce problème de contexte, nous pouvons transmettre des informations sur la présentation du contenu à l&#39;aide des composants [`<T>`](/docs/react/reference/components/t) et [`<Branch>`](/docs/react/reference/components/branch).
Dans notre exemple, notre &quot;traducteur&quot; aurait ainsi une vision plus complète de ce que signifient &quot;on&quot; et &quot;off&quot;.

```jsx
<T>
  <span>Dark Mode:</span>
  <button>
    <Branch branch={enabled.toString()} true="On" false="Off" />
  </button>
</T>
```

### Flexibilité

Au-delà du contexte, la traduction par LLM présente un autre atout intéressant : sa compréhension du code.
Prenons un exemple où l&#39;ordre des composants peut varier selon la langue :

```jsx
<T>
  I eat lunch at <Branch branch={atHome.toString()} true="home" false="work" />.
</T>
```

Nous avons donc deux phrases possibles :

* « Je déjeune **à la maison** »
* « Je déjeune **au travail** »

En mandarin, cela donnerait :

* « 我**在家**吃午餐 »
* « 我**在公司**吃午餐 »

Le composant [`<T>`](/docs/react/reference/components/t) détecte que l&#39;ordre des mots doit changer ici et réorganise ses éléments enfants
en conséquence — ce qui est difficilement réalisable avec des opérateurs ternaires et la traduction de chaînes.

```jsx
<T>
  我在
  <Branch branch={atHome.toString()} true="家" false="公司" />
  吃午餐。
</T>
```

### Conclusion

S&#39;il ne fallait retenir qu&#39;une chose de cet article, c&#39;est qu&#39;il faut toujours chercher à tirer parti du contexte et de la flexibilité dans votre code.
Le composant [`<Branch />`](/docs/react/reference/components/branch) est sans doute l&#39;un des moyens les plus simples d&#39;y parvenir.

Pour en savoir plus, consultez la documentation du [composant `<Branch />`](/docs/react/reference/components/branch).
