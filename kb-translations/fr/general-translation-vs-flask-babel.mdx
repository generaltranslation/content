Babel formate les dates, les nombres et les devises à l’aide des données Unicode CLDR, et sa commande `pybabel` extrait, met à jour et compile les catalogues de messages gettext. Flask-Babel intègre ces outils à la gestion des requêtes de Flask et aux modèles Jinja. General Translation remplit les catalogues entre l’extraction et la compilation : votre application bénéficie ainsi d’une traduction automatisée tout en conservant sa configuration initiale Flask-Babel.

## Les points forts de Babel et Flask-Babel

* **Formatage des paramètres régionaux à partir de CLDR.** [Babel 2.18.0 intègre les données CLDR 47](https://babel.pocoo.org/en/latest/changelog.html#version-2-18-0) pour plus d’un millier d’identifiants de paramètres régionaux. `format_currency(1234.5, "EUR")` renvoie « 1.234,50 € » en espagnol, et `format_date` renvoie « 16 października 2026 » en polonais.
* **Outils de catalogue.** [`pybabel extract`](https://babel.pocoo.org/en/latest/cmdline.html) analyse les fichiers Python et les modèles Jinja à l’aide d’une correspondance `babel.cfg`, `pybabel init` crée un fichier PO avec la bonne règle de pluriel et le nombre de formes adéquat (trois pour le polonais), `pybabel update` fusionne les nouvelles chaînes et marque comme fuzzy celles qui ont été modifiées, et `pybabel compile` génère les fichiers `.mo`.
* **Intégration Flask.** Un `locale_selector` et un `timezone_selector` [déterminent le paramètre régional et le fuseau horaire de chaque requête](https://python-babel.github.io/flask-babel/#configuration), `lazy_gettext` gère les chaînes définies au moment de l’import, les modèles Jinja disposent de `_()`, de `{% trans %}` et de filtres de formatage, et `force_locale` permet de changer temporairement de paramètre régional, par exemple pour envoyer un e-mail dans une autre langue.
* **Stables et gratuits.** Tous deux sont distribués sous licence BSD (voir [la licence de Babel](https://babel.pocoo.org/en/latest/license.html)). Babel fonctionne dans n’importe quel programme Python ; la [version actuelle de Flask-Babel est la 4.0.0](https://github.com/python-babel/flask-babel/releases/tag/v4.0.0).

## Ce que Babel et Flask-Babel laissent à votre charge

Voici une petite application Flask-Babel :

```python title="app.py"
from datetime import date
from flask import Flask, request
from flask_babel import Babel, gettext, ngettext, format_currency, format_date


def select_locale():
    return request.accept_languages.best_match(["en", "es", "pl"])


app = Flask(__name__)
babel = Babel(app, locale_selector=select_locale)


@app.route("/inbox/<int:count>")
def inbox(count):
    return {
        "title": gettext("Inbox"),
        "unread": ngettext("You have %(num)d unread message.", "You have %(num)d unread messages.", count),
        "price": format_currency(1234.5, "EUR"),
        "date": format_date(date(2026, 10, 16), format="long"),
    }
```

`pybabel extract`, `pybabel init -l pl` et `pybabel compile` génèrent un catalogue polonais où tous les `msgstr` sont vides. Avec Flask-Babel 4.0.0, une requête envoyée avec `Accept-Language: pl` a alors renvoyé :

```json title="Output"
{
  "date": "16 października 2026",
  "price": "1 234,50 €",
  "title": "Inbox",
  "unread": "You have 5 unread messages."
}
```

Babel formate la date et le prix pour le polonais, mais toutes les chaînes restent en anglais, sans le moindre avertissement. Chaque chaîne attend que quelqu&#39;un remplisse son entrée PO, y compris les trois formes du pluriel du polonais, puis qu&#39;on exécute `pybabel compile` et qu&#39;on redéploie. Et pour chaque chaîne ajoutée ou modifiée, il faut recommencer dans chaque langue.

## Traduire les catalogues Babel avec General Translation

Si Flask-Babel vous convient déjà, conservez-le et laissez le CLI de General Translation générer les catalogues. Créez une seule fois un catalogue anglais, puis mettez-le à jour après chaque extraction, afin que la source figure dans la même arborescence que les traductions :

```bash
pybabel extract -F babel.cfg -k lazy_gettext -o messages.pot .
pybabel init -i messages.pot -d translations -l en     # une seule fois
pybabel update -i messages.pot -d translations -l en   # après chaque extraction
```

Faites ensuite pointer `gt.config.json` vers ce fichier. Cette configuration a été testée avec `gt` 2.26.5 :

```json title="gt.config.json"
{
  "defaultLocale": "en",
  "locales": ["es", "pl", "pt_BR"],
  "customMapping": { "pt_BR": { "code": "pt-BR" } },
  "files": {
    "pot": {
      "include": ["translations/[locale]/LC_MESSAGES/messages.po"],
      "transformationFormat": "PO"
    }
  }
}
```

La clé `pot` lit les fichiers PO et POT, et `"transformationFormat": "PO"` génère des fichiers `.po` traduits (voir la [référence du format PO / POT](/docs/cli/reference/formats/po-pot-files)). [`customMapping`](/docs/cli/reference/config#custom-mapping) fait correspondre le répertoire `pt_BR` de Babel au code de langue standard `pt-BR`. Configurez le [CLI](/docs/cli/quickstart). Si vous disposez déjà de traductions, importez-les avec [`npx gt upload`](/docs/cli/reference/commands/upload) avant d&#39;en générer de nouvelles. Exécutez ensuite [`npx gt translate`](/docs/cli/reference/commands/translate), puis `pybabel compile -d translations`.

General Translation envoie chaque entrée accompagnée de son `msgctxt`, des commentaires du traducteur, des références source et des options comme contexte. Pour les entrées au pluriel, il écrit l&#39;en-tête `Plural-Forms` de la langue cible et remplit chaque emplacement `msgstr[n]` (le polonais reçoit ainsi ses trois formes), puis vérifie que les espaces réservés tels que `%(num)d` sont conservés intacts. Lors de l&#39;exécution suivante, les entrées inchangées réutilisent les traductions existantes. Un glossaire et des instructions personnalisées définis dans un [groupe de contexte](/docs/platform/dashboard/guides/defining-context-for-translations) garantissent une terminologie cohérente entre vos catalogues et le reste de votre produit, et les relecteurs peuvent [modifier chaque entrée](/docs/platform/dashboard/guides/reviewing-translations) dans le tableau de bord. Exécutez le CLI dans votre CI pour que chaque déploiement intègre des catalogues à jour. Si vous apportez ensuite des modifications locales, enregistrez-les avec [`npx gt save-local`](/docs/cli/reference/commands/save-local) avant de relancer la génération.

## Babel et Flask-Babel vs General Translation : comparatif rapide

| Fonctionnalité                                             | Babel et Flask-Babel                                                           | General Translation                                                            |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| Écriture des chaînes                                       | Appels `gettext` et balises Jinja `{% trans %}`, extraits dans des fichiers PO | Conservez ces appels et ces modèles ; traduisez les catalogues extraits        |
| Traduction de votre contenu                                | Non                                                                            | Oui, avec [`npx gt translate`](/docs/cli/reference/commands/translate)         |
| Formes du pluriel                                          | `pybabel init` crée les emplacements ; vous les remplissez un par un           | Génère tous les emplacements PO pour la langue cible                           |
| Formatage des dates, des nombres et des valeurs monétaires | Oui, à partir du CLDR                                                          | Conserve le formatage de Babel                                                 |
| Modèles Jinja                                              | Oui                                                                            | Traduit les messages extraits de vos modèles existants                         |
| Frameworks                                                 | Babel partout ; Flask-Babel pour Flask                                         | CLI pour les catalogues PO issus de Flask ou d&#39;autres applications gettext |
| Licence                                                    | BSD                                                                            | CLI sous licence MIT                                                           |
| Coût                                                       | Gratuit                                                                        | [Traduction facturée à l&#39;usage](https://generaltranslation.com/pricing)    |

## Quand utiliser l&#39;un ou l&#39;autre

Conservez votre processus de traduction actuel si des traducteurs ou un TMS vous livrent déjà les catalogues dont vous avez besoin. Ajoutez General Translation si vous souhaitez faire traduire les messages nouveaux ou modifiés dès le développement, avec les outils de terminologie et de relecture que votre équipe partage d&#39;un projet à l&#39;autre. Flask-Babel continue de gérer Jinja, les paramètres régionaux de la requête, les dates et les devises ; le code de votre application reste inchangé.

## Points clés

* Babel formate les dates, les nombres et les devises pour n&#39;importe quel paramètre régional et gère les catalogues gettext, tandis que Flask-Babel l&#39;intègre à Flask, mais aucun des deux ne traduit vos chaînes.
* La CLI de General Translation traduit les fichiers PO de Babel grâce à la clé `pot`, à `"transformationFormat": "PO"` et à `customMapping` pour les répertoires comme `pt_BR`, en remplissant toutes les formes plurielles de chaque langue.
* Conservez l&#39;affichage et le formatage de Flask-Babel, importez vos traductions existantes et intégrez General Translation entre l&#39;extraction et la compilation.
