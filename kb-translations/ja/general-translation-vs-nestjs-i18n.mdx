nestjs-i18n は NestJS 向けのオープンソース i18n モジュールです。クエリ文字列、ヘッダー、クッキー、または `Accept-Language` から各リクエストの言語を判定し、`I18nContext` または `I18nService` がカタログからその言語のメッセージを返します。翻訳をレンダリングすることはできても、翻訳を生成することはできません。そのため、各言語のカタログは、開発者自身や翻訳者、あるいは外部サービスが作成し、常に最新の状態に保つ必要があります。General Translation は、この不足を 2 つの方法で補います。CLI が nestjs-i18n のカタログを翻訳し、`gt-node` ライブラリが実行時にしか存在しないコンテンツを翻訳します。

## nestjs-i18n の強み

* **Nest 向けに設計。** `I18nModule.forRoot()` を一度呼び出すだけで導入でき、[`I18nContext` を受け取る `@I18n()` パラメータデコレーターや、サービス内で使える `I18nContext.current()`](https://nestjs-i18n.com/quick-start) が用意されています。HTTP、GraphQL、gRPC、WebSockets のいずれでも動作します。
* **言語リゾルバー。** [`QueryResolver`、`HeaderResolver`、`CookieResolver`、`AcceptLanguageResolver`](https://nestjs-i18n.com/concepts/resolver) は指定した順に実行されます。GraphQL と gRPC にはそれぞれ専用のリゾルバーがあり、独自のリゾルバーを作成することもできます。
* **シンプルなカタログ。** 言語ごとに 1 つのフォルダー (`src/i18n/en/`、`src/i18n/es/`) を用意し、その中に [JSON または YAML ファイル](https://nestjs-i18n.com/concepts/loader)を配置します。各ファイル名がそのまま名前空間 (`inbox.title`) になり、開発中はライブリロードにも対応しています。
* **複数形と補間。** `{name}` プレースホルダー、他のキーを参照する `$t()`、そして `Intl.PluralRules` によって [`zero`、`one`、`two`、`few`、`many`、`other` のキーが選択される複数形オブジェクト](https://nestjs-i18n.com/guides/plurals)に対応しています。[10.8.0 で追加された](https://github.com/toonvanstrijp/nestjs-i18n/releases/tag/v10.8.0)オプトインの `useICU` 設定を有効にすると、代わりに ICU MessageFormat でメッセージをフォーマットできます。
* **型安全性。** [`typesOutputPath` によって `I18nTranslations` 型と `I18nPath` 型が生成される](https://nestjs-i18n.com/guides/type-safety)ため、キーの入力ミスはコンパイルエラーになります。また、`nestjs-i18n check` コマンドを使えば、キーが不足している言語がある場合にエラーで終了します。
* **バリデーションメッセージ。** `I18nValidationPipe`、`I18nValidationExceptionFilter`、`i18nValidationMessage()` を使って、[DTO の class-validator エラーを翻訳](https://nestjs-i18n.com/guides/dto_validation/global-validation)できます。

MIT ライセンスで提供されており、[バージョン 10.8.5 では Node.js 22 以降が必要です](https://github.com/toonvanstrijp/nestjs-i18n/blob/v10.8.5/package.json)。

## nestjs-i18n が開発者任せにしていること

次の例は、複数形を含む英語の受信トレイ用カタログです。

```json title="src/i18n/en/inbox.json"
{
  "title": "Inbox",
  "unread": {
    "one": "You have {count} unread message.",
    "other": "You have {count} unread messages."
  }
}
```

スペイン語フォルダーにはファイルを翻訳したコピーがあり、コントローラーは `i18n.t('inbox.unread', { args: { count } })` を返します。ドイツ語フォルダーはありません。nestjs-i18n 10.8.5 を使った最小構成の Nest 11 アプリにリクエストを送ると、結果は次のようになります：

```text title="Output"
?lang=es&count=3  "Tienes 3 mensajes sin leer."
?lang=de&count=3  "You have 3 unread messages."
```

ドイツ語のカタログがまだ翻訳されていないため、ドイツ語は英語にフォールバックします。言語検出自体は機能していますが、存在しないテキストを補うことはできません。ここが nestjs-i18n が開発者に任せている部分です。つまり、カタログを作成し、英語の文言が変わるたびに最新の状態に保つ作業です。

## NestJS アプリにおける General Translation の位置づけ

General Translation の CLI は、nestjs-i18n のカタログを現在の配置のまま翻訳します。`json` エントリに言語フォルダを指定してください。

```json title="gt.config.json"
{
  "defaultLocale": "en",
  "locales": [
    "es",
    "de"
  ],
  "files": {
    "json": {
      "include": [
        "src/i18n/[locale]/*.json"
      ]
    }
  }
}
```

[`npx gt translate`](/docs/cli/reference/commands/translate) は `src/i18n/en/inbox.json` を読み込み、すべてのキーを保持したまま `src/i18n/es/inbox.json` と `src/i18n/de/inbox.json` を書き出します。CI で実行すれば、変更のないエントリは以前の翻訳がそのまま再利用されます。生成されたカタログは、nestjs-i18n が既存のローダー経由で読み込みます。

この例では、`one` と `other` の形式を持つ英語、スペイン語、ドイツ語のメッセージを使用します。生成されたメッセージを件数 1 と 3 でプレビューし、リリース前に `nestjs-i18n check -p src/i18n` を実行して、不足しているキーがないか確認してください。

チームメンバーの投稿やデータベースのレコードなど、実行時にしか存在しないコンテンツには、General Translation の [`gt-node`](/docs/node/quickstart) を使用します。一度初期化しておき、[`tx`](/docs/node/reference/functions/tx) を呼び出す際に、nestjs-i18n が解決した言語を [`withGT`](/docs/node/reference/functions/with-gt) に渡します：

```ts title="src/main.ts"
import { NestFactory } from '@nestjs/core';
import { initializeGT } from 'gt-node';
import { AppModule } from './app.module';

// 環境変数から GT_PROJECT_ID と GT_API_KEY（実行時翻訳が有効なプロジェクトキー）を読み込みます。
initializeGT({ defaultLocale: 'en', locales: ['en', 'es', 'de'] });

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  await app.listen(3000);
}
bootstrap();
```

```ts title="src/posts.controller.ts"
import { Controller, Get, Param } from '@nestjs/common';
import { I18n, I18nContext } from 'nestjs-i18n';
import { tx, withGT } from 'gt-node';
import { PostsService } from './posts.service';

@Controller('posts')
export class PostsController {
  constructor(private readonly posts: PostsService) {}

  @Get(':id')
  async findOne(@Param('id') id: string, @I18n() i18n: I18nContext) {
    return withGT(i18n.lang, async () => {
      const post = await this.posts.findOne(id);
      return { ...post, body: await tx(post.body, { $context: 'A post written by a user' }) };
    });
  }
}
```

どちらのツールも、既存の nestjs-i18n リゾルバーが選択した言語を使用するようになりました。`?lang=es` が `Accept-Language: de` より優先される場合、カタログのメッセージも翻訳された投稿もスペイン語になります。固定の UI 文言にはカタログを、ユーザーが作成したコンテンツには [`tx`](/docs/node/reference/functions/tx) を使用してください。

型付きキー、カタログ参照、バリデーションメッセージには、引き続き nestjs-i18n を使用してください。General Translation は、翻訳の生成、共有の用語集とカスタムプロンプト、[ダッシュボードでのレビュー](/docs/platform/dashboard/guides/reviewing-translations)を提供します。固定の文言には上記のカタログワークフローを、動的コンテンツには `tx` を使いましょう。

## nestjs-i18n と General Translation の比較一覧

| 機能           | nestjs-i18n                                            | General Translation                                                                                                |
| ------------ | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| 役割           | リクエストの言語を解決し、カタログのメッセージをレンダリングする                       | カタログを翻訳し、動的コンテンツを実行時に翻訳する                                                                                          |
| コンテンツの翻訳     | なし                                                     | あり ([`npx gt translate`](/docs/cli/reference/commands/translate) と [`tx`](/docs/node/reference/functions/tx) で対応)  |
| 言語検出         | クエリ、ヘッダー、クッキー、`Accept-Language`、GraphQL、gRPC、カスタムリゾルバー | [`withGT`](/docs/node/reference/functions/with-gt) を通じて、解決済みの同じ言語を使用                                               |
| 複数形          | 言語ごとのカテゴリキーを `Intl.PluralRules` で選択                    | ソースファイル内の複数形キーを翻訳                                                                                                  |
| 型安全性         | キーの型の生成と欠落キーのチェック                                      | カタログのキーを保持し、同じ生成型をそのまま利用可能                                                                                         |
| バリデーションメッセージ | class-validator インテグレーション                              | メッセージの元となるカタログを翻訳                                                                                                  |
| 費用           | 無料 (MIT ライセンス)                                         | [従量課金制](https://generaltranslation.com/pricing)                                                                    |

## 使い分けの指針

リゾルバー、型付きキー、バリデーションとのインテグレーションを活用したい場合は、引き続き nestjs-i18n を使用してください。英語のソースが変更されるたびに CI でカタログを翻訳したい場合や、API が返すユーザーコンテンツやデータベースのコンテンツをその場で翻訳する必要がある場合は、General Translation を追加しましょう。既存のコントローラーはこれまでと同じキーをそのまま使い続けられ、各キーに対応するテキストは General Translation によって常に最新の状態に保たれます。

## 両方を併用する

1. nestjs-i18n とそのフォルダはそのまま残しておきます。
2. カタログのパスを指定した `gt.config.json` を追加し、`GT_API_KEY` と `GT_PROJECT_ID` を設定します。 ([CLI の設定](/docs/cli/guides/configuring#credentials)を参照してください。) 
3. 既存の翻訳を [`npx gt upload`](/docs/cli/reference/commands/upload) でアップロードし、CI で [`npx gt translate`](/docs/cli/reference/commands/translate) を実行します。
4. その後ローカル翻訳を編集した場合は、再生成する前に [`npx gt save-local`](/docs/cli/reference/commands/save-local) を実行してください。実行時翻訳が必要な箇所には `gt-node` を追加します。

## 重要なポイント

* nestjs-i18n は NestJS での言語検出、型付きキー、複数形、バリデーションメッセージを処理しますが、各言語の複数形も含め、すべての言語のカタログを自分で作成する必要があります。
* General Translation の CLI は nestjs-i18n の JSON カタログをインプレースで翻訳し、`gt-node` は同じリクエスト言語で動的コンテンツを翻訳します。
* 両者を組み合わせて使いましょう。レンダリングは nestjs-i18n、翻訳は General Translation が担います。
