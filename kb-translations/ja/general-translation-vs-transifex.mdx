翻訳を React の開発ワークフローに組み込みたいなら、General Translation が適しています。JSX を [`<T>`](/docs/react/reference/components/t) でマークし、ビルド前に翻訳を生成すれば、そのままアプリに含めてリリースできます。一方、Transifex は 2025年1月から [XTM International の傘下](https://xtm.ai/news/xtm-international-acquires-transifex)にある翻訳管理システム (TMS) で、AI、翻訳者、パートナーベンダーを組み合わせて翻訳を行います。

Transifex は、リソースファイルと、Transifex Native を使ってコード内で直接マークした文字列の両方に対応しています。Native はメッセージを Transifex にプッシュし、コンテンツ配信サービス (CDS) から翻訳を読み込みます。General Translation はマークした JSX を抽出して翻訳し、その結果をアプリがバンドル済みのファイルまたは CDN から読み込めるようにします。

## Transifex の強み

* **ファイルを使わずにコードから文字列を扱える。** [Transifex Native](https://developers.transifex.com/docs/javascript-sdk) では、翻訳関数または React コンポーネントで文字列をマークします。デフォルトでは原文がキーとして使われ、`txjs-cli push` で文字列をプッシュします。SDK と [CDS](https://github.com/transifex/transifex-delivery) は Apache-2.0 ライセンスのオープンソースで、CDS はセルフホストも可能です。
* **品質スコア付きの AI 翻訳。** Transifex AI は用語集、翻訳メモリ、文脈を活用して翻訳し、その結果を [Translation Quality Index (TQI)](https://help.transifex.com/en/articles/9465000-translation-quality-index-tqi) が採点します。設定したしきい値を満たした翻訳は、自動的にレビュー済みにできます。
* **人手翻訳パートナー。** e2f、Gengo、TextMaster などの[パートナーへの翻訳発注](https://help.transifex.com/en/articles/6235673-ordering-translations)を Transifex 内で行えます。
* **コード変更なしでウェブサイトを翻訳。** [Transifex Live](https://help.transifex.com/en/articles/6244596-introduction-to-transifex-live) を使えば、JavaScript スニペットを埋め込むだけでウェブサイトを翻訳できます。ただし、React や Vue のアプリには Native の利用が推奨されています。
* **共同作業者数は無制限。** 現行プランでは、シート数、プロジェクト数、ホストするコンテンツ量に応じた課金はありません。
* **豊富なファイル形式。** XLIFF、Office ファイル、字幕など [46 以上の形式](https://help.transifex.com/en/articles/6219670-introduction-to-file-formats)に対応しています。

## Transifex を導入してもエンジニアに残る作業

エンジニアは、アプリを Transifex の翻訳・配信ワークフローに接続する必要があります。

1. Transifex 向けに各文字列をマークします。キーを付けてリソースファイルに抽出するか、Native の翻訳関数または React コンポーネントでラップします。
2. [`tx push`](https://github.com/transifex/cli)、Git インテグレーション、または `txjs-cli push` を使って Transifex に送信します。通常は CI のステップとして実行します。
3. AI 翻訳またはパートナーベンダーを設定し、必要に応じてレビュー要件も設定します。
4. 翻訳を配信します。ファイルワークフローでは、ある言語の翻訳が完了率のしきい値に達すると、[Git インテグレーション](https://help.transifex.com/en/articles/6265125-github-via-transifex-ui)がプルリクエストを作成するか、直接コミットします。Native は [CDS](https://developers.transifex.com/docs/content-delivery-service) から翻訳を取得します。CDS のコンテンツはデフォルトで 1 時間経過すると古いものとして扱われます。この更新間隔は変更できます。

Transifex AI は、[用語集の用語、翻訳メモリ、文脈フィールド、企業情報](https://help.transifex.com/en/articles/9867663-context-in-transifex-ai)を活用します。開発者メモや文字列ごとの指示を有効にすることもできます。General Translation の React ライブラリは、マークされた JSX の構造と名前付きプレースホルダーから文脈を提供し、さらに開発者メモとプロジェクトの用語によって翻訳の精度を高めます。

料金プランは AI ファーストのプラン 1 つのみで、営業経由での販売となり、AI 翻訳された単語数に応じて課金されます。料金は公開されていません ([Transifex の料金](https://www.transifex.com/pricing)を参照、2026 年 10 月時点) 。

## Transifex と General Translation の比較

| 機能         | Transifex                                                                         | General Translation                                                                |
| ---------- | --------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 文字列の取り込み方法 | `tx push` または Git インテグレーションでリソースファイルを取り込むか、`txjs-cli push` で Native SDK の文字列を取り込む | コンテンツは [`<T>`](/docs/react/reference/components/t) 内でコードに保持されるか、既存のリソースファイルをそのまま利用 |
| 翻訳の担い手     | TQI スコア付きの Transifex AI、またはパートナーベンダー                                              | コード、用語集、カスタムプロンプトの文脈を活用する AI が翻訳し、ダッシュボードでチームがレビュー                                 |
| 各文字列の文脈    | 用語集、翻訳メモリ、文脈フィールド、任意の開発者メモ                                                        | マークされた JSX、名前付きプレースホルダー、開発者メモ、用語集、カスタムプロンプト                                        |
| 配信         | ファイルはプルリクエストまたはコミットで配信、Native は実行時に CDS 経由で配信                                     | ローカルにバンドルされた翻訳、または General Translation の CDN                                       |
| 料金         | AI 翻訳の単語量に基づく従量制、見積もりは営業経由                                                        | 公開済みの[利用料金](https://generaltranslation.com/pricing)                                |

## チームが Transifex ではなく General Translation を選ぶ理由

* **より速い。** [`npx gt translate`](/docs/cli/reference/commands/translate) は、マークされたコンテンツの抽出、翻訳の生成、結果のダウンロードまでをアプリのビルド前に行います。そのため、リリース時に実行する翻訳ステップは 1 つだけで済みます。GitHub で変更をレビューしたい場合は、コードが変更されると [Locadex](/docs/platform/locadex/quickstart) がプルリクエストを作成します。
* **運用コストが低い。** General Translation は、リッチな UI の翻訳にかかるエンジニアリング作業を削減します。文をメッセージ文字列として組み立て直す必要はなく、リンク、フォーマット、動的な値を 1 つの [`<T>`](/docs/react/reference/components/t) ブロック内に含めたまま扱えます。翻訳コストは[公開されている料金](https://generaltranslation.com/pricing)から直接見積もれます。
* **より高品質。** 文とそのネストされた要素をまとめて扱うことで、単語、リンク、プレースホルダーの関係性を踏まえた翻訳が可能になります。曖昧な文言は開発者のメモで補足でき、割り当てた[コンテキストグループ](/docs/platform/dashboard/guides/defining-context-for-translations)によってアプリとウェブサイトで用語を統一できます。出力は[翻訳エディター](/docs/platform/dashboard/guides/reviewing-translations)でチームが仕上げられます。
* **リスクが低い。** [ローカル翻訳](/docs/react/guides/storing-translations)を使えば、アプリはリリースにバンドルされたファイルからレンダリングされ、General Translation へのランタイム呼び出しは発生しません。再デプロイなしで翻訳の修正を公開したい場合は、General Translation の CDN を利用することもできます。MIT ライセンスの JavaScript ライブラリは、翻訳を自前で用意すればアカウントなしでも動作します。

Sierra は General Translation を活用し、ウェブサイトや市場開拓 (GTM) 向けコンテンツを 7 以上のロケールで展開しています。 ([本番環境での導入事例](https://generaltranslation.com/enterprise)を参照)

## Transifex のほうが適しているケース

コードを変更せずにスニペットだけでウェブサイトを翻訳したい場合、パートナーベンダーに人手による翻訳を発注したい場合、TQI に基づく自動承認がレビュープロセスに合う場合、XLIFF、Office、字幕ファイルをやり取りする場合、あるいはネイティブの iOS / Android アプリで[オフラインバンドルを使った OTA (over-the-air) アップデート](https://developers.transifex.com/docs/ios-sdk)が必要な場合は、Transifex を選ぶとよいでしょう。

## Transifex から General Translation への移行

JSON、YAML、PO、iOS／Android のリソースファイルなど、サポート対象の形式を使用するファイルベースのプロジェクトでは、[CLI クイックスタート](/docs/cli/quickstart)の手順に従ってください。翻訳元とロケールのパスを設定したら、新しい翻訳を生成する前に [`npx gt upload`](/docs/cli/reference/commands/upload) で既存の翻訳をインポートします。

Native を使用している React アプリでは、[Reactクイックスタート](/docs/react/react-quickstart)または [Next.js クイックスタート](/docs/react/nextjs-quickstart)に従って `gt-react` または `gt-next` をセットアップします。移行は1画面ずつ進めましょう。対象画面の文言とマークアップを [`<T>`](/docs/react/reference/components/t) で囲み、[`npx gt translate`](/docs/cli/reference/commands/translate) を実行します。翻訳済みの画面をレビューしている間は、残りの画面を Native のまま残しておけます。用語集を[コンテキストグループ](/docs/platform/dashboard/guides/defining-context-for-translations)にインポートすれば、製品の用語をそのまま引き継げます。

## General Translation は Transifex の代替になりますか？

はい。General Translation を使えば、ビルド前に構造化された JSX から翻訳を生成し、バンドル済みファイルとして、または General Translation の CDN 経由で配信できます。既存のファイルベースのアプリはそのままに、General Translation でカタログを翻訳することも可能です。ベンダーをより広く比較したい場合は、[TMS ではなく General Translation を使う理由](/kb/general-translation-vs-tms)を参照してください。

## Transifex Native と General Translation の違いは？

どちらもオープンソースSDKを採用しており、原文をコード内に保持できます。[Transifex の React SDK](https://developers.transifex.com/docs/react-sdk) では、`<T _str="...">` メッセージに React 要素を補間値として渡せます。一方、General Translation の [`<T>`](/docs/react/reference/components/t) は、文とネストされた要素を JSX 内にそのまま記述し、その構造を抽出して翻訳します。また、Native は CDS 経由で翻訳を配信するのに対し、General Translation ではバンドルされたファイルと自社の CDN のどちらかを選べます。

## 重要なポイント

* Transifex は、オープンソースの Native SDK、品質スコア付きの AI 翻訳、パートナーベンダー、そしてウェブサイト向けの Transifex Live を備えた TMS です。
* Native もコード内の文字列にはすでに対応しています。React における General Translation の強みは、構造化された JSX をそのまま記述・翻訳でき、開発者向けのメモや共通の用語集も活用できる点にあります。
* General Translation はビルド前に翻訳を生成し、バンドルに同梱する配信方式と CDN による更新の両方に対応しているため、翻訳済みコンテンツをユーザーに届ける方法を自由に選べます。
