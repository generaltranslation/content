Crowdin の[ローカライゼーションプラットフォーム](https://crowdin.com/)は、翻訳プロジェクトを軸にローカライゼーションを進める仕組みです。エンジニアはリソースファイルを保守して Crowdin に接続し、翻訳済みのカタログをアプリに取り込みます。Crowdin の自動化機能は、このワークフローに沿ってコンテンツを処理していきます。一方、General Translation は翻訳を開発プロセスそのものに組み込みます。テキストはコンポーネント内に置いたまま、翻訳はビルド時に生成されます。

## Crowdin の強み

* **無料で始められる。** [Free プラン](https://crowdin.com/pricing)ではホスト単語数は 60,000 ワードまでです (翻訳は Crowdin の翻訳メモリに共有されます) 。また、[オープンソースライセンスの基準](https://crowdin.com/product/for-open-source) (OSI ライセンスであること、関連する商用製品がないことなど) を満たすオープンソースプロジェクトは、無料ライセンスを取得できます。
* **開発者向けツール。** `crowdin.yml` で設定する CLI、GitHub・GitLab・Bitbucket・Azure Repos 向けの Git インテグレーション、GitHub Action、MCP サーバー、さらに [700 以上のアプリとインテグレーション](https://store.crowdin.com/)が用意されています。
* **文脈を活用した AI。** [OpenAI、Anthropic、Gemini などのプロバイダーの API キーを持ち込む](https://support.crowdin.com/crowdin-ai/)ことも、Crowdin が管理するモデルを使うこともできます。各リクエストには文字列の文脈、キー、最大文字数が含まれ、プロンプトには用語集、翻訳メモリ、スタイルガイド、前後の文字列、タグ付けされたスクリーンショットを追加できます。
* **人手による翻訳。** 翻訳会社のマーケットプレイスがあるほか、プロジェクト内から [Crowdin Language Services](https://crowdin.com/features/vendor-integrations) に直接発注できます。
* **文脈と品質チェック。** 文字列にタグ付けされたスクリーンショット、[Web アプリ向けの In-Context エディター](https://support.crowdin.com/in-context-localization/)、Figma プラグイン、組み込みの QA チェックを利用できます。
* **モバイルの OTA 更新。** iOS、Android、Flutter 向けの SDK と JavaScript クライアントを使えば、アプリをリリースし直さなくても [Crowdin の CDN](https://support.crowdin.com/content-delivery/) から文字列を更新できます。

## Crowdin を使ってもエンジニアに残る作業

アプリと Crowdin の翻訳プロジェクト間の往復のやり取りは、引き続きエンジニアが構築・保守する必要があります。

1. i18nライブラリを導入し、英語の各文字列をキーを付けてリソースファイルに抽出し、コンポーネント側でそのキーを参照します。
2. `crowdin.yml` に対象ファイルを記述し、[`crowdin upload sources`](https://crowdin.github.io/crowdin-cli/commands/crowdin-upload-sources) で送信します。Git インテグレーションや GitHub Action を使うこともできます。
3. AI、機械翻訳、ベンダー、または自社の翻訳者を手配して各言語の翻訳を用意し、プロジェクトに必要なレビュー工程を整えます。
4. 翻訳済みのカタログをアプリに取り込みます。[Crowdin の GitHub連携](https://support.crowdin.com/github-integration/)では、`l10n_` サービスブランチ経由で翻訳が戻されます。自動同期はデフォルトで1時間ごとに実行されます。間隔は変更でき、即時同期のオプションもあります。

Crowdin はコードから文脈を収集することもできます。コーディングエージェント向けのスキルや [`crowdin context` コマンド](https://crowdin.github.io/crowdin-cli/commands/crowdin-context)を使うと、エージェントがコードベースを解析し、文字列の説明をアップロードします。一方、General Translation の [`<T>`](/docs/react/reference/components/t) では、マークした JSX 自体が、翻訳に使うテキスト、ネストされた要素、名前付きプレースホルダーを提供します。

有料プランの料金は、主にホスト単語数 (翻訳元の単語数 × 対象言語数) とマネージャーのシート数で決まります。そのため、言語を追加するたびにホスト単語数が増えます。 ([Crowdin の料金](https://crowdin.com/pricing)を参照。2026年10月時点で確認。)

| コードとの連携方法    | CLI と `crowdin.yml`、Git インテグレーション、または GitHub Action | ビルド時に実行する [`npx gt translate`](/docs/cli/reference/commands/translate)、または [Locadex](/docs/platform/locadex/quickstart) のプルリクエスト |
| 翻訳の担い手       | 機械翻訳や AI プロバイダー、ベンダー、または自社の翻訳者                      | コード、用語集、カスタムプロンプトの文脈を踏まえた AI が翻訳し、チームがダッシュボードでレビュー                                                                               |

| 料金           | 無料プランあり。有料プランはホスト単語数とマネージャーのシート数に応じて課金            | 翻訳の使用量に応じて課金。詳細は[料金](https://generaltranslation.com/pricing)を参照                                                                  |

| オープンソース      | 条件を満たすオープンソースプロジェクトには無料ライセンスを提供                     | MIT ライセンスの JavaScript ライブラリと CLI                                                                                                 |

## チームが Crowdin ではなく General Translation を選ぶ理由

General Translation を使えば、React UI のカタログ作成作業が不要になります。文言は [`<T>`](/docs/react/reference/components/t) で囲んだまま、コンポーネント内に記述できます。コンポーネントを削除すればそのインラインの文言も一緒に消えるため、別の場所に残ったキーを後から整理する必要はありません。

* **より速く。** アプリのビルド前に [`npx gt translate`](/docs/cli/reference/commands/translate) を実行すれば、同じワークフロー内で翻訳の生成とダウンロードまで完了します。既存の翻訳は再利用され、新規または変更されたコンテンツのみが生成されます。プルリクエストベースのワークフローなら、[Locadex](/docs/platform/locadex/quickstart) が翻訳の変更を自動で用意します。
* **運用コストを抑えられる。** Crowdin のホスト単語数は、翻訳元カタログと対象言語の数に応じて増えていきます。一方、General Translation はカタログのホスティングではなく、翻訳の使用量に対して課金します。完了した翻訳を保持しても継続的な翻訳料金は発生しません。使用料金は[料金ページ](https://generaltranslation.com/pricing)をご確認ください。
* **より高品質。** [`<T>`](/docs/react/reference/components/t) ブロックには見出し、文、リンク、動的なプレースホルダーをまとめて含められるため、翻訳者はばらばらのキーではなく、要素同士の関係ごと把握できます。製品固有の用語については、開発者向けのメモや共有の[用語集とカスタムプロンプト](/docs/platform/dashboard/guides/defining-context-for-translations)を追加できます。レビュー担当者は[翻訳エディター](/docs/platform/dashboard/guides/reviewing-translations)で結果を編集できます。
* **リスクを抑えられる。** 既存の i18nライブラリをそのまま使い続けながら、新しい翻訳の生成方法を切り替える前にレビュー済みの翻訳をインポートできます。すべてのコンポーネントを書き直したり、翻訳者の成果物を無駄にしたりすることなく、General Translation を導入できます。

Cursor は General Translation を使って、Web とドキュメントで 14 以上のロケールを提供しています。 ([本番環境での導入事例](https://generaltranslation.com/enterprise)をご覧ください。)

## Crowdin のほうが適しているケース

次のような場合は Crowdin を選ぶとよいでしょう：オープンソースプロジェクトが Crowdin の無料ライセンスの対象で、コミュニティの翻訳者を活用したい場合。ベンダーを交えた多段階レビューによる人手による翻訳のプログラムを運用している場合。XLIFF や Office ファイルをやり取りする場合。あるいは、ネイティブモバイルアプリで Crowdin の OTA (over-the-air) SDK が必要な場合。

## Crowdin から General Translation への移行

JSON、YAML、PO、iOS や Android のリソースファイルなど、サポート対象のカタログについては、`gt.config.json` で翻訳元とロケールのパスを設定してください。[ファイル翻訳のセットアップ](/docs/cli/quickstart)の手順に従い、新しい翻訳を生成する前に [`npx gt upload`](/docs/cli/reference/commands/upload) を実行して既存の翻訳をインポートします。また、用語集を[コンテキストグループ](/docs/platform/dashboard/guides/defining-context-for-translations)に取り込んでおけば、新しい翻訳でも同じ用語が使われます。

React アプリの場合は、その後、新しい画面を構築するタイミングで [`<T>`](/docs/react/reference/components/t) を導入していけます。各ベンダーとの比較については、[TMS ではなく General Translation を使う理由](/kb/general-translation-vs-tms)をご覧ください。

## General TranslationはCrowdinの代替になりますか？

はい。General Translationは、AI翻訳、人手によるレビューのためのエディター、そしてReactの文言をJSX内に記述したまま扱えるライブラリを組み合わせて提供します。既存のカタログも翻訳できるため、Crowdinから移行する際に、i18nライブラリを先に置き換える必要はありません。

## 重要なポイント

* Crowdin は、オープンソースや人手による翻訳プログラムに適した強力な TMS です。無料プランがあり、キー、スクリーンショット、用語集を参照する AI 機能も備えています。
* Crowdin はカタログの配信を自動化しますが、カタログをアプリに組み込み、翻訳ワークフローを設定する作業は引き続きエンジニアが行う必要があります。
* React のコード記述からキーベースのカタログをなくしたい、リリース時に翻訳を生成したい、導入時に既存のレビュー済み翻訳をそのまま活かしたい場合は、General Translation をお選びください。
