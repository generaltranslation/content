Google 翻訳は、外国語のページを読んだり、段落をその場で翻訳したりするには手軽で便利です。しかし製品のローカライゼーションで難しいのは、すべての文字列を UI 上での意味に沿って翻訳すること、リリースをまたいで用語の一貫性を保つこと、そしてアプリが読み込める場所に翻訳を配置することです。アプリで Google 翻訳をどのように活用しても、こうした作業の一部は自分で担うことになります。

## アプリでGoogle翻訳を使う3つの方法

### 訪問者のブラウザにページを翻訳させる

Chrome は、ユーザーが読めない言語のページを開くと翻訳を提案します。翻訳はページの読み込み後、訪問者のブラウザ内で行われます。Google の翻訳スクリプトが、ページ内のテキストを `<font>` 要素でラップした翻訳済みテキストに置き換える仕組みです。開発者はその結果を目にすることもレビューすることもできず、検索エンジンがクロールできる翻訳版の URL も存在しません。一方、Google は多言語サイト向けのガイダンスで、言語ごとに個別の URL で公開することを推奨しています ([Managing multilingual sites](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)) 。

さらに、この書き換えによって React アプリが壊れることもあります。React は自身がレンダリングしたテキストノードへの参照を保持しているため、翻訳でそれらが置き換えられると、次の更新時に `NotFoundError: Failed to execute 'removeChild' on 'Node'` で失敗する場合があります。React のメンテナーは 2018 年にこの issue ([react#11538](https://github.com/react/react/issues/11538)) をクローズしており、他のバグを隠したり一般的なケースのパフォーマンスを落としたりせずに React 側で回避することはできない、と説明しています。なお、`translate="no"` が指定された要素は書き換えの対象外です。

### Website Translator ウィジェットを追加する

Google の埋め込み型 Website Translator を利用できるのは、教育機関、政府機関、非営利団体のサイトおよび非商用サイトに限られるため、企業が自社製品に組み込むことはできません ([Google Translate Help](https://support.google.com/translate/answer/2534559?co=GENIE.Platform%3DDesktop)) 。

### Cloud Translation API を呼び出す

Cloud Translation API は、開発者向けに設計された選択肢です。HTML タグはそのまま保持されます。Advanced エディションでは、HTML 入力に含まれる `translate="no"` または `class="notranslate"` が指定されたテキストを翻訳対象から除外できるほか、用語集、例文ペアに基づく適応型翻訳、Gemini をベースにした Translation LLM も利用できます。リクエストにはテキストと言語を指定し、必要に応じてモデルと用語集も含めます。

```json title="translateText request body"
{
  "contents": ["Save"],
  "mimeType": "text/plain",
  "sourceLanguageCode": "en",
  "targetLanguageCode": "de"
}
```

文字列がどこに表示されるかを指定するフィールドはありません。ドイツ語では「Save」は *speichern* (ファイルを保存する) にも *sparen* (節約する) にもなりますが、一語だけのリクエストではモデルには判断の手がかりがありません。パイプラインのそれ以外の部分は自前で構築する必要があります。i18n ファイルからの文字列の抽出、`{{count}}` などのプレースホルダーの保護、各言語の複数形の生成、結果の書き戻し、変更のたびの再実行、そして次回の実行で上書きされないようにレビュアーが出力を修正できる場の用意などです。出力をユーザーに表示する場合は、Google が定める帰属表示も必要です。具体的には、結果の横に「powered by Google Translate」バッジを表示すること、未修正の出力には免責事項を添えること、検索エンジンにインデックスされるページには機械翻訳であることを示すマークアップを付けることが求められます ([帰属表示の要件](https://docs.cloud.google.com/translate/attribution)) 。

## 各選択肢の比較

| アプローチ                 | 各文字列の文脈                    | 変数と複数形                                                                                                                              | 検索エンジン                                           | レビューと更新                                                |
| --------------------- | -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ | ------------------------------------------------------ |
| ブラウザ翻訳                | ページ上に表示されているテキスト           | プレーンテキストとして翻訳される                                                                                                                    | 新たにインデックスされるものはない                                | レビューなし。訪問者のブラウザごとに毎回翻訳し直される                            |
| Cloud Translation API | テキストに加え、任意で用語集や例文ペア        | プレースホルダーの保護や各言語の複数形の構築は自分で行う                                                                                                        | 言語ごとに個別の URL で公開すればインデックスされる                     | スクリプトの再実行もレビューの仕組みづくりも自分で行う                            |
| General Translation   | 周囲の JSX、文脈メモ、用語集、カスタムプロンプト | [`<Var>`](/docs/react/reference/components/var) の値は翻訳対象から除外され、[`<Plural>`](/docs/react/reference/components/plural) の分岐は文全体として翻訳される | `/es/about` のような `gt-next` のロケールルーティングでインデックスされる | ビルドや Locadex のプルリクエストのたびに変更箇所が翻訳され、レビュアーはダッシュボードで編集できる |

外国語のコンテンツを読む場合や、社内向けのテキストを一度だけ翻訳する場合は Google 翻訳 が適しています。機械翻訳の結果だけが必要で、文脈、プレースホルダー、複数形、レビュー、帰属表示の仕組みを自前で構築するなら Cloud Translation API を使いましょう。アプリの UI、ドキュメント、マーケティングサイトなど、製品に組み込んで提供する翻訳で、どの言語でも自然に読め、リリースのたびに最新の状態を保つ必要がある場合は General Translation を使いましょう。

## General Translation はここが違う

General Translation は、Google 翻訳 では手の届かないローカライゼーションの領域を担うために設計されています。主な違いは次の2点です。

* **文脈全体を理解します。** Cloud Translation のリクエストに含まれるのは、テキストと言語、そして任意の用語集だけです。一方 General Translation は、各文字列をプロダクト内での位置づけを踏まえて翻訳します。周囲のコンポーネントや要素、文中の変数や複数形、追加した文脈メモ、さらに用語集とカスタムプロンプトまで考慮します。コンテキストグループを使えば、割り当てたすべてのプロジェクトに同じ用語とトーンが適用されるため、アプリ、ドキュメント、マーケティングサイトで言葉づかいを統一できます。
* **ローカライゼーションのワークフロー全体を自動化します。** オープンソースのライブラリで React、Next.js、Vue、Node.js のコードを国際化でき、Next.js と React のアプリなら、General Translation の AIエージェントである [Locadex](/docs/platform/locadex/quickstart) がそのコードを代わりに書くこともできます。[`npx gt translate`](/docs/cli/reference/commands/translate) はビルドや CI の中で実行され、翻訳をリポジトリまたは General Translation の CDN に書き出します。レビュアーはダッシュボードの **Translations** ページで翻訳を編集でき、すべてのリリースを全言語で同時に提供できます。

では、コード上で文脈がどう表れるかを見てみましょう。この請求トグルのバッジには「Save 20%」と表示されています。

```tsx title="BillingToggle.tsx"
import { T, Var } from 'gt-react';

export function BillingToggle({ discount }: { discount: string }) {
  return (
    <T context="Pricing page billing toggle. Save means pay less, not store data.">
      <button>Yearly</button>
      <span className="badge">Save <Var>{discount}</Var></span>
    </T>
  );
}
```

[`<T>`](/docs/react/reference/components/t) は、ブロックをその要素 (ボタンとバッジ) および [`context`](/docs/react/reference/components/t#context) のメモとあわせて1つの単位として送信します。これにより、翻訳時に &quot;Save&quot; の意味を正しく解決し、割引表記を各言語の自然な位置に配置できます。[`<Var>`](/docs/react/reference/components/var) は割引額のプレースホルダーを保持し、その値が General Translation API に送信されることはありません。用語集を使えば製品名などの用語をすべての言語で統一でき、カスタムプロンプトではドイツ語で敬称の &quot;Sie&quot; を使うといったルールを設定できます ([翻訳の文脈を定義する](/docs/platform/dashboard/guides/defining-context-for-translations)および[翻訳のレビューと編集](/docs/platform/dashboard/guides/reviewing-translations)を参照) 。ユーザー生成コンテンツや CMS のテキストなど、実行時にしか存在しないコンテンツは、`gt-node` の [`tx`](/docs/node/reference/functions/tx) がリクエストに応じて翻訳します。

General Translation は 120 以上のロケールに対応しています。まずは [Next.js クイックスタート](/docs/react/nextjs-quickstart)または [Reactクイックスタート](/docs/react/react-quickstart)から始めましょう。

## 重要なポイント

* Google 翻訳はテキストを十分な精度で翻訳します。しかし、ブラウザ翻訳ではレビューができず、インデックス可能なページも生成されないうえ、React アプリを壊すおそれがあります。また、Website Translator ウィジェットは非商用サイトでしか利用できません。
* Cloud Translation API のリクエストには、文字列がどこに表示されるかを指定するフィールドがありません。また、プレースホルダー、複数形、レビュー、配信、帰属表示はすべて自前で構築する必要があります。
* General Translation は、コード内の各文字列の文脈を理解したうえで、コードの国際化からレビュー、そしてすべてのリリースを全言語で出荷するまで、翻訳に関わるワークフローを自動化します。
