Mobility は、データベース内のデータを翻訳するための Ruby gem です。モデルで `translates :title` を宣言すると、`post.title` は任意のストレージバックエンドから現在のロケールのタイトルを読み込んで返します。Mobility が担うのは翻訳の保存と取得であり、翻訳そのものの作成は編集者や翻訳者、あるいは外部サービスに任されています。General Translation は、その翻訳を HTTP API 経由で提供します。翻訳された属性は Mobility によって既存のデータベースに保持されるため、現在お使いのクエリやモデルメソッドをそのまま利用できます。

## Mobility の優れている点

* **ストレージを選択できる。** デフォルトの `key_value` バックエンドは、[すべての翻訳を 2 つの共有テーブルに保存します](https://github.com/shioyama/mobility/wiki/KeyValue-Backend) (文字列用とテキスト用に 1 つずつ) 。`table` バックエンドはモデルごとに翻訳テーブルを使用し (Globalize と同じ方式) 、`column` は `title_en` や `title_es` のようなサフィックス付きのカラムを使用し、`serialized` は 1 つのテキストカラムにまとめて保存します。PostgreSQL では、`json`、`jsonb`、`hstore`、`container` (モデルごとに 1 つの jsonb カラム) を使ってネイティブに保存できます。独自のバックエンドを作成することも可能です。
* **どのバックエンドでも共通の API。** 読み書きは `I18n.locale` に従い、プラグイン (フォールバック、`post.title_es` のようなロケールアクセサ、変更追跡、キャッシュ、存在チェック) は[どのバックエンドを選んでも同じように動作します](https://github.com/shioyama/mobility#backends)。
* **クエリ。** [`Post.i18n.where(title: "...")`](https://github.com/shioyama/mobility#querying) は現在のロケールに応じた結合を自動で構築するため、保存方法を意識せずに翻訳済みの属性を検索できます。
* **ORM のサポート。** [Active Record 7.0 以降および Sequel で動作し](https://github.com/shioyama/mobility#installation)、wiki には Globalize からの移行ガイドも用意されています。
* **無料。** MIT ライセンスで提供されており、[現在のリリースは 1.3.2 です](https://rubygems.org/gems/mobility)。

## Mobility が対応しない部分

以下は、英語のタイトルと本文を持つ投稿の例です。SQLite 上で `key_value` バックエンドを使用し、タイトルのみスペイン語から英語へのフォールバックを設定しています。

```ruby title="app/models/post.rb"
class Post < ApplicationRecord
  extend Mobility
  translates :title, type: :string, fallbacks: { es: :en }
  translates :body,  type: :text
end
```

```ruby
post = Post.create!(title: "Spring sale", body: "Everything is 20% off this week.")

I18n.with_locale(:es) { post.title } # => "Spring sale"（フォールバックにより英語）
I18n.with_locale(:es) { post.body }  # => nil
I18n.with_locale(:ja) { post.title } # => nil
```

これはストレージ層としては正しい動作です。Mobility が保存したのは英語の値だけで、それ以外のロケールは誰かが書き込むまで空のままです。フォールバックを設定していればスペイン語の読者には英語が表示され、設定していなければ何も表示されません。商品リスト、記事、ヘルプページなど日々更新されるコンテンツでは、新規作成・編集されたレコードを誰かが言語ごとに翻訳し、対応するロケールで保存しなければなりません。

## General TranslationでMobilityの属性を埋める

General Translationの実行時翻訳エンドポイント `POST https://api.gtx.dev/v2/translate` は、文字列をオンデマンドで翻訳します。認証には、**Runtime translation** 権限を持つプロジェクトのAPIキーをベアラートークンとして渡します。ボディには、独自のIDをキーとする `requests` オブジェクトを含めます。各エントリには `source` 文字列と、必要に応じて `context` メモなどの `metadata` を指定します。加えて、`sourceLocale`、`targetLocale`、トップレベルの `metadata` オブジェクト (空でも可) も含めます。レスポンスは同じIDをキーとして返されます。これは小さなRubyメソッド1つで実装できます：

```ruby title="app/services/gt_translate.rb"
require "net/http"
require "json"

# { field => text } 形式のハッシュを General Translation のランタイム API で翻訳します。
# 要求されたすべての翻訳を返します。失敗時はデータベースへの書き込み前に例外を発生させます。
def gt_translate(fields, from:, to:, context: nil)
  uri = URI("https://api.gtx.dev/v2/translate")
  requests = fields.to_h do |field, text|
    [field.to_s, { source: text, metadata: { dataFormat: "STRING", context: context }.compact }]
  end

  request = Net::HTTP::Post.new(uri)
  request["Authorization"] = "Bearer #{ENV.fetch("GT_API_KEY")}" # Runtime translation 権限を持つプロジェクトキー
  request["Content-Type"] = "application/json"
  request["gt-api-version"] = "2026-03-06.v1"
  request.body = { requests:, sourceLocale: from.to_s, targetLocale: to.to_s, metadata: {} }.to_json

  response = Net::HTTP.start(uri.host, uri.port, use_ssl: true,
                            open_timeout: 5, read_timeout: 30) { |http| http.request(request) }
  raise "Translation request failed (#{response.code})" unless response.is_a?(Net::HTTPSuccess)

  results = JSON.parse(response.body)
  requests.keys.to_h do |field|
    result = results.fetch(field)
    unless result["success"] == true && result["translation"].is_a?(String)
      raise "Translation incomplete for #{field}"
    end
    [field, result.fetch("translation")]
  end
end
```

上記の投稿を一度だけ翻訳する場合は、英語の属性を読み取り、完成したスペイン語の翻訳結果を保存します。

```ruby
source = Mobility.with_locale(:en) do
  { title: post.title(fallback: false), body: post.body(fallback: false) }
end
translated = gt_translate(source,
                          from: :en, to: :es, context: "Blog post for an online shoe store")
Mobility.with_locale(:es) { post.update!(translated) }
```

このヘルパーは、投稿を更新する前に、リクエストしたすべてのフィールドに翻訳が存在することを確認します。モデルの通常のバリデーションも引き続き適用されます。 (リクエストおよびレスポンスのフィールドについては、[エンドポイントリファレンス](/docs/platform/openapi/reference/translation/translate-runtime)を参照してください。) 

General Translation は、単に機械翻訳を呼び出すだけではありません。このエンドポイントはプロジェクトの[用語集とカスタムプロンプト](/docs/platform/dashboard/guides/defining-context-for-translations)を適用して翻訳するため、製品名やトーンがプロダクト全体と統一されます。文脈メモによって、このテキストが靴店向けであることが伝わり、共通の用語によって商品説明がアプリやマーケティングサイトと一貫したものになります。APIキーはサーバー側で管理してください。継続的に自動化する場合は、既存のコンテンツ公開ワークフローに翻訳を組み込み、APIの[レート制限](/docs/platform/openapi/overview#api-basics)を守ってください。

この例ではモデルに直接保存しています。公開前に編集者の承認が必要なコンテンツの場合は、翻訳元の記事と同じ下書き・公開プロセスを通じて結果を保存してください。

## Mobility と General Translation の比較概要

| 機能             | Mobility                    | General Translation                                              |
| -------------- | --------------------------- | ---------------------------------------------------------------- |
| 概要             | 翻訳済みのモデル属性を保存するための Ruby gem | HTTP API、CLI、JavaScript および Python 向けライブラリ、ダッシュボードを備えた翻訳プラットフォーム |
| データベースへの翻訳の保存  | 対応 (8 種類のストレージバックエンド)       | 同じモデル属性に翻訳を提供                                                    |
| 翻訳の生成          | 非対応                         | 対応 (`POST /v2/translate` を使用)                                    |
| Ruby インテグレーション | モデル属性とロケールアクセサ              | Ruby から HTTP API を呼び出し                                           |
| 用語とトーンの一貫性     | 翻訳者に依存                      | すべてのリクエストに用語集とカスタムプロンプトを適用                                       |
| 料金             | 無料 (MIT ライセンス)              | [従量課金制](https://generaltranslation.com/pricing)                  |

## Mobility だけで十分な場合

すでに人の手で翻訳を作成しているなら、Mobility 単体での運用で問題ありません。たとえば、編集者が管理画面のフォームで言語ごとに入力している場合、翻訳会社に依頼している場合、あるいは法的文書のように人手による翻訳が欠かせないコンテンツを扱う場合です。対応言語が 2〜3 程度で、レコードの更新頻度が低い場合も、Mobility だけで十分です。一方、ユーザーの出品情報、サポート記事、数千点の商品を扱うカタログなど、人手での翻訳が追いつかないペースでコンテンツが増え、新しいレコードを保存した時点ですべての言語で利用できるようにしたい場合は、General Translation を導入してください。

## 重要なポイント

* Mobility は、翻訳済みのモデル属性を 8 種類のバックエンドで保存・取得でき、フォールバックやクエリにも対応しています。ただし、翻訳そのものは生成しません。
* Rails アプリから General Translation の `POST /v2/translate` エンドポイントを呼び出し、翻訳された属性を Mobility 経由で保存します。
* General Translation は用語集、カスタムプロンプト、コンテンツ固有の文脈を適用して翻訳します。既存のモデルや公開ワークフローはそのまま使い続けられます。
