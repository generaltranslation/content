いま「best localization software」で検索すると、ローカライゼーションベンダーが書いた記事が十数本ヒットし、どれも自社を1位に据えています。機能比較表を並べ、メリットとデメリットを挙げたうえで、 (意外なことに！) 自社製品を選ぶべきだと締めくくっています。

この記事ではそうしたことはしません。代わりに、このカテゴリ全体がなぜ見当違いの問題を解決しようとしているのか、そして本来解決すべき問題に取り組むとはどういうことなのかを解説します。

## ローカライゼーションスタックは3つに分断されている

2026年に多言語アプリをリリースするには、まったく別々の3つのシステムをつなぎ合わせる必要があります。

1. **i18nライブラリ** — コードベース内で文字列の抽出、補間、複数形処理、ロケールルーティングを担います。翻訳をレンダリングはしますが、翻訳を生成するわけではありません。
2. **翻訳管理システム (TMS)&#x20;**&#x20;— 翻訳ファイルの保存、ワークフローの管理、受け渡しの調整を担います。コードと翻訳者の間に立ちますが、翻訳そのものは行いません。
3. **言語サービスプロバイダー (LSP)&#x20;**&#x20;— 実際に翻訳済みコンテンツを生み出す人間の翻訳者、翻訳会社、あるいは機械翻訳エンジンです。コードのこともTMSのことも一切把握していません。

ライブラリは翻訳を知らず、TMSはコードを知らず、翻訳プロバイダーはそのどちらも知りません。これらを連携させるには、まず初期構築だけで数週間分のエンジニアリング工数がかかります。その後もスプリントのたびに、ファイルの同期、マージコンフリクトの解消、Webhookのデバッグ、そしてもともとパイプラインとして設計されていない仕組みのお守りに、何時間も奪われ続けることになります。

## 「エンドツーエンド」の本当の意味

General Translation は単なるライブラリではありません。TMS でもありません。パイプライン全体を担うものであり、Cursor、Ramp、Profound、Cognition、Sierra、ClickHouse など、開発者優先のチームに利用されています。

* **オープンソースの開発者向けライブラリ**：[`gt-next`](/docs/react/nextjs-quickstart)、[`gt-react`](/docs/react/react-quickstart)、そして [React Native/Expo](/docs/react/react-native-quickstart) のサポート。TypeScript に完全対応し、そのまま組み込める SDK です。
* **AI ファーストの翻訳プラットフォーム**：コードベース、プロダクト、用語を理解したうえで翻訳します。汎用的な機械翻訳を後付けしたものではありません。
* **AIエージェント Locadex**：コードベースをスキャンしてコードを国際化し、翻訳を作成して、プッシュのたびにプルリクエストを作成する[自動化された国際化エンジニア](/docs/platform/locadex/quickstart)です。

ライブラリと翻訳エンジンを一体で開発しているからこそ、ローカライゼーションが10倍簡単になります。JSON のエクスポートやインポートも、ファイル管理も、翻訳会社との調整も必要ありません。翻訳はソースコードから本番環境へ直接反映されます。

## 従来のTMSプラットフォームの問題点

従来の翻訳管理システムは、AI以前の世界を前提に作られています。想定しているのは決まったワークフローです。コンテンツをコードベースから抽出し、ダッシュボードにアップロードし、翻訳者に割り当て、レビューと承認を経てエクスポートし、再びコードに組み込む。うまくいくこともありますが、時間もコストもかかり、壊れやすい仕組みです。

**管理しているのはコードではなくファイルです。** TMSは翻訳ファイル (JSON、XLIFF、POなど) を取り込み、それらを管理するためのツールを提供します。しかし、本当の信頼できる情報源はコードベース、つまりコンポーネント、変数、UIの階層です。コードを理解せずにファイルだけを管理していては、受け渡しの過程で必ず文脈が失われます。

ここ数年で、ほとんどのプラットフォームがAI/MT機能を追加しました。たいていはサードパーティの機械翻訳エンジンに文字列を渡し、使うエンジンを選べるようにしただけのものです。AIが目にするのは、切り離された個々の文字列だけです。コンポーネントツリーも、変数名も、周囲のUIも見えていません。だからこそ、MTの出力にはいまだに大幅な手直しが必要なのです。

**作業を減らすのではなく、人を増やすことでスケールします。** TMSのビジネスモデルは、ロール、権限、多段階のレビュー、承認ワークフローなど、人間の翻訳者を取りまとめることを中心に成り立っています。規制の厳しいエンタープライズ向けコンテンツには必要な仕組みですが、SaaSアプリを20言語で提供する開発チームにとっては無駄なオーバーヘッドでしかありません。

では、価格はどうでしょうか。人気のプラットフォームの中には、金額を知るだけでも営業担当者との商談が必要なものが少なくありません。また、チームの拡大に伴って膨れ上がるシート単位の料金を課すものもあります。コストが予測できなければ、新しい言語を追加するための予算も立てにくくなります。

## スタンドアロンの i18n ライブラリの何が問題なのか

React や Next.js 向けの人気 i18n ライブラリは、補間、複数形処理、ロケールルーティング、Server Component のサポートなど、レンダリングについては十分にこなします。

**しかし、翻訳は一切してくれません。**

渡されたものをそのままレンダリングするだけです。結局、次の作業は自分で行う必要があります。

* すべての翻訳可能な文字列を JSON ファイルに抽出する
* ロケールごとに個別のファイルを管理する
* それらのファイルを手作業で翻訳するか、翻訳者を雇うか、TMS を導入する
* コードベースの変更に合わせて、すべてのファイルを同期し続ける

10 言語で 500 キーなら、管理すべきエントリは 5,000 件です。50 言語なら 25,000 件にもなります。ライブラリはこうした作業を何も手伝ってくれません。渡されたものをレンダリングするだけで、解決できるのはせいぜい問題の半分です。

## General Translation がループを完結させる仕組み

**1. インストールしてコードを書く。** [セットアップウィザード](/docs/cli/quickstart)を実行し、コンテンツを [`<T>`](/docs/react/reference/components/t) コンポーネントでラップします。キーの抽出も JSON ファイルも不要です。

```tsx
import { T } from 'gt-next';

export default function Home() {
  return (
    <T>
      <h1>Welcome to our app</h1>
      <p>This content is translated automatically.</p>
    </T>
  );
}
```

**2. 開発する。** 翻訳はオンデマンドで表示されます。言語を切り替えれば、すぐに結果を確認できます。

**3. リリースする。** コマンド1つで、すべての翻訳をビルド時に生成します。翻訳は事前生成済みのものがキャッシュされ、CDN経由で配信されます。[デプロイガイドを見る →](/docs/react/nextjs-quickstart#11-deploy-to-production)

**4. 自動化する。** [Locadex](/docs/platform/locadex/quickstart) がリポジトリを監視します。コードをプッシュすると、変更をスキャンして新しいコンテンツを国際化し、翻訳を生成してPRを作成します。人が介入する必要は一切ありません (もちろん、介入したい場合は可能です) 。その場合は翻訳エディターで差分を並べて確認でき、コンテンツの公開前でも公開後でも編集できます。

## 多くの翻訳AIがうまくいかない理由

多くのローカライゼーションAIは、文字列を1つずつ、個別に翻訳します。「Apple」は果物かもしれませんし、企業名かもしれません。「Cell」は生物の細胞かもしれませんし、スプレッドシートのセルかもしれません。文脈がなければ、AIは推測するしかありません。

General TranslationのAIは、コードベース全体の文脈を把握します。コンポーネントの階層、変数名、周囲のUI、そしてプロダクトの用語集まで考慮するため、手作業で修正しなくても自然な訳文が得られます。判断が難しいケースでは、コンポーネント内で直接[明示的な文脈を追加](/docs/react/reference/components/t#props)できます。

## 人数ではなく利用量に応じた料金体系

GT は従量課金制です。料金は翻訳した分だけ。チームが大きくなるほど膨らむシート単位の料金はかかりません。営業担当との商談も不要です。[料金の詳細を見る →](https://generaltranslation.com/pricing)
