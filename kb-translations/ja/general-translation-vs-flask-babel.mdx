Babel は Unicode CLDR データを使って日付、数値、通貨をフォーマットし、`pybabel` コマンドで gettext メッセージカタログの抽出、更新、コンパイルを行います。Flask-Babel は、これらのツールを Flask のリクエスト処理や Jinja テンプレートに統合します。General Translation は抽出とコンパイルの間でカタログを埋めるため、既存の Flask-Babel のセットアップはそのままに、アプリに自動翻訳を導入できます。

## Babel と Flask-Babel の優れている点

* **CLDR に基づくロケールのフォーマット。** [Babel 2.18.0 には CLDR 47](https://babel.pocoo.org/en/latest/changelog.html#version-2-18-0) のデータが同梱されており、1,000 を超えるロケール識別子に対応しています。たとえば `format_currency(1234.5, "EUR")` はスペイン語なら「1.234,50 €」、`format_date` はポーランド語なら「16 października 2026」を返します。
* **カタログツール。** [`pybabel extract`](https://babel.pocoo.org/en/latest/cmdline.html) は `babel.cfg` のマッピングに従って Python ファイルと Jinja テンプレートを読み込みます。`pybabel init` は適切な複数形規則とスロット (ポーランド語なら 3 つ) を備えた PO ファイルを作成し、`pybabel update` は新しい文字列をマージして、変更された文字列に fuzzy マークを付けます。`pybabel compile` は `.mo` ファイルをビルドします。
* **Flask とのインテグレーション。** `locale_selector` と `timezone_selector` で[リクエストごとのロケールとタイムゾーンを決定](https://python-babel.github.io/flask-babel/#configuration)でき、インポート時に定義される文字列には `lazy_gettext` で対応できます。Jinja テンプレートでは `_()`、`{% trans %}`、フォーマット用フィルターが使えます。また `force_locale` を使えば、別の言語でメールを送信する場合などにロケールを一時的に切り替えられます。
* **安定性と無償利用。** どちらも BSD ライセンスです ([Babel のライセンス](https://babel.pocoo.org/en/latest/license.html)を参照) 。Babel はどの Python プログラムでも動作し、Flask-Babel の[現在のリリースは 4.0.0](https://github.com/python-babel/flask-babel/releases/tag/v4.0.0) です。

## Babel と Flask-Babel が開発者任せにしていること

以下は、Flask-Babel を使った小さなアプリの例です。

```python title="app.py"
from datetime import date
from flask import Flask, request
from flask_babel import Babel, gettext, ngettext, format_currency, format_date


def select_locale():
    return request.accept_languages.best_match(["en", "es", "pl"])


app = Flask(__name__)
babel = Babel(app, locale_selector=select_locale)


@app.route("/inbox/<int:count>")
def inbox(count):
    return {
        "title": gettext("Inbox"),
        "unread": ngettext("You have %(num)d unread message.", "You have %(num)d unread messages.", count),
        "price": format_currency(1234.5, "EUR"),
        "date": format_date(date(2026, 10, 16), format="long"),
    }
```

`pybabel extract`、`pybabel init -l pl`、`pybabel compile` を実行すると、すべての `msgstr` が空のポーランド語カタログが生成されます。この状態で Flask-Babel 4.0.0 に `Accept-Language: pl` を指定したリクエストを送ると、次の結果が返されました。

```json title="Output"
{
  "date": "16 października 2026",
  "price": "1 234,50 €",
  "title": "Inbox",
  "unread": "You have 5 unread messages."
}
```

Babel は日付と価格をポーランド語向けにフォーマットしますが、文字列はすべて英語のまま残り、警告も一切出ません。各文字列は、誰かが PO エントリ (ポーランド語の 3 つの複数形をすべて含む) を記入し、さらに `pybabel compile` を実行して再デプロイするまで翻訳されないままです。文字列を追加または編集するたびに、この作業を言語ごとに繰り返さなければなりません。

## General Translation で Babel のカタログを翻訳する

Flask-Babel ですでに問題なく運用できているなら、そのまま使い続け、カタログの書き出しは General Translation の CLI に任せましょう。英語のカタログを一度作成し、抽出のたびに更新しておけば、翻訳元を翻訳と同じツリーに置いておけます：

```bash
pybabel extract -F babel.cfg -k lazy_gettext -o messages.pot .
pybabel init -i messages.pot -d translations -l en     # 初回のみ
pybabel update -i messages.pot -d translations -l en   # 抽出するたびに実行
```

次に、`gt.config.json` でそのファイルを指定します。この設定は `gt` 2.26.5 で動作確認済みです：

```json title="gt.config.json"
{
  "defaultLocale": "en",
  "locales": ["es", "pl", "pt_BR"],
  "customMapping": { "pt_BR": { "code": "pt-BR" } },
  "files": {
    "pot": {
      "include": ["translations/[locale]/LC_MESSAGES/messages.po"],
      "transformationFormat": "PO"
    }
  }
}
```

`pot` キーは PO ファイルと POT ファイルを読み込み、`"transformationFormat": "PO"` は翻訳済みの `.po` ファイルを書き出します ([PO / POT フォーマットリファレンス](/docs/cli/reference/formats/po-pot-files)を参照) 。[`customMapping`](/docs/cli/reference/config#custom-mapping) は、Babel の `pt_BR` ディレクトリを標準のロケールコード `pt-BR` に対応付けます。まず [CLI](/docs/cli/quickstart) をセットアップしてください。既存の翻訳がある場合は、新しい翻訳を生成する前に [`npx gt upload`](/docs/cli/reference/commands/upload) でインポートします。次に [`npx gt translate`](/docs/cli/reference/commands/translate) を実行し、続けて `pybabel compile -d translations` を実行します。

General Translation は、各エントリを `msgctxt`、翻訳者コメント、ソース参照、フラグとともに文脈として送信します。複数形のエントリでは、対象言語の `Plural-Forms` ヘッダーを書き込み、すべての `msgstr[n]` スロットを埋めます (たとえばポーランド語なら 3 つすべて) 。さらに、`%(num)d` などのプレースホルダーが崩れずに保持されているかも検証します。変更のないエントリについては、次回の実行時に以前の翻訳が再利用されます。[コンテキストグループ](/docs/platform/dashboard/guides/defining-context-for-translations)で用語集とカスタムプロンプトを設定すれば、カタログだけでなく製品全体で用語の一貫性を保てます。また、レビュー担当者はダッシュボードで[各エントリを編集](/docs/platform/dashboard/guides/reviewing-translations)できます。CI で CLI を実行すれば、デプロイのたびに最新のカタログを反映できます。後からローカルで編集した場合は、再度生成する前に [`npx gt save-local`](/docs/cli/reference/commands/save-local) で保存してください。

## Babel・Flask-Babel と General Translation の比較早見表

| 機能              | Babel と Flask-Babel                                    | General Translation                                                    |
| --------------- | ------------------------------------------------------ | ---------------------------------------------------------------------- |
| 文字列の書き方         | `gettext` の呼び出しと Jinja の `{% trans %}` で記述し、PO ファイルに抽出 | 既存の呼び出しやテンプレートはそのままで、抽出されたカタログを翻訳                                      |
| コンテンツの翻訳        | 非対応                                                    | 対応 ([`npx gt translate`](/docs/cli/reference/commands/translate) を使用)  |
| 複数形             | `pybabel init` がスロットを作成し、各スロットは手動で記入                   | 対象言語に必要なすべての PO スロットを生成                                                |
| 日付・数値・通貨のフォーマット | 対応 (CLDR に基づく)                                         | Babel のフォーマットをそのまま利用                                                   |
| Jinja テンプレート    | 対応                                                     | 既存のテンプレートから抽出されたメッセージを翻訳                                               |
| フレームワーク         | Babel は環境を問わず利用可能、Flask-Babel は Flask 専用               | Flask などの gettext アプリケーションの PO カタログに対応した CLI                           |
| ライセンス           | BSD                                                    | MIT ライセンスの CLI                                                         |
| 料金              | 無料                                                     | [翻訳量に応じた従量課金](https://generaltranslation.com/pricing)                  |

## 使い分けの指針

翻訳者や TMS から必要なカタログがすでに提供されている場合は、現在の翻訳プロセスをそのまま使い続けてください。新規・変更されたメッセージを開発中に翻訳し、チームがプロジェクト間で共有する用語管理やレビューツールも活用したい場合は、General Translation を追加してください。Jinja、リクエストのロケール、日付、通貨は引き続き Flask-Babel が処理し、アプリケーションのコードもそのままです。

## 重要なポイント

* Babel はあらゆるロケールに対応した日付・数値・通貨のフォーマットと gettext カタログの管理を担い、Flask-Babel はそれを Flask に統合します。ただし、どちらも文字列の翻訳は行いません。
* General Translation の CLI は、`pot` キー、`"transformationFormat": "PO"`、および `pt_BR` などのディレクトリ用の `customMapping` を使って Babel の PO ファイルを翻訳し、言語ごとにすべての複数形スロットを埋めます。
* Flask-Babel のレンダリングとフォーマットはそのまま活かし、既存の翻訳をインポートしたうえで、抽出とコンパイルの間に General Translation を組み込みましょう。
