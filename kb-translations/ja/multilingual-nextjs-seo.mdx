## 多言語SEOに特別な配慮が必要な理由

Next.jsアプリにi18nを導入する開発者の多くは、UIを翻訳しただけで完了としてしまいがちです。
しかし、検索エンジンが各言語版を発見・インデックスし、適切に関連付けられなければ、
せっかくの翻訳も誰の目にも届きません。

SEOを適切にセットアップしていない多言語サイトでは、次のような問題が起こります。

* Googleが1つの言語版だけをインデックスし、他の言語版を無視することがある
* スペイン語で検索したユーザーに英語のページが表示される
* Googleが `/en/about` と `/fr/about` を同一ページとみなし、重複コンテンツとしてペナルティを受ける
* 検索結果のスニペットに誤った言語が表示される

**朗報です：** Next.jsで多言語SEOを正しく設定するのは、決して難しくありません。
押さえるべきポイントは6つあり、本ガイドでは [`gt-next`](/docs/react/nextjs-quickstart) を使ってそのすべてを解説します。

***

## 1. ロケールに基づくURLルーティング

多言語SEOの基本は、言語ごとに別々のURLを用意することです。
検索エンジンが各言語版を個別にインデックスするには、言語ごとにクロール可能な独立したURLが必要です。

つまり、**URLにロケールを含める**必要があります。クッキーやクエリパラメーター、`Accept-Language` による検出だけでは不十分です。

```text
✅ generaltranslation.com/en/about
✅ generaltranslation.com/fr/about
✅ generaltranslation.com/es/about

❌ generaltranslation.com/about?lang=fr
❌ generaltranslation.com/about （ロケールをクッキーで保持）
```

### gt-next でロケールルーティングを設定する

まず、ページを `[locale]` 動的セグメント配下に配置します：

```text
app/
└── [locale]/
    ├── layout.tsx
    ├── page.tsx
    └── about/
        └── page.tsx
```

次に、プロジェクトルートにミドルウェアを作成します (Next.js 16以降は `proxy.ts`、Next.js 15以前は `middleware.ts`) 。

```ts title="proxy.ts"
import { createNextMiddleware } from 'gt-next/middleware';

export default createNextMiddleware();

export const config = {
  matcher: ['/((?!api|static|.*\\..*|_next).*)'],
};
```

これにより、ロケールのプレフィックス付きURLが自動的に生成されます。
デフォルトでは、デフォルトロケール (例：英語) にはプレフィックスが付かないため、`/about` はシンプルなままです。
一方、スペイン語のユーザーは `/es/about`、フランス語のユーザーは `/fr/about` にアクセスすることになります。

## 2. HTML の `lang` 属性を設定する

`<html>` タグの `lang` 属性は、そのページが何語で書かれているかをブラウザや検索エンジンに伝えます。
アクセシビリティと SEO の向上のために実施できる、最も手軽で効果の高い施策の一つです。

この属性がないと、スクリーンリーダーは言語を推測するしかなく (誤ることも多い) 、検索エンジンも言語を確信を持って判定しにくくなります。

{/* useLocale はクライアント側でもサーバー側でもレンダリングされるコンポーネントで使えますが、非同期コンポーネントでは使えません */}

gt-next には [`useLocale`](/docs/react/reference/hooks/use-locale) フックが用意されているため、ルートレイアウトで簡単に設定できます：

```tsx title="app/[locale]/layout.tsx"
import { useLocale, GTProvider } from 'gt-next';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  const locale = useLocale();

  return (
    <html lang={locale}>
      <body>
        <GTProvider>
          {children}
        </GTProvider>
      </body>
    </html>
  );
}
```

[`useLocale`](/docs/react/reference/hooks/use-locale) は BCP 47 形式のロケールコード (例: `en-US`、`ar`、`zh-Hans`) を返します。

## 3. カノニカル URL

カノニカルタグは、どの URL がページの「プライマリ」バージョンであるかを検索エンジンに伝えます。
多言語サイトでは、各言語バージョンが自分自身をカノニカルとして指定する必要があります:

```html
<!-- /fr/about ページの場合 -->
<link rel="canonical" href="https://example.com/fr/about" />
```

これにより、検索エンジンがフランス語のページを英語のページの重複として扱うのを防げます。

Next.js では、[メタデータ API](https://nextjs.org/docs/app/api-reference/functions/generate-metadata) を使ってカノニカルを設定します。
gt-next&#39;s の [`getLocale`](/docs/react/nextjs/reference/functions/get-locale) と組み合わせれば、ロケールごとに正しいカノニカルを生成できます。

```tsx title="app/[locale]/about/page.tsx"
import { getLocale } from 'gt-next/server';

const BASE_URL = 'https://example.com';

export async function generateMetadata() {
  const locale = await getLocale();

  return {
    alternates: {
      canonical: `${BASE_URL}/${locale}/about`,
    },
  };
}

export default function AboutPage() {
  return <h1>About Us</h1>;
}
```

デフォルトロケールでプレフィックスを付けない場合は、次のように調整してください:

```tsx
import { getDefaultLocale } from 'gt-next';
import { getLocale } from 'gt-next/server';

export async function generateMetadata() {
  const locale = await getLocale();
  const defaultLocale = getDefaultLocale();
  const path = '/about';

  const prefix = locale === defaultLocale ? '' : `/${locale}`;

  return {
    alternates: {
      canonical: `${BASE_URL}${prefix}${path}`,
    },
  };
}
```

## 4. hreflang タグ

hreflang タグは、多言語 SEO において最も重要なシグナルです。
hreflang タグは検索エンジンに「このページには以下の言語版もあり、それぞれの URL はこちらです」と伝える役割を果たします。

hreflang がない場合、Google は検索結果にどの言語版を表示すべきかを推測するしかなく、その判断はしばしば誤ります。

```html
<link rel="alternate" hreflang="en" href="https://example.com/about" />
<link rel="alternate" hreflang="fr" href="https://example.com/fr/about" />
<link rel="alternate" hreflang="es" href="https://example.com/es/about" />
<link rel="alternate" hreflang="x-default" href="https://example.com/about" />
```

`x-default` タグは、ユーザーに一致する言語が指定されていない場合にどの URL を表示すべきかを検索エンジンに伝えます。

Next.js では、メタデータ API の `alternates.languages` プロパティを使って hreflang を追加できます。
以下は gt-next で使える再利用可能なヘルパーです：

```tsx title="lib/i18n-metadata.ts"
import { getDefaultLocale } from 'gt-next';
import { getLocale } from 'gt-next/server';

const BASE_URL = 'https://example.com';
const SUPPORTED_LOCALES = ['en', 'fr', 'es'];

export async function getI18NMetadata(path: string) {
  const locale = await getLocale();
  const defaultLocale = getDefaultLocale();

  const getUrl = (loc: string) => {
    const prefix = loc === defaultLocale ? '' : `/${loc}`;
    return `${BASE_URL}${prefix}${path}`;
  };

  const languages: Record<string, string> = {};
  for (const loc of SUPPORTED_LOCALES) {
    languages[loc] = getUrl(loc);
  }
  languages['x-default'] = getUrl(defaultLocale);

  return {
    alternates: {
      canonical: getUrl(locale),
      languages,
    },
  };
}
```

あとは、任意のページで次のように使用します：

```tsx title="app/[locale]/about/page.tsx"
import { getI18NMetadata } from '@/lib/i18n-metadata';

export async function generateMetadata() {
  return await getI18NMetadata('/about');
}
```

これにより、カノニカルタグとすべての hreflang タグを 1 回の呼び出しでまとめて生成できます。

## 5. 翻訳済みメタデータ

検索エンジンは、ページのタイトルと説明文を検索結果に表示します。
フランス語のページなのにこれらが英語のままだと、ユーザーにクリックされにくくなるうえ、Google によって検索順位を下げられる可能性もあります。

gt-next の [`getGT`](/docs/react/nextjs/reference/functions/get-gt) 関数を使って、メタデータの文字列を翻訳しましょう：

```tsx title="app/[locale]/about/page.tsx"
import { getGT } from 'gt-next/server';
import { getI18NMetadata } from '@/lib/i18n-metadata';

export async function generateMetadata() {
  const t = await getGT();
  const i18nMeta = await getI18NMetadata('/about');

  return {
    title: t('About Us'),
    description: t('Learn about our mission and team.'),
    ...i18nMeta,
  };
}
```

これにより、検索結果にローカライズされたタイトルと説明文が表示されるため、
英語以外の検索クエリでのクリック率が大幅に向上します。

## 6. 多言語サイトマップ

サイトマップを用意すると、各言語版を含むすべてのページを検索エンジンが見つけやすくなります。
多言語サイトでは、サイトマップにも hreflang 注釈を含めるようにしましょう。

Next.js では、`sitemap.ts` ファイルを使って[サイトマップをプログラムで生成](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/sitemap)できます。

```ts title="app/sitemap.ts"
import { MetadataRoute } from 'next';

const BASE_URL = 'https://example.com';
const LOCALES = ['en', 'fr', 'es'];
const DEFAULT_LOCALE = 'en';
const PAGES = ['/', '/about', '/blog', '/contact'];

export default function sitemap(): MetadataRoute.Sitemap {
  return PAGES.flatMap((path) => {
    const getUrl = (locale: string) => {
      const prefix = locale === DEFAULT_LOCALE ? '' : `/${locale}`;
      return `${BASE_URL}${prefix}${path === '/' ? '' : path}`;
    };

    const languages: Record<string, string> = {};
    for (const locale of LOCALES) {
      languages[locale] = getUrl(locale);
    }

    return LOCALES.map((locale) => ({
      url: getUrl(locale),
      lastModified: new Date(),
      alternates: { languages },
    }));
  });
}
```

これにより、ページ×ロケールごとに 1 つのエントリを持つサイトマップが生成され、
各エントリには、すべての言語バージョンを指す hreflang 注釈が含まれます。

## チェックリスト

ここまでの内容を簡単にまとめます。

| SEO 要件           | 実装方法                                                                                                            |
| ---------------- | --------------------------------------------------------------------------------------------------------------- |
| URL にロケールを含める    | [`createNextMiddleware()`](/docs/react/nextjs/reference/functions/create-next-middleware) と `[locale]` 動的セグメント  |
| HTML の `lang` 属性 | ルートレイアウトで [`useLocale()`](/docs/react/reference/hooks/use-locale) を使用                                           |
| カノニカル URL        | [`getLocale()`](/docs/react/nextjs/reference/functions/get-locale) + Next.js メタデータ API の `alternates.canonical` |
| hreflang タグ      | Next.js メタデータ API の `alternates.languages` にすべてのサポート対象のロケールを指定                                                  |
| 翻訳済みメタデータ        | ページのタイトルと説明文に [`getGT()`](/docs/react/nextjs/reference/functions/get-gt) を使用                                     |
| 多言語サイトマップ        | ロケールごとのエントリと hreflang 代替リンクを含む `sitemap.ts`                                                                     |
