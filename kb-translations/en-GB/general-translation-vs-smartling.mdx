Smartling sells end-to-end localisation: a translation management system (TMS) with a CAT (computer-assisted translation) tool and translation memory, AI translation through its AI Hub, human translation from Smartling Language Services, and a Global Delivery Network (GDN) that translates websites as a proxy. For software, the code side runs through files: resource files in your repository become files in Smartling, their strings are parsed out and translated, and translations come back via the GitHub Connector, a self-hosted Repository Connector or the CLI. General Translation, by contrast, starts from the code.

## What Smartling does well

* **AI and human translation from one vendor.** Smartling&#39;s [translation services page](https://www.smartling.com/translation-services) lists machine and AI translation with instant turnaround, AI Human Translation (AI-assisted human translation) at 1 day, and Creative Translation (expert translation for complex projects) at 2 days, from a language services team of more than 4,000 linguists.
* **AI Hub.** [LLMs and machine translation engines](https://help.smartling.com/hc/en-us/articles/10318350761883-Smartling-s-AI-Hub) such as DeepL, Google and Microsoft, with your glossary and translation memory pulled into prompts.
* **Websites without code changes.** The GDN serves translated pages as a [translation proxy](https://help.smartling.com/hc/en-us/articles/18558261190683-Introduction-to-the-GDN).
* **Visual context.** [HTML captured with a Chrome extension or JavaScript library](https://help.smartling.com/hc/en-us/articles/360057484273--Overview-of-Visual-Context), screenshots matched to strings with OCR, PDFs and video.
* **Quality tooling.** A CAT tool, quality checks and an [LQA Agent](https://help.smartling.com/hc/en-us/articles/49428460628507-LQA-Agent-AI-Powered-Quality-Assurance) that scores jobs against the MQM framework.
* **Compliance and connectors.** [PCI Level 1, SOC 2, HIPAA, HITRUST, ISO 27001 and ISO 42001](https://www.smartling.com/security), plus 50+ connectors for CMSs and marketing tools such as AEM, Contentful and Salesforce.

## What Smartling still leaves to your engineers

Smartling&#39;s repository workflow moves resource files through a translation job:

1. Set up an i18n library and extract or write the resource files it loads. [Smartling&#39;s SDKs](https://help.smartling.com/hc/en-us/articles/1260806475390-Smartling-SDKs-Overview) connect to its API.
2. Connect the repository. The hosted GitHub Connector watches pull requests or commits, the self-hosted [Repository Connector](https://help.smartling.com/hc/en-us/articles/360008032174-Options-for-Automation-with-Source-Repositories) serves GitHub Enterprise, GitLab, Bitbucket and SVN, or you push files with `smartling-cli files push`.
3. Wait for the translation job. In the GitHub Connector&#39;s [pull request mode](https://help.smartling.com/hc/en-us/articles/14901568064411-GitHub-Configuration-Modes-Pull-Request-Single-Branch-On-Demand), Smartling&#39;s docs say a pull request shouldn&#39;t be merged or deleted until its translations are delivered, so a feature pull request is held up waiting for translation.
4. Merge the delivery pull request (the [Repository Connector commits to the branch](https://help.smartling.com/hc/en-us/articles/44557348474139-Repository-Connector-Architecture-Overview) instead), wire each new language into the app, and check every screen.

App strings also start without visual context: the GitHub Connector doesn&#39;t capture it automatically, and Smartling&#39;s [supported file types](https://help.smartling.com/hc/en-us/articles/360007998893--Supported-File-Types) table lists none by default for JSON, iOS and Android files, so it has to come from screenshots or captures your team adds.

Smartling has a free-to-start Core plan and an Enterprise plan available through sales, and it publishes per-word starting rates for each kind of translation. (See [Smartling plans](https://www.smartling.com/plans), checked October 2026.)

| ----------------------- | ------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Where strings live      | Resource files whose strings Smartling parses and stores                                    | In your code inside [`<T>`](/docs/react/reference/components/t), or in the resource files you already have                                |
| How code connects       | GitHub Connector, Repository Connector, CLI or API                                          | [`npx gt translate`](/docs/cli/reference/commands/translate) in your build, or [Locadex](/docs/platform/locadex/quickstart) pull requests |

## Why teams choose General Translation over Smartling

With General Translation, the same code change that introduces copy can generate its translations. Copy stays readable inside [`<T>`](/docs/react/reference/components/t), and your build produces the language files the app needs.

* **Faster.** Put [`npx gt translate`](/docs/cli/reference/commands/translate) before the application build to generate translations for the release you&#39;re shipping. Alternatively, configure [Locadex](/docs/platform/locadex/guides/configuring-automations) to open translation pull requests from repository events. Engineers can run localisation through their existing build and review process instead of coordinating a separate delivery job.
* **Cheaper to run.** Inline [`<T>`](/docs/react/reference/components/t) blocks remove key creation and resource-file handoffs from routine copy changes. The CLI reuses unchanged translations, so repeated builds generate only new or changed text. See [General Translation pricing](https://generaltranslation.com/pricing) for usage rates and [Smartling&#39;s service rates](https://www.smartling.com/translation-services) for its AI and human options.
* **Higher quality.** Smartling lists no visual context by default for JSON, iOS and Android files; teams have to supply screenshots or captures. General Translation carries the structure of marked JSX and variable placeholders into translation, with [context notes](/docs/react/reference/components/t) to clarify intent and your Glossary and Custom Prompts for product terminology. Reviewers can correct the output in the [Dashboard Translation Editor](/docs/platform/dashboard/guides/reviewing-translations), keeping generation and review in one workflow.
* **Lower risk.** The MIT-licensed `gt-react` and `gt-next` libraries can render [bundled translations](/docs/react/guides/storing-translations) without a General Translation account or runtime service call. The generated files stay with your app, giving you control over its deployed copy.

General Translation is SOC 2 Type II and ISO 27001 certified and GDPR compliant, and Enterprise plans add SSO, SCIM provisioning, audit logs, custom roles and forward-deployed engineers. (See its [Trust Centre](https://trust.inc/generaltranslation).)

Cursor uses General Translation across its web product and documentation in 14+ locales. (See [production deployments](https://generaltranslation.com/enterprise).)

## When Smartling is the better fit

Choose Smartling when you want AI and human translation purchased from a single vendor with a quality guarantee, when marketing sites need translating through a proxy without code changes, when your industry requires certifications such as PCI or HIPAA, when content lives in many enterprise CMS and marketing tools, or when you exchange XLIFF, TMX or Office files with vendors.

## Moving from Smartling to General Translation

Start with the resource files your app already loads, such as JSON or PO. [Configure the CLI](/docs/cli/guides/configuring) for those files and run [`npx gt upload`](/docs/cli/reference/commands/upload) to import the sources and existing translations before your first [`npx gt translate`](/docs/cli/reference/commands/translate) run. Your existing i18n library and file layout can stay in place.

Import your glossary into a [Context Group](/docs/platform/dashboard/guides/defining-context-for-translations), then review the generated copy in the Dashboard. Adopting inline [`<T>`](/docs/react/reference/components/t) is a separate option for teams that also want to stop maintaining source keys. For the broader platform decision, see [Why use General Translation instead of a TMS?](/kb/general-translation-vs-tms).

## Is General Translation an alternative to Smartling?

Yes. General Translation combines code-aware generation, build automation and Dashboard review for software teams. You can keep existing catalogues or use inline JSX. Smartling is a strong fit if you want a website translation proxy or human translation services from the same vendor.

## Key takeaways

* Smartling is a full-service enterprise platform, at its strongest when you want AI and human translation, a website proxy and broad compliance from a single vendor.
* Engineers still maintain keyed resource files, and in pull request mode a feature pull request waits until its translations are delivered.
* General Translation brings code context, generation and review into the release workflow, while bundled translations keep production delivery within your app.
