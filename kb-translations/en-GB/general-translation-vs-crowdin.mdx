Crowdin&#39;s [localisation platform](https://crowdin.com/) organises localisation around translation projects: engineers maintain resource files, connect them to Crowdin and bring translated catalogues back into the app. Its automation moves content through that workflow. General Translation brings translation into development itself: copy stays in your components, and translations are generated with your build.

## What Crowdin does well

* **Free to start.** The [Free plan](https://crowdin.com/pricing) includes 60,000 hosted words, with translations shared into Crowdin&#39;s translation memory, and open-source projects that meet its [open-source licence criteria](https://crowdin.com/product/for-open-source) (such as an OSI licence and no related commercial product) can get a free licence.
* **Developer tooling.** A CLI configured in `crowdin.yml`, Git integrations for GitHub, GitLab, Bitbucket and Azure Repos, a GitHub Action, an MCP server, and [700+ apps and integrations](https://store.crowdin.com/).
* **AI with context.** You can [bring your own OpenAI, Anthropic, Gemini or other provider keys](https://support.crowdin.com/crowdin-ai/), or use a Crowdin-managed model. Each request includes the string&#39;s context, key and maximum length, and prompts can add your glossary, translation memory, style guide, neighbouring strings and tagged screenshots.
* **Human translation.** A vendor marketplace, plus [Crowdin Language Services](https://crowdin.com/features/vendor-integrations), which can be ordered from within a project.
* **Context and QA.** Screenshots tagged to strings, an [In-Context editor for web apps](https://support.crowdin.com/in-context-localization/), a Figma plugin and built-in QA checks.
* **Mobile over-the-air updates.** iOS, Android and Flutter SDKs and a JavaScript client update strings from [Crowdin&#39;s CDN](https://support.crowdin.com/content-delivery/) without the need for a new app release.

## What Crowdin still leaves to your engineers

Engineers still have to set up and maintain the round trip between the app and Crowdin&#39;s translation projects:

1. Set up an i18n library, extract each English string into a resource file under a key, and reference the key in the component.
2. Describe the files in `crowdin.yml` and send them with [`crowdin upload sources`](https://crowdin.github.io/crowdin-cli/commands/crowdin-upload-sources), or use a Git integration or GitHub Action.
3. Set up AI, machine translation, vendors or your own translators to fill in each language, with whatever review steps your project needs.
4. Bring translated catalogues into the app. [Crowdin&#39;s GitHub integration](https://support.crowdin.com/github-integration/) returns them through an `l10n_` service branch. Its automatic sync runs hourly by default, with a configurable interval and an option to sync immediately.

Crowdin can also collect context from code: its coding-agent skills and [`crowdin context` commands](https://crowdin.github.io/crowdin-cli/commands/crowdin-context) have an agent analyse the codebase and upload descriptions for strings. With General Translation&#39;s [`<T>`](/docs/react/reference/components/t), the marked JSX itself supplies the text, nested elements and named placeholders used for translation.

Paid plans are priced mainly by hosted words (source words multiplied by target languages), plus manager seats, so each new language increases the hosted-word count. (See [Crowdin pricing](https://crowdin.com/pricing), checked October 2026.)

## Why teams choose General Translation over Crowdin

General Translation removes the catalogue authoring work for React UI: copy stays in your components inside [`<T>`](/docs/react/reference/components/t). Deleting a component removes its inline copy too, rather than leaving keys to clean up elsewhere.

* **Faster.** Put [`npx gt translate`](/docs/cli/reference/commands/translate) before your app build to generate and download translations in the same workflow. It reuses existing translations and generates only new or changed content. For a pull-request workflow, [Locadex](/docs/platform/locadex/quickstart) prepares the translation changes for you.
* **Cheaper to run.** Crowdin&#39;s hosted-word count grows with the source catalogue and the number of target languages. General Translation charges for translation usage rather than for hosting that catalogue. Keeping completed translations does not create a recurring translation charge; [pricing](https://generaltranslation.com/pricing) lists the usage rates.
* **Higher quality.** A [`<T>`](/docs/react/reference/components/t) block can keep a heading, sentence, link and dynamic placeholders together, so the translator sees how they relate rather than receiving isolated keys. Add developer notes and a shared [Glossary and Custom Prompts](/docs/platform/dashboard/guides/defining-context-for-translations) for product terminology. Reviewers can edit the result in the [Translation Editor](/docs/platform/dashboard/guides/reviewing-translations).
* **Lower risk.** You can keep your existing i18n library and import reviewed translations before changing how new ones are produced. This lets you adopt General Translation without rewriting every component or discarding your translators&#39; work.

Cursor ships 14+ locales across web and docs with General Translation. (See [production deployments](https://generaltranslation.com/enterprise).)

## When Crowdin is the better fit

Choose Crowdin when an open-source project qualifies for its free licence and wants community translators, when you run a human translation programme with vendors and multi-step review, when you exchange XLIFF or Office files, or when native mobile apps need its over-the-air SDKs.

## Moving from Crowdin to General Translation

For supported catalogues such as JSON, YAML, PO, and iOS or Android resource files, configure their source and locale paths in `gt.config.json`. Follow the [file translation set-up](/docs/cli/quickstart) and run [`npx gt upload`](/docs/cli/reference/commands/upload) to import existing translations before generating new ones. Bring your glossary into a [Context Group](/docs/platform/dashboard/guides/defining-context-for-translations) so that new translations use the same terminology.

In a React app, you can then introduce [`<T>`](/docs/react/reference/components/t) as you build new screens. For a comparison across vendors, see [Why use General Translation instead of a TMS?](/kb/general-translation-vs-tms).

## Is General Translation an alternative to Crowdin?

Yes. General Translation combines AI translation, an editor for human review, and libraries that keep React copy in JSX. It also translates existing catalogues, so replacing Crowdin doesn&#39;t mean replacing your i18n library first.

## Key takeaways

* Crowdin is a strong TMS for open-source and human translation programmes, with a free plan and AI that draws on keys, screenshots and glossaries.
* Crowdin automates catalogue delivery; engineers still connect those catalogues to the app and configure the translation workflow.
* Choose General Translation to remove keyed catalogues from React authoring, generate translations during a release, and keep your existing reviewed translations during adoption.
