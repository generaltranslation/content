A translation management system (TMS) is where strings go to be translated. You sync resource files or keys from your repository into the TMS, translators and AI translate them there with translation memory and glossaries, and the results come back as files or a pull request. Smartling, Lokalise, Phrase, Crowdin and Transifex all work this way, and the model suits large translation programmes run by localisation managers and language vendors. For a development team, the cost lies in the work around the TMS: the steps engineers still do by hand, and the context a string loses when it leaves the code.

## What a TMS does well

A TMS is built to coordinate people and content at scale:

* **Translation tooling.** Editors with translation memory, glossaries, and QA checks for placeholders, length and terminology, plus workflows that chain translation, review and proofreading steps.
* **Human translation.** Smartling has its own language services team of more than 4,000 linguists, Lokalise and Phrase let you order professional translation on a per-word basis, and Crowdin runs a vendor marketplace.
* **File formats.** Each platform reads the common app formats, plus ARB and XLIFF, the format that translation vendors use to exchange files.
* **Context for translators.** Screenshots matched to strings, Figma plugins, key descriptions with character limits, and in-context editors for websites.
* **AI translation.** Every vendor now offers it, and their AI features can draw on your glossary, translation memory and style guide.
* **Mobile delivery.** Lokalise, Phrase, Crowdin and Transifex ship SDKs that update strings in native mobile apps without an app release.

## What a TMS still leaves to your engineers

With a TMS, getting new copy into every language is still a manual process for an engineer:

1. Set up an i18n library, extract each English string into a resource file under a key, and replace the string in the component with a key lookup.
2. Send the files to the TMS through its CLI or a Git integration.
3. Wait for the translations. AI translation can come back quickly, but human translation takes longer: [Smartling&#39;s help centre](https://help.smartling.com/hc/en-us/articles/4427220505755-Module-2-Translation-Cost-and-Turnaround-Times) says many vendors translate and edit about 1,500 to 2,000 words in two working days, and that a review step can make it take significantly longer.
4. Bring the translated files back, merge them, and wire each language into the product: load its files, register the locale, and check every screen.

Git integrations automate moving the files (Crowdin&#39;s GitHub integration syncs hourly by default, and Lokalise and Phrase return translations as a pull request), but extracting strings, waiting, and wiring the results in remain with your team, and new copy stays untranslated until the round trip is complete.

Two more costs come with the hand-off. Context has to be rebuilt: a TMS attaches screenshots, Figma frames, and key descriptions to each string, but a string list can&#39;t carry the code itself, such as the component a string sits in, the variables around it, and the conditions that choose between sentences. Smartling&#39;s [supported file types](https://help.smartling.com/hc/en-us/articles/360007998893--Supported-File-Types) table, for example, lists no visual context by default for JSON, iOS, and Android files. And cost tracks what you store or who logs in: Crowdin prices mainly by hosted words (source words multiplied by target languages), Phrase by Strings seats and managed words, and Lokalise by plan tier, with allowances for processed words, seats, and integrations. ([Crowdin pricing](https://crowdin.com/pricing), [Phrase pricing](https://phrase.com/pricing/), and [Lokalise pricing](https://lokalise.com/pricing/), checked October 2026.)

## Why teams choose General Translation instead

General Translation starts from the code, so the manual steps above disappear: copy stays in your components inside [`<T>`](/docs/react/reference/components/t), and translation runs with each release. That makes it:

* **Faster.** Adding a language takes one line in `gt.config.json`, and the next build translates the whole project into it, so a new language can go live as soon as your team has reviewed it. After that, [`npx gt translate`](/docs/cli/reference/commands/translate) in your build or a [Locadex](/docs/platform/locadex/quickstart) pull request translates each change, so every release ships in every language.
* **Cheaper to run.** You pay for usage, not seats or hosted words, and engineers skip the translation chores. With [`<T>`](/docs/react/reference/components/t), there are no keys to create, and the CLI or Locadex sends content for translation and writes the results back, so nothing is sent out or merged by hand. Starter has a $0 platform fee and usage-based billing with unlimited users, projects and languages, so adding reviewers doesn&#39;t mean paying for extra seats.
* **Higher quality.** Every translation carries the context of the code: the component and elements around a string, the variables and branches in the sentence, and any [`context`](/docs/react/reference/components/t#context) note, plus your Glossary and Custom Prompts. A Context Group applies the same terms and tone to every project you assign it to, so web, docs and mobile use the same words, and your team reviews and edits translations on the Dashboard&#39;s **Translations** page.
* **Lower risk.** There&#39;s no vendor lock-in. General Translation&#39;s libraries and CLI are open source under the MIT licence and work without an account, translations can live as files in your repository, and the libraries load translations from any source, so you can change how translations are produced without rewriting your app.

General Translation is SOC 2 Type II and ISO 27001 certified and GDPR compliant, and Enterprise plans add SSO (SAML and OIDC), SCIM provisioning, audit logs, custom roles and forward-deployed engineers who build custom workflows. Deployments listed on General Translation&#39;s [Enterprise page](https://generaltranslation.com/enterprise) include:

* Ramp: 11+ locales across dashboard, landing page, iOS
* Cursor: 14+ locales across web, docs
* Profound: 47+ locales across platform, docs

## When a TMS is the better fit

Choose a TMS when:

* linguists or agencies translate in a CAT (computer-assisted translation) editor with translation memory and multi-step review;
* you exchange XLIFF, ARB, or Office files with vendors (General Translation doesn&#39;t support XLIFF, ARB, CSV, or DOCX files, though it translates Google Docs and Slides through its [Google Drive integration](/docs/integrations/google-drive/quickstart));
* you want to buy professional human translation through the same platform;
* native iOS and Android apps need over-the-air string updates through an SDK.

Choose General Translation when most of your product&#39;s text lives in code and ships on a release schedule, and you want translation to happen as part of that release.

## Moving from a TMS

You don&#39;t have to change your file layout. The CLI translates the resource files you already have, including JSON, YAML, Markdown and MDX, PO, iOS `.xcstrings` and `.strings`, and Android `strings.xml`. Point `gt.config.json` at them and run [`npx gt upload`](/docs/cli/reference/commands/upload), which sends your source files and any existing translations to the platform. Glossary imports accept CSV, TSV, JSON and text files, so terms exported from a TMS can go into a Context Group. (See [Defining context for translations](/docs/platform/dashboard/guides/defining-context-for-translations).) Current rates are on the [pricing page](https://generaltranslation.com/pricing).

## Key takeaways

* With a TMS, engineers still have to extract strings, send them out, wait for translations and then wire them back into the product.
* General Translation translates content where it&#39;s written, with the context of the code, so new languages launch faster, engineers spend less time on translation chores and translations fit the whole product.
* Its libraries and CLI are open source, so there&#39;s no lock-in. Keep a TMS for XLIFF exchange, professional translation services or native mobile over-the-air updates.
