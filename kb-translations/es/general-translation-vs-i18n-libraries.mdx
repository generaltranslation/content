Una biblioteca de internacionalización (i18n) cumple dos funciones mientras tu aplicación se ejecuta: elige el mensaje correspondiente a la configuración regional del usuario y da formato a los plurales, las fechas y los números según esa configuración regional. Las bibliotecas de código abierto como i18next, react-intl, next-intl, Lingui y vue-i18n se encargan de ambas, pero ninguna traduce tu contenido. Ese trabajo te corresponde a ti, antes de que la aplicación se ejecute: llevar cada cadena a un archivo de catálogo, ya sea mediante claves o extrayendo mensajes inline, conseguir que se traduzcan todos los catálogos y mantenerlos actualizados a medida que cambia la UI. Las bibliotecas de General Translation cumplen esas mismas funciones en tiempo de ejecución, y además General Translation se encarga de traducir: los textos se mantienen inline en tus componentes y las traducciones se generan como un paso más de la compilación.

## Lo que las bibliotecas consolidadas hacen bien

Todas estas bibliotecas son maduras, gratuitas y muy utilizadas, y cada una tiene un punto fuerte distinto:

* **i18next** es la más descargada. Funciona en cualquier entorno de JavaScript, y el `i18next-cli` oficial extrae las claves de tu código y genera sus tipos de TypeScript.
* **react-intl** (FormatJS) se basa en el formato de mensajes ICU, la sintaxis estándar para plurales y selecciones. Su documentación recomienda escribir cada `defaultMessage` inline junto con una `description` para los traductores y luego reunirlos en un catálogo con `formatjs extract`.
* **next-intl** está diseñada para el App Router de Next.js. Sus traducciones funcionan en Componentes de servidor, los mensajes que solo usan los Componentes de servidor pueden mantenerse fuera del cliente y las claves de los mensajes admiten comprobación de tipos. Su API de mensajes inline, añadida en la versión 4.5, sigue marcada como experimental.
* **Lingui** mantiene el texto de origen inline mediante macros como `<Trans>`, genera automáticamente los ID de los mensajes y extrae los mensajes a catálogos PO.
* **vue-i18n** es el plugin de i18n para Vue 3, con mensajes en JSON, YAML o bloques `<i18n>` dentro de componentes de un solo archivo.

Todas guardan las traducciones en formatos de catálogo, como JSON y PO, con los que ya trabajan los traductores y los sistemas de gestión de traducciones (TMS).

## Lo que queda en tus manos

Ninguna de estas bibliotecas traduce nada. Las traducciones las aportas tú, tus traductores o un servicio independiente, como Locize, del equipo de i18next, o un TMS como Crowdin. Este es un pequeño componente de bandeja de entrada con react-i18next:

```json title="locales/en/translation.json"
{
  "inbox": {
    "title": "Inbox",
    "unread_one": "You have {{count}} unread message.",
    "unread_other": "You have {{count}} unread messages."
  }
}
```

```tsx title="Inbox.tsx"
import { useTranslation } from 'react-i18next';

export function Inbox({ count }: { count: number }) {
  const { t } = useTranslation();
  return (
    <section>
      <h1>{t('inbox.title')}</h1>
      <p>{t('inbox.unread', { count })}</p>
    </section>
  );
}
```

Además, cada uno de los demás idiomas necesita su propio archivo, como `locales/es/translation.json`, escrito a mano o enviado a traducir. Cada archivo debe incluir también las formas plurales de su idioma como claves independientes: el japonés usa una, el polaco cuatro y el árabe seis (`_zero`, `_one`, `_two`, `_few`, `_many` y `_other`). Si se añade una cadena al componente, faltará en todos los demás archivos hasta que alguien la agregue, y quien traduzca el catálogo verá `inbox.unread_other` y una frase, no la pantalla en la que aparece.

## General Translation hace lo mismo y, además, genera las traducciones

Las bibliotecas de General Translation hacen el mismo trabajo que i18next, react-intl y next-intl. Eligen los mensajes adecuados para cada configuración regional, aplican sus reglas de plural y dan formato a números, monedas y fechas con [`<Num>`](/docs/react/reference/components/num), [`<Currency>`](/docs/react/reference/components/currency) y [`<DateTime>`](/docs/react/reference/components/datetime). Admiten variables con formato ICU en las cadenas de [`useGT`](/docs/react/reference/hooks/use-gt), diccionarios con claves mediante [`useTranslations`](/docs/react/reference/hooks/use-translations) para los equipos que prefieren trabajar con claves y, en `gt-next`, una URL para cada configuración regional. Pero General Translation va más allá que las demás bibliotecas: genera las traducciones.

Esta es la misma bandeja de entrada con `gt-react`. El texto permanece en el componente, [`<T>`](/docs/react/reference/components/t) marca el JSX que se va a traducir y [`<Plural>`](/docs/react/reference/components/plural) contiene las formas en inglés:

```tsx title="Inbox.tsx"
import { T, Plural, Num } from 'gt-react';

export function Inbox({ count }: { count: number }) {
  return (
    <T>
      <section>
        <h1>Inbox</h1>
        <Plural
          n={count}
          one={<p>You have <Num>{count}</Num> unread message.</p>}
          other={<p>You have <Num>{count}</Num> unread messages.</p>}
        />
      </section>
    </T>
  );
}
```

Ejecutar [`npx gt translate`](/docs/cli/reference/commands/translate) antes de la compilación envía cada bloque [`<T>`](/docs/react/reference/components/t), con su estructura de elementos, a la API de General Translation y genera una traducción para cada configuración regional de destino. Tú escribes las formas plurales que usa el inglés, y la traducción genera las formas que necesita cada idioma de destino, como `few` y `many` en polaco. Después, [`<Plural>`](/docs/react/reference/components/plural) elige una rama traducida según las reglas de plural de la configuración regional del lector. [`<Num>`](/docs/react/reference/components/num) da formato al número según la configuración regional del lector durante el renderizado, y un valor envuelto en [`<Var>`](/docs/react/reference/components/var) nunca se envía a la API. Si editas la oración, la siguiente ejecución la vuelve a traducir; si eliminas el componente, sus traducciones desaparecen con él.

Las bibliotecas de General Translation abarcan Next.js (`gt-next`), React (`gt-react`), Vue 3 (`gt-vue`) y Node.js (`gt-node`), además de bibliotecas experimentales para React Native, TanStack Start y Flask y FastAPI de Python. Tienen licencia MIT y funcionan sin una cuenta de General Translation: cargan traducciones desde cualquier origen, y [`gt generate`](/docs/cli/reference/commands/generate) genera archivos de plantilla para los equipos que traducen manualmente. Ni `gt-react` ni `gt-next` dependen de ninguna otra biblioteca de i18n, ya que el análisis y el formato de mensajes ICU corren a cargo de paquetes propios de General Translation. De forma predeterminada, las traducciones se incluyen como archivos en la compilación, aunque también pueden cargarse desde la CDN de General Translation.

## Comparación de las bibliotecas

| Biblioteca                                                        | Cómo se escribe el texto                                                                                                    | ¿Traduce tu contenido? | De dónde provienen las traducciones                                                                                               | Plurales                                                                                                                            |
| ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| [i18next](/kb/general-translation-vs-i18next) con `react-i18next` | Claves en un archivo JSON por configuración regional                                                                        | No                     | Tú, traductores o un servicio como Locize                                                                                         | Una clave por forma plural                                                                                                          |
| [`react-intl`](/kb/general-translation-vs-react-intl) (FormatJS)  | Texto `defaultMessage` inline, extraído a un catálogo JSON                                                                  | No                     | Tú, traductores o un TMS                                                                                                          | Formato de mensajes ICU                                                                                                             |
| `next-intl`                                                       | Claves en un archivo JSON por configuración regional                                                                        | No                     | Tú, traductores o un TMS como Crowdin                                                                                             | Formato de mensajes ICU                                                                                                             |
| [Lingui](/kb/general-translation-vs-lingui)                       | Macros inline, extraídas a catálogos PO                                                                                     | No                     | Tú, traductores o un TMS como Crowdin                                                                                             | Formato de mensajes ICU                                                                                                             |
| [`vue-i18n`](/kb/general-translation-vs-vue-i18n)                 | Claves en objetos de mensajes por configuración regional                                                                    | No                     | Tú, traductores o un TMS                                                                                                          | Formas separadas por una barra vertical; la versión 11 requiere una regla personalizada para idiomas como el polaco                 |
| General Translation (`gt-react`, `gt-next`, `gt-vue`)             | JSX dentro de [`<T>`](/docs/react/reference/components/t), o cadenas mediante [`useGT`](/docs/react/reference/hooks/use-gt) | Sí                     | Generadas por [`npx gt translate`](/docs/cli/reference/commands/translate) con el contexto de tu código, o escritas por tu equipo | Ramas de [`<Plural>`](/docs/react/reference/components/plural); la traducción genera las formas que requiere cada idioma de destino |

Quédate con i18next, react-intl, next-intl, Lingui o vue-i18n si tus catálogos y tu proceso de traducción ya funcionan, si los traductores o un TMS trabajan con archivos de catálogo, o si tu framework no es compatible con las bibliotecas de General Translation. Usa las bibliotecas de General Translation si quieres que el texto siga siendo legible en tus componentes, que las traducciones se generen con el contexto de tu código y que todos los idiomas estén al día con cada compilación, sin tener que esperar a una ronda de traducción.

## Conserva tu biblioteca o migra ruta por ruta

Cambiar de biblioteca es opcional. La CLI `gt` detecta `next-intl` o `i18next` en tu `package.json` y traduce sus archivos JSON conservando su sintaxis de mensajes. Esto también funciona con proyectos de `react-i18next` y `next-i18next` cuando `i18next` es una dependencia directa. Configura `gt.config.json` para que apunte a tus catálogos:

```json title="gt.config.json"
{
  "defaultLocale": "en",
  "locales": ["es", "fr", "ja"],
  "files": {
    "json": {
      "include": ["locales/[locale]/*.json"]
    }
  }
}
```

Para darle a una clave el contexto que su texto no puede transmitir, agrega un archivo complementario como `locales/en/translation.metadata.json` con una entrada `context` o `maxChars` para esa clave. (Consulta [Metadatos asociados a claves](/docs/cli/reference/keyed-metadata) y [Generar traducciones](/docs/cli/guides/generating-translations)).

Para migrar a [`<T>`](/docs/react/reference/components/t), sigue la guía [Migrar bibliotecas de i18n](/docs/react/guides/migrating-i18n-libraries). En ella se describen tres opciones: sustituir las búsquedas por clave por texto inline, conservar tus diccionarios y llamar a [`useTranslations`](/docs/react/reference/hooks/use-translations), o usar ambas bibliotecas a la vez mientras migras una ruta tras otra.

Los mejores equipos de desarrollo del mundo confían en General Translation, entre ellos los de Cursor, Ramp, Profound, Cognition, Sierra y ClickHouse. Para probarlo en tu aplicación, empieza con el [Inicio rápido de Next.js](/docs/react/nextjs-quickstart), el [Quickstart de React](/docs/react/react-quickstart) o el [Inicio rápido de Vue](/docs/vue/quickstart).

## Puntos clave

* i18next, react-intl, next-intl y otras bibliotecas de i18n de código abierto no traducen nada. Se limitan a renderizar y dar formato a traducciones que tú mismo generas y mantienes al día.
* Las bibliotecas de General Translation hacen el mismo trabajo de renderizado y formato, y también son de código abierto con licencia MIT. Pero, además, General Translation se encarga de la traducción a partir del texto escrito inline en [`<T>`](/docs/react/reference/components/t), así que no hay claves ni catálogos que mantener sincronizados.
* Puedes seguir usando i18next o next-intl y utilizar la CLI de `gt` para traducir sus archivos JSON, o bien migrar ruta por ruta.
