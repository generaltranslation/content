## Introducción

Uno de los errores más comunes que veo en la internacionalización es la tendencia a
dividir expresiones ternarias simples en varias llamadas de traducción.
Suele tener un aspecto parecido a este:

```jsx
'use client'

import { T, useGT } from 'gt-react'

export default function ThemeSetting({ enabled }) {
  const gt = useGT()

  return (
    <>
      <span>
        <T>Dark Mode:</T>
      </span>
      <button>{enabled ? gt('On') : gt('Off')}</button>
    </>
  )
}
```

En general, esto funciona como se espera. Antes de implementar i18n, el código probablemente era algo así como `{ enabled ? 'On' : 'Off' }`.
Añadir la función `gt()` para i18n seguramente fue una extensión natural de la estructura de código existente.

Cada vez que veo esto, me da un poco de escalofríos. La biblioteca no se diseñó en absoluto para usarse así.
Hay dos razones por las que esto es un error, sobre todo cuando se usa traducción automática: (1) el contexto y (2) la flexibilidad.

### Contexto

El significado no reside solo en las palabras, sino también en cómo se presentan.
La palabra &quot;back&quot; en una flecha para volver atrás probablemente signifique algo muy distinto que la palabra &quot;back&quot; (espalda) en el currículum de un quiropráctico.
Además, sin un contexto más amplio, a los traductores (incluso a los humanos) les puede costar traducir la palabra correctamente.
Hay una anécdota famosa sobre el departamento de i18n de WhatsApp, que tradujo al alemán la palabra &quot;crop&quot; (recortar) de una herramienta de edición de imágenes como si se tratara de &quot;crop&quot; en el sentido agrícola, es decir, cosecha.

Para resolver este problema de contexto, podemos pasar información sobre cómo se presenta el contenido mediante los componentes [`<T>`](/docs/react/reference/components/t) y [`<Branch>`](/docs/react/reference/components/branch).
En nuestro ejemplo, esto le daría a nuestro &quot;traductor&quot; una visión más completa de lo que significan &quot;on&quot; y &quot;off&quot;.

```jsx
<T>
  <span>Dark Mode:</span>
  <button>
    <Branch branch={enabled.toString()} true="On" false="Off" />
  </button>
</T>
```

### Flexibilidad

Además del contexto, otra forma interesante de aprovechar la traducción con LLM es a través de su comprensión del código.
Veamos un ejemplo en el que el orden de los componentes puede cambiar según el idioma:

```jsx
<T>
  I eat lunch at <Branch branch={atHome.toString()} true="home" false="work" />.
</T>
```

Así que tenemos dos oraciones posibles:

* &quot;Almuerzo **en casa**&quot;
* &quot;Almuerzo **en el trabajo**&quot;

En mandarín tendríamos:

* &quot;我**在家**吃午餐&quot;
* &quot;我**在公司**吃午餐&quot;

El componente [`<T>`](/docs/react/reference/components/t) detecta que aquí debe cambiar el orden de la oración y reorganiza sus hijos
en consecuencia, algo que no resulta sencillo con operadores ternarios y traducción de cadenas.

```jsx
<T>
  我在
  <Branch branch={atHome.toString()} true="家" false="公司" />
  吃午餐。
</T>
```

### Conclusión

Si hay algo que debes llevarte de este artículo, es que siempre conviene buscar formas de aprovechar el contexto y la flexibilidad en tu código.
Usar el componente [`<Branch />`](/docs/react/reference/components/branch) es probablemente una de las formas más sencillas de conseguirlo.

Consulta la documentación del [componente `<Branch />`](/docs/react/reference/components/branch) para obtener más información.
