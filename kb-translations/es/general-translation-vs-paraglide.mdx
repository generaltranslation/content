Paraglide JS es una biblioteca de i18n de inlang centrada en el compilador. Los mensajes se guardan en archivos JSON como `messages/en.json`, y su compilador convierte cada mensaje en una función tipada que se invoca como `m.greeting({ name })`, de modo que tu empaquetador puede descartar los mensajes que una página no utiliza. Lo que Paraglide deja en tus manos es la traducción en sí: cada mensaje en cada idioma tiene que venir de ti, de un traductor o de un comando de traducción automática que ejecutes sobre los archivos. Las bibliotecas de General Translation también renderizan traducciones, pero, además, General Translation las genera a partir de textos que escribes una sola vez, inline, en tus componentes.

## Lo que Paraglide JS hace bien

* **Seguridad de tipos.** Las claves y los parámetros de los mensajes se generan como tipos. En la versión 2.29.0, tanto un `m.greting()` mal escrito como una llamada a `m.greeting({})` sin su parámetro `name` producen errores de TypeScript.
* **Tamaño del paquete.** Los mensajes se compilan a módulos ES, de modo que los que no se usan se eliminan mediante tree-shaking. En el [benchmark publicado](https://paraglidejs.com/benchmark) por Paraglide, una página que usaba 100 de 200 mensajes en cinco configuraciones regionales transfirió 47 KB con Paraglide frente a 205 KB con i18next.
* **Plurales y variantes.** El formato de mensajes predeterminado [declara un selector de plural](https://paraglidejs.com/variants) y evalúa categorías de CLDR como `one`, `few` y `many`. Los [plugins](https://paraglidejs.com/file-formats) añaden compatibilidad con el formato de mensajes ICU 1 y con archivos de i18next, y los formateadores cubren números, fechas y tiempo relativo mediante `Intl`.
* **Estrategias de configuración regional.** Una [lista `strategy`](https://paraglidejs.com/strategy) ordenada resuelve la configuración regional a partir de la URL, una cookie, `localStorage`, el idioma preferido del navegador, una variable global, estrategias personalizadas o el `baseLocale`. En la 2.29.0, el [orden predeterminado](https://github.com/opral/paraglide-js/blob/main/src/compiler/compiler-options.ts) es `cookie`, `globalVariable` y, por último, `baseLocale`. El [middleware de servidor](https://paraglidejs.com/middleware) y `localizeUrl` se encargan de las rutas localizadas.
* **Compatibilidad con frameworks.** Paraglide [funciona con cualquier aplicación de Vite](https://paraglidejs.com/vite) y ofrece guías para React, Vue, Solid, SvelteKit, TanStack Start, React Router, Astro y Next.js. Es el [complemento que se instala con `npx sv add paraglide`](https://paraglidejs.com/sveltekit) en la CLI de Svelte. Su [guía de Next.js](https://paraglidejs.com/next-js) cubre el App Router mediante un plugin de webpack, que se ejecuta con la opción `--webpack`.
* **Herramientas gratuitas y abiertas.** La biblioteca tiene [licencia MIT](https://github.com/opral/paraglide-js/blob/main/LICENSE). La [CLI de inlang](https://inlang.com/m/2qj2w8pu/app-inlang-cli) valida proyectos en CI, [Sherlock](https://inlang.com/m/r7kp499g/app-inlang-ideExtension) muestra las traducciones inline en VS Code y [Fink](https://fink.inlang.com/) es un editor gratuito para el navegador que hace commit de los cambios de los traductores en un repositorio de GitHub.

## Lo que Paraglide JS deja en tus manos

Un proyecto de inlang es una carpeta `project.inlang` cuyo `settings.json` enumera tus configuraciones regionales, tus plugins y la ruta a tus archivos de mensajes. Este es un ejemplo de bandeja de entrada con un mensaje simple, un parámetro y un plural:

```json title="messages/en.json"
{
  "inbox_title": "Inbox",
  "greeting": "Hello {name}!",
  "unread_messages": [
    {
      "declarations": ["input count", "local countPlural = count: plural"],
      "selectors": ["countPlural"],
      "match": {
        "countPlural=one": "You have {count} unread message.",
        "countPlural=*": "You have {count} unread messages."
      }
    }
  ]
}
```

```tsx title="Inbox.tsx"
import { m } from './paraglide/messages.js';

export function Inbox({ name, count }: { name: string; count: number }) {
  return (
    <section>
      <h1>{m.inbox_title()}</h1>
      <p>{m.greeting({ name })}</p>
      <p>{m.unread_messages({ count })}</p>
    </section>
  );
}
```

Cada una de las demás configuraciones regionales necesita su propio archivo con las mismas claves y las variantes que requiera ese idioma: el polaco usa `one`, `few`, `many` y `*`. Cuando falta una clave en `messages/pl.json`, la función compilada recurre a la configuración regional base sin mostrar ninguna advertencia. Así se ve el componente renderizado con un archivo en polaco al que le falta `greeting`:

```text title="Output"
pl  <h1>Skrzynka odbiorcza</h1><p>Hello Ada!</p><p>Masz 2 nieprzeczytane wiadomości.</p>
```

`npx @inlang/cli check` lo detectó: informó de que `greeting` no tenía traducción al polaco y terminó con el código de salida 1, así que la CI puede bloquear ese hueco. Pero rellenarlo sigue siendo cosa tuya. De forma predeterminada, `inlang machine translate` traduce los mensajes que faltan con un servicio gratuito mantenido por la comunidad, o bien con tu propia clave de Google Cloud Translation o DeepL, mensaje a mensaje y sin el componente en el que aparece cada uno. La propia documentación de la CLI de inlang sugiere que los agentes de programación que cuentan con contexto del producto y del código pueden generar mejores borradores que la traducción automática genérica.

## General Translation escribe las traducciones

Las bibliotecas de General Translation se encargan del mismo trabajo de renderizado. La diferencia está en dónde vive el texto y quién lo traduce. Esta es la misma bandeja de entrada con `gt-react`:

```tsx title="Inbox.tsx"
import { T, Plural, Num, Var } from 'gt-react';

export function Inbox({ name, count }: { name: string; count: number }) {
  return (
    <T>
      <section>
        <h1>Inbox</h1>
        <p>Hello <Var>{name}</Var>!</p>
        <Plural
          n={count}
          singular={<p>You have <Num>{count}</Num> unread message.</p>}
          plural={<p>You have <Num>{count}</Num> unread messages.</p>}
        />
      </section>
    </T>
  );
}
```

No hay ningún archivo de mensajes que mantener sincronizado: el texto en inglés es el propio componente. [`npx gt translate`](/docs/cli/reference/commands/translate) envía cada bloque [`<T>`](/docs/react/reference/components/t), junto con su estructura de elementos, a la API de General Translation y escribe una traducción para cada configuración regional de destino, de modo que una frase nueva queda traducida antes de la compilación en lugar de mostrarse en inglés. Los valores dentro de [`<Var>`](/docs/react/reference/components/var) nunca se envían a la API, y [`<Plural>`](/docs/react/reference/components/plural) elige una rama según las reglas de plural de la configuración regional del lector. [`npx gt validate`](/docs/cli/reference/commands/validate) comprueba el proyecto sin llamar a la API, y [`gt generate`](/docs/cli/reference/commands/generate) genera archivos de plantilla para los equipos que traducen manualmente.

El encabezado, el saludo y las ramas de plural de este bloque se envían juntos para su traducción. General Translation también aplica el [glosario y los prompts personalizados](/docs/platform/dashboard/guides/defining-context-for-translations) asignados al proyecto, y los revisores editan los resultados en el panel de control. Añade la CLI a tu CI o configura [Locadex](/docs/platform/locadex/quickstart) para que abra pull requests de traducción cada vez que cambie tu código.

Las bibliotecas de JavaScript de General Translation tienen licencia MIT y funcionan sin cuenta con traducciones que proporciones tú. Si incluyes las traducciones en el paquete de tu aplicación, el renderizado no depende del servicio alojado; con la entrega mediante CDN, puedes publicar cambios en las traducciones sin esperar a un nuevo lanzamiento de la aplicación. Consulta [almacenamiento de traducciones](/docs/react/guides/storing-translations) para ver la configuración inicial.

Sierra publica su web y su contenido comercial en más de 7 configuraciones regionales con General Translation. (Consulta los [despliegues en producción](https://generaltranslation.com/enterprise)).

## Paraglide JS vs. General Translation de un vistazo

| Característica         | Paraglide JS                                                                                            | General Translation                                                                                                                                 |
| ---------------------- | ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cómo escribes el texto | Claves en un archivo JSON por configuración regional, que se invocan como `m.key()`                     | JSX dentro de [`<T>`](/docs/react/reference/components/t), cadenas mediante [`useGT`](/docs/react/reference/hooks/use-gt) o diccionarios con claves |
| Traduce tu contenido   | No; `inlang machine translate` usa un servicio comunitario, Google o DeepL                              | Sí, con [`npx gt translate`](/docs/cli/reference/commands/translate)                                                                                |
| Qué ve el traductor    | El contenido del mensaje que se envía a la herramienta de traducción elegida                            | El bloque JSX marcado, las notas del desarrollador y el glosario y los prompts personalizados asignados                                             |
| Seguridad de tipos     | Tipos generados para cada clave y parámetro                                                             | JSX inline, sin claves de mensaje que puedan escribirse mal                                                                                         |
| Paquete                | Tree-shaking por mensaje                                                                                | Las traducciones se cargan por configuración regional                                                                                               |
| Traducción faltante    | Recurre a la configuración regional base; `inlang check` la notifica                                    | La genera [`npx gt translate`](/docs/cli/reference/commands/translate); el contenido sin traducir se renderiza en el idioma de origen               |
| Frameworks             | Aplicaciones Vite, React, Vue, Solid, SvelteKit, Astro, TanStack Start, React Router, Next.js (webpack) | React, Next.js, Vue, Node.js y [otros SDK](/docs/overview/get-started)                                                                              |
| Costo                  | Gratuito y de código abierto                                                                            | Bibliotecas de JavaScript gratuitas; [traducción facturada según el uso](https://generaltranslation.com/pricing)                                    |

Quédate con Paraglide JS si desarrollas con SvelteKit, Astro o Solid, si lo que más te importa es el tree-shaking por mensaje y las funciones de mensaje tipadas, o si tu equipo ya escribe o encarga sus propias traducciones. Usa General Translation si quieres que el texto se lea directamente en tus componentes y que cada idioma se genere con el contexto de tu código en cada compilación.

## Migrar a General Translation componente a componente

Es posible migrar un componente a la vez. Los mensajes de Paraglide son funciones simples y no necesitan un proveedor, así que una llamada a `m.*` y un bloque [`<T>`](/docs/react/reference/components/t) pueden renderizarse en paralelo mientras conviertes las rutas. En [Migrar bibliotecas de i18n](/docs/react/guides/migrating-i18n-libraries) se describen los pasos, empezando por el [Quickstart de React](/docs/react/react-quickstart) o el [Inicio rápido de Next.js](/docs/react/nextjs-quickstart).

## Conclusiones clave

* Paraglide JS compila los catálogos en funciones tipadas y compatibles con tree-shaking. Por separado, las herramientas de inlang pueden generar traducciones para esos catálogos.
* General Translation mantiene el texto inline en [`<T>`](/docs/react/reference/components/t) y genera traducciones con contexto a partir de tu código, tu glosario y tus prompts personalizados, que puedes revisar en el panel de control.
* Mantén en funcionamiento los mensajes existentes de Paraglide mientras migras los componentes a General Translation. Cada componente migrado lleva su texto de origen y su contexto de traducción en el propio JSX.
