Phrase 自称[语言智能平台](https://phrase.com/) (Language Intelligence Platform) 。面向软件团队，它提供 Phrase Strings 和 Phrase TMS ([前身为 Memsource](https://phrase.com/memsource/)) ：前者用于存储键并与你的代码仓库同步；后者是一款翻译管理系统 (TMS) 兼 CAT (计算机辅助翻译) 工具，用于管理文档、供应商和大型翻译项目。Language AI 则将两者接入机器翻译和 LLM 引擎。General Translation 将应用文案和文档纳入发布工作流，从源文件生成译文，并在各项目间共享术语。

## Phrase 的优势

* **一个平台，两种工具。** [Phrase Strings](https://phrase.com/platform/strings/) 供开发者管理键，Phrase TMS 则负责文档、供应商管理和基于 CAT 的翻译。
* **Language AI。** 提供 [30 多种机器翻译和 LLM 引擎](https://phrase.com/platform/ai/)，可自动选择引擎；Next GenMT 会利用翻译记忆库的匹配结果；质量评估功能会标出得分最低的片段，供人工审校。
* **代码仓库自动化。** [适用于 GitHub](https://support.phrase.com/hc/en-us/articles/5784125562012-GitHub-Strings)、GitLab 和 Bitbucket 的 Repo Sync 会从受监控的分支导入文件，并以拉取请求的形式导出译文；另有 GitHub Action 可在 CI 中运行 CLI。
* **移动端和 Web 端 OTA 更新。** [适用于 iOS、Android、React Native、Flutter、i18next 和 Rails 的 SDK](https://support.phrase.com/hc/en-us/articles/5804059067804-Over-the-Air-Strings) 无需发布新版本即可获取最新译文，必要时回退到最近缓存或打包在应用包中的文件。
* **为译者提供上下文。** 支持[文本与键自动匹配的截图](https://support.phrase.com/hc/en-us/articles/5822309698204-Screenshot-Management-Strings)、键描述和字符数限制，还提供 Figma 插件。
* **人工翻译。** 可直接在 Phrase Strings 内向 Gengo 或 TextMaster 下订单；据 Phrase 称，[大多数译文会在 24 小时内交付](https://support.phrase.com/hc/en-us/articles/5821933165596-Ordering-Professional-Translations-Strings)。
* **托管位置可选。** [数据可托管在欧盟或美国](https://support.phrase.com/hc/en-us/articles/5748008399388-Data-Centers)。

## Phrase 仍留给工程师处理的工作

Phrase Strings 通过基于资源文件的工作流对接软件项目：

1. 配置国际化库，并编写或提取它所加载的资源文件。
2. 在 `.phrase.yml` 中声明你的文件，然后使用 [`phrase push`](https://developers.phrase.com/en/developer-tools/strings-cli) 上传，或让 Repo Sync 从受监控的分支导入。
3. 通过 AI 或译员工作流将内容翻译为目标语言。
4. 使用 `phrase pull` 或 Repo Sync 导出将译文拉回，后者会创建一个拉取请求。

Repo Sync 和 CI 可以自动完成文件交换，但你的团队仍需维护应用的键结构，以及代码、资源文件与 Phrase 项目之间的映射。译员则需依靠这些内容附带的键描述和截图来开展工作。

[Phrase 订阅](https://phrase.com/pricing/)包含 Strings 席位、托管字数额度和翻译用量，也可额外购买容量。其公开的软件方案不限语言数量。

## Phrase 与 General Translation 速览

| 功能      | Phrase                                                    | General Translation                                                                                                         |
| ------- | --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 字符串存放位置 | 以键的形式存放在 Phrase Strings 中，并与你的资源文件同步                      | 直接写在代码的 [`<T>`](/docs/react/reference/components/t) 中，或保留在你现有的资源文件里                                                         |
| 代码接入方式  | `phrase` CLI、Repo Sync 或 GitHub Action                    | 在构建流程中运行 [`npx gt translate`](/docs/cli/reference/commands/translate)，或通过 [Locadex](/docs/platform/locadex/quickstart) 拉取请求 |
| 翻译执行方   | Language AI 引擎，或 Gengo、TextMaster 等供应商                    | AI 结合代码、词汇表和自定义提示词中的上下文完成翻译，再由你的团队在仪表板中审核                                                                                   |
| 字符串上下文  | 翻译记忆库、术语库、风格指南、键描述和截图                                     | 带标记的 JSX 结构和上下文备注，外加跨项目共享的词汇表和自定义提示词                                                                                        |
| 定价      | 订阅制，按 Strings 席位、托管词数和翻译容量计费                              | [按用量计费](https://generaltranslation.com/pricing)                                                                             |
| 原生移动应用  | 提供适用于 iOS、Android、React Native 和 Flutter 的 OTA (空中下载) SDK | 支持翻译 iOS 和 Android 资源文件；React Native 使用 `gt-react-native`                                                                   |

## 为什么团队选择 General Translation 而非 Phrase

General Translation 将软件文案及其说明文档纳入同一个翻译工作流。应用文本保留在 [`<T>`](/docs/react/reference/components/t) 中，Markdown 或 MDX 可与之一同翻译，并共用同一套产品术语。

* **更快。** 在 CI 中运行 [`npx gt translate`](/docs/cli/reference/commands/translate)，翻译某次发布中有改动的源文件。General Translation 既支持应用内容，也支持 [Markdown 和 MDX](/docs/cli/reference/formats/mdx-md-files)，因此新功能及其帮助页面可以在同一发布流程中完成翻译。[Locadex](/docs/platform/locadex/quickstart) 还能通过拉取请求处理后续的持续更新。
* **运行成本更低。** General Translation 会在后续构建中复用未更改的译文。你只需为翻译工作付费，已完成的翻译可以持续使用，无需为存储的文案额外购买托管字数额度。可将 [General Translation 的用量费率](https://generaltranslation.com/pricing)与你的 Phrase 订阅中包含的 Strings 额度对比一下。
* **质量更高。** 为应用项目和文档项目分配同一个[上下文分组](/docs/platform/dashboard/guides/defining-context-for-translations)，相同的产品定义和语气指令便会同时作用于两者：引导页面中出现的功能名称，会沿用其帮助文章中定义的术语。经过标记的 JSX 还会保留消息结构和变量占位符，审校人员也可以[在仪表板中编辑译文](/docs/platform/dashboard/guides/reviewing-translations)。
* **风险更低。** 先从一个应用现有的消息目录入手，并继续沿用其国际化库。先导入已审校的译文，再生成新译文，准备就绪后再扩展到其他项目。在软件本地化中采用 General Translation，无需同时迁移独立的文档项目或供应商项目。

Profound 借助 General Translation 将其平台和文档翻译为 47 种以上的区域设置。 (参见[生产环境部署案例](https://generaltranslation.com/enterprise)。)

## 何时更适合选择 Phrase

如果你需要一个平台同时承载软件字符串翻译和以文档为主、由供应商在 CAT 工具中完成的翻译项目；希望将翻译任务分发到多种机器翻译和 LLM 引擎；需要为原生应用和 React Native 应用提供 OTA (over-the-air) 更新；需要与供应商交换 [XLIFF 或 Office 文件](https://phrase.com/platform/tms/)；或者需要在欧盟和美国托管之间自由选择，那么 Phrase 会是更好的选择。

## 从 Phrase 迁移到 General Translation

运行 `phrase pull` 下载你现有的译文。如果使用的是[支持的格式](/docs/cli/reference/config#files)，请将 `gt.config.json` 指向这些源文件和目标文件，先运行 [`npx gt upload`](/docs/cli/reference/commands/upload)，再使用 [`npx gt translate`](/docs/cli/reference/commands/translate) 生成翻译。这样就能以你已审校的译文和应用当前的键为起点。

将你的术语导入[上下文分组](/docs/platform/dashboard/guides/defining-context-for-translations)，并将其分配给应用项目和文档项目。将翻译生成迁移到 General Translation 与采用内联 JSX 是两件独立的事；你可以继续使用现有的库。如需更全面的平台对比，请参阅[为什么选择 General Translation 而不是 TMS？](/kb/general-translation-vs-tms)。

## General Translation 可以替代 Phrase 吗？

可以，尤其适合希望将应用和文档翻译纳入构建工作流的软件团队。General Translation 支持现有消息目录和内联 JSX，并提供共享术语和仪表板审校功能。而 Phrase TMS 更适合以文档为主、借助 CAT 工具与供应商协作开展的翻译项目。

## 要点总结

* 如果你希望在同一平台上同时管理软件字符串和大规模、以文档为主的翻译项目，Phrase 是不错的选择：它支持多种翻译引擎，并提供空中下载 (OTA) 更新 SDK。
* Phrase Strings 可自动交换资源文件；其订阅方案包含 Strings 席位和托管字数额度。
* General Translation 借助共享术语、增量翻译和审校流程，将应用与文档的发布打通，同时让你保留现有的消息目录。
