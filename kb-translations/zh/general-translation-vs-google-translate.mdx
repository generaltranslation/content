借助 Google Translate，你可以快速阅读外语网页，或临时翻译一段文字。但产品本地化真正的难点在于：按照每个字符串在 UI 中的实际含义进行翻译，在多次发布中保持术语一致，并把译文交付到应用加载它们的位置。无论以哪种方式在应用中使用 Google Translate，总有一部分工作得由你自己完成。

## 用 Google Translate 翻译应用的三种方式

### 让访问者的浏览器翻译页面

当页面语言不是用户能阅读的语言时，Chrome 会主动提示翻译。翻译发生在页面加载之后、访问者的浏览器中：Google 的翻译脚本会把页面文本替换为译文，并用 `<font>` 元素包裹。你既看不到、也无法审核翻译结果，而且没有可供搜索引擎抓取的翻译版 URL；而 Google 对多语言网站的建议是为每种语言发布独立的 URL ([管理多语言网站](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)) 。

这种改写还可能导致 React 应用出错。React 会保留对其渲染的文本节点的引用，一旦翻译替换了这些节点，下一次更新就可能报错 `NotFoundError: Failed to execute 'removeChild' on 'Node'`。React 维护者已于 2018 年关闭了相关 issue ([react#11538](https://github.com/react/react/issues/11538)) ，并解释说 React 本身无法规避这一问题，否则就会掩盖其他 bug 或拖慢常见场景。标记了 `translate="no"` 的元素不会被改动。

### 添加 Website Translator 小部件

Google 的可嵌入式 Website Translator 仅限学术、政府、非营利及非商业网站使用，因此企业无法在自家产品中添加该小部件 ([Google Translate Help](https://support.google.com/translate/answer/2534559?co=GENIE.Platform%3DDesktop)) 。

### 调用 Cloud Translation API

Cloud Translation API 是专为开发者打造的方案，会完整保留 HTML 标签。对于 HTML 输入，其 Advanced 版本会跳过标记为 `translate="no"` 或 `class="notranslate"` 的文本，并额外提供词汇表、基于示例句对的自适应翻译，以及基于 Gemini 构建的 Translation LLM。每个请求包含文本和语言，还可以指定模型和词汇表：

```json title="translateText request body"
{
  "contents": ["Save"],
  "mimeType": "text/plain",
  "sourceLanguageCode": "en",
  "targetLanguageCode": "de"
}
```

API 中没有用于说明字符串出现位置的字段。在德语中，&quot;Save&quot; 既可以译作 *speichern* (保存文件) ，也可以译作 *sparen* (节省开支) ，而只含一个单词的请求根本无法让模型作出判断。流水线的其余部分都得你自己构建：从 i18n 文件中提取字符串、保护 `{{count}}` 之类的占位符、生成每种语言的复数形式、写回结果、每次变更后重新运行，还要为审校人员提供修改译文的地方，并确保这些修改不会被下一次运行覆盖。如果要向用户展示译文，Google 还要求注明出处：在结果旁显示 &quot;powered by Google Translate&quot; 标识，为未经修改的译文添加免责声明，并在会被搜索引擎索引的页面上添加机器翻译标记 ([出处注明要求](https://docs.cloud.google.com/translate/attribution)) 。

## 各方案对比

| 方案                    | 每个字符串的上下文                   | 变量与复数形式                                                                                                                    | 搜索引擎                                    | 审校与更新                                   |
| --------------------- | --------------------------- | -------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- | --------------------------------------- |
| 浏览器翻译                 | 页面上可见的文本                    | 作为纯文本翻译                                                                                                                    | 不产生新的可索引内容                              | 无审校；每位访问者的浏览器都会重新翻译一遍                   |
| Cloud Translation API | 文本本身，外加可选的词汇表或示例对           | 需自行保护占位符，并为每种语言构建复数形式                                                                                                      | 将每种语言发布到独立 URL 后即可被索引                   | 需自行重新运行脚本，并自建审校流程                       |
| General Translation   | 周围的 JSX、上下文备注、你的词汇表以及自定义提示词 | [`<Var>`](/docs/react/reference/components/var) 的值不参与翻译，[`<Plural>`](/docs/react/reference/components/plural) 的各分支作为完整句子翻译 | 借助 `gt-next` 区域设置路由 (如 `/es/about`) 被索引 | 每次构建或 Locadex 拉取请求都会翻译变更内容，审校人员可在仪表板中编辑 |

如果只是阅读外语内容，或一次性翻译内部文本，请使用 Google Translate。如果你只需要原始机器翻译，并愿意自行处理上下文、占位符、复数形式、审校和署名，请使用 Cloud Translation API。如果译文要随产品一起交付，例如应用 UI、文档或营销网站，需要在每种语言中都准确通顺，并随每次发布保持同步，请使用 General Translation。

## General Translation 有何不同

Google Translate 把本地化中的许多工作留给你自己处理，而 General Translation 正是为这些部分而打造的。它有两大不同之处：

* **它能理解完整的上下文。** 一次 Cloud Translation 请求只包含文本和语言，外加一个可选的词汇表。而 General Translation 在翻译每个字符串时，都会结合它在你产品中所处的位置：周围的组件和元素、句子中的变量和复数形式、你添加的上下文备注，以及你的词汇表和自定义提示词。上下文分组会将相同的术语和语气应用到所分配的每个项目中，让你的应用、文档和营销网站保持措辞一致。
* **它能自动化整个本地化工作流。** 开源库可在 React、Next.js、Vue 和 Node.js 中为你的代码实现国际化；对于 Next.js 和 React 应用，General Translation 的 AI 智能体 [Locadex](/docs/platform/locadex/quickstart) 还能替你编写这些代码。[`npx gt translate`](/docs/cli/reference/commands/translate) 在构建或 CI 中运行，将译文写入你的代码仓库或 General Translation 的 CDN；审校人员可在仪表板的 **译文** 页面中编辑译文，每次发布都能同时覆盖所有语言。

下面来看看上下文在代码中是什么样子。这个计费切换开关上的徽章显示的是“Save 20%”：

```tsx title="BillingToggle.tsx"
import { T, Var } from 'gt-react';

export function BillingToggle({ discount }: { discount: string }) {
  return (
    <T context="Pricing page billing toggle. Save means pay less, not store data.">
      <button>Yearly</button>
      <span className="badge">Save <Var>{discount}</Var></span>
    </T>
  );
}
```

[`<T>`](/docs/react/reference/components/t) 会将整个块作为一个整体发送，连同其中的元素 (一个按钮和一个徽章) 以及 [`context`](/docs/react/reference/components/t#context) 备注一并提交，这样翻译时就能准确理解 &quot;Save&quot; 的含义，并按照每种语言的习惯摆放折扣信息。[`<Var>`](/docs/react/reference/components/var) 为折扣预留一个占位符，其值绝不会发送到 General Translation API。词汇表可在所有语言中固定产品名称等术语，自定义提示词则可设定各类规则，例如在德语中使用正式称呼 &quot;Sie&quot;。 (参见[为翻译定义上下文](/docs/platform/dashboard/guides/defining-context-for-translations)和[审阅与编辑译文](/docs/platform/dashboard/guides/reviewing-translations)。) 对于仅在运行时才存在的内容 (例如用户生成内容或 CMS 文本) ，可使用 `gt-node` 中的 [`tx`](/docs/node/reference/functions/tx) 按需翻译。

General Translation 支持 120 多种区域设置。请从 [Next.js 快速入门](/docs/react/nextjs-quickstart)或 [React 快速入门](/docs/react/react-quickstart)开始上手。

## 要点总结

* Google Translate 的文本翻译质量不错。但浏览器翻译既不支持审校，也无法生成可被索引的页面，还可能导致 React 应用出错；Website Translator 小部件则仅限非商业网站使用。
* Cloud Translation API 的请求中没有字段可用于说明字符串出现在何处，占位符、复数形式、审校、投递和署名都得由你自己实现。
* General Translation 能理解代码中每个字符串的上下文，并将围绕翻译的整个工作流自动化：从代码国际化到审校，再到让每次发布都以所有语言上线。
