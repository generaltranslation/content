vue-i18n 负责在 Vue 应用中以用户的语言渲染消息。你为每个区域设置定义消息，在模板中按键引用，再由它负责格式化复数形式、日期和数字。但它本身不做任何翻译：每种语言的消息都得由你、你的译者或翻译管理系统 (TMS) 提供。General Translation 的 `gt-vue` 渲染译文的方式与之相同，不同的是，General Translation 还能根据你在模板中内联编写的文案直接生成译文。

## vue-i18n 的优势

* **成熟稳定。** vue-i18n 自 2014 年起就已发布在 npm 上。[目前维护的是版本 11](https://vue-i18n.intlify.dev/guide/maintenance)，版本 12 正处于 alpha 阶段。
* **Nuxt。** [`@nuxtjs/i18n` 模块基于 vue-i18n 11 构建](https://i18n.nuxtjs.org/docs/getting-started)，并提供带区域设置前缀的路由、本地化路径、浏览器语言检测、译文懒加载，以及 hreflang 替代项等 SEO 标签。
* **格式化与富文本。** `datetimeFormats` 和 `numberFormats` 接受 `Intl` 选项；[`<i18n-t>` 组件](https://vue-i18n.intlify.dev/guide/advanced/component)无需借助 `v-html`，即可在翻译后的消息中嵌入元素。
* **消息与组件放在一起。** 借助 `@intlify/unplugin-vue-i18n`，[`<i18n>` 块](https://vue-i18n.intlify.dev/guide/advanced/sfc)可以将组件的消息直接写在其单文件组件中。
* **工具链。** [官方 ESLint 插件](https://eslint-plugin-vue-i18n.intlify.dev/rules/)可以标记出模板中的原始文本，以及缺失或未使用的键。

## vue-i18n 需要你自己处理的部分

下面用 vue-i18n 的 Composition API 实现了一个小型收件箱。每个字符串都对应一个键，英文文本则存放在消息文件中：

```json title="locales/en.json"
{
  "inbox": {
    "heading": "Inbox",
    "unread": "You have {n} unread message | You have {n} unread messages"
  }
}
```

```vue title="Inbox.vue"
<script setup>
import { useI18n } from 'vue-i18n'

defineProps({ count: { type: Number, required: true } })
const { t } = useI18n()
</script>

<template>
  <section>
    <h1>{{ t('inbox.heading') }}</h1>
    <p>{{ t('inbox.unread', count) }}</p>
  </section>
</template>
```

每种目标语言都需要翻译好的消息，可由你的团队或翻译服务提供。就本示例而言，有两个实现细节需要注意：

* **复数规则。** vue-i18n 11 的默认规则按位置选择复数形式。波兰语使用 `one`、`few`、`many` 和 `other` 四个类别，因此需要配置一个[自定义 `pluralRules` 函数](https://github.com/intlify/vue-i18n/blob/master/docs/guide/v11/essentials/pluralization.md)，将数量映射到相应的翻译形式。目前仍处于 alpha 阶段的 vue-i18n 12 已[改用 `Intl.PluralRules`](https://github.com/intlify/vue-i18n/releases/tag/v12.0.0-alpha.4)。
* **消息中的数字。** 复数消息中的 `{n}` 不会按区域设置进行格式化，因此除非传入已格式化的值，否则 12345 在西班牙语中会渲染为 &quot;12345&quot;，而不是 &quot;12.345&quot;。

## 内联模板与自动生成的译文

`gt-vue` 承担的工作与 vue-i18n 相同：渲染每个区域设置的消息，按各区域设置的 CLDR 规则选择复数形式，并通过 [`<Num>`](/docs/vue/reference/components/num)、[`<Currency>`](/docs/vue/reference/components/currency) 和 [`<DateTime>`](/docs/vue/reference/components/datetime) 格式化数字、货币和日期。不仅如此，General Translation 还能完成 vue-i18n 做不到的事：自动生成译文。下面仍以同一个收件箱为例，只是文案改为内联编写：

```vue title="Inbox.vue"
<script setup>
import { Num, Plural, T } from 'gt-vue'

defineProps({ count: { type: Number, required: true } })
</script>

<template>
  <section>
    <T><h1>Inbox</h1></T>
    <p>
      <T>
        <Plural :n="count">
          <template #singular>You have <Num :value="count" /> unread message</template>
          <template #plural>You have <Num :value="count" /> unread messages</template>
        </Plural>
      </T>
    </p>
  </section>
</template>
```

[`npx gt translate`](/docs/cli/reference/commands/translate) 会扫描你的模板，将每个 [`<T>`](/docs/vue/reference/components/t) 块连同其结构一并发送到 General Translation API，并为每个目标区域设置生成一个目录文件。`singular` 和 `plural` 插槽为目标语言的各种复数形式提供源文本。[`<Plural>`](/docs/vue/reference/components/plural) 根据区域设置规则选择对应的形式，[`<Num>`](/docs/vue/reference/components/num) 则负责格式化数量：英语中显示为 12,345，西班牙语中为 12.345，波兰语中为 12 345。

本示例使用 `gt-vue` 0.1.22 及 Vue 3.3 或更高版本；插件和目录加载器的初始化设置请参阅 [Vue 快速入门](/docs/vue/quickstart)。你的团队可以在[仪表板](/docs/platform/dashboard/guides/reviewing-translations)中润色生成的文本，[共享的词汇表术语和自定义提示词](/docs/platform/dashboard/guides/defining-context-for-translations)则能确保各项目的术语保持一致。

## vue-i18n 与 General Translation 对比一览

| 功能     | vue-i18n                                      | General Translation (`gt-vue`)                                            |
| ------ | --------------------------------------------- | ------------------------------------------------------------------------- |
| 文案编写方式 | 在各区域设置的消息文件或 `<i18n>` 块中使用键                   | 直接内联在模板中，包裹在 [`<T>`](/docs/vue/reference/components/t) 内                  |
| 是否翻译内容 | 否                                             | 是，通过 [`npx gt translate`](/docs/cli/reference/commands/translate)         |
| 复数形式   | 各形式以竖线分隔；版本 11 需为波兰语等语言编写自定义规则                | [`<Plural>`](/docs/vue/reference/components/plural) 插槽，按 CLDR 规则为每个区域设置选择 |
| 消息中的数字 | 需传入已格式化的值                                     | [`<Num>`](/docs/vue/reference/components/num) 按各区域设置自动格式化                 |
| 应用集成   | Vue 插件；`@nuxtjs/i18n` 提供 Nuxt 路由、语言检测和 SEO 标签 | Vue 插件，支持响应式区域设置切换和目录加载                                                   |

如果你依赖 `@nuxtjs/i18n` 实现 Nuxt 路由和 SEO，或者想保留现有的目录工作流，请继续使用 vue-i18n。如果你希望 Vue 模板中的文案保持可读、在构建时生成译文，并让审阅者在仪表板中编辑译文，请选择 General Translation。

## 从 vue-i18n 迁移

逐个组件进行迁移：将每处键查找替换为放在 [`<T>`](/docs/vue/reference/components/t) 中的英文文案，并将以竖线分隔的复数消息改写为 [`<Plural>`](/docs/vue/reference/components/plural) 中的 `singular` 和 `plural` 插槽，如上例所示。尚未迁移的组件可继续使用 vue-i18n 及其已审校的翻译目录。按照 [Vue 快速入门](/docs/vue/quickstart) 设置 `gt-vue`，然后在构建前运行 [`npx gt translate`](/docs/cli/reference/commands/translate)。

## 为什么 vue-i18n 在波兰语中显示错误的复数形式？

在 vue-i18n 11 中配置一个 `pluralRules` 函数，将波兰语的复数类别映射到消息中对应的位置。例如，1 对应 `one`，2 和 22 对应 `few`，5 对应 `many`。使用 General Translation 时，内联示例提供源文本，服务负责生成各个翻译形式，再由 [`<Plural>`](/docs/vue/reference/components/plural) 从中选出正确的形式。

## 要点总结

* vue-i18n 是一款成熟的 i18n 插件，对 Nuxt 支持良好，但它本身并不负责翻译；而且在 11 版本中，波兰语等语言需要自定义复数规则。
* General Translation 的 CLI 会根据内联的 [`<T>`](/docs/vue/reference/components/t) 块生成译文；`gt-vue` 负责渲染这些译文，并针对每个区域设置处理复数选择和数字格式化。
* 如果你已有成熟的 Nuxt 或消息目录工作流，可以继续使用 vue-i18n；如果不想再维护基于键的源文件，请选择 `gt-vue`。
