Smartling 主打端到端本地化方案，包括：内置 CAT (计算机辅助翻译) 工具和翻译记忆库的翻译管理系统 (TMS) 、由 AI Hub 提供的 AI 翻译、由 Smartling Language Services 提供的人工翻译，以及以代理方式翻译网站的 Global Delivery Network (GDN) 。在软件方面，代码侧的流程围绕文件展开：代码仓库中的资源文件会作为文件导入 Smartling，从中解析出字符串进行翻译，译文再通过 GitHub Connector、自托管的 Repository Connector 或 CLI 回传。General Translation 则直接从代码入手。

## Smartling 的优势

* **一家供应商同时提供 AI 翻译和人工翻译。** 根据 Smartling 的[翻译服务页面](https://www.smartling.com/translation-services)，其机器翻译和 AI 翻译可即时交付，AI Human Translation (AI 辅助人工翻译) 1 天交付，Creative Translation (面向复杂项目的专家翻译) 2 天交付，背后是由 4,000 多名语言专家组成的语言服务团队。
* **AI Hub。** 支持 DeepL、Google、Microsoft 等[大语言模型和机器翻译引擎](https://help.smartling.com/hc/en-us/articles/10318350761883-Smartling-s-AI-Hub)，并会将你的词汇表和翻译记忆库纳入提示词。
* **无需改动代码即可翻译网站。** GDN 以[翻译代理](https://help.smartling.com/hc/en-us/articles/18558261190683-Introduction-to-the-GDN)的方式提供翻译后的页面。
* **可视化上下文。** 支持[通过 Chrome 扩展或 JavaScript 库捕获的 HTML](https://help.smartling.com/hc/en-us/articles/360057484273--Overview-of-Visual-Context)、借助 OCR 与字符串匹配的截图、PDF 以及视频。
* **质量工具。** 提供 CAT 工具、质量检查，以及依据 MQM 框架为任务评分的 [LQA 智能体](https://help.smartling.com/hc/en-us/articles/49428460628507-LQA-Agent-AI-Powered-Quality-Assurance)。
* **合规与连接器。** 已通过 [PCI Level 1、SOC 2、HIPAA、HITRUST、ISO 27001 和 ISO 42001](https://www.smartling.com/security) 认证，并为 AEM、Contentful、Salesforce 等 CMS 和营销工具提供 50 多个连接器。

## Smartling 仍需你的工程师处理哪些工作

Smartling 的代码仓库工作流通过翻译任务来流转资源文件：

1. 搭建国际化库，并提取或编写它所加载的资源文件。[Smartling 的 SDK](https://help.smartling.com/hc/en-us/articles/1260806475390-Smartling-SDKs-Overview) 负责对接其 API。
2. 连接代码仓库。托管式 GitHub Connector 会监听拉取请求或提交；自托管的 [Repository Connector](https://help.smartling.com/hc/en-us/articles/360008032174-Options-for-Automation-with-Source-Repositories) 支持 GitHub Enterprise、GitLab、Bitbucket 和 SVN；你也可以使用 `smartling-cli files push` 推送文件。
3. 等待翻译任务完成。在 GitHub Connector 的[拉取请求模式](https://help.smartling.com/hc/en-us/articles/14901568064411-GitHub-Configuration-Modes-Pull-Request-Single-Branch-On-Demand)下，Smartling 的文档指出，在译文交付之前不应合并或删除拉取请求，因此功能拉取请求只能等翻译完成后才能推进。
4. 合并交付译文的拉取请求 ([Repository Connector 则直接提交到分支](https://help.smartling.com/hc/en-us/articles/44557348474139-Repository-Connector-Architecture-Overview)) ，将每种新语言接入应用，并逐一检查每个界面。

此外，应用字符串起初也缺少可视化上下文：GitHub Connector 不会自动捕获可视化上下文，而根据 Smartling 的[支持的文件类型](https://help.smartling.com/hc/en-us/articles/360007998893--Supported-File-Types)表格，JSON、iOS 和 Android 文件默认均不提供可视化上下文，因此只能依靠团队自行添加截图或采集内容。

Smartling 提供可免费起步的 Core 方案，以及需联系销售团队购买的 Enterprise 方案，并公布了各类翻译的每字起价。 (参见 [Smartling 方案](https://www.smartling.com/plans)，查阅于 2026 年 10 月。)

## Smartling 与 General Translation 对比一览

| 功能        | Smartling                                            | General Translation                                                                                                           |
| --------- | ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 字符串存放位置   | 资源文件，由 Smartling 解析并存储其中的字符串                         | 位于代码中的 [`<T>`](/docs/react/reference/components/t) 内，或保留在您现有的资源文件中                                                            |
| 代码接入方式    | GitHub Connector、Repository Connector、CLI 或 API      | 在构建流程中运行 [`npx gt translate`](/docs/cli/reference/commands/translate)，或通过 [Locadex](/docs/platform/locadex/quickstart) 提交拉取请求 |
| 翻译方       | AI Hub 引擎、Smartling AI Translation 或 Smartling 的语言专家 | 由 AI 结合代码、词汇表和自定义提示词提供的上下文进行翻译，再由您的团队在仪表板中审校                                                                                  |
| 每个字符串的上下文 | 可视化上下文捕获、带 OCR 识别的截图、词汇表、翻译记忆库和风格指南                  | 标记的 JSX 结构、变量占位符、上下文备注、词汇表和自定义提示词                                                                                             |
| 网站        | GDN 翻译代理                                             | 翻译代码中的内容，并通过 `gt-next` 提供区域设置路由                                                                                               |
| 定价        | Core 和 Enterprise 方案，另按字数收取翻译费用                      | [按用量计费](https://generaltranslation.com/pricing)                                                                               |

## 为什么团队选择 General Translation 而非 Smartling

使用 General Translation，新增文案的那次代码变更就能同时生成对应的译文。文案在 [`<T>`](/docs/react/reference/components/t) 中保持可读，构建过程会生成应用所需的语言文件。

* **更快。** 在应用构建之前运行 [`npx gt translate`](/docs/cli/reference/commands/translate)，即可为即将发布的版本生成译文。也可以配置 [Locadex](/docs/platform/locadex/guides/configuring-automations)，根据代码仓库事件自动创建翻译拉取请求。工程师可以直接借助现有的构建和评审流程完成本地化，无需再单独协调交付任务。
* **运行成本更低。** 使用内联 [`<T>`](/docs/react/reference/components/t) 代码块后，日常文案变更不再需要创建键或交接资源文件。CLI 会复用未变更的译文，因此重复构建时只会为新增或修改的文本生成译文。用量费率请参阅 [General Translation 定价](https://generaltranslation.com/pricing)，Smartling 的 AI 与人工翻译选项请参阅 [Smartling 服务费率](https://www.smartling.com/translation-services)。
* **质量更高。** Smartling 默认不为 JSON、iOS 和 Android 文件提供可视化上下文，需要团队自行提供截图或屏幕录制。General Translation 会将已标记 JSX 的结构和变量占位符一并带入翻译，并通过[上下文备注](/docs/react/reference/components/t)阐明意图，借助词汇表和自定义提示词统一产品术语。评审人员可以在[仪表板翻译编辑器](/docs/platform/dashboard/guides/reviewing-translations)中修正结果，让生成与评审在同一工作流中完成。
* **风险更低。** 采用 MIT 许可证的 `gt-react` 和 `gt-next` 库无需 General Translation 账户，也无需调用运行时服务，即可渲染[打包的译文](/docs/react/guides/storing-translations)。生成的文件随应用一起保存，已部署的文案完全由你掌控。

General Translation 已通过 SOC 2 Type II 和 ISO 27001 认证并符合 GDPR 要求，Enterprise 方案还提供 SSO、SCIM 预配、审计日志、自定义角色以及前向部署工程师。 (参见其[信任中心](https://trust.inc/generaltranslation)。) 

Cursor 在其 Web 产品和文档中使用 General Translation，覆盖 14 个以上的区域设置。 (参见[生产环境部署案例](https://generaltranslation.com/enterprise)。)

## 何时更适合选择 Smartling

如果你希望从同一家供应商采购 AI 翻译和人工翻译并获得质量保证；需要通过代理翻译营销网站，且无需改动代码；所在行业要求具备 PCI 或 HIPAA 等认证；内容分散在众多企业级 CMS 和营销工具中；或者需要与供应商交换 XLIFF、TMX 或 Office 文件，那么 Smartling 会是更好的选择。

## 从 Smartling 迁移到 General Translation

先从应用当前加载的资源文件入手，例如 JSON 或 PO 文件。针对这些文件[配置 CLI](/docs/cli/guides/configuring)，然后在首次运行 [`npx gt translate`](/docs/cli/reference/commands/translate) 之前，先运行 [`npx gt upload`](/docs/cli/reference/commands/upload) 导入源文件和现有译文。现有的国际化库和文件结构均可保持不变。

将词汇表导入[上下文分组](/docs/platform/dashboard/guides/defining-context-for-translations)，然后在仪表板中审阅生成的文案。如果团队还希望不再维护源键，可以另行选择采用内联 [`<T>`](/docs/react/reference/components/t)。如需从平台整体层面进行决策，请参阅[为什么选择 General Translation 而不是 TMS？](/kb/general-translation-vs-tms)。

## General Translation 可以替代 Smartling 吗？

可以。General Translation 专为软件团队打造，集代码感知的生成、构建自动化和仪表板审核于一体。你既可以沿用现有的翻译目录，也可以直接使用内联 JSX。如果你希望由同一家供应商同时提供网站翻译代理或人工翻译服务，Smartling 会是不错的选择。

## 要点总结

* Smartling 是一个全方位服务的企业级平台，如果你希望由同一家供应商提供 AI 翻译与人工翻译、网站代理以及全面的合规支持，它的优势最为突出。
* 工程师仍需维护基于键的资源文件；在拉取请求模式下，功能拉取请求必须等到其译文交付后才能继续。
* General Translation 将代码上下文、译文生成和审校融入发布工作流，而打包进应用的译文则让生产环境中的交付始终在你的应用内完成。
