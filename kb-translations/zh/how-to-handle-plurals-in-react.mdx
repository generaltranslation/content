## 为什么复数处理在 React 中很重要

我们经常看到一些应用显示这样别扭的消息：

```text
You have 1 new message(s)
```

这一眼就能看出，开发者没有认真考虑过用户体验。

React 应用经常需要进行复数处理——比如通知数量、列表长度或搜索结果。
**而且把复数处理做对并不难，尤其是当你的应用只需支持英语时。**
但新手开发者很容易踩进各种坑，在构建多语言界面时尤其如此。

本指南将介绍如何简洁地处理英语复数形式、如何按不同区域设置格式化数字，以及如何在 React 和 Next.js 中构建一套完整的多语言复数系统。

### 硬编码复数形式的问题

许多项目都会硬编码复数逻辑，其中甚至不乏一些规模庞大、举足轻重的项目。

```jsx
export default function Example({ n }) {
  return (
    <p>
      Displaying {n} item{n === 1 ? '' : 's'}
    </p>
  )
}
```

但复数处理往往远不止在单词末尾加一个 &quot;s&quot; 那么简单。
有些名词的复数形式不规则，比如 &quot;child&quot; 和 &quot;children&quot;。
有时，句子的其他部分也要随名词一起变化，比如
根据数量使用 &quot;is&quot; 或 &quot;are&quot;。

下表列出了一些常见场景：

| 场景   | 示例                                                                                          | 备注                                                         |
| ---- | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 观看人数 | &quot;1 person is watching&quot; <br /> &quot;2 people are watching&quot;                   | 需要处理不规则名词 (&quot;person&quot; → &quot;people&quot;) 和动词变化。 |
| 删除条目 | &quot;Delete this message?&quot; <br /> &quot;Delete these 2 messages?&quot;                | 指示代词变化 (&quot;this&quot; 与 &quot;these&quot;) ，外加名词复数处理。   |
| 搜索结果 | &quot;No results&quot; <br /> &quot;1 result found&quot; <br /> &quot;2 results found&quot; | 零个、一个和多个结果需要不同的措辞。                                         |

用条件表达式来处理，很快就会变得难以维护。

而一旦需要将应用发布到其他语言，这简直就是一场噩梦。
在英语中可行的写法，放到波兰语或阿拉伯语等语言中往往完全行不通，因为这些语言处理数量的规则截然不同。
**与我们合作的许多公司之所以迟迟不推进国际化，
正是因为重构这类硬编码 UI 太过痛苦。**

## 如何处理英语中的复数形式

在英语中，要在应用中正确使用复数形式通常并不难。

对于简单的名词复数处理，可以编写一个工具函数：

```jsx
export function pluralize(
  count: number,
  singular: string,
  plural: string = singular + 's'
) {
  return `${count === 1 ? singular : plural}`;
}
```

现在只需一个函数就能处理所有复数逻辑，
而且连不规则复数形式也同样适用：

```js
pluralize(2, 'user') // "users"
pluralize(2, 'person', 'people') // "people"
pluralize(2, 'child', 'children') // "children"
```

但如果你需要更复杂的逻辑呢？例如：

```text
"No one is watching"
"1 person is watching"
"2 people are watching"
```

到了这一步，你就该认真考虑引入一个低维护成本的国际化 (&quot;i18n&quot;) 库了。

开发者往往认为国际化库只适用于多语言界面，
但其实即便是单语言应用，它们在处理复数和变量格式化时也非常有用。
在底层，大多数国际化库都借助 JavaScript 内置的 `Intl.PluralRules` API 来确定任意语言的正确复数形式。

React 国际化库有很多，其中也包括我们的 [`gt-react`](/docs/react/overview) (如果你使用的是 Next.js，则可选择 [`gt-next`](/docs/react/nextjs-quickstart)) 。
用 gt-react 显示英文复数非常简单：

```jsx
import { Plural } from 'gt-react'

function Example({ count }) {
  return (
    <Plural n={count} zero={'No one is watching'} one={`${count} person is watching`}>
      {count} people are watching
    </Plural>
  )
}
```

UI 会根据 `n` 的值进行条件渲染。

大多数库使用 JavaScript 的 [`Intl.PluralRules`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules) API 来决定显示哪种复数形式。
也就是说，在英语中，你需要用 `"one"` 表示单数，用 `"other"` 表示复数。
我们的 [`<Plural>`](/docs/react/reference/components/plural) 组件会先检查精确匹配的复数类别，再检查通用的 `plural` 和 `other` 属性。只有当这些属性都未提供时，才会回退到其子元素。

即使应用只支持英语，在这里使用库也是最佳实践，而且能让日后的国际化工作轻松得多。

## 多语言 React 应用中的复数处理 (i18n) 

如果你的应用只面向英语用户，上述方法可能就已足够——但大多数生产环境中的应用最终都需要支持多种语言，这时事情就变得有意思了。

* 在阿拉伯语中，名词会根据数量是零、一、二还是多个而采用不同的形式
* 在 `de-DE`、`es-ES` 和 `it-IT` 等区域设置中，大数字用句点而不是逗号分隔，因此 1,000,000 会写成 1.000.000
* 在印地语中，数字按两位一组分隔，因此 1,000,000 会写成 10,00,000

**对于国际化应用，应当使用专门的国际化库**，这类库都有各自的文档，说明如何处理复数形式和数字格式化。

### 针对不同区域设置格式化数字

你可以使用 `Intl` 对象，按任意区域设置来[格式化数字](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/NumberFormat)。
最简单的方法是使用内置的 `toLocaleString()` 方法。

默认情况下，该方法会使用运行时的当前区域设置：

```javascript
const n = 1000000
n.toLocaleString() // 当运行时区域设置为 "en-US"（美式英语）时，显示 1,000,000
n.toLocaleString('de') // 显示 1.000.000，因为已将区域设置指定为 "de"（德语）
```

gt-react 还提供了 [`<Num>`](/docs/react/reference/components/num) 组件，其底层基于 `Intl.NumberFormat` 实现。

```jsx
import { Num } from 'gt-react'

// 当语言为 "en-US" 时显示 1,000,000
// 当语言为 "de" 时显示 1.000.000
// 当语言为 "hi" 时显示 10,00,000
export default function Example() {
  return <Num>1000000</Num>
}
```

### 理解不同语言中的复数形式

JavaScript 的 `Intl.PluralRules` API 支持六种复数形式：`zero`、`one`、`two`、`few`、`many`、`other`。
英语只用到 `one` (&quot;单数&quot;) 和 `other` (&quot;复数&quot;) ，
而阿拉伯语、波兰语等语言的复数形式则不止这两种。

例如，英语用户可能期望看到：

```text
"No one is watching"
"1 person is watching"
"2 people are watching"
```

而说阿拉伯语的用户则可能期望单数、
双数 (数量恰好为两个时) 以及少量复数和大量复数这几种复数形式各有不同的表达方式：

```text
"لا أحد يشاهد"
"1 شخص يشاهد"
"2 شخصان يشاهدان"
"3 أشخاص يشاهدون"
"11 شخصاً يشاهدون"
```

这正是国际化库不可或缺的原因。
每种语言在何时、如何显示复数形式上都有自己的一套规则，
因此最好交给专门的库来正确处理。

一个好的国际化库会做两件事：

1. 根据区域设置决定使用哪种复数形式 (`one`、`many`、`other` 等) 
2. 找到该形式在目标语言中对应的翻译

**如果你已经在使用某个国际化库，
请查阅其文档中有关复数格式化的说明。**
几乎所有库都有专门介绍如何渲染复数形式的文档。

### 完整示例：多语言 React 应用中的复数形式

如果你还没有使用国际化库，不妨试试 [`gt-react`](/docs/react/react-quickstart)！

gt-react 的 [`<Plural>`](/docs/react/reference/components/plural) 组件：

* 以简单的声明式方式，在 React 中正确渲染复数形式
* 原生支持 [`<Num>`](/docs/react/reference/components/num) 格式化组件
* 原生支持 [`<T>`](/docs/react/reference/components/t) 翻译组件，后者与我们的[翻译服务](https://generaltranslation.com)集成，可自动生成复数形式

把这些模块组合在一起，就得到了一个完整的多语言组件：

```jsx
import { T, Plural, Num } from 'gt-react'

// 开箱即用，支持 100 多种语言
function Example({ count }) {
  return (
    <T>
      <Plural
        n={count}
        zero={'No one is watching'}
        one={
          <>
            <Num>{count}</Num> person is watching
          </>
        }
      >
        <Num>{count}</Num> people are watching
      </Plural>
    </T>
  )
}
```

***

如需设置复数处理，React 应用请参阅 [`gt-react` 快速入门](/docs/react/react-quickstart)，Next.js 应用请参阅 [`gt-next` 快速入门](/docs/react/nextjs-quickstart)。完整的组件 API 请参阅 [`<Plural>` API 参考](/docs/react/reference/components/plural)。

复数处理是 React 中最常见的 i18n 难题之一——从一开始就把它做好，能省去日后大量的重构工作。
