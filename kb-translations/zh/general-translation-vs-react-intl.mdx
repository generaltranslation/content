react-intl 是 [FormatJS 推出的 React 库](https://formatjs.github.io/docs/react-intl)。使用时，你需要用 ICU MessageFormat 把每条消息内联写成 `defaultMessage`，为译者补充 `description`，再通过 `formatjs extract` 将所有消息提取到 JSON 消息目录中，最后借助 `IntlProvider` 渲染翻译后的消息目录。它本身并不负责翻译：提取出的消息目录需要交给你自己、译者或翻译管理系统 (TMS) 处理，拿回翻译后的文件后再进行编译。General Translation 的库同样能渲染 ICU 消息，不同的是，General Translation 还能直接生成译文。

## react-intl 的优势

* **全面采用 ICU MessageFormat。** [支持使用 `#` 的复数形式、`=0` 等精确匹配、`select` 以及 `selectordinal`](https://formatjs.github.io/docs/core-concepts/icu-syntax)，底层基于浏览器的 `Intl` API。
* **内联源文本。** FormatJS [建议以内联方式编写 `defaultMessage` 和 `description`](https://formatjs.github.io/docs/getting-started/message-declaration)，再由 `babel-plugin-formatjs` 或 `@swc/plugin-formatjs` 自动生成消息 ID，因此无需人工命名键。
* **面向 TMS 工作流的工具链。** [`formatjs extract`](https://formatjs.github.io/docs/tooling/cli) 负责生成消息目录，内置格式化器可为 Crowdin、Lokalise、Smartling 和 Transifex 输出文件，`formatjs compile` 会预解析消息，`formatjs verify` 则检查消息目录中是否存在缺失或多余的键。
* **TypeScript 支持。** [第 12 版可为每条消息的 ICU 参数提供类型定义](https://formatjs.github.io/docs/react-intl/upgrade-guide-12.x)。
* **持续维护。** [第 12 版于 2026 年 9 月发布](https://github.com/formatjs/formatjs/blob/main/packages/react-intl/CHANGELOG.md)，采用 BSD-3-Clause 许可证。

## react-intl 没替你做的事

下面用 react-intl 实现一个简单的收件箱。英文文本以 `defaultMessage` 的形式保留在组件中：

```jsx title="Inbox.jsx"
import { FormattedMessage } from 'react-intl';

export function Inbox({ count }) {
  return (
    <section>
      <h1>
        <FormattedMessage defaultMessage="Inbox" description="Heading of the inbox page" />
      </h1>
      <p>
        <FormattedMessage
          defaultMessage="You have {count, plural, one {# unread message} other {# unread messages}}."
          description="Number of unread messages in the inbox"
          values={{ count }}
        />
      </p>
    </section>
  );
}
```

`formatjs extract` 会将这些消息提取为一个以自动生成的 ID 为键的目录：

```json title="lang/en.json"
{
  "U5vJOY": {
    "defaultMessage": "You have {count, plural, one {# unread message} other {# unread messages}}.",
    "description": "Number of unread messages in the inbox"
  },
  "gBGgGs": {
    "defaultMessage": "Inbox",
    "description": "Heading of the inbox page"
  }
}
```

每种目标语言都需要提供翻译后的消息，并保持其 ICU 语法完整。`IntlProvider` 既可接受消息字符串，也可接受预编译消息；后者由 `formatjs compile` 生成。提取出的描述符包含每条消息及其描述。若要使用本示例中自动生成的 ID，请在构建流程中配置 Babel 或 SWC 插件。在 [Next.js App Router](https://formatjs.github.io/docs/guides/nextjs-app-router) 中，react-intl 的组件运行在客户端组件中，而服务端代码则通过 `react-intl/server` 中的 `createIntl` 来格式化消息。

## 保留 ICU 消息并生成译文

General Translation 的库与 react-intl 作用相同：渲染 ICU 消息、应用各区域设置的复数规则，并格式化数字、货币和日期。由于 [`useGT`](/docs/react/reference/hooks/use-gt) 采用相同的语法，您的 ICU 字符串几乎无需修改即可直接迁移：

```tsx title="Inbox.tsx"
import { useGT } from 'gt-react';

export function Inbox({ count }: { count: number }) {
  const gt = useGT();
  return (
    <section>
      <h1>{gt('Inbox', { $context: 'Heading of the inbox page' })}</h1>
      <p>
        {gt('You have {count, plural, one {# unread message} other {# unread messages}}.', {
          count,
          $context: 'Number of unread messages in the inbox',
        })}
      </p>
    </section>
  );
}
```

[`npx gt translate`](/docs/cli/reference/commands/translate) 只需一条命令，即可提取这些字符串、结合其上下文备注生成译文，并写入目标消息目录。本示例将两条 FormatJS 描述都保留为 `$context`。共享的[词汇表术语和自定义提示词](/docs/platform/dashboard/guides/defining-context-for-translations)用于统一术语和语气，审校人员可在[仪表板](/docs/platform/dashboard/guides/reviewing-translations)中编辑翻译结果。

`#` 会按各区域设置进行格式化，因此数值 12345 在英语中显示为 &quot;12,345&quot;，在西班牙语中显示为 &quot;12.345&quot;。对于包含标记的 JSX，[`<T>`](/docs/react/reference/components/t) 会翻译整个被包裹的代码块，其中的元素也一并翻译。在 `gt-next` 中，它可直接用于服务端组件。

借助 General Translation，Ramp 的仪表板、落地页和 iOS 应用已支持 11 种以上的区域设置。 (参见[生产环境部署案例](https://generaltranslation.com/enterprise)。)

## react-intl 与 General Translation 对比速览

| 功能                 | react-intl                                                                                    | General Translation                                                                                                  |
| ------------------ | --------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 文案编写方式             | 以 ICU 格式内联编写 `defaultMessage`，并提取到 JSON 消息目录                                                  | 在 [`<T>`](/docs/react/reference/components/t) 中内联编写 JSX，或在 [`useGT`](/docs/react/reference/hooks/use-gt) 中使用 ICU 字符串 |
| 是否翻译你的内容           | 否                                                                                             | 是，通过 [`npx gt translate`](/docs/cli/reference/commands/translate)                                                    |
| 消息目录工作流            | 提取消息，通过你选择的工作流完成翻译，可选预编译；由插件生成 ID                                                             | [`npx gt translate`](/docs/cli/reference/commands/translate) 在构建前完成提取和翻译                                             |
| 翻译上下文              | 消息本身及其描述                                                                                      | 带 `$context` 的 ICU 字符串；包含内联组件的标记化 JSX 结构；共享的词汇表和自定义提示词                                                               |
| Next.js App Router | 在客户端组件中使用组件；在服务端使用 `createIntl`                                                               | 在 服务端组件 和 客户端组件 中均可使用 [`<T>`](/docs/react/reference/components/t)                            |
| 许可证                | [BSD-3-Clause](https://github.com/formatjs/formatjs/blob/main/packages/react-intl/LICENSE.md) | JavaScript 库和 CLI 均采用 MIT 许可证                                                                                        |

如果你的 ICU 消息目录和 TMS 格式化工具已运行良好，或者你依赖其类型化消息参数或 `formatjs verify`，又或者你需要在 React 之外使用 FormatJS，那么继续使用 react-intl 即可。如果你希望沿用 ICU 编写方式，同时将翻译生成和审校纳入开发工作流，那就选择 General Translation。

## 从 react-intl 迁移

每次只迁移一个组件或路由。将每个 `<FormattedMessage>` 替换为 [`useGT`](/docs/react/reference/hooks/use-gt) 调用，保留原有的 ICU 字符串，并将其描述作为 `$context` 传入，如上文所示。对于富 JSX 内容，请使用 [`<T context="…">`](/docs/react/reference/components/t#context)。尚未迁移的组件则继续加载现有的 react-intl 消息目录。待所有组件迁移完成后，移除 FormatJS 插件以及 extract 和 compile 脚本。 (参见[迁移国际化库](/docs/react/guides/migrating-i18n-libraries)。)

## 要点总结

* react-intl 负责格式化 ICU 消息并提供消息目录工具，但翻译的生成需要另行搭建工作流。
* General Translation 只需一条 CLI 命令即可完成提取和翻译，同时保留 description 上下文，并为审阅者提供仪表板编辑器。
* 你的 ICU 字符串几乎无需改动即可迁移到 [`useGT`](/docs/react/reference/hooks/use-gt)，并且可以逐个组件迁移。
