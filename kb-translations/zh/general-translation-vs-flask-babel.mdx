Babel 基于 Unicode CLDR 数据格式化日期、数字和货币，其 `pybabel` 命令可用于提取、更新和编译 gettext 消息目录。Flask-Babel 则将这些工具接入 Flask 的请求处理流程和 Jinja 模板。General Translation 负责在提取与编译之间填充目录，你的应用无需改动现有的 Flask-Babel 初始化设置，即可获得自动翻译能力。

## Babel 和 Flask-Babel 的优势

* **基于 CLDR 的区域设置格式化。**[Babel 2.18.0 内置了 CLDR 47](https://babel.pocoo.org/en/latest/changelog.html#version-2-18-0) 数据，覆盖一千多个区域设置标识符。`format_currency(1234.5, "EUR")` 在西班牙语中输出“1.234,50 €”，`format_date` 在波兰语中输出“16 października 2026”。
* **目录工具。**[`pybabel extract`](https://babel.pocoo.org/en/latest/cmdline.html) 通过 `babel.cfg` 映射读取 Python 文件和 Jinja 模板；`pybabel init` 会生成一个 PO 文件，并预置正确的复数规则和对应槽位 (波兰语为三个) ；`pybabel update` 合并新增字符串，并将有改动的字符串标记为 fuzzy；`pybabel compile` 则负责构建 `.mo` 文件。
* **Flask 集成。**`locale_selector` 和 `timezone_selector` [决定每个请求使用的区域设置和时区](https://python-babel.github.io/flask-babel/#configuration)；`lazy_gettext` 用于处理在导入时定义的字符串；Jinja 模板中可使用 `_()`、`{% trans %}` 以及各类格式化过滤器；`force_locale` 可临时切换区域设置，例如用其他语言发送邮件。
* **稳定且免费。**&#x4E24;者均采用 BSD 许可证 (参见 [Babel 的许可证](https://babel.pocoo.org/en/latest/license.html)) 。Babel 适用于任何 Python 程序；Flask-Babel 的[当前版本为 4.0.0](https://github.com/python-babel/flask-babel/releases/tag/v4.0.0)。

## Babel 和 Flask-Babel 需要你自己处理的部分

下面是一个简单的 Flask-Babel 应用：

```python title="app.py"
from datetime import date
from flask import Flask, request
from flask_babel import Babel, gettext, ngettext, format_currency, format_date


def select_locale():
    return request.accept_languages.best_match(["en", "es", "pl"])


app = Flask(__name__)
babel = Babel(app, locale_selector=select_locale)


@app.route("/inbox/<int:count>")
def inbox(count):
    return {
        "title": gettext("Inbox"),
        "unread": ngettext("You have %(num)d unread message.", "You have %(num)d unread messages.", count),
        "price": format_currency(1234.5, "EUR"),
        "date": format_date(date(2026, 10, 16), format="long"),
    }
```

依次运行 `pybabel extract`、`pybabel init -l pl` 和 `pybabel compile` 后，会生成一个波兰语目录，其中所有 `msgstr` 均为空。在 Flask-Babel 4.0.0 下，发送带有 `Accept-Language: pl` 的请求，返回结果如下：

```json title="Output"
{
  "date": "16 października 2026",
  "price": "1 234,50 €",
  "title": "Inbox",
  "unread": "You have 5 unread messages."
}
```

Babel 会按波兰语格式化日期和价格，但所有字符串依然是英文，而且不会有任何警告。每个字符串都得等人填好对应的 PO 条目 (包括波兰语全部三种复数形式) ，再运行 `pybabel compile` 并重新部署。每新增或修改一个字符串，每种语言都要把这套流程重走一遍。

## 使用 General Translation 翻译 Babel 目录

如果 Flask-Babel 已经能满足你的需求，可以继续沿用，由 General Translation 的 CLI 负责写入目录。只需创建一次英文目录，并在每次提取后更新它，这样源文本就会与译文位于同一目录树中：

```bash
pybabel extract -F babel.cfg -k lazy_gettext -o messages.pot .
pybabel init -i messages.pot -d translations -l en     # 只需执行一次
pybabel update -i messages.pot -d translations -l en   # 每次 extract 后执行
```

然后在 `gt.config.json` 中指向该文件。此配置已基于 `gt` 2.26.5 验证：

```json title="gt.config.json"
{
  "defaultLocale": "en",
  "locales": ["es", "pl", "pt_BR"],
  "customMapping": { "pt_BR": { "code": "pt-BR" } },
  "files": {
    "pot": {
      "include": ["translations/[locale]/LC_MESSAGES/messages.po"],
      "transformationFormat": "PO"
    }
  }
}
```

`pot` 键用于读取 PO 和 POT 文件，`"transformationFormat": "PO"` 则会输出翻译后的 `.po` 文件 (参见 [PO / POT 格式参考](/docs/cli/reference/formats/po-pot-files)) 。[`customMapping`](/docs/cli/reference/config#custom-mapping) 将 Babel 的 `pt_BR` 目录映射到标准区域设置代码 `pt-BR`。请先设置好 [CLI](/docs/cli/quickstart)。如果你已有译文，请在生成新译文之前使用 [`npx gt upload`](/docs/cli/reference/commands/upload) 导入。然后运行 [`npx gt translate`](/docs/cli/reference/commands/translate)，再运行 `pybabel compile -d translations`。

General Translation 会将每个条目的 `msgctxt`、译者注释、源引用和标志一并作为上下文发送。对于复数条目，它会写入目标语言的 `Plural-Forms` 头部字段，并填充每个 `msgstr[n]` 槽位 (例如波兰语的三种形式都会填好) ，同时检查 `%(num)d` 等占位符是否完整保留。未更改的条目会在下次运行时复用之前的译文。[上下文分组](/docs/platform/dashboard/guides/defining-context-for-translations)中的词汇表和自定义提示词可确保术语在你的目录与产品其他部分之间保持一致，审校人员也可以在仪表板中[编辑每个条目](/docs/platform/dashboard/guides/reviewing-translations)。在 CI 中运行 CLI，确保每次部署都附带最新的目录。之后如有本地修改，请在再次生成前使用 [`npx gt save-local`](/docs/cli/reference/commands/save-local) 保存。

## Babel 和 Flask-Babel 与 General Translation 对比一览

| 功能          | Babel 和 Flask-Babel                            | General Translation                                               |
| ----------- | ---------------------------------------------- | ----------------------------------------------------------------- |
| 字符串编写方式     | 使用 `gettext` 调用和 Jinja `{% trans %}`，提取到 PO 文件 | 沿用这些调用和模板，翻译提取出的目录                                                |
| 翻译你的内容      | 否                                              | 是，使用 [`npx gt translate`](/docs/cli/reference/commands/translate) |
| 复数形式        | `pybabel init` 生成各个槽位，需由你逐一填写                  | 为目标语言生成全部 PO 槽位                                                   |
| 日期、数字和货币格式化 | 是，基于 CLDR                                      | 沿用 Babel 的格式化                                                     |
| Jinja 模板    | 是                                              | 翻译从现有模板中提取的消息                                                     |
| 框架          | Babel 适用于任何场景；Flask-Babel 适用于 Flask            | CLI 适用于 Flask 或其他 gettext 应用的 PO 目录                               |
| 许可证         | BSD                                            | CLI 采用 MIT 许可证                                                    |
| 费用          | 免费                                             | [翻译按用量计费](https://generaltranslation.com/pricing)                 |

## 如何选择

如果译员或 TMS 已经能交付您所需的目录，请沿用现有的翻译流程。如果您希望在开发阶段就翻译新增和变更的消息，并借助团队跨项目共享的术语和审校工具，请引入 General Translation。Jinja、请求区域设置、日期和货币仍由 Flask-Babel 处理，您的应用代码无需任何改动。

## 关键要点

* Babel 可以按任意区域设置格式化日期、数字和货币，并管理 gettext 目录；Flask-Babel 则负责将其集成到 Flask 中。但两者都不会翻译你的字符串。
* General Translation 的 CLI 可借助 `pot` 键、`"transformationFormat": "PO"`，以及针对 `pt_BR` 等目录的 `customMapping` 来翻译 Babel 的 PO 文件，并为每种语言填充全部复数形式。
* 继续沿用 Flask-Babel 的渲染和格式化功能，导入现有译文，然后在提取和编译之间加入 General Translation 即可。
