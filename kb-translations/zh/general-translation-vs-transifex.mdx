如果你希望翻译融入 React 开发工作流，General Translation 更为合适：用 [`<T>`](/docs/react/reference/components/t) 标记 JSX，在构建前生成译文，并随应用一同发布。Transifex 是一款翻译管理系统 (TMS) ，自 2025 年 1 月起[归属 XTM International 旗下](https://xtm.ai/news/xtm-international-acquires-transifex)，将 AI、译员与合作供应商结合在一起。

Transifex 既支持资源文件，也支持通过 Transifex Native 直接在代码中标记字符串。Native 会将消息推送到 Transifex，并从其内容分发服务 (CDS) 加载译文。General Translation 则会提取带标记的 JSX 进行翻译，应用可以从打包的文件或其 CDN 加载翻译结果。

## Transifex 的优势

* **无需文件，直接从代码中获取字符串。** [Transifex Native](https://developers.transifex.com/docs/javascript-sdk) 通过翻译函数或 React 组件标记字符串，默认以源文本作为键，并使用 `txjs-cli push` 推送字符串。其 SDK 和 [CDS](https://github.com/transifex/transifex-delivery) 均基于 Apache-2.0 许可证开源，CDS 还支持自托管。
* **AI 翻译附带质量评分。** Transifex AI 会结合你的词汇表、翻译记忆库和上下文进行翻译，并通过 [Translation Quality Index (TQI)](https://help.transifex.com/en/articles/9465000-translation-quality-index-tqi) 为 AI 译文打分。达到设定阈值的译文可自动标记为已审校。
* **人工翻译合作伙伴。** 你可以直接在 Transifex 中[向 e2f、Gengo、TextMaster 等合作伙伴订购翻译服务](https://help.transifex.com/en/articles/6235673-ordering-translations)。
* **无需改动代码即可翻译网站。** [Transifex Live](https://help.transifex.com/en/articles/6244596-introduction-to-transifex-live) 只需嵌入一段 JavaScript 代码片段即可翻译网站，不过对于 React 和 Vue 应用，Transifex 更推荐使用 Native。
* **协作者数量不限。** 当前套餐不按席位、项目数或托管内容收费。
* **文件格式丰富。** 支持 [46 种以上格式](https://help.transifex.com/en/articles/6219670-introduction-to-file-formats)，包括 XLIFF、Office 文件和字幕。

## Transifex 仍需工程师完成的工作

工程师需要将应用接入 Transifex 的翻译与投递工作流：

1. 为 Transifex 标记每个字符串：将其提取到资源文件中并分配一个键，或用 Native 的翻译函数或 React 组件将其包裹。
2. 通过 [`tx push`](https://github.com/transifex/cli)、Git 集成或 `txjs-cli push` 将字符串发送到 Transifex，这一步通常放在 CI 中执行。
3. 配置 AI 翻译或合作供应商，并设置所需的审校要求。
4. 交付译文。在文件工作流中，当某种语言的完成度达到阈值时，[Git 集成](https://help.transifex.com/en/articles/6265125-github-via-transifex-ui)会创建拉取请求或直接提交。Native 从 [CDS](https://developers.transifex.com/docs/content-delivery-service) 获取译文，其内容默认一小时后过期，刷新间隔可自行配置。

Transifex AI 会利用[词汇表术语、翻译记忆库、上下文字段和公司信息](https://help.transifex.com/en/articles/9867663-context-in-transifex-ai)，还可以启用开发者备注和字符串说明。General Translation 的 React 库则通过已标记的 JSX 结构和命名占位符提供上下文，并辅以开发者备注和项目术语来指导翻译。

定价方面，Transifex 仅提供一个 AI 优先的方案，需联系销售购买，按 AI 翻译字数计费，未公开价格。 (参见 [Transifex 定价](https://www.transifex.com/pricing)，查阅于 2026 年 10 月。)

## Transifex 与 General Translation 速览

| 功能        | Transifex                                                         | General Translation                                                     |
| --------- | ----------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 字符串如何导入   | 通过 `tx push` 或 Git 集成导入资源文件，或通过 `txjs-cli push` 导入 Native SDK 字符串 | 内容直接保留在代码中的 [`<T>`](/docs/react/reference/components/t) 内，或保留在你现有的资源文件中 |
| 由谁翻译      | 带 TQI 评分的 Transifex AI，或合作供应商                                     | AI 结合代码上下文、词汇表和自定义提示词进行翻译，再由你的团队在仪表板中审核                                 |
| 每个字符串的上下文 | 词汇表、翻译记忆库、上下文字段以及可选的开发者备注                                          | 已标记的 JSX、命名占位符、开发者备注、词汇表和自定义提示词                                         |
| 交付方式      | 文件通过拉取请求或提交交付；Native 在运行时通过 CDS 交付                                | 译文打包在本地，或通过 General Translation 的 CDN 分发                                |
| 定价        | 按 AI 翻译字数计费，需联系销售获取报价                                             | 公开的[使用费率](https://generaltranslation.com/pricing)                       |

## 为什么团队选择 General Translation 而非 Transifex

* **更快。** [`npx gt translate`](/docs/cli/reference/commands/translate) 会在应用构建之前提取已标记的内容、生成译文并下载结果。这样，每次发布只需运行一个翻译步骤。如果你更习惯在 GitHub 中审查变更，[Locadex](/docs/platform/locadex/quickstart) 会在代码变更时自动创建拉取请求。
* **运行成本更低。** General Translation 减少了翻译富 UI 所需的工程工作量：一个句子可以将其中的链接、格式和动态值保留在同一个 [`<T>`](/docs/react/reference/components/t) 块中，而无需拆解重组为消息字符串。你可以直接根据[公开价格](https://generaltranslation.com/pricing)估算翻译成本。
* **质量更高。** 将句子与其嵌套元素放在一起，翻译时就能把握文字、链接和占位符之间的关系。开发者备注可以澄清有歧义的文案，而已分配的[上下文组](/docs/platform/dashboard/guides/defining-context-for-translations)能让你的应用和网站使用统一的术语。你的团队还可以在[翻译编辑器](/docs/platform/dashboard/guides/reviewing-translations)中进一步完善译文。
* **风险更低。** 使用[本地译文](/docs/react/guides/storing-translations)时，应用直接基于发布版本中打包的文件进行渲染，运行时不会调用 General Translation。如果团队希望无需重新部署即可发布译文修改，也可以改用 General Translation 的 CDN。只要自行提供译文，采用 MIT 许可证的 JavaScript 库无需账号即可使用。

Sierra 借助 General Translation，在其网站和市场推广内容中支持 7 个以上的区域设置。 (参见[生产环境部署案例](https://generaltranslation.com/enterprise)。)

## 何时 Transifex 更合适

以下情况更适合选择 Transifex：希望只嵌入一段代码片段、无需改动代码即可翻译网站；希望向其合作供应商订购人工翻译；基于 TQI 的自动审批契合你的审校流程；需要交换 XLIFF、Office 或字幕文件；或者原生 iOS 和 Android 应用需要[支持离线应用包的 OTA (空中) 更新](https://developers.transifex.com/docs/ios-sdk)。

## 从 Transifex 迁移到 General Translation

如果是基于文件的项目，且使用 JSON、YAML、PO 或 iOS 和 Android 资源文件等受支持的格式，请按照 [CLI 快速入门](/docs/cli/quickstart)操作。先配置源文件路径和区域设置路径，再使用 [`npx gt upload`](/docs/cli/reference/commands/upload) 导入现有译文，然后生成新的译文。

如果是使用 Native 的 React 应用，请按照 [React 快速入门](/docs/react/react-quickstart)或 [Next.js 快速入门](/docs/react/nextjs-quickstart)设置 `gt-react` 或 `gt-next`。一次迁移一个页面：将该页面的文案和标记放入 [`<T>`](/docs/react/reference/components/t) 中，然后运行 [`npx gt translate`](/docs/cli/reference/commands/translate)。在审核已翻译页面期间，其余页面可继续使用 Native。将词汇表导入[上下文分组](/docs/platform/dashboard/guides/defining-context-for-translations)，即可沿用现有的产品术语。

## General Translation 可以替代 Transifex 吗？

可以。使用 General Translation，你可以在构建前基于结构化 JSX 生成译文，并将其打包到应用中，或通过 General Translation 的 CDN 交付。你也可以保留现有的基于文件的应用，只用 General Translation 来翻译其消息目录。如需更全面的供应商对比，请参阅[为什么选择 General Translation 而不是 TMS？](/kb/general-translation-vs-tms)。

## Transifex Native 与 General Translation 有何不同？

两者都使用开源 SDK，也都可以将源文本保留在代码中。在 [Transifex 的 React SDK](https://developers.transifex.com/docs/react-sdk) 中，`<T _str="...">` 消息可以接收 React 元素作为插值的值。General Translation 的 [`<T>`](/docs/react/reference/components/t) 则将句子和嵌套元素直接保留在 JSX 中，并提取这一结构进行翻译。Native 通过 CDS 交付译文；而 General Translation 允许你选择将译文文件打包进应用包，或通过其 CDN 交付。

## 要点总结

* Transifex 是一款 TMS，提供开源的 Native SDK、附带质量评分的 AI 翻译、合作供应商，以及面向网站的 Transifex Live。
* Native 已支持代码中的字符串。General Translation 在 React 上的优势在于可以编写和翻译结构化 JSX，并支持开发者备注和共享术语。
* General Translation 在构建前生成译文，既支持随应用包投递，也支持通过 CDN 更新，你可以自行选择已翻译内容送达用户的方式。
