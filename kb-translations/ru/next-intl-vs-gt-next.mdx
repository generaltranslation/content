И next-intl, и gt-next локализуют приложения на Next.js App Router, включая серверные компоненты. Разница в том, откуда берутся переводы: next-intl отображает сообщения, которые ваша команда или сервис перевода записывает в JSON-каталог для каждого языка, а gt-next хранит исходный текст прямо в JSX, и General Translation генерирует все переводы на этапе сборки.

Отсюда три варианта. Оставить next-intl и текущий процесс перевода. Оставить next-intl и поручить перевод его каталогов General Translation — без каких-либо изменений в компонентах. Или перейти на gt-next со встроенным текстом и автоматически генерируемыми переводами.

## Чем отличаются next-intl и gt-next?

| Вопрос                       | next-intl                                                                                                        | gt-next (General Translation)                                                                                                                                          |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Переводит ли он ваш контент? | Нет. Он только рендерит сообщения, которые вы предоставляете сами: от вашей команды или из сервиса вроде Crowdin | Да. [`gt translate`](/docs/cli/reference/commands/translate) генерирует переводы с учётом контекста из вашего кода, либо ваша команда может написать их сама           |
| Где хранится исходный текст? | Сообщения с ключами в JSON-каталоге; встроенное извлечение с помощью `useExtracted` пока экспериментальное       | Встроенный JSX внутри [`<T>`](/docs/react/reference/components/t) и строки через [`useGT`](/docs/react/reference/hooks/use-gt); словари с ключами также поддерживаются |
| Серверные компоненты?        | Да, с отдельными API для синхронных и асинхронных компонентов                                                    | Да: [`<T>`](/docs/react/reference/components/t), [`useGT`](/docs/react/reference/hooks/use-gt) и [`getGT`](/docs/react/nextjs/reference/functions/get-gt)              |
| Клиентские компоненты?       | Внутри `NextIntlClientProvider`                                                                                  | Внутри [`GTProvider`](/docs/react/reference/components/gt-provider)                                                                                                    |
| Маршрутизация по локалям     | Промежуточное ПО и маршруты с префиксом локали                                                                   | [`createNextMiddleware`](/docs/react/nextjs/app-router-middleware) с сегментом `app/[locale]`                                                                          |
| Формы множественного числа   | ICU MessageFormat в каждом каталоге                                                                              | Ветви [`<Plural>`](/docs/react/reference/components/plural), которые переводятся вместе с остальным блоком                                                             |
| Доставка переводов           | Файлы каталогов входят в бандл приложения                                                                        | Файлы в бандле или CDN General Translation для обновлений без повторного развёртывания                                                                                 |
| Лицензия                     | MIT                                                                                                              | MIT                                                                                                                                                                    |

Источники: [настройка next-intl для App Router](https://next-intl.dev/docs/getting-started/app-router), [использование next-intl на сервере и клиенте](https://next-intl.dev/docs/environments/server-client-components), [быстрый старт gt-next](/docs/react/nextjs-quickstart).

## Как один и тот же заголовок выглядит в каждой библиотеке?

В рабочем процессе next-intl, основанном на каталогах, исходное сообщение хранится в JSON-файле:

```json
{
  "Projects": {
    "heading": "Find your next project"
  }
}
```

Компонент выбирает сообщение по пространству имён и ключу:

```tsx
import { useTranslations } from 'next-intl';

export default function ProjectHeading() {
  const t = useTranslations('Projects');
  return <h1>{t('heading')}</h1>;
}
```

С gt-next то же предложение остаётся внутри компонента:

```tsx
import { T } from 'gt-next';

export default function ProjectHeading() {
  return (
    <T>
      <h1>Find your next project</h1>
    </T>
  );
}
```

Оба фрагмента предполагают, что провайдер и конфигурация каждой библиотеки уже настроены. См. [руководство по настройке next-intl](https://next-intl.dev/docs/getting-started/app-router) и [справочник по `<T>`](/docs/react/reference/components/t).

Каталог позволяет рецензентам читать тексты отдельно от кода. Встроенные тексты позволяют рецензентам видеть каждое предложение прямо в JSX, к которому оно относится, а General Translation — переводить его, используя эту структуру как контекст. Если формулировка всё равно остаётся неоднозначной, можно воспользоваться [пропом `context` компонента `<T>` в gt-next](/docs/react/reference/components/t#context) или [описаниями сообщений в экспериментальном механизме извлечения next-intl](https://next-intl.dev/docs/usage/extraction#descriptions).

Экспериментальный API [`useExtracted`](https://next-intl.dev/docs/usage/extraction) в next-intl тоже позволяет писать сообщения прямо в коде и извлекать их в каталоги. Извлечение меняет способ написания текстов, но не переводит извлечённые каталоги: их по-прежнему должна переводить ваша команда или сторонний сервис.

## Можно ли использовать General Translation, не отказываясь от next-intl?

Да. CLI `gt` определяет next-intl по вашему `package.json` и [переводит его JSON-каталоги](/docs/cli/guides/generating-translations), сохраняя синтаксис сообщений next-intl. Ваши компоненты, вызовы перевода и маршрутизация не меняются.

Чтобы попробовать, укажите в `gt.config.json` исходные и целевые каталоги, импортируйте уже имеющиеся переводы и переведите приложение на одну новую локаль. Рецензенты могут исправить результат в [Редакторе переводов в панели управления](/docs/platform/dashboard/guides/reviewing-translations). Если же они правят загруженные каталоги прямо в вашем репозитории, выполните [`gt save-local`](/docs/cli/reference/commands/save-local) перед следующим запуском перевода, чтобы эти правки не потерялись.

Если позже вы решите перейти на gt-next, в [руководстве по миграции](/docs/react/guides/migrating-i18n-libraries) описано, как импортировать проверенные переводы, сохранить ваши словари и использовать обе библиотеки одновременно, мигрируя маршруты по одному.

## Как каждая библиотека работает с серверными и клиентскими компонентами?

Ни одна из библиотек не требует превращать страницу App Router в клиентский компонент ради локализации. Разница лишь в том, какой API вызывать в каждой среде.

| Компонент                       | next-intl                                                                                                                                                             | gt-next                                                                                                                                                           |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Синхронный серверный компонент  | [`useTranslations`](https://next-intl.dev/docs/environments/server-client-components#using-internationalization-in-server-components) с конфигурацией запроса         | [`<T>`](/docs/react/reference/components/t) для JSX; [`useGT`](/docs/react/reference/hooks/use-gt) для строк                                                      |
| Асинхронный серверный компонент | Вызовите [`getTranslations`](https://next-intl.dev/docs/environments/server-client-components#async-components) из `next-intl/server` через `await`                   | Вызовите [`getGT`](/docs/react/nextjs/reference/functions/get-gt) из `gt-next/server` через `await`, а затем вызовите полученную функцию                          |
| Клиентский компонент            | [`useTranslations`](https://next-intl.dev/docs/environments/server-client-components#using-internationalization-in-client-components) внутри `NextIntlClientProvider` | [`<T>`](/docs/react/reference/components/t) или [`useGT`](/docs/react/reference/hooks/use-gt) внутри [`GTProvider`](/docs/react/reference/components/gt-provider) |

В обеих библиотеках интерактивные элементы управления лучше оставлять в клиентских компонентах, а остальную страницу переводить на сервере. Кроме того, next-intl позволяет [передавать уже переведённые подписи](https://next-intl.dev/docs/environments/server-client-components#option-1-passing-translated-labels-to-client-components) из серверного компонента в клиентский элемент управления, чтобы клиент не получал весь каталог целиком.

## Как gt-next доставляет переводы в рабочей среде?

gt-next поддерживает два варианта доставки:

* **Встраивание переводов в бандл приложения** с помощью [локального загрузчика](/docs/react/guides/storing-translations). Приложение в рабочей среде читает собственные файлы перевода и не обращается к General Translation во время выполнения. Обновления попадают в приложение со следующей сборкой.
* **Загрузка переводов из CDN General Translation** с помощью [конфигурации удалённой доставки](/docs/react/nextjs/config). Опубликованные правки попадают в развёрнутое приложение без пересборки — с учётом настроек версии и кеширования.

gt-next распространяется [по лицензии MIT](https://github.com/generaltranslation/gt) и выполняет рендеринг переводов из бандла без учётной записи General Translation — так же, как next-intl рендерит свои каталоги.

## Какие команды используют gt-next в рабочей среде?

General Translation используют команды разработчиков Cursor, Ramp, Profound, Cognition, Sierra и ClickHouse. Profound локализует с помощью General Translation свой основной продукт — приложение Next.js на App Router. Подробнее см. [примеры развёртываний в рабочей среде](https://generaltranslation.com/enterprise).

## Когда выбирать next-intl, а когда gt-next?

**Оставайтесь на next-intl**, если её модель каталогов подходит вашему приложению, а процесс перевода уже отлажен. Если главная проблема — рутинное управление ключами, попробуйте её экспериментальное извлечение, прежде чем переходить на другое решение.

**Оставьте next-intl и добавьте General Translation**, если узкое место — сама подготовка переводов. CLI `gt` переводит ваши существующие каталоги, поэтому компоненты, вызовы и маршрутизация остаются прежними.

**Выбирайте gt-next**, если хотите писать тексты прямо в JSX и получать переводы при каждой сборке. Опробуйте его на одном маршруте, где используются серверные и клиентские компоненты, формы множественного числа, форматированный текст и метаданные. Сохраняйте URL-адреса локалей этого маршрута и существующие переводы, пока не будет готова замена, и проверьте сборку для рабочей среды, прежде чем переносить другие маршруты.

Для начала следуйте руководству [Быстрый старт для Next.js App Router](/docs/react/nextjs-quickstart). Сравнение с другими библиотеками см. в статье [General Translation в сравнении с i18next, react-intl и next-intl](/kb/general-translation-vs-i18n-libraries).

## Часто задаваемые вопросы

### Переводит ли next-intl мой контент?

Нет. next-intl выполняет рендеринг и форматирование сообщений из ваших каталогов. Переводы выполняет ваша команда, переводчики или сторонний сервис, например [Crowdin](https://next-intl.dev/docs/workflows/localization-management). Кроме того, General Translation может переводить каталоги next-intl без миграции.

### Можно ли использовать General Translation вместе с next-intl?

Да. CLI `gt` переводит JSON-каталоги next-intl с сохранением синтаксиса сообщений next-intl, поэтому ваши компоненты и маршрутизация остаются без изменений. Подробнее см. в разделе [Генерация переводов](/docs/cli/guides/generating-translations).

### gt-next — бесплатная библиотека с открытым исходным кодом?

Да. gt-next распространяется под лицензией MIT и выполняет рендеринг переводов из бандла без учётной записи. О генерации переводов с помощью облачного сервиса General Translation читайте на странице [тарифов](https://generaltranslation.com/pricing).

### Поддерживает ли gt-next серверные компоненты React?

Да. В синхронных серверных компонентах используйте [`<T>`](/docs/react/reference/components/t) и [`useGT`](/docs/react/reference/hooks/use-gt), а в асинхронных — [`getGT`](/docs/react/nextjs/reference/functions/get-gt).

### Можно ли мигрировать с next-intl на gt-next постепенно, по одному маршруту за раз?

Да. В [руководстве по миграции](/docs/react/guides/migrating-i18n-libraries) описано, как использовать обе библиотеки параллельно, импортировать существующие переводы и сохранить словари с ключами там, где они вам удобнее.

## Ключевые выводы

* next-intl и gt-next поддерживают App Router, серверные компоненты и маршрутизацию по локалям, и обе библиотеки распространяются под лицензией MIT.
* next-intl выполняет рендеринг переводов, которые вы предоставляете. gt-next тоже выполняет их рендеринг, но General Translation ещё и генерирует их из встроенного JSX, используя ваш код как контекст.
* Чтобы пользоваться General Translation, мигрировать не обязательно: CLI `gt` переводит существующие каталоги next-intl.
* Если вы всё же решите мигрировать, переносите маршруты по одному и не отключайте загрузку существующих переводов, пока для них не будет готова замена.
