Tolgee — это платформа локализации с открытым исходным кодом: вы назначаете каждой строке ключ, синхронизируете ключи с проектом Tolgee через его CLI или SDK, переводите их там с помощью машинного перевода, ИИ и своей команды, а затем загружаете результаты обратно в приложение в виде файлов или из CDN Tolgee. Платформу можно развернуть самостоятельно из образа Docker или использовать Tolgee Cloud. Её главная особенность — редактирование в контексте: зажмите ALT и щёлкните по любому тексту в запущенном приложении, чтобы перевести его. Однако весь цикл работы с ключами вокруг этого редактора Tolgee оставляет на инженерах. General Translation, напротив, отталкивается от кода: контент остаётся в ваших компонентах, а перевод выполняется в рамках сборки.

## Сильные стороны Tolgee

* **Открытый исходный код и возможность самостоятельного хостинга.** Ядро платформы распространяется под лицензией [Apache 2.0](https://tolgee.io/licencing), а функции из каталога `ee` (например, SSO, детальные разрешения, глоссарии, задачи, ветвление и вебхуки) подпадают под лицензию Tolgee EE и требуют лицензионного ключа. [Бесплатная версия для самостоятельного хостинга](https://tolgee.io/pricing/self-hosted) включает основные функции, неограниченное число ключей, до 10 пользовательских мест и машинный перевод с вашими собственными ключами провайдеров.
* **Редактирование в контексте.** В режиме разработки зажмите ALT (Option на Mac) и щёлкните по строке в запущенном приложении, чтобы отредактировать её перевод. [Расширение Tolgee Tools](https://docs.tolgee.io/js-sdk/in-context) для Chrome и Firefox добавляет в то же диалоговое окно создание скриншотов и позволяет редактировать в контексте в рабочей среде.
* **SDK для множества стеков.** [JavaScript SDK](https://docs.tolgee.io/js-sdk) поддерживает React, Vue, Angular, Svelte и чистый JavaScript, а также включает интеграцию с i18next. SDK для [iOS](https://docs.tolgee.io/ios-sdk) и Android обновляют строки из CDN Tolgee без выпуска нового релиза приложения.
* **CLI, который читает ваш код.** `@tolgee/cli` [извлекает ключи и их значения по умолчанию](https://docs.tolgee.io/tolgee-cli/extraction/parsers) из кода на React, Vue, Svelte и Angular, а команды `push`, `pull`, `sync` и `compare` синхронизируют проект Tolgee с вашим репозиторием. CLI поддерживает импорт и экспорт множества форматов, включая XLIFF, ARB и Java properties.
* **ИИ с учётом контекста.** [Машинный перевод](https://docs.tolgee.io/platform/translation_process/machine_translation) выполняется через DeepL, Google, Amazon или Azure, а AI Translator использует модели Claude или OpenAI в Tolgee Cloud либо модели вашего собственного провайдера: OpenAI, Azure OpenAI, Anthropic, Gemini или любого OpenAI-совместимого. При переводе он учитывает скриншоты, описания ключей и проекта, память переводов и [связи между ключами, которые записывает SDK](https://docs.tolgee.io/platform/translation_process/ai_translator).
* **Варианты доставки.** [Content Delivery](https://docs.tolgee.io/platform/projects_and_organizations/content_delivery) публикует переводы в CDN Tolgee или в ваше собственное хранилище S3 или Azure, поэтому веб-приложение получает изменения без пересборки.

## Что Tolgee по-прежнему оставляет на долю ваших инженеров

В Tolgee каждая строка в UI — это ключ со значением по умолчанию:

```tsx title="src/Inbox.tsx"
import { T, useTranslate } from '@tolgee/react';

export function Inbox({ count }: { count: number }) {
  const { t } = useTranslate();
  return (
    <section>
      <h1>
        <T keyName="inbox_title" defaultValue="Inbox" />
      </h1>
      <p>
        {t('inbox_unread', '{count, plural, one {# unread message} other {# unread messages}}', { count })}
      </p>
    </section>
  );
}
```

Если запустить `npx @tolgee/cli extract print` для этого файла (CLI 2.21.0), команда найдёт оба ключа и их английские значения по умолчанию:

```text title="Output"
2 keys found in src/Inbox.tsx:
	line 8: inbox_title
		default: Inbox
	line 11: inbox_unread
		default: {count, plural, one {# unread message} other {# unread messages}}
```

Извлечение находит ключи, но чтобы новый текст появился на всех языках, по-прежнему приходится проходить один и тот же цикл:

1. Придумать ключ для каждой строки и указать английский текст как его значение по умолчанию.
2. Создать ключи в проекте Tolgee с помощью `tolgee push` или [`tolgee sync`](https://docs.tolgee.io/tolgee-cli/extraction/syncing-strings).
3. Перевести строки с помощью машинного перевода, AI Translator или своих переводчиков и проверить результат.
4. Выполнить [`tolgee pull`](https://docs.tolgee.io/tolgee-cli/push-pull-strings) и закоммитить файлы либо настроить Content Delivery и подключить к нему SDK, а затем добавить каждый новый язык в приложение.

Пока ключ не переведён, читатели видят резервный язык или английское значение по умолчанию. К тому же AI Translator опирается на скриншоты и описания, которые кто-то должен прикрепить, и на то, какие ключи отображаются вместе на экране, — но не на компонент, который выполняет рендеринг строки.

Стоимость Tolgee Cloud определяется в основном количеством размещённых слов, причём базовый язык и каждый перевод учитываются отдельно; объём кредитов на машинный перевод зависит от тарифа, а число мест на текущих тарифах не ограничено. Лицензии для self-hosted-развёртывания тарифицируются по количеству ключей и мест. (См. [цены Tolgee](https://tolgee.io/pricing), данные проверены в октябре 2026 г.)

## Почему команды выбирают General Translation, а не Tolgee

General Translation работает непосредственно с кодом, поэтому не нужно придумывать имена ключам и синхронизировать их. Компонент [`<T>`](/docs/react/reference/components/t) оборачивает сам контент. Вот тот же почтовый ящик на `gt-react` после [настройки провайдера](/docs/react/react-quickstart):

```tsx title="src/Inbox.tsx"
import { T, Plural, Num } from 'gt-react';

export function Inbox({ count }: { count: number }) {
  return (
    <T>
      <section>
        <h1>Inbox</h1>
        <p>
          <Plural
            n={count}
            singular={<><Num>{count}</Num> unread message</>}
            plural={<><Num>{count}</Num> unread messages</>}
          />
        </p>
      </section>
    </T>
  );
}
```

Заголовок и сообщение остаются рядом в исходном коде. [`npx gt translate`](/docs/cli/reference/commands/translate) генерирует переведённый блок, включая все формы множественного числа, которые нужны каждому целевому языку.

* **Быстрее.** [`npx gt translate`](/docs/cli/reference/commands/translate) запускается во время сборки, либо Locadex открывает пул-реквест при изменении кода, так что новый текст выходит уже переведённым в том же релизе, в котором он появился. Чтобы добавить язык, достаточно одной строки в `gt.config.json`, и следующая сборка переведёт на него весь проект.
* **Дешевле в эксплуатации.** Инженеры редактируют читаемый JSX, не придумывая ключ для каждого предложения и не поддерживая отдельный исходный словарь. Изменения текста и компоненты, которые его используют, проходят одно и то же рецензирование кода.
* **Выше качество.** В примере с почтовым ящиком заголовок, структура сообщения и ветви множественного числа отправляются вместе. Так у перевода больше контекста, чем у отдельного предложения. Glossary и пользовательские промпты задают продуктовую терминологию и тон через [контекстные группы](/docs/platform/dashboard/guides/defining-context-for-translations).
* **Ниже риски.** Проверяйте сгенерированный текст в [Редакторе переводов на панели управления](/docs/platform/dashboard/guides/reviewing-translations) и храните переводы в собственной сборке. JavaScript-библиотеки под лицензией MIT выполняют рендеринг этих файлов без аккаунта General Translation и без обращений к сервисам во время выполнения.

Ramp локализует свою панель управления, лендинг и iOS-приложение более чем на 11 локалей с помощью General Translation. (См. [развёртывания в рабочей среде](https://generaltranslation.com/enterprise).)

## Когда лучше выбрать Tolgee

Выбирайте Tolgee, если вам нужно развернуть всю платформу на собственных серверах, если переводчики или продакт-менеджеры хотят править текст, кликая по нему прямо в работающем приложении, если ваш фронтенд написан на Angular или Svelte, если вы обмениваетесь [файлами XLIFF, ARB или CSV](https://docs.tolgee.io/platform/supported_formats) или если нативным приложениям для iOS и Android нужны обновления строк по воздуху (OTA). Выбирайте General Translation, если большая часть текста вашего продукта находится в коде на React, Next.js или Vue и вы хотите, чтобы каждый релиз выходил сразу на всех языках без этапа синхронизации ключей.

## Переход с Tolgee на General Translation

Переносите функции по одной. Замените каждый `<T keyName="…" defaultValue="…" />` на компонент [`<T>`](/docs/react/reference/components/t) от General Translation, обернув им английский контент, а каждый вызов `t('key', 'default')` — на [`useGT`](/docs/react/reference/hooks/use-gt). Если ваша команда хочет сохранить ключи, поместите английские значения в словарь и считывайте их с помощью [`useTranslations`](/docs/react/reference/hooks/use-translations). Продолжайте загружать переводы Tolgee, пока все функции не будут перенесены. (См. [Миграция i18n-библиотек](/docs/react/guides/migrating-i18n-libraries).) Не забудьте перенести и глоссарий: в контекстную группу можно импортировать файлы CSV, TSV, JSON и текстовые файлы. (См. [Определение контекста для переводов](/docs/platform/dashboard/guides/defining-context-for-translations).)

## Может ли General Translation заменить Tolgee?

Да, если основная часть текста вашего продукта находится в коде на React, Next.js или Vue. General Translation переводит этот контент во время сборки, и вам не нужно создавать и синхронизировать ключи. Tolgee по-прежнему лучше подходит, если вам нужно развернуть платформу на собственных серверах или вы хотите, чтобы переводчики редактировали текст прямо в работающем приложении.

## Главное

* Tolgee — платформа локализации с открытым исходным кодом, которую можно развернуть на собственных серверах. Она поддерживает редактирование в контексте, предлагает SDK для множества стеков и использует ИИ, который учитывает скриншоты и описания.
* Её SDK и CLI связывают исходные сообщения с ключами с процессами перевода, проверки и доставки.
* Благодаря встроенному написанию текстов в General Translation больше не нужно поддерживать ключи сообщений: исходный текст остаётся читаемым прямо в JSX, переводы создаются во время сборки, а проверить их можно в панели управления.
