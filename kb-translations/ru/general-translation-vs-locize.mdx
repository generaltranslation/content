Locize — это система управления переводами (TMS), созданная командой i18next. Ваше приложение по-прежнему использует i18next (или другую библиотеку интернационализации), Locize хранит ключи и их переводы, ИИ или ваши переводчики заполняют их для каждого языка, а приложение загружает результаты из CDN Locize. Благодаря этому исправленный перевод вступает в силу без повторного развёртывания. Locize дополняет вашу библиотеку интернационализации, а не заменяет её, поэтому настройка библиотеки, ключи и их интеграция в код остаются заботой ваших инженеров. General Translation может взять на себя и то и другое: предоставить собственные библиотеки интернационализации с открытым исходным кодом вместе с переводом — или только переводить уже имеющиеся у вас файлы i18next.

## Сильные стороны Locize

* **Создан для i18next.** [`i18next-locize-backend`](https://github.com/locize/i18next-locize-backend) загружает переводы из CDN Locize, а с опцией i18next `saveMissing` отправляет новые ключи в Locize прямо в процессе разработки. [`i18next-cli`](https://github.com/i18next/i18next-cli) включает команды Locize для синхронизации, загрузки и миграции, а его команда `localize` за один запуск оборачивает жёстко заданные строки в `t()`, извлекает ключи, подключает проект Locize и запрашивает перевод с помощью ИИ.
* **Обновления без повторного развёртывания.** Переводы публикуются в CDN (Standard CDN доступен на всех тарифах, Pro CDN — начиная с тарифа Growth). [Длительность кеширования настраивается для каждой версии](https://www.locize.com/docs/integration/cdn-types-standard-vs-pro), также доступна приватная публикация с доступом только по API-ключу.
* **Версии.** У проекта есть рабочая версия `latest`, версия `production` и любые пользовательские версии — например, `staging` или отдельная версия для каждого релиза мобильного приложения. Благодаря этому продвигать или откатывать переводы можно независимо от кода. (См. [управление версиями в Locize](https://www.locize.com/docs/versioning).)
* **Редактирование в контексте.** [Пакет `locize`](https://github.com/locize/locize) добавляет на сайт всплывающее окно редактора, если URL содержит `?incontext=true`, а скриншоты сопоставляются с ключами с помощью распознавания текста.
* **ИИ и машинный перевод.** Перевод выполняет [собственный ИИ-сервис Locize](https://www.locize.com/ai) или ваш ключ OpenAI, Gemini, Mistral либо DeepL — с учётом вашего руководства по стилю, глоссария и памяти переводов. Доступны оценка качества, ИИ-проверка и рабочий процесс проверки человеком.
* **Ключи форм множественного числа для каждого языка.** Для JSON-файлов i18next Locize [генерирует ключи форм множественного числа](https://www.locize.com/docs/integration/i18n-formats/pluralization), необходимые каждому целевому языку (например, `_few` и `_many` для польского), и показывает все формы в своём редакторе.
* **Не только i18next.** [`locize-cli`](https://github.com/locize/locize-cli) импортирует и экспортирует различные форматы, в том числе XLIFF, Android XML, Apple `.strings`, PO, RESX, Fluent и Java properties, а Locize публикует примеры для react-intl, vue-i18n и Lingui. Также доступны GitHub Action, MCP-сервер и плагин для Figma.

## Что Locize по-прежнему перекладывает на ваших инженеров

Вот как работает `saveMissing` в `i18next` 26.4.7 и `i18next-locize-backend` 10.0.3 при рендеринге испанской версии для ключа, которого Locize ещё не видел. Функция запроса подменяет серверы Locize и логирует каждый вызов:

```js title="test.mjs"
import i18next from 'i18next';
import Backend from 'i18next-locize-backend';

// Имитация CDN: пока что и в английском, и в испанском есть по одному ключу.
const cdn = {
  en: { inbox: { title: 'Inbox' } },
  es: { inbox: { title: 'Bandeja de entrada' } },
};

await i18next.use(Backend).init({
  lng: 'es',
  fallbackLng: 'en',
  saveMissing: true,
  backend: {
    projectId: 'demo-project',
    apiKey: 'demo-write-key', // ключ записи: только для разработки
    referenceLng: 'en',
    allowedAddOrUpdateHosts: () => true,
    reloadInterval: false,
    request: async ({ url, method, body }) => {
      console.log(method, url, body ? JSON.stringify(body) : '');
      const lng = url.match(/latest\/(\w+)\//)?.[1];
      return { status: 200, data: JSON.stringify(method === 'GET' ? cdn[lng] ?? {} : {}) };
    },
  },
});

// Новый текст в коде с английским значением по умолчанию
console.log(i18next.t('inbox.title'));
console.log(i18next.t('inbox.empty', 'No messages yet.'));
await new Promise((r) => setTimeout(r, 6000)); // saveMissing срабатывает с задержкой (debounce)
```

```text title="Output"
GET https://api.lite.locize.app/demo-project/latest/es/translation
GET https://api.lite.locize.app/demo-project/latest/en/translation
Bandeja de entrada
No messages yet.
POST https://api.lite.locize.app/missing/demo-project/latest/en/translation {"inbox.empty":"No messages yet."}
```

Этот пример показывает, что именно регистрирует `saveMissing`: английский ключ и его значение. Перевод и публикация выполняются уже после регистрации. Интеграция с Locize связывает эти шаги воедино:

1. Настройте i18next, задайте ключ для каждой строки и вызывайте с ним `t()`.
2. Отправляйте новые ключи в Locize с помощью `saveMissing` в среде разработки (по умолчанию эта функция работает только на `localhost`, а [ключ записи ни в коем случае не должен попасть в продакшен-сборку](https://www.locize.com/docs/guides/going-to-production)) или с помощью команды синхронизации в CI.
3. Переведите строки с помощью ИИ или своих переводчиков, проверьте результаты и опубликуйте их в той версии, из которой читает данные ваше приложение.
4. Загружайте переводы из CDN во время выполнения или скачивайте их в сборку, а каждый новый язык регистрируйте в приложении.

Переводчик или ИИ получает в качестве контекста ключ, его английское значение, заметку с контекстом (если она есть) и [привязанные к ключу скриншоты](https://www.locize.com/docs/context), но не компонент, который рендерит строку.

Тарифы Locize предусматривают ежемесячную базовую плату, в которую входят слова, загрузки из CDN, языки, пространства имён и версии. На более крупных тарифах можно докупать пакеты слов и загрузок, а ИИ и машинный перевод оплачиваются по токенам или символам. (См. [цены Locize](https://www.locize.com/pricing), данные проверены в октябре 2026 г.)

## General Translation для команд, использующих i18next

Чтобы попробовать General Translation, ничего переписывать не придётся. CLI находит `i18next` в вашем `package.json` и переводит JSON-файлы, сохраняя синтаксис интерполяции i18next (или синтаксис ICU, если вы используете `i18next-icu`):

```json title="gt.config.json"
{
  "defaultLocale": "en",
  "locales": [
    "es"
  ],
  "files": {
    "json": {
      "include": [
        "locales/[locale]/*.json"
      ]
    }
  }
}
```

[`npx gt translate --dry-run`](/docs/cli/reference/commands/translate) находит `locales/en/translation.json`, а [`npx gt translate`](/docs/cli/reference/commands/translate) записывает `locales/es/translation.json`. Этот рабочий процесс на основе файлов подходит для сообщений, у которых структура ключей в исходном и целевом файлах совпадает. С помощью сопутствующего файла метаданных к любому ключу можно привязать заметку `context` или ограничение `maxChars`. Подробнее см. в разделе [Метаданные, привязанные к ключам](/docs/cli/reference/keyed-metadata).

Можно пойти дальше и использовать General Translation ещё и в качестве библиотеки. [`<T>`](/docs/react/reference/components/t) оборачивает JSX и переводит его на месте, а [`useGT`](/docs/react/reference/hooks/use-gt) отвечает за строки, так что придумывать имена ключей не придётся. Для команд, которым нужен словарь с ключами, есть [`useTranslations`](/docs/react/reference/hooks/use-translations). `gt-next`, `gt-react` и `gt-vue` распространяются по лицензии MIT, не используют i18next под капотом и работают без аккаунта General Translation.

## Locize и General Translation: краткое сравнение

| Возможность                  | Locize                                                                                                           | General Translation                                                                                                                             |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Что это                      | TMS, которая работает в связке с i18next или другой библиотекой интернационализации                              | Библиотеки интернационализации с открытым исходным кодом и ИИ-перевод либо перевод ваших существующих файлов                                    |
| Где хранятся строки          | Ключи — в коде, значения — в Locize                                                                              | В коде внутри [`<T>`](/docs/react/reference/components/t) или в уже имеющихся у вас файлах ресурсов                                             |
| Как добавляются новые тексты | `saveMissing` при разработке или команды синхронизации в CI                                                      | [`npx gt translate`](/docs/cli/reference/commands/translate) при сборке или пул-реквесты [Locadex](/docs/platform/locadex/quickstart)           |
| Кто переводит                | ИИ Locize, ваш собственный ключ для ИИ или машинного перевода либо ваши переводчики                              | ИИ с учетом контекста из вашего кода, Glossary и пользовательских промптов; ваша команда проверяет результат в панели управления                |
| Контекст для каждой строки   | Ключ, значение на английском, контекстные заметки, скриншоты, глоссарий и руководство по стилю                   | Размеченная структура JSX во встроенных библиотеках; метаданные, привязанные к ключам, для каталогов; общие Glossary и пользовательские промпты |
| Доставка                     | По умолчанию через CDN с поддержкой версий либо загрузка в сборку                                                | Файлы в бандле или опубликованные обновления через CDN General Translation без повторного развертывания приложения                              |
| Цены                         | Тарифные планы с лимитами на слова, загрузки из CDN, языки и версии; ИИ и машинный перевод оплачиваются отдельно | [Оплата перевода по факту использования](https://generaltranslation.com/pricing)                                                                |

## Почему команды выбирают General Translation вместо Locize

General Translation позволяет команде, работающей с i18next, сначала перейти на автоматическую генерацию переводов и их проверку в панели управления, а затем — на встроенные тексты, если она захочет избавиться ещё и от сопровождения ключей.

* **Быстрее.** Запускайте перевод перед сборкой, чтобы новые тексты сразу выходили на всех поддерживаемых языках. CLI повторно использует готовые переводы и переводит только новый или изменённый контент, а чтобы добавить язык, достаточно одной строки в `gt.config.json`.
* **Дешевле в эксплуатации.** Начните с файлов i18next, которые у вас уже есть. Перевод функциональности на [`<T>`](/docs/react/reference/components/t) избавляет от необходимости придумывать имена ключей и синхронизировать исходный словарь с компонентами.
* **Выше качество.** Добавьте контекстную заметку к ключу каталога или используйте встроенные блоки [`<T>`](/docs/react/reference/components/t), чтобы передавать в перевод JSX-структуру предложения и ветви множественного числа. Общая [контекстная группа](/docs/platform/dashboard/guides/defining-context-for-translations) обеспечивает единую продуктовую терминологию в проектах приложения и документации, а рецензенты правят результаты в панели управления.
* **Ниже риски.** Сохраняйте i18next и проверенные переводы, пока оцениваете General Translation. Файлы перевода, включённые в бандл, не обращаются к General Translation во время выполнения, а JavaScript-библиотеки General Translation под лицензией MIT работают и без аккаунта, если вы предоставляете переводы самостоятельно.

С помощью General Translation Cursor поддерживает более 14 локалей в веб-приложении и документации. (См. [развёртывания в рабочей среде](https://generaltranslation.com/enterprise).)

## Когда Locize подходит лучше

Выбирайте Locize, если переводчикам нужно редактировать тексты прямо на работающем сайте, если вы храните отдельные версии переводов для каждого релиза мобильного приложения или если вы обмениваетесь файлами XLIFF, Fluent или Java properties. Выбирайте встроенные библиотеки General Translation, если хотите, чтобы исходный текст в компонентах оставался читаемым, а размеченная структура JSX учитывалась при переводе. Чтобы оценить перевод и проверку в панели управления до смены библиотек, попробуйте CLI General Translation с уже существующими каталогами.

## Переход с Locize на General Translation

Скачайте текущие переводы с помощью `locize-cli` и сохраните их в своём репозитории, затем укажите в `gt.config.json` путь к файлам на английском языке и выполните [`npx gt upload`](/docs/cli/reference/commands/upload), чтобы загрузить исходные тексты и существующие переводы на платформу. Дальше можно либо продолжать использовать i18next, поручив CLI переводить новые ключи, либо переходить на [`<T>`](/docs/react/reference/components/t) постепенно, по одной функции за раз. (См. [Миграция с других библиотек интернационализации](/docs/react/guides/migrating-i18n-libraries).) Термины Glossary тоже можно перенести: при импорте в контекстную группу поддерживаются файлы CSV, TSV, JSON и обычные текстовые файлы.

## Ключевые выводы

* Locize от создателей i18next — мощная TMS для приложений на i18next: доставка через CDN, `saveMissing`, версии, редактирование в контексте и ИИ-перевод.
* Она работает в связке с вашей библиотекой интернационализации и её каталогами с ключами; перевод, проверка и публикация выстраиваются вокруг этих каталогов.
* General Translation может перевести уже имеющиеся у вас файлы i18next или взять на себя роль и библиотеки интернационализации, и инструмента перевода — с учётом контекста кода и поддержкой всех языков в каждом релизе.
