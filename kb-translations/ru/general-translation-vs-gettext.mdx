GNU gettext — это набор инструментов, на котором до сих пор держится большая часть перевода программного обеспечения. Вы оборачиваете видимые пользователю строки в `_()` или `gettext()`, `xgettext` извлекает их в шаблон POT, `msginit` создаёт PO-файл для каждого языка, `msgmerge` обновляет эти файлы при изменении источника, а `msgfmt` компилирует их в файлы `.mo`, которые программа загружает во время выполнения. Этот формат используют программы на C, расширение gettext в PHP, модуль `gettext` в Python, WordPress, Django и Babel. А вот основную часть перевода gettext оставляет вам: начиная с версии 1.0 он умеет готовить черновики записей с помощью локальной LLM, но каждый `msgstr` в каждом PO-файле всё равно доводите до ума вы, ваши переводчики или сторонний сервис. General Translation не заменяет ни один из инструментов этого набора: его CLI генерирует PO-файлы из вашего шаблона, а остальная настройка gettext остаётся прежней.

## Сильные стороны gettext

* **Исходный текст служит ключом.** В коде пишется `_("Inbox")`, а не имя ключа, а для строки без перевода [подставляется исходный текст](https://www.gnu.org/software/gettext/manual/html_node/Interface-to-gettext.html) вместо ошибки.
* **Правила множественного числа для каждого языка.** Каждый PO-файл содержит [заголовок `Plural-Forms` с правилом для своего языка](https://www.gnu.org/software/gettext/manual/html_node/Plural-forms.html), и `msginit` заполняет его автоматически. Для польского задаётся правило с тремя формами, а у каждой записи с множественным числом — три слота `msgstr[n]`.
* **Контекст хранится вместе со строкой.** `msgctxt` (из `pgettext`) [позволяет различать «Archive» как глагол и «Archive» как существительное](https://www.gnu.org/software/gettext/manual/html_node/Contexts.html), комментарии `#.` передают заметки переводчикам (`xgettext --add-comments`), строки `#:` указывают на место в исходном коде, а флаги вроде `python-format` позволяют `msgfmt --check` отклонить перевод, в котором сломана подсказка.
* **Безопасные обновления.** `msgmerge` [сохраняет существующие переводы при изменении шаблона](https://www.gnu.org/software/gettext/manual/html_node/msgmerge-Invocation.html) и помечает записи с изменившимся исходным текстом как fuzzy, сохраняя прежний вариант для сравнения (`--previous`).
* **Черновики от локальной LLM.** Начиная с версии 1.0, [`msgpre` и `spit` выполняют предварительный перевод PO-файлов](https://www.gnu.org/software/gettext/manual/html_node/Pretranslating.html) с помощью локально установленной LLM через ollama — переводчик получает готовую основу для проверки.
* **Повсеместная поддержка.** Формат PO читают и записывают PO-редакторы вроде Poedit и большинство систем управления переводами (TMS), а сами инструменты — [свободное ПО](https://www.gnu.org/software/gettext/manual/html_node/Licenses.html) (GPL; библиотека среды выполнения распространяется под LGPL).

## Что gettext перекладывает на вас

Вот небольшой скрипт на Python, использующий модуль `gettext` из стандартной библиотеки:

```python title="inbox.py"
import gettext, sys

lang = sys.argv[1]
count = int(sys.argv[2])
t = gettext.translation("inbox", localedir="locale", languages=[lang], fallback=True)
_ = t.gettext

# TRANSLATORS: заголовок страницы «Входящие»
print(_("Inbox"))
print(t.ngettext("You have %d unread message.", "You have %d unread messages.", count) % count)
print(t.pgettext("email verb", "Archive"))
```

Рабочий процесс gettext в [GNU gettext 1.0](https://lists.gnu.org/archive/html/info-gnu/2026-01/msg00007.html):

```bash
xgettext --language=Python --keyword=pgettext:1c,2 --add-comments=TRANSLATORS -o po/inbox.pot inbox.py
msginit --no-translator --locale=pl_PL.UTF-8 -i po/inbox.pot -o po/pl.po
# кто-нибудь заполняет все msgstr в po/pl.po
msgfmt --check -o locale/pl/LC_MESSAGES/inbox.mo po/pl.po
```

Когда польский файл заполнен, `python3 inbox.py pl 5` выводит «Masz 5 nieprzeczytanych wiadomości.» Затем кто-то меняет в коде «unread message» на «new message». `xgettext` и `msgmerge --update --previous` переносят старый польский перевод и помечают его как fuzzy, поскольку теперь это перевод уже другого текста:

```text title="po/pl.po"
#: inbox.py:10
#, fuzzy, python-format
#| msgid "You have %d unread message."
#| msgid_plural "You have %d unread messages."
msgid "You have %d new message."
msgid_plural "You have %d new messages."
msgstr[0] "Masz %d nieprzeczytaną wiadomość."
msgstr[1] "Masz %d nieprzeczytane wiadomości."
msgstr[2] "Masz %d nieprzeczytanych wiadomości."
```

`msgfmt` [пропускает нечёткие (fuzzy) записи](https://www.gnu.org/software/gettext/manual/html_node/msgfmt-Invocation.html) (и сообщает &quot;2 translated messages, 1 fuzzy translation&quot;), поэтому та же команда теперь выводит &quot;You have 5 new messages.&quot; по-английски прямо посреди польского интерфейса. В старом польском переводе по-прежнему стоит «непрочитанных», так что перевод нужно обновить. General Translation может сгенерировать обновлённый перевод из нового шаблона в рамках вашей сборки.

## Перевод каталогов gettext с помощью General Translation

CLI General Translation считывает ваш POT-шаблон, переводит каждую запись и создаёт PO-файл для каждого целевого языка. Укажите в `gt.config.json` путь к шаблону и задайте, куда сохранять файл для каждого языка. Эта конфигурация проверена на `gt` версии 2.26.5:

```json title="gt.config.json"
{
  "defaultLocale": "en",
  "locales": ["de", "pl", "pt_BR"],
  "customMapping": {
    "pt_BR": { "code": "pt-BR" }
  },
  "files": {
    "pot": {
      "include": ["po/inbox.pot"],
      "transform": {
        "match": "^po/inbox\\.pot$",
        "replace": "po/{locale}.po"
      },
      "transformationFormat": "PO"
    }
  }
}
```

* **`pot` читает файлы PO и POT**, а `"transformationFormat": "PO"` указывает, что на выходе должны получаться переведённые файлы `.po`. (См. [справочник по формату PO / POT](/docs/cli/reference/formats/po-pot-files).)
* **`transform` задаёт имена выходных файлов.** `{locale}` подставляет локаль ровно в том виде, в каком она указана в `locales`, поэтому получаются файлы `po/pl.po` и `po/pt_BR.po`. (См. [`transform`](/docs/cli/reference/config#files).)
* **Сохраняйте имена локалей gettext.** [`customMapping`](/docs/cli/reference/config#custom-mapping) сопоставляет `pt_BR` со стандартным кодом локали `pt-BR`. Тот же паттерн подходит и для других структур, например для файлов `languages/my-plugin.pot` и `languages/my-plugin-de_DE.po` в плагине WordPress.

После настройки CLI (см. [Быстрый старт CLI](/docs/cli/quickstart)) рабочий процесс выглядит так:

```bash
xgettext --language=Python --keyword=pgettext:1c,2 --add-comments=TRANSLATORS -o po/inbox.pot inbox.py
msgconv --to-code=UTF-8 -o po/inbox.pot po/inbox.pot
npx gt translate
msgfmt --check -o locale/pl/LC_MESSAGES/inbox.mo po/pl.po
```

`xgettext` оставляет `charset=CHARSET` в качестве подсказки в заголовке шаблона, а `msgconv` подставляет вместо него UTF-8 — так же, как это сделал бы `msginit` для языкового файла. [`npx gt translate`](/docs/cli/reference/commands/translate) отправляет каждую запись вместе со всем, что о ней известно из PO-файла, в качестве контекста: `msgctxt`, комментарии для переводчиков `#.`, ссылки `#:` и флаги формата. Для записи с формами множественного числа General Translation прописывает заголовок `Plural-Forms` целевого языка и заполняет все слоты `msgstr[n]`, которые требует этот заголовок (три для польского, шесть для арабского), а также проверяет, что подсказки вроде `%d` сохраняются без изменений.

Если `msgid` меняется, при следующем запуске General Translation генерирует перевод нового текста; для неизменённых записей используются прежние переводы. Перед первым запуском генерации импортируйте существующие PO-переводы с помощью [`npx gt upload`](/docs/cli/reference/commands/upload). Если позже вы вносите правки в локальном PO-редакторе, сохраните их на платформе командой [`npx gt save-local`](/docs/cli/reference/commands/save-local) перед повторной генерацией.

Но General Translation не ограничивается заполнением `msgstr` — вы получаете весь остальной стек. Glossary и пользовательские промпты в [контекстной группе](/docs/platform/dashboard/guides/defining-context-for-translations) обеспечивают единообразие терминологии и тона во всех ваших PO-файлах и в любой другой области взаимодействия с пользователем, которую вы переводите; рецензенты могут [проверять и редактировать](/docs/platform/dashboard/guides/reviewing-translations) каждую запись PO с учётом форм множественного числа целевого языка в панели управления, а CLI работает в CI, так что каждый релиз выходит с актуальными каталогами.

Запускайте CLI для Node.js в процессе сборки, а затем компилируйте полученные PO-файлы с помощью `msgfmt`. Приложение, как и прежде, загружает скомпилированные переводы локально.

## Когда что использовать

Используйте только gettext, если ваши PO-файлы уже заполняют переводчики или TMS, если каждый перевод до релиза должен писать человек или если в вашей сборке нельзя запустить Node.js. Подключайте General Translation, если хотите, чтобы каждый PO-файл переводился на все языки сразу после изменения шаблона — с заполненными формами множественного числа и единообразной терминологией — и без ожидания очередного раунда перевода.

Мигрировать ничего не нужно: General Translation сохраняет ваши вызовы `_()`, шаблон, PO-файлы и среду выполнения. Он заменяет ручной шаг между `msgmerge` и `msgfmt`. (О настройке для конкретных фреймворков читайте в статьях [General Translation и фреймворк перевода Django](/kb/general-translation-vs-django-i18n) и [General Translation, Babel и Flask-Babel](/kb/general-translation-vs-flask-babel).)

## Ключевые выводы

* GNU gettext извлекает, объединяет, компилирует и находит переводы, а начиная с версии 1.0 умеет готовить их черновики с помощью локальной LLM, но не доводит перевод до конца. Новые и изменённые строки отображаются на языке-источнике, пока кто-нибудь их не переведёт или не проверит.
* CLI General Translation переводит шаблон POT в отдельный PO-файл для каждого языка. Для этого используются ключ `pot`, `"transformationFormat": "PO"`, `transform` для задания пути к выходным файлам и `customMapping` для имён вроде `pt_BR`.
* Для каждой записи с формами множественного числа General Translation прописывает заголовок `Plural-Forms` целевого языка и заполняет все слоты `msgstr[n]`, используя `msgctxt` и комментарии для переводчиков в качестве контекста. `msgfmt` и ваша среда выполнения gettext остаются на месте.
