Во время работы приложения библиотека интернационализации (i18n) решает две задачи: выбирает сообщение для локали пользователя и форматирует под эту локаль формы множественного числа, даты и числа. Библиотеки с открытым исходным кодом, такие как i18next, react-intl, next-intl, Lingui и vue-i18n, справляются с обеими, но ни одна из них не переводит ваш контент. Эта работа ложится на вас и выполняется ещё до запуска приложения: нужно перенести каждую строку в файл каталога — по ключу или путём извлечения встроенных сообщений, — перевести все каталоги и поддерживать их в актуальном состоянии по мере изменения интерфейса. Библиотеки General Translation решают те же задачи во время работы приложения, а General Translation вдобавок берёт на себя перевод: тексты остаются встроенными в ваши компоненты, а переводы генерируются на этапе сборки.

## Сильные стороны популярных библиотек

Все эти библиотеки зрелые, бесплатные и широко используются, но у каждой свои сильные стороны:

* **i18next** — самая скачиваемая. Она работает в любой среде JavaScript, а официальный `i18next-cli` извлекает ключи из вашего кода и генерирует для них типы TypeScript.
* **react-intl** (FormatJS) построена на ICU MessageFormat — стандартном синтаксисе для форм множественного числа и выбора вариантов. В её документации рекомендуется писать каждый `defaultMessage` прямо в коде вместе с `description` для переводчиков, а затем собирать их в каталог с помощью `formatjs extract`.
* **next-intl** создана для Next.js App Router. Переводы работают в серверных компонентах, сообщения, которые используются только в серверных компонентах, можно не отправлять на клиент, а ключи сообщений поддерживают проверку типов. API для встроенных сообщений, появившийся в версии 4.5, пока помечен как экспериментальный.
* **Lingui** позволяет хранить исходный текст прямо в коде с помощью макросов вроде `<Trans>`, сама генерирует ID сообщений и извлекает сообщения в каталоги PO.
* **vue-i18n** — плагин i18n для Vue 3; сообщения хранятся в JSON, YAML или в блоках `<i18n>` внутри однофайловых компонентов.

Все они хранят переводы в форматах каталогов, таких как JSON и PO, с которыми уже работают переводчики и системы управления переводами (TMS).

## Что остаётся на вашей стороне

Ни одна из этих библиотек сама ничего не переводит. Переводы делаете вы, ваши переводчики или сторонний сервис — например, Locize от команды i18next или TMS вроде Crowdin. Вот небольшой компонент «Входящие» на react-i18next:

```json title="locales/en/translation.json"
{
  "inbox": {
    "title": "Inbox",
    "unread_one": "You have {{count}} unread message.",
    "unread_other": "You have {{count}} unread messages."
  }
}
```

```tsx title="Inbox.tsx"
import { useTranslation } from 'react-i18next';

export function Inbox({ count }: { count: number }) {
  const { t } = useTranslation();
  return (
    <section>
      <h1>{t('inbox.title')}</h1>
      <p>{t('inbox.unread', { count })}</p>
    </section>
  );
}
```

Затем для каждого другого языка нужен отдельный файл, например `locales/es/translation.json`, который пишут вручную или отдают на перевод. Кроме того, формы множественного числа каждого языка должны быть оформлены в его файле отдельными ключами: в японском языке такая форма одна, в польском — четыре, а в арабском — шесть (`_zero`, `_one`, `_two`, `_few`, `_many` и `_other`). Строка, добавленная в компонент, отсутствует во всех остальных файлах, пока кто-нибудь её туда не внесёт, а переводчик каталога видит `inbox.unread_other` и предложение, но не экран, на котором оно отображается.

## General Translation делает то же самое — и генерирует переводы

Библиотеки General Translation решают те же задачи, что i18next, react-intl и next-intl. Они выбирают нужные сообщения для каждой локали, применяют её правила множественного числа и форматируют числа, денежные суммы и даты с помощью [`<Num>`](/docs/react/reference/components/num), [`<Currency>`](/docs/react/reference/components/currency) и [`<DateTime>`](/docs/react/reference/components/datetime). Они поддерживают переменные в стиле ICU в строках [`useGT`](/docs/react/reference/hooks/use-gt), словари с ключами через [`useTranslations`](/docs/react/reference/hooks/use-translations) для команд, которые предпочитают работать с ключами, а в `gt-next` — отдельный URL для каждой локали. Но General Translation умеет и то, чего не умеют другие библиотеки: генерирует переводы.

Вот тот же почтовый ящик на `gt-react`. Текст остаётся в компоненте, [`<T>`](/docs/react/reference/components/t) помечает JSX для перевода, а [`<Plural>`](/docs/react/reference/components/plural) содержит формы на английском:

```tsx title="Inbox.tsx"
import { T, Plural, Num } from 'gt-react';

export function Inbox({ count }: { count: number }) {
  return (
    <T>
      <section>
        <h1>Inbox</h1>
        <Plural
          n={count}
          one={<p>You have <Num>{count}</Num> unread message.</p>}
          other={<p>You have <Num>{count}</Num> unread messages.</p>}
        />
      </section>
    </T>
  );
}
```

Если перед сборкой запустить [`npx gt translate`](/docs/cli/reference/commands/translate), каждый блок [`<T>`](/docs/react/reference/components/t) вместе со структурой его элементов отправляется в API General Translation, и для каждой целевой локали записывается перевод. Вы пишете только те формы множественного числа, которые есть в английском, а при переводе генерируются формы, нужные каждому целевому языку, например польские `few` и `many`. Затем [`<Plural>`](/docs/react/reference/components/plural) выбирает переведённую ветку по правилам множественного числа локали читателя. [`<Num>`](/docs/react/reference/components/num) форматирует число для локали читателя при рендеринге, а значение, обёрнутое в [`<Var>`](/docs/react/reference/components/var), никогда не отправляется в API. Если вы измените предложение, при следующем запуске оно будет переведено заново; если удалите компонент, вместе с ним удалятся и его переводы.

Библиотеки General Translation поддерживают Next.js (`gt-next`), React (`gt-react`), Vue 3 (`gt-vue`) и Node.js (`gt-node`); кроме того, есть экспериментальные библиотеки для React Native, TanStack Start и Python-фреймворков Flask и FastAPI. Они распространяются по лицензии MIT и работают без аккаунта General Translation: переводы можно загружать из любого источника, а для команд, которые переводят вручную, [`gt generate`](/docs/cli/reference/commands/generate) создаёт файлы шаблонов. В основе `gt-react` и `gt-next` нет сторонней библиотеки интернационализации: разбор и форматирование сообщений ICU реализованы в собственных пакетах General Translation. По умолчанию переводы поставляются в виде файлов в составе сборки, но их также можно загружать из CDN General Translation.

| [Lingui](/kb/general-translation-vs-lingui)                      | Встроенные макросы, извлекаемые в PO-каталоги                                                                         | Нет                    | Вы, переводчики или TMS вроде Crowdin                                                                                                        | ICU MessageFormat                                                                                                                    |
| [`vue-i18n`](/kb/general-translation-vs-vue-i18n)                | Ключи в объектах сообщений для каждой локали                                                                          | Нет                    | Вы, переводчики или TMS                                                                                                                      | Формы через вертикальную черту; в версии 11 для языков вроде польского нужно собственное правило                                     |
| General Translation (`gt-react`, `gt-next`, `gt-vue`)            | JSX внутри [`<T>`](/docs/react/reference/components/t) или строки через [`useGT`](/docs/react/reference/hooks/use-gt) | Да                     | Генерируются командой [`npx gt translate`](/docs/cli/reference/commands/translate) с учётом контекста вашего кода или пишутся вашей командой | Ветки [`<Plural>`](/docs/react/reference/components/plural); при переводе генерируются все формы, необходимые каждому целевому языку |

Оставайтесь на i18next, react-intl, next-intl, Lingui или vue-i18n, если ваши каталоги и процесс перевода уже отлажены, если переводчики или TMS работают с файлами каталогов или если ваш фреймворк не поддерживается библиотеками General Translation. Выбирайте библиотеки General Translation, если хотите, чтобы тексты оставались читаемыми прямо в компонентах, переводы генерировались с учётом контекста вашего кода, а все языки обновлялись с каждой сборкой, не дожидаясь очередного раунда перевода.

## Сохраните текущую библиотеку или мигрируйте постепенно, по одному маршруту

Переходить на другую библиотеку не обязательно. CLI `gt` определяет `next-intl` или `i18next` по вашему `package.json` и переводит JSON-файлы этой библиотеки, сохраняя её синтаксис сообщений. Это работает и для проектов на `react-i18next` и `next-i18next`, если `i18next` указан как прямая зависимость. Укажите в `gt.config.json` пути к вашим каталогам:

```json title="gt.config.json"
{
  "defaultLocale": "en",
  "locales": ["es", "fr", "ja"],
  "files": {
    "json": {
      "include": ["locales/[locale]/*.json"]
    }
  }
}
```

Чтобы передать ключу контекст, который не может выразить его текст, добавьте сопутствующий файл, например `locales/en/translation.metadata.json`, с записью `context` или `maxChars` для этого ключа. (См. [Метаданные, привязанные к ключам](/docs/cli/reference/keyed-metadata) и [Генерация переводов](/docs/cli/guides/generating-translations).)

Чтобы перейти на [`<T>`](/docs/react/reference/components/t), воспользуйтесь руководством [Миграция с i18n-библиотек](/docs/react/guides/migrating-i18n-libraries). В нём описаны три пути: заменить поиск по ключу встроенным текстом, сохранить словари и вызывать [`useTranslations`](/docs/react/reference/hooks/use-translations) либо временно использовать обе библиотеки и переносить маршруты по одному.

General Translation доверяют лучшие команды разработчиков в мире, в том числе в Cursor, Ramp, Profound, Cognition, Sierra и ClickHouse. Чтобы попробовать его в своём приложении, начните с руководства [Быстрый старт Next.js](/docs/react/nextjs-quickstart), [Быстрый старт React](/docs/react/react-quickstart) или [Быстрый старт Vue](/docs/vue/quickstart).

## Ключевые выводы

* i18next, react-intl, next-intl и другие open-source-библиотеки для i18n ничего не переводят. Они лишь выполняют рендеринг и форматирование переводов, которые вы сами создаёте и поддерживаете в актуальном состоянии.
* Библиотеки General Translation выполняют ту же работу по рендерингу и форматированию и тоже распространяются с открытым исходным кодом под лицензией MIT, но General Translation ещё и переводит — прямо из текста, встроенного в [`<T>`](/docs/react/reference/components/t), так что ключи и каталоги не нужно держать в синхронизации.
* Можно оставить i18next или next-intl и переводить их JSON-файлы с помощью CLI `gt` либо мигрировать постепенно, по одному маршруту за раз.
