vue-i18n отображает сообщения на языке пользователя в приложениях Vue. Вы определяете сообщения для каждой локали, обращаетесь к ним в шаблонах по ключу, а библиотека форматирует формы множественного числа, даты и числа. При этом сама она ничего не переводит: сообщения для всех языков предоставляете вы, ваши переводчики или система управления переводами (TMS). `gt-vue` от General Translation выполняет рендеринг переводов точно так же, но General Translation ещё и создаёт их из текста, который вы пишете прямо в шаблонах.

## Сильные стороны vue-i18n

* **Зрелость.** vue-i18n публикуется в npm с 2014 года. [Сейчас поддерживается ветка 11](https://vue-i18n.intlify.dev/guide/maintenance), а версия 12 находится в стадии альфа-тестирования.
* **Nuxt.** [Модуль `@nuxtjs/i18n` построен на vue-i18n 11](https://i18n.nuxtjs.org/docs/getting-started) и добавляет маршруты с префиксом локали, локализованные пути, определение языка браузера, ленивую загрузку переводов и SEO-теги, например альтернативные версии hreflang.
* **Форматирование и форматированный текст.** `datetimeFormats` и `numberFormats` принимают параметры `Intl`, а [компонент `<i18n-t>`](https://vue-i18n.intlify.dev/guide/advanced/component) позволяет вставлять элементы в переведённое сообщение без `v-html`.
* **Сообщения рядом с компонентами.** При использовании `@intlify/unplugin-vue-i18n` [блок `<i18n>`](https://vue-i18n.intlify.dev/guide/advanced/sfc) позволяет хранить сообщения компонента прямо в его однофайловом компоненте.
* **Инструменты.** [Официальный плагин ESLint](https://eslint-plugin-vue-i18n.intlify.dev/rules/) находит непереведённый текст в шаблонах, а также отсутствующие и неиспользуемые ключи.

## Что vue-i18n оставляет на ваше усмотрение

Вот небольшой почтовый ящик на Composition API из vue-i18n. Каждой строке назначается ключ, а английский текст хранится в файле сообщений:

```json title="locales/en.json"
{
  "inbox": {
    "heading": "Inbox",
    "unread": "You have {n} unread message | You have {n} unread messages"
  }
}
```

```vue title="Inbox.vue"
<script setup>
import { useI18n } from 'vue-i18n'

defineProps({ count: { type: Number, required: true } })
const { t } = useI18n()
</script>

<template>
  <section>
    <h1>{{ t('inbox.heading') }}</h1>
    <p>{{ t('inbox.unread', count) }}</p>
  </section>
</template>
```

Для каждого целевого языка нужны переведённые сообщения — их готовит ваша команда или сервис перевода. Для этого примера важны две детали реализации:

* **Правила множественного числа.** Правило по умолчанию в vue-i18n 11 выбирает форму по её позиции. В польском языке есть категории `one`, `few`, `many` и `other`, поэтому настройте [собственную функцию `pluralRules`](https://github.com/intlify/vue-i18n/blob/master/docs/guide/v11/essentials/pluralization.md), которая сопоставляет числа с переведёнными формами. В vue-i18n 12, которая пока находится в стадии альфа-версии, [используется `Intl.PluralRules`](https://github.com/intlify/vue-i18n/releases/tag/v12.0.0-alpha.4).
* **Числа внутри сообщений.** `{n}` в сообщении с формами множественного числа не форматируется с учётом локали, поэтому в испанском 12345 отображается как &quot;12345&quot;, а не &quot;12.345&quot;, если не передать отформатированное значение.

## Встроенные шаблоны со сгенерированными переводами

`gt-vue` решает те же задачи, что и vue-i18n. Он рендерит сообщения для каждой локали, выбирает формы множественного числа по правилам CLDR соответствующей локали и форматирует числа, денежные суммы и даты с помощью [`<Num>`](/docs/vue/reference/components/num), [`<Currency>`](/docs/vue/reference/components/currency) и [`<DateTime>`](/docs/vue/reference/components/datetime). А затем General Translation делает то, чего не умеет vue-i18n: генерирует переводы. Вот тот же почтовый ящик, но с текстом прямо в коде:

```vue title="Inbox.vue"
<script setup>
import { Num, Plural, T } from 'gt-vue'

defineProps({ count: { type: Number, required: true } })
</script>

<template>
  <section>
    <T><h1>Inbox</h1></T>
    <p>
      <T>
        <Plural :n="count">
          <template #singular>You have <Num :value="count" /> unread message</template>
          <template #plural>You have <Num :value="count" /> unread messages</template>
        </Plural>
      </T>
    </p>
  </section>
</template>
```

[`npx gt translate`](/docs/cli/reference/commands/translate) сканирует ваши шаблоны, отправляет каждый блок [`<T>`](/docs/vue/reference/components/t) вместе с его структурой в API General Translation и создаёт каталог для каждой целевой локали. Слоты `singular` и `plural` задают исходные формулировки, на основе которых строятся грамматические формы целевого языка. [`<Plural>`](/docs/vue/reference/components/plural) выбирает нужную форму по правилам локали, а [`<Num>`](/docs/vue/reference/components/num) форматирует число: 12,345 на английском, 12.345 на испанском и 12 345 на польском.

В примере используется `gt-vue` 0.1.22 с Vue 3.3 или новее; настройка плагина и загрузчика каталогов описана в разделе [Быстрый старт для Vue](/docs/vue/quickstart). Ваша команда может доработать сгенерированный текст в [панели управления](/docs/platform/dashboard/guides/reviewing-translations), а [общие термины Glossary и пользовательские промпты](/docs/platform/dashboard/guides/defining-context-for-translations) помогают поддерживать единую терминологию во всех проектах.

## vue-i18n и General Translation: краткое сравнение

| Возможность                | vue-i18n                                                                                                                   | General Translation (`gt-vue`)                                                                          |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Где пишется текст          | Ключи в файле сообщений или в блоке `<i18n>` для каждой локали                                                             | Прямо в шаблонах, внутри [`<T>`](/docs/vue/reference/components/t)                                      |
| Переводит ваш контент      | Нет                                                                                                                        | Да, с помощью [`npx gt translate`](/docs/cli/reference/commands/translate)                              |
| Формы множественного числа | Формы разделяются вертикальной чертой; в версии 11 для некоторых языков, например польского, требуется собственное правило | Слоты [`<Plural>`](/docs/vue/reference/components/plural) выбираются по правилам CLDR для каждой локали |
| Числа в сообщениях         | Форматируются, только если передать уже отформатированное значение                                                         | [`<Num>`](/docs/vue/reference/components/num) форматирует числа для каждой локали                       |
| Интеграция с приложением   | Плагин Vue; `@nuxtjs/i18n` добавляет маршрутизацию Nuxt, определение языка и SEO-теги                                      | Плагин Vue с реактивным переключением локали и загрузкой каталогов                                      |

Оставайтесь на vue-i18n, если вы используете `@nuxtjs/i18n` для маршрутизации и SEO в Nuxt или у вас уже налажен рабочий процесс с каталогами, который вы хотите сохранить. Выбирайте General Translation, если хотите, чтобы текст оставался читаемым прямо в шаблонах Vue, переводы создавались во время сборки, а рецензенты могли редактировать их в панели управления.

## Переход с vue-i18n

Переносите компоненты по одному: замените каждый поиск по ключу английским текстом внутри [`<T>`](/docs/vue/reference/components/t), а сообщения с формами множественного числа, разделёнными вертикальной чертой, преобразуйте в слоты `singular` и `plural` компонента [`<Plural>`](/docs/vue/reference/components/plural), как в примере выше. Для компонентов, которые ещё не перенесены, оставьте vue-i18n и проверенные каталоги переводов. Настройте `gt-vue` по руководству [Быстрый старт для Vue](/docs/vue/quickstart), а затем запускайте [`npx gt translate`](/docs/cli/reference/commands/translate) перед сборкой.

## Почему vue-i18n показывает неправильную форму множественного числа для польского языка?

Настройте в vue-i18n 11 функцию `pluralRules`, которая сопоставляет польские категории с позициями в вашем сообщении. Например, для 1 выбирается `one`, для 2 и 22 — `few`, а для 5 — `many`. При использовании General Translation встроенный пример задаёт исходную формулировку, сервис генерирует переведённые формы, а [`<Plural>`](/docs/vue/reference/components/plural) отвечает за выбор нужной из них.

## Ключевые выводы

* vue-i18n — зрелый i18n-плагин с хорошей поддержкой Nuxt, но сам он ничего не переводит, а в версии 11 для таких языков, как польский, нужно писать собственное правило множественного числа.
* CLI General Translation генерирует переводы из встроенных блоков [`<T>`](/docs/vue/reference/components/t), а `gt-vue` выполняет их рендеринг с выбором формы множественного числа и форматированием чисел для каждой локали.
* Если у вас уже налажен рабочий процесс на Nuxt или с каталогами сообщений, оставайтесь на vue-i18n. Выбирайте `gt-vue`, если не хотите больше поддерживать исходные файлы с ключами.
