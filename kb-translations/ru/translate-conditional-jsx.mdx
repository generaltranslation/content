## Введение

Одна из самых распространённых ошибок, которые я встречаю в интернационализации, — привычка
разбивать простые тернарные выражения на несколько вызовов перевода.
Обычно это выглядит примерно так:

```jsx
'use client'

import { T, useGT } from 'gt-react'

export default function ThemeSetting({ enabled }) {
  const gt = useGT()

  return (
    <>
      <span>
        <T>Dark Mode:</T>
      </span>
      <button>{enabled ? gt('On') : gt('Off')}</button>
    </>
  )
}
```

В целом это работает как задумано. До внедрения i18n код, вероятно, выглядел примерно так: `{ enabled ? 'On' : 'Off' }`.
Добавление функции `gt()` для i18n, скорее всего, стало просто естественным продолжением существующей структуры кода.

Каждый раз, когда я вижу такое, меня слегка передёргивает. Библиотека задумывалась совсем не для этого.
Это ошибка — особенно если речь идёт о машинном переводе, — и тому есть две причины: (1) контекст и (2) гибкость.

### Контекст

Смысл заключён не только в самих словах, но и в том, как они представлены.
Слово &quot;back&quot; на кнопке со стрелкой «назад», скорее всего, означает совсем не то, что слово &quot;back&quot; («спина») в резюме мануального терапевта.
Кроме того, без более широкого контекста переводчикам (даже живым) бывает трудно правильно перевести слово.
Известна история о том, как отдел интернационализации WhatsApp перевёл на немецкий слово &quot;crop&quot; («обрезать») в редакторе изображений как «урожай» — в сельскохозяйственном смысле.

Чтобы решить проблему контекста, можно передавать сведения о том, как представлен контент, с помощью компонентов [`<T>`](/docs/react/reference/components/t) и [`<Branch>`](/docs/react/reference/components/branch).
В нашем примере это даст нашему «переводчику» более полное представление о том, что означают &quot;on&quot; и &quot;off&quot;.

```jsx
<T>
  <span>Dark Mode:</span>
  <button>
    <Branch branch={enabled.toString()} true="On" false="Off" />
  </button>
</T>
```

### Гибкость

Помимо контекста, у LLM-перевода есть ещё одно интересное преимущество — понимание кода.
Рассмотрим пример, в котором порядок компонентов может меняться в зависимости от языка:

```jsx
<T>
  I eat lunch at <Branch branch={atHome.toString()} true="home" false="work" />.
</T>
```

Итак, у нас есть два возможных предложения:

* &quot;Я обедаю **дома**&quot;
* &quot;Я обедаю **на работе**&quot;

На китайском (путунхуа) они будут выглядеть так:

* &quot;我**在家**吃午餐&quot;
* &quot;我**在公司**吃午餐&quot;

Компонент [`<T>`](/docs/react/reference/components/t) понимает, что здесь нужно изменить порядок слов в предложении, и соответствующим образом переставляет свои дочерние элементы
— а при переводе строк с помощью тернарных операторов добиться этого не так-то просто.

```jsx
<T>
  我在
  <Branch branch={atHome.toString()} true="家" false="公司" />
  吃午餐。
</T>
```

### Заключение

Если и стоит вынести из этой статьи что-то одно, то вот что: всегда ищите способы использовать контекст и гибкость в своём коде.
Компонент [`<Branch />`](/docs/react/reference/components/branch) — пожалуй, один из самых простых способов это сделать.

Подробнее см. в документации по [компоненту `<Branch />`](/docs/react/reference/components/branch).
