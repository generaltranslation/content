Rails I18n — это встроенный в Ruby on Rails API интернационализации: вы вызываете `t` и `l` в представлениях и контроллерах, а Rails находит сообщение для текущей локали в YAML-файлах в каталоге `config/locales`. Он рендерит переводы, а их создание оставляет вам, вашим переводчикам или стороннему сервису. General Translation пишет эти переводы на основе английского исходного текста с учётом терминологии вашего продукта. Ваши представления, контроллеры и вызовы Rails I18n остаются без изменений.

## Что Rails I18n делает хорошо

* **Встроенная поддержка.** Rails [автоматически загружает все файлы `.yml` и `.rb` из `config/locales`](https://guides.rubyonrails.org/i18n.html#configuring-the-load-paths-and-default-locale). Корневым ключом каждого YAML-файла служит ключ локали (`en:`, `es:`), поэтому в одном приложении переводы можно распределить по множеству файлов.
* **Ленивый поиск по ключу.** В `app/views/inbox/show.html.erb` [`t(".title")` разрешается в `inbox.show.title`](https://guides.rubyonrails.org/i18n.html#lazy-lookup), а в действии контроллера `t(".success")` разрешается с учётом имени контроллера и действия, так что ключи повторяют структуру ваших файлов.
* **Интерполяция и безопасный HTML.** Сообщения принимают именованные значения, например `%{name}`, а [ключи с окончанием `_html` рендерятся без экранирования](https://guides.rubyonrails.org/i18n.html#using-safe-html-translations), при этом интерполируемые в них значения всё равно экранируются.
* **Резервные варианты и ограничение локалей.** В новых приложениях Rails для рабочей среды задано `config.i18n.fallbacks = true`, поэтому при отсутствии ключа текст рендерится на языке по умолчанию, а [`config.i18n.available_locales` ограничивает набор локалей, которые принимает приложение](https://guides.rubyonrails.org/configuring.html#config-i18n-available-locales).
* **Данные локалей от сообщества.** Gem [rails-i18n](https://github.com/svenfuchs/rails-i18n) (8.1.0, MIT) добавляет форматы дат, времени и чисел, сообщения об ошибках Active Record и правила множественного числа CLDR для более чем 100 локалей.
* **Без регистрации.** Это обычный Ruby и YAML, а [руководство Rails](https://guides.rubyonrails.org/i18n.html) подробно описывает всё от начала до конца.

## Что Rails I18n оставляет на ваше усмотрение

Rails I18n знает только те сообщения, которые вы ему передали. Вот представление папки «Входящие» и его сообщения на английском:

```yaml title="config/locales/en.yml"
en:
  inbox:
    show:
      title: "Inbox"
      unread:
        one: "You have %{count} unread message."
        other: "You have %{count} unread messages."
```

```erb title="app/views/inbox/show.html.erb"
<h1><%= t(".title") %></h1>
<p><%= t(".unread", count: @count) %></p>
```

Если выбрать испанский язык, этот файл сам не переведётся. При включённых резервных вариантах на английском испаноязычные читатели по-прежнему увидят &quot;Inbox&quot; и &quot;You have 3 unread messages.&quot; Чтобы показывать текст на испанском, Rails нужен испанский каталог. Каждое новое или изменённое английское сообщение добавляет столько же работы для каждого языка.

Гем [rails-i18n](https://github.com/svenfuchs/rails-i18n) предоставляет форматы локалей и правила множественного числа. [i18n-tasks](/kb/general-translation-vs-i18n-tasks) находит отсутствующие ключи и формы множественного числа. А General Translation предоставляет переведённые сообщения, с которыми работают эти инструменты.

## Перевод файлов локалей Rails с помощью General Translation

Поиск по ключу оставьте за Rails I18n, а остальные файлы локалей пусть создаёт General Translation. CLI `gt` работает на Node.js, переводит YAML и сохраняет ваши ключи. В этом примере (перевод с английского на испанский) храните сообщения в `translations/en.yml` без внешнего ключа `en:`:

```yaml title="translations/en.yml"
inbox:
  show:
    title: "Inbox"
    unread:
      one: "You have %{count} unread message."
      other: "You have %{count} unread messages."
```

Укажите эти рабочие файлы в `gt.config.json`. Небольшой шаг экспорта добавляет ключи локалей Rails и записывает каталоги, которые загружает приложение:

```json title="gt.config.json"
{
  "defaultLocale": "en",
  "locales": [
    "es"
  ],
  "files": {
    "yaml": {
      "include": [
        "translations/[locale].yml"
      ]
    }
  }
}
```

Задайте `GT_PROJECT_ID` и `GT_API_KEY`, как описано в разделе [Генерация переводов](/docs/cli/guides/generating-translations). Если у вас уже есть переводы для этого каталога, поместите их в `translations/es.yml` без корневого ключа `es:` и выполните [`npx gt upload`](/docs/cli/reference/commands/upload), прежде чем генерировать новые переводы.

```ruby title="script/export_rails_locales.rb"
require "json"
require "yaml"
require "fileutils"

config = JSON.parse(File.read("gt.config.json"))
locales = ([config.fetch("defaultLocale")] + config.fetch("locales")).uniq
catalogs = locales.to_h do |locale|
  messages = YAML.safe_load_file("translations/#{locale}.yml", aliases: true)
  raise "Expected a message map for #{locale}" unless messages.is_a?(Hash)
  [locale, { locale => messages }.to_yaml]
end

FileUtils.mkdir_p("config/locales")
catalogs.each do |locale, catalog|
  File.write("config/locales/#{locale}.yml", catalog)
end
```

```bash
npx gt translate && ruby script/export_rails_locales.rb
```

При экспорте этот каталог записывается в `config/locales/en.yml` и `config/locales/es.yml`. Продолжайте редактировать рабочие файлы в `translations/`, а приложение будет загружать экспортированные копии. Перед следующим запуском перевода синхронизируйте локальные правки переводов с помощью [`npx gt save-local`](/docs/cli/reference/commands/save-local).

General Translation переводит каждый файл с учётом [Glossary и пользовательских промптов](/docs/platform/dashboard/guides/defining-context-for-translations) вашего проекта, поэтому название продукта или официальный тон остаются единообразными во всех файлах локалей, а ваша команда может [просматривать и редактировать переводы](/docs/platform/dashboard/guides/reviewing-translations) в панели управления. Для неизменённых записей повторно используются уже готовые переводы, поэтому при запуске CLI в CI после каждого слияния переводятся только изменения.

Перед релизом выполните `i18n-tasks missing` и `i18n-tasks check-consistent-interpolations`, чтобы проверить ключи, формы множественного числа и заполнители `%{count}` в экспортированных каталогах.

## Rails I18n и General Translation: краткое сравнение

| Возможность                            | Rails I18n                                                            | General Translation                                                                     |
| -------------------------------------- | --------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Что это                                | Библиотека Ruby для поиска и форматирования переводов                 | Платформа перевода с CLI, библиотеками для JavaScript и Python и панелью управления     |
| Рендеринг переводов в приложении Rails | Да, в представлениях, контроллерах и мейлерах                         | Предоставляет каталоги для тех же вызовов Rails I18n                                    |
| Создание переводов                     | Нет                                                                   | Да, YAML-файлы с помощью [`npx gt translate`](/docs/cli/reference/commands/translate)   |
| Правила множественного числа           | По умолчанию — правила английского языка; правила CLDR — с rails-i18n | Переводит настроенные формы исходного текста; Rails выбирает нужную во время выполнения |
| Единообразие между файлами             | Зависит от ваших переводчиков                                         | Glossary и пользовательские промпты применяются к каждому файлу                         |
| Проверка                               | Ваш процесс ревью пул-реквестов                                       | Панель управления плюс ваш процесс ревью пул-реквестов                                  |
| Стоимость                              | Бесплатно, MIT                                                        | [Оплата по факту использования](https://generaltranslation.com/pricing)                 |

Используйте только Rails I18n, если файлы локалей уже поставляют переводчики или подрядчик либо если вы поддерживаете один-два языка и редактируете их вручную. Подключите General Translation, если английский текст часто меняется и вы хотите, чтобы все файлы локалей автоматически перегенерировались в CI с единообразной терминологией, а не ждать, пока переводы вернутся от переводчиков.

## Основные выводы

* Rails I18n рендерит переводы из `config/locales` и форматирует даты и числа; rails-i18n добавляет правила множественного числа и данные локали. Ни один из них не создаёт переводы.
* General Translation переводит YAML с учётом вашего Glossary и пользовательских промптов и поддерживает переводы в актуальном состоянии при изменении английского текста.
* Храните редактируемые каталоги в `translations/`, а после запуска [`npx gt translate`](/docs/cli/reference/commands/translate) экспортируйте их в корневые каталоги локалей Rails.
