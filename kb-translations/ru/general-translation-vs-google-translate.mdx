Google Translate позволяет быстро прочитать страницу на другом языке или разово перевести абзац. Но самое сложное в локализации продукта — другое: переводить каждую строку с учётом того значения, которое она имеет в вашем UI, сохранять единообразие терминов от релиза к релизу и доставлять переводы туда, откуда их загружает приложение. Как бы вы ни использовали Google Translate для приложения, часть этой работы всё равно останется на вас.

## Три способа перевести приложение с помощью Google Translate

### Перевод страницы средствами браузера посетителя

Chrome предлагает перевести страницы на языках, которыми пользователь не владеет. Перевод выполняется в браузере посетителя уже после загрузки страницы: скрипт Google Translate заменяет текст страницы переведённым текстом, обёрнутым в элементы `<font>`. Вы не видите результат и не можете его проверить, а у переведённой версии нет собственного URL, который могли бы проиндексировать поисковые системы. При этом Google рекомендует для многоязычных сайтов размещать каждую языковую версию по отдельному URL ([Managing multilingual sites](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)).

Кроме того, такая подмена может ломать React-приложения. React хранит ссылки на отрендеренные им текстовые узлы, поэтому после того как перевод их заменит, следующее обновление может завершиться ошибкой `NotFoundError: Failed to execute 'removeChild' on 'Node'`. Мейнтейнеры React закрыли соответствующий issue ([react#11538](https://github.com/react/react/issues/11538)) ещё в 2018 году, пояснив, что сам React не может обойти эту проблему, не маскируя другие ошибки и не замедляя типичные сценарии. Элементы с атрибутом `translate="no"` браузер не трогает.

### Добавление виджета Website Translator

Встраиваемый виджет Website Translator от Google доступен только академическим, государственным, некоммерческим организациям и прочим сайтам, не преследующим коммерческих целей, поэтому компания не может добавить его в свой продукт ([Google Translate Help](https://support.google.com/translate/answer/2534559?co=GENIE.Platform%3DDesktop)).

### Вызов Cloud Translation API

Cloud Translation API — вариант, созданный специально для разработчиков. Он сохраняет HTML-теги в неизменном виде. При обработке HTML редакция Advanced пропускает текст, помеченный `translate="no"` или `class="notranslate"`, а также добавляет глоссарии, адаптивный перевод на основе пар примеров предложений и Translation LLM на базе Gemini. Запрос содержит текст, языки и, при необходимости, модель и глоссарий:

```json title="translateText request body"
{
  "contents": ["Save"],
  "mimeType": "text/plain",
  "sourceLanguageCode": "en",
  "targetLanguageCode": "de"
}
```

Поля, указывающего, где отображается строка, нет. В немецком «Save» — это *speichern* (сохранить файл) или *sparen* (экономить), и по запросу из одного слова модели не на что опереться при выборе. Остальную часть конвейера придётся строить самостоятельно: извлекать строки из i18n-файлов, защищать заполнители вроде `{{count}}`, формировать формы множественного числа для каждого языка, записывать результаты обратно, перезапускать перевод при каждом изменении и дать рецензентам место, где они смогут исправлять перевод так, чтобы следующий запуск не перезаписал правки. Если вы показываете результат пользователям, Google также требует указывать авторство: значок «powered by Google Translate» рядом с результатами, оговорку для неотредактированного перевода и разметку машинного перевода на страницах, индексируемых поисковыми системами ([требования к указанию авторства](https://docs.cloud.google.com/translate/attribution)).

| --------------------- | ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Перевод в браузере    | Видимый текст страницы                                              | Переводятся как обычный текст                                                                                                                                           | Индексировать нечего                                                               | Без проверки; перевод заново выполняется в браузере каждого посетителя                                             |
| Cloud Translation API | Текст, а также необязательный глоссарий или примеры пар             | Вы сами защищаете заполнители и составляете формы множественного числа для каждого языка                                                                                | Индексируется, если опубликовать каждый язык по отдельному URL                     | Вы сами повторно запускаете скрипт и выстраиваете процесс проверки                                                 |

Google Translate подходит, чтобы читать контент на иностранных языках или разово перевести внутренний текст. Cloud Translation API подойдёт, если вам нужен «сырой» машинный перевод, а контекст, заполнители, формы множественного числа, проверку и атрибуцию вы готовы реализовать сами. General Translation стоит выбрать, если переводы входят в ваш продукт — например, интерфейс приложения, документация или маркетинговый сайт, — должны естественно звучать на каждом языке и не отставать ни от одного релиза.

## Чем отличается General Translation

General Translation создан для той части локализации, которую Google Translate оставляет на вас. Его отличают две особенности:

* **Он учитывает весь контекст.** Запрос к Cloud Translation содержит только текст и языки, а также необязательный глоссарий. General Translation переводит каждую строку с учётом её места в вашем продукте: окружающего компонента и элементов, переменных и форм множественного числа в предложении, добавленной вами заметки с контекстом, а также вашего Glossary и пользовательских промптов. Контекстная группа применяет одни и те же термины и тон ко всем проектам, которым она назначена, поэтому в вашем приложении, документации и маркетинговом сайте используются одни и те же формулировки.
* **Он автоматизирует весь рабочий процесс локализации.** Библиотеки с открытым исходным кодом интернационализируют ваш код на React, Next.js, Vue и Node.js, а в приложениях на Next.js и React этот код за вас может написать [Locadex](/docs/platform/locadex/quickstart) — AI-агент General Translation. [`npx gt translate`](/docs/cli/reference/commands/translate) запускается при сборке или в CI и записывает переводы в ваш репозиторий или в CDN General Translation, ревьюеры редактируют их на странице **Translations** в панели управления, и каждый релиз выходит сразу на всех языках.

Вот как контекст выглядит в коде. На значке этого переключателя тарифа оплаты написано «Save 20%»:

```tsx title="BillingToggle.tsx"
import { T, Var } from 'gt-react';

export function BillingToggle({ discount }: { discount: string }) {
  return (
    <T context="Pricing page billing toggle. Save means pay less, not store data.">
      <button>Yearly</button>
      <span className="badge">Save <Var>{discount}</Var></span>
    </T>
  );
}
```

[`<T>`](/docs/react/reference/components/t) отправляет блок целиком — вместе с его элементами (кнопкой и бейджем) и заметкой [`context`](/docs/react/reference/components/t#context), — поэтому при переводе можно однозначно определить значение «Save» и поставить скидку туда, где она стоит в каждом языке. [`<Var>`](/docs/react/reference/components/var) содержит заполнитель для скидки, а само её значение никогда не отправляется в API General Translation. Glossary закрепляет единый перевод терминов, например названий продуктов, во всех языках, а пользовательские промпты задают правила — например, вежливое обращение «Sie» в немецком. (См. [Определение контекста для переводов](/docs/platform/dashboard/guides/defining-context-for-translations) и [Проверка и редактирование переводов](/docs/platform/dashboard/guides/reviewing-translations).) Контент, который появляется только во время выполнения, например пользовательский текст или текст из CMS, переводит по запросу функция [`tx`](/docs/node/reference/functions/tx) из `gt-node`.

General Translation поддерживает более 120 локалей. Начните с [Быстрого старта Next.js](/docs/react/nextjs-quickstart) или [Быстрого старта React](/docs/react/react-quickstart).

## Ключевые выводы

* Google Translate хорошо переводит текст. Однако браузерный перевод не позволяет проверять переводы, не создаёт индексируемых страниц и может ломать React-приложения, а виджет Website Translator доступен только для некоммерческих сайтов.
* В запросе к Cloud Translation API нет поля, указывающего, где отображается строка, а заполнители, формы множественного числа, проверку, доставку и атрибуцию придётся реализовывать самостоятельно.
* General Translation понимает контекст каждой строки в вашем коде и автоматизирует весь рабочий процесс вокруг перевода — от интернационализации кода и проверки до выпуска каждого релиза на всех языках.
