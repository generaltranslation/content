Intlayer — это [библиотека интернационализации с открытым исходным кодом](https://github.com/aymericzip/intlayer), которая размещает контент в файле объявлений рядом с каждым компонентом (например, `inbox.content.ts`), где все переводы строки перечислены в одном вызове `t({ en, es, pl })`. Хук вроде `useIntlayer('inbox')` возвращает этот контент типизированным и в текущей локали. Intlayer дополняет недостающие языки с помощью настроенного вами ИИ-провайдера, а также предлагает бесплатный визуальный редактор и необязательную облачную CMS. Однако все языковые версии каждой строки по-прежнему хранятся в ваших исходных файлах, и писать, дополнять и проверять их приходится вам. General Translation идёт другим путём: вы пишете текст один раз, прямо в коде, на языке-источнике, а General Translation генерирует остальные языки с учётом контекста вашего кода.

## Сильные стороны Intlayer

* **Контент рядом с компонентом.** Отдельный файл объявлений для каждого компонента позволяет держать текст рядом с кодом, который его рендерит.
* **Типобезопасность.** Ключи `useIntlayer` типизированы: в версии 9.7.0 `useIntlayer('inbx')` вызывает ошибку TypeScript. Вызов `t()`, в котором не хватает одной из настроенных локалей, тоже отмечается (в тесте на 9.7.0 это ошибка типа, а строгость проверки задаётся параметром `strictMode`), так что пропуски обнаруживаются ещё до релиза.
* **Разнообразные типы контента.** Помимо текста для каждой локали, объявления поддерживают [формы множественного числа по категориям CLDR](https://intlayer.org/doc/concept/content/plural) (`plural({ one, few, many, other })`), перечисления, условия, грамматический род, Markdown, HTML, вложенность и вставку значений.
* **Собственная модель.** `intlayer fill` переводит недостающие локали с помощью OpenAI, Anthropic, Mistral, Gemini, DeepSeek, Ollama, OpenRouter и других провайдеров, которые задаются в разделе [`ai` файла `intlayer.config.ts`](https://intlayer.org/doc/concept/configuration) или через `--provider` и `--api-key`. Если у вас есть собственный ключ и установлен пакет `@intlayer/ai`, [команда выполняется локально](https://intlayer.org/doc/concept/cli/fill), а оплата идёт напрямую провайдеру.
* **Визуальное редактирование.** Пакет `intlayer-editor` загружает запущенное приложение в редактор, где авторы выбирают и правят текст, а затем записывает изменения обратно в файлы объявлений. [Согласно документации Intlayer](https://intlayer.org/doc/concept/editor), редактор распространяется под лицензией Apache 2.0, бесплатен для коммерческого использования и предназначен для сред разработки и staging.
* **Широкая поддержка фреймворков.** [Руководства](https://intlayer.org/doc/get-started) охватывают Next.js, React с Vite, React Router, TanStack Start, React Native, Vue и Nuxt, Svelte и SvelteKit, Solid, Preact, Astro, Angular, а также серверные фреймворки — Express, NestJS, Fastify и Hono.

## Что Intlayer оставляет вам

Вот файл контента для раздела «Входящие» с тремя локалями:

```ts title="inbox.content.ts"
import { t, plural, type Dictionary } from 'intlayer';

const inboxContent = {
  key: 'inbox',
  content: {
    title: t({
      en: 'Inbox',
      es: 'Bandeja de entrada',
      pl: 'Skrzynka odbiorcza',
    }),
    unread: t({
      en: plural({
        one: 'You have {{count}} unread message.',
        other: 'You have {{count}} unread messages.',
      }),
      es: plural({
        one: 'Tienes {{count}} mensaje sin leer.',
        other: 'Tienes {{count}} mensajes sin leer.',
      }),
      pl: plural({
        one: 'Masz {{count}} nieprzeczytaną wiadomość.',
        few: 'Masz {{count}} nieprzeczytane wiadomości.',
        many: 'Masz {{count}} nieprzeczytanych wiadomości.',
        other: 'Masz {{count}} nieprzeczytanej wiadomości.',
      }),
    }),
  },
} satisfies Dictionary;

export default inboxContent;
```

```tsx title="Inbox.tsx"
import { useIntlayer } from 'react-intlayer';

export function Inbox({ count }: { count: number }) {
  const { title, unread } = useIntlayer('inbox');
  return (
    <section>
      <h1>{title}</h1>
      <p>{unread({ count })}</p>
    </section>
  );
}
```

Такой вариант корректно рендерится в каждой локали, но файл разрастается с каждой новой: при 20 локалях у каждой строки по 20 записей. И новой строке тоже нужны все они. Добавление `archive: t({ en: 'Archive' })` привело к ошибке типов с перечислением локалей, которых ещё не хватает:

```text title="Output"
Type '{ en: string; }' is missing the following properties from type
'Required<Record<keyof __RequiredLocalesRegistry, unknown>>': es, pl
```

Во время выполнения для отсутствующих локалей подставлялся английский. Чтобы восполнить пробел, нужно написать переводы самостоятельно или запустить `intlayer fill`. Fill передаёт модели содержимое словаря, [его описание](https://intlayer.org/doc/concept/content) и строку `applicationContext` из вашей конфигурации. Ни компонент, ни окружающий строку JSX модель не видит. [Компилятор Intlayer](https://intlayer.org/doc/compiler) умеет во время сборки извлекать простой текст из JSX в файлы контента, так что объявления можно не писать вручную, но переводы всё равно хранятся в этих файлах.

## General Translation хранит в коде только один язык

Библиотеки General Translation выполняют рендеринг переводов так же: выбирают сообщения для каждой локали и применяют её правила множественного числа. Разница в том, что в ваших компонентах остаётся только язык-источник. Вот тот же почтовый ящик на `gt-react`:

```tsx title="Inbox.tsx"
import { T, Plural, Num } from 'gt-react';

export function Inbox({ count }: { count: number }) {
  return (
    <T>
      <section>
        <h1>Inbox</h1>
        <Plural
          n={count}
          singular={<p>You have <Num>{count}</Num> unread message.</p>}
          plural={<p>You have <Num>{count}</Num> unread messages.</p>}
        />
      </section>
    </T>
  );
}
```

Здесь нет ни файла с контентом, ни ключей. [`npx gt translate`](/docs/cli/reference/commands/translate) отправляет каждый блок [`<T>`](/docs/react/reference/components/t) вместе со структурой его элементов в API General Translation и записывает переводы для каждой целевой локали в отдельные файлы, поэтому при добавлении локали меняется `gt.config.json`, а не ваши компоненты. Вы пишете формы множественного числа, которые есть в английском, при переводе создаются формы, нужные каждому целевому языку, а [`<Plural>`](/docs/react/reference/components/plural) выбирает переведённую ветку по правилам локали читателя. [`npx gt validate`](/docs/cli/reference/commands/validate) проверяет проект без обращения к API, а [`gt generate`](/docs/cli/reference/commands/generate) создаёт шаблоны для команд, которые переводят вручную.

Результат определяется контекстом. General Translation переводит текст и JSX-структуру внутри каждого размеченного блока целиком, а заметки разработчика уточняют смысл. Кнопка «Save» для документа по-немецки — «speichern», а предложение сэкономить деньги — «sparen». [Контекстные группы](/docs/platform/dashboard/guides/defining-context-for-translations) применяют ваш Glossary и пользовательские промпты к назначенным проектам. Рецензенты редактируют переводы в панели управления, а CLI или [Locadex](/docs/platform/locadex/quickstart) обрабатывают обновления по мере изменения кода. Команды, которые хотят автоматически размечать существующий JSX, могут включить [автоматическое внедрение JSX](/docs/cli/guides/using-auto-jsx).

JavaScript-библиотеки распространяются по лицензии MIT и могут рендерить готовые переводы без учётной записи. Храните переводы в своей сборке или публикуйте их в CDN General Translation.

Cursor использует General Translation для более чем 14 локалей на сайте и в документации. (См. [развёртывания в рабочей среде](https://generaltranslation.com/enterprise).)

## Intlayer и General Translation: краткое сравнение

| Возможность                    | Intlayer                                                                                                                                                            | General Translation                                                                                                                        |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Как пишется текст              | `t({ en, es, ... })` в файле объявлений для каждого компонента, чтение через `useIntlayer`                                                                          | JSX внутри [`<T>`](/docs/react/reference/components/t), строки через [`useGT`](/docs/react/reference/hooks/use-gt) или словари с ключами   |
| Где хранятся переводы          | В файлах объявлений или в отдельных файлах контента для каждой локали                                                                                               | В отдельных файлах для каждой локали или в CDN General Translation                                                                         |
| ИИ-перевод                     | `intlayer fill` с ключом вашего провайдера или через сервис Intlayer                                                                                                | [`npx gt translate`](/docs/cli/reference/commands/translate) через API General Translation                                                 |
| Какой контекст получает модель | Содержимое словаря, описание и строка с контекстом приложения                                                                                                       | Размеченная структура JSX, заметки разработчиков, а также назначенные Glossary и пользовательские промпты                                            |
| Отсутствующие локали           | Помечаются (в тесте на версии 9.7.0 — как ошибка типов); о них сообщает [`intlayer test`](https://intlayer.org/doc/concept/cli/test)                                | Генерируются командой [`npx gt translate`](/docs/cli/reference/commands/translate); непереведённый контент отображается на языке-источнике |
| Редактирование                 | Бесплатный локальный визуальный редактор; облачная CMS — по желанию                                                                                                 | Редактирование и проверка переводов в панели управления                                                                                    |
| Фреймворки                     | React, Next.js, Vue, Svelte, Solid, Angular, Astro, React Native и серверы на Node.js                                                                               | React, Next.js, Vue, Node.js и [другие SDK](/docs/overview/get-started)                                                                    |
| Лицензия и стоимость           | Apache 2.0; стоимость тарифов облачной CMS зависит от числа проектов, мест и объёма хранилища ([цены](https://app.intlayer.org/pricing), данные на октябрь 2026 г.) | JavaScript-библиотеки под лицензией MIT; [оплата перевода по факту использования](https://generaltranslation.com/pricing)                  |

Выбирайте Intlayer, если хотите видеть все языки рядом с компонентом, получать ошибки типов при отсутствии локалей, дать авторам редактор прямо на странице или если вам нужна интеграция со Svelte, Solid или Angular. Выбирайте General Translation, если предпочитаете писать текст один раз на языке-источнике, а переводы на все остальные языки генерировать с учётом контекста вашего кода, вашего Glossary и пользовательских промптов.

## Переход с Intlayer на General Translation

Переносите компоненты по одному: пусть каждый компонент использует переводы Intlayer, пока его версия на General Translation не будет готова. При серверном рендеринге с `react-intlayer` 9.7.0 и `gt-react` 11.4.12 компонент Intlayer и компонент [`<T>`](/docs/react/reference/components/t) успешно рендерились рядом внутри `IntlayerProvider` и [`GTProvider`](/docs/react/reference/components/gt-provider). Скопируйте значения `en` компонента в JSX внутри [`<T>`](/docs/react/reference/components/t), создайте переводы с помощью [`npx gt translate`](/docs/cli/reference/commands/translate) и проверьте результат, прежде чем переключать компонент. Начните с руководства [Быстрый старт Next.js](/docs/react/nextjs-quickstart) или [Быстрый старт React](/docs/react/react-quickstart), а о том, как использовать две библиотеки одновременно во время перехода, читайте в разделе [Миграция i18n-библиотек](/docs/react/guides/migrating-i18n-libraries).

## Ключевые выводы

* Intlayer хранит контент каждого компонента в типизированном файле объявлений, где все языки расположены рядом, распознаёт отсутствующие локали как ошибки типов и заполняет их с помощью выбранного вами ИИ-провайдера.
* General Translation хранит в компонентах только язык-источник, а все остальные языки генерирует с учётом контекста из вашего кода, Glossary и пользовательских промптов; переводы можно проверить в панели управления.
* Intlayer поддерживает больше фреймворков и предлагает визуальное редактирование прямо на странице. Перейти на General Translation можно постепенно, компонент за компонентом: обе библиотеки способны работать параллельно.
