## Почему многоязычному SEO нужно уделить особое внимание

Большинство разработчиков, добавляя i18n в своё приложение Next.js, переводят интерфейс и на этом останавливаются.
Но если поисковые системы не могут найти, проиндексировать и правильно связать между собой языковые версии сайта,
вся работа по переводу пропадает впустую.

У многоязычного сайта без правильной настройки SEO возникают проблемы:

* Google может проиндексировать только одну языковую версию и проигнорировать остальные
* Пользователи, которые ищут на испанском, попадают на английскую страницу
* Возникают санкции за дублированный контент, потому что Google считает `/en/about` и `/fr/about` одной и той же страницей
* В сниппетах поисковой выдачи отображается не тот язык

**Хорошая новость:** правильно настроить многоязычное SEO в Next.js несложно.
Нужно учесть шесть моментов, и в этом руководстве все они разобраны на примере [`gt-next`](/docs/react/nextjs-quickstart).

***

## 1. Маршрутизация URL на основе локали

Основа многоязычного SEO — отдельный URL для каждого языка.
Поисковым системам нужны отдельные URL, доступные для сканирования, чтобы индексировать каждую языковую версию независимо.

Иными словами, **локаль должна быть в URL**, а не в cookie-файлах или параметрах строки запроса, и определения по `Accept-Language` самого по себе недостаточно.

```text
✅ generaltranslation.com/en/about
✅ generaltranslation.com/fr/about
✅ generaltranslation.com/es/about

❌ generaltranslation.com/about?lang=fr
❌ generaltranslation.com/about (локаль хранится в cookie-файле)
```

### Настройка маршрутизации по локалям с помощью gt-next

Сначала разместите страницы внутри динамического сегмента `[locale]`:

```text
app/
└── [locale]/
    ├── layout.tsx
    ├── page.tsx
    └── about/
        └── page.tsx
```

Затем создайте промежуточное ПО в корневом каталоге проекта (`proxy.ts` для Next.js 16+ или `middleware.ts` для Next.js 15 и более ранних версий):

```ts title="proxy.ts"
import { createNextMiddleware } from 'gt-next/middleware';

export default createNextMiddleware();

export const config = {
  matcher: ['/((?!api|static|.*\\..*|_next).*)'],
};
```

Так вы автоматически получаете URL-адреса с префиксом локали.
По умолчанию у локали по умолчанию (например, английской) префикса нет — `/about` остаётся без изменений,
а испаноязычные пользователи видят `/es/about`, франкоязычные — `/fr/about`.

## 2. Установка HTML-атрибута `lang`

Атрибут `lang` в теге `<html>` сообщает браузерам и поисковым системам, на каком языке написана страница.
Это одно из самых простых и при этом самых действенных улучшений для доступности и SEO.

Без него программы чтения с экрана пытаются угадать язык (и часто ошибаются), а поисковые системы менее уверенно определяют язык страницы.

{/* useLocale работает в компонентах как с клиентским, так и с серверным рендерингом, но не в асинхронных компонентах */}

В gt-next есть хук [`useLocale`](/docs/react/reference/hooks/use-locale), с которым сделать это в корневом макете проще простого:

```tsx title="app/[locale]/layout.tsx"
import { useLocale, GTProvider } from 'gt-next';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  const locale = useLocale();

  return (
    <html lang={locale}>
      <body>
        <GTProvider>
          {children}
        </GTProvider>
      </body>
    </html>
  );
}
```

[`useLocale`](/docs/react/reference/hooks/use-locale) возвращает код локали в формате BCP 47 (например, `en-US`, `ar`, `zh-Hans`).

## 3. Канонические URL-адреса

Канонические теги сообщают поисковым системам, какой URL-адрес считается «основной» версией страницы.
На многоязычных сайтах каждая языковая версия должна указывать в качестве канонической на саму себя:

```html
<!-- На странице /fr/about -->
<link rel="canonical" href="https://example.com/fr/about" />
```

Так поисковые системы не будут считать вашу французскую страницу дубликатом английской.

В Next.js канонические URL задаются через [API метаданных](https://nextjs.org/docs/app/api-reference/functions/generate-metadata).
Используйте его вместе с [`getLocale`](/docs/react/nextjs/reference/functions/get-locale) из gt-next, чтобы формировать правильный канонический URL для каждой локали:

```tsx title="app/[locale]/about/page.tsx"
import { getLocale } from 'gt-next/server';

const BASE_URL = 'https://example.com';

export async function generateMetadata() {
  const locale = await getLocale();

  return {
    alternates: {
      canonical: `${BASE_URL}/${locale}/about`,
    },
  };
}

export default function AboutPage() {
  return <h1>About Us</h1>;
}
```

Если локаль по умолчанию используется без префикса, внесите соответствующие изменения:

```tsx
import { getDefaultLocale } from 'gt-next';
import { getLocale } from 'gt-next/server';

export async function generateMetadata() {
  const locale = await getLocale();
  const defaultLocale = getDefaultLocale();
  const path = '/about';

  const prefix = locale === defaultLocale ? '' : `/${locale}`;

  return {
    alternates: {
      canonical: `${BASE_URL}${prefix}${path}`,
    },
  };
}
```

## 4. Теги hreflang

Теги hreflang — важнейший сигнал для многоязычного SEO.
Они сообщают поисковым системам: «эта страница доступна также на этих языках, и вот их URL-адреса».

Без hreflang Google приходится угадывать, какую языковую версию показывать в результатах поиска, — и нередко он ошибается.

```html
<link rel="alternate" hreflang="en" href="https://example.com/about" />
<link rel="alternate" hreflang="fr" href="https://example.com/fr/about" />
<link rel="alternate" hreflang="es" href="https://example.com/es/about" />
<link rel="alternate" hreflang="x-default" href="https://example.com/about" />
```

Тег `x-default` указывает поисковым системам, какой URL показывать, если ни один из указанных языков не соответствует пользователю.

В Next.js hreflang можно добавить с помощью свойства `alternates.languages` в API метаданных.
Вот переиспользуемая вспомогательная функция для работы с gt-next:

```tsx title="lib/i18n-metadata.ts"
import { getDefaultLocale } from 'gt-next';
import { getLocale } from 'gt-next/server';

const BASE_URL = 'https://example.com';
const SUPPORTED_LOCALES = ['en', 'fr', 'es'];

export async function getI18NMetadata(path: string) {
  const locale = await getLocale();
  const defaultLocale = getDefaultLocale();

  const getUrl = (loc: string) => {
    const prefix = loc === defaultLocale ? '' : `/${loc}`;
    return `${BASE_URL}${prefix}${path}`;
  };

  const languages: Record<string, string> = {};
  for (const loc of SUPPORTED_LOCALES) {
    languages[loc] = getUrl(loc);
  }
  languages['x-default'] = getUrl(defaultLocale);

  return {
    alternates: {
      canonical: getUrl(locale),
      languages,
    },
  };
}
```

Затем используйте его на любой странице:

```tsx title="app/[locale]/about/page.tsx"
import { getI18NMetadata } from '@/lib/i18n-metadata';

export async function generateMetadata() {
  return await getI18NMetadata('/about');
}
```

Этот вызов генерирует сразу и канонический тег, и все теги hreflang.

## 5. Переведённые метаданные

Поисковые системы показывают в результатах заголовок и описание вашей страницы.
Если у французской страницы они на английском, пользователи реже переходят по ссылке, а Google может понизить её в выдаче.

Чтобы перевести строки метаданных, используйте функцию [`getGT`](/docs/react/nextjs/reference/functions/get-gt) из gt-next:

```tsx title="app/[locale]/about/page.tsx"
import { getGT } from 'gt-next/server';
import { getI18NMetadata } from '@/lib/i18n-metadata';

export async function generateMetadata() {
  const t = await getGT();
  const i18nMeta = await getI18NMetadata('/about');

  return {
    title: t('About Us'),
    description: t('Learn about our mission and team.'),
    ...i18nMeta,
  };
}
```

Благодаря этому в результатах поиска отображаются локализованные заголовки и описания,
что значительно повышает CTR по запросам на других языках, помимо английского.

## 6. Многоязычные карты сайта

Карта сайта помогает поисковым системам находить все страницы вашего сайта, включая все языковые версии.
Для многоязычных сайтов в карту сайта также следует добавить аннотации hreflang.

Next.js поддерживает [программную генерацию карт сайта](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/sitemap) с помощью файла `sitemap.ts`:

```ts title="app/sitemap.ts"
import { MetadataRoute } from 'next';

const BASE_URL = 'https://example.com';
const LOCALES = ['en', 'fr', 'es'];
const DEFAULT_LOCALE = 'en';
const PAGES = ['/', '/about', '/blog', '/contact'];

export default function sitemap(): MetadataRoute.Sitemap {
  return PAGES.flatMap((path) => {
    const getUrl = (locale: string) => {
      const prefix = locale === DEFAULT_LOCALE ? '' : `/${locale}`;
      return `${BASE_URL}${prefix}${path === '/' ? '' : path}`;
    };

    const languages: Record<string, string> = {};
    for (const locale of LOCALES) {
      languages[locale] = getUrl(locale);
    }

    return LOCALES.map((locale) => ({
      url: getUrl(locale),
      lastModified: new Date(),
      alternates: { languages },
    }));
  });
}
```

В результате генерируется карта сайта с отдельной записью для каждой страницы в каждой локали,
причём каждая запись содержит аннотации hreflang со ссылками на все языковые версии.

## Контрольный список

Краткая сводка всего, что мы рассмотрели:

| Требование SEO           | Реализация                                                                                                                    |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| Локаль в URL             | [`createNextMiddleware()`](/docs/react/nextjs/reference/functions/create-next-middleware) с динамическим сегментом `[locale]` |
| HTML-атрибут `lang`      | [`useLocale()`](/docs/react/reference/hooks/use-locale) в корневом макете                                                     |
| Канонические URL         | [`getLocale()`](/docs/react/nextjs/reference/functions/get-locale) + `alternates.canonical` в API метаданных Next.js          |
| Теги hreflang            | `alternates.languages` в API метаданных Next.js со всеми поддерживаемыми локалями                                             |
| Переведённые метаданные  | [`getGT()`](/docs/react/nextjs/reference/functions/get-gt) для заголовков и описаний страниц                                  |
| Многоязычная карта сайта | `sitemap.ts` с записями для каждой локали и альтернативными версиями hreflang                                                 |

Затем настройте маршрутизацию по [руководству по промежуточному ПО](/docs/react/nextjs/app-router-middleware), создайте многоязычные страницы с помощью [генерации статических сайтов](/docs/react/nextjs/app-router-static-site-generation) и добавьте [поддержку right-to-left](/docs/react/guides/managing-locales).
