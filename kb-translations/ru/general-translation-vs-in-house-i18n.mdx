Интернационализацию (i18n) можно реализовать самостоятельно: объект сообщений для каждого языка, вспомогательная функция `t()`, которая находит ключ и подставляет переменные, переключатель локали и встроенные API `Intl` для чисел и дат. Для одного-двух языков и нескольких десятков строк этого часто достаточно — и именно такой код обычно пишет ИИ-агент, если попросить его добавить язык. С ростом приложения разрастается всё, что окружает эту функцию: правила множественного числа, отсутствующие ключи, синхронизация каждого языкового файла с кодом и, в первую очередь, создание самих переводов. Открытые библиотеки General Translation берут на себя ту часть работы, что выполняется во время работы приложения, а General Translation генерирует и обновляет переводы на основе вашего кода.

## Когда достаточно самописной i18n

* **Никаких сторонних зависимостей.** Словарь и вспомогательная функция — ваши, и каждая строка кода под вашим контролем.
* **Форматированием занимается платформа.** `Intl.NumberFormat`, `Intl.DateTimeFormat`, `Intl.PluralRules` и `Intl.Locale` [встроены в современные браузеры и Node.js](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl) и форматируют валюты, даты и категории множественного числа с учётом локали.
* **Небольшой объём редко меняющегося текста.** Прототипу, внутреннему инструменту или сайту с одним дополнительным языком, тексты для которого пишет коллега, большего и не нужно.
* **Языки, в которых множественное число устроено как в английском.** В английском и немецком используются только категории [`one` и `other`](https://www.unicode.org/cldr/charts/latest/supplemental/language_plural_rules.html).

## Что ломается по мере роста

Вот типичная первая версия, в которую добавлен польский словарь:

```js title="i18n.mjs"
const messages = {
  en: {
    greeting: 'Hello, {name}!',
    files: { one: '{count} file', other: '{count} files' },
    checkout: 'Checkout',
  },
  pl: {
    greeting: 'Cześć, {name}!',
    files: { one: '{count} plik', other: '{count} pliki' },
    // «checkout» ещё не переведён
  },
};

export function t(locale, key, vars = {}) {
  let message = messages[locale][key];
  if (typeof message === 'object') {
    message = vars.count === 1 ? message.one : message.other;
  }
  return message.replace(/\{(\w+)\}/g, (_, name) => vars[name]);
}

console.log(t('pl', 'greeting', { name: 'Ania' }));
console.log([1, 2, 5].map((count) => t('pl', 'files', { count })).join(', '));
console.log(t('pl', 'checkout'));
```

Запускаем с Node.js 24:

```text title="Output"
Cześć, Ania!
1 plik, 2 pliki, 5 pliki
TypeError: Cannot read properties of undefined (reading 'replace')
```

Сразу всплывают две ошибки. &quot;5 pliki&quot; — неверная форма (по-польски нужно &quot;5 plików&quot;), а непереведённый ключ `checkout` ломает рендеринг. На платформе есть всё необходимое, чтобы исправить обе:

```js title="intl.mjs"
// Категории множественного числа для каждого языка
for (const locale of ['en', 'ja', 'pl', 'ar']) {
  console.log(locale, new Intl.PluralRules(locale).resolvedOptions().pluralCategories.join(' '));
}
const pl = new Intl.PluralRules('pl');
console.log([1, 2, 5, 22].map((n) => `${n} → ${pl.select(n)}`).join(', '));

// Валюты и даты
const date = new Date(Date.UTC(2026, 9, 16));
for (const locale of ['en-US', 'de-DE', 'ja-JP']) {
  const price = new Intl.NumberFormat(locale, { style: 'currency', currency: 'EUR' }).format(1234.5);
  const day = new Intl.DateTimeFormat(locale, { dateStyle: 'long', timeZone: 'UTC' }).format(date);
  console.log(locale, price, day);
}

// Направление текста
console.log(new Intl.Locale('ar').getTextInfo().direction);
```

```text title="Output"
en one other
ja other
pl one few many other
ar zero one two few many other
1 → one, 2 → few, 5 → many, 22 → few
en-US €1,234.50 October 16, 2026
de-DE 1.234,50 € 16. Oktober 2026
ja-JP €1,234.50 2026年10月16日
rtl
```

Каждое исправление по отдельности невелико, но вместе они дают заметный эффект:

* **Формы множественного числа.** Проверка `n === 1` не работает для польского (четыре категории) и арабского (шесть), поэтому вспомогательной функции нужен [`Intl.PluralRules`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules), а в каждом словаре — отдельная строка для каждой категории. (См. [Как обрабатывать формы множественного числа в React?](/kb/how-to-handle-plurals-in-react))
* **Порядок слов.** Заполнители вроде `{name}` позволяют каждому языку ставить значение в нужное место. С конкатенацией так не выйдет: `t('by') + ' ' + author` ставит имя в конец, а по-японски пишут «Ana 著».
* **Форматирование.** `{count}` вставляет число как есть, поэтому вспомогательной функции нужен ещё и [`Intl.NumberFormat`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/NumberFormat), чтобы в польском 12,500 выводилось как «12 500».
* **Отсутствующие ключи.** Вспомогательной функции нужна цепочка резервных вариантов (целевой язык, затем исходный, затем сам ключ), иначе пользователи увидят `undefined` или приложение упадёт.
* **Синхронизация файлов.** Вы не узнаете, что в `pl` нет `checkout` или осталась прошломесячная формулировка, пока это не заметит пользователь.
* **Языки с написанием справа налево.** Для арабского и иврита на странице нужны `lang` и `dir="rtl"`, а также зеркальная вёрстка.
* **Поисковые системы.** Если переключатель хранит выбор в состоянии или cookie-файле, все языки остаются на одном URL, тогда как Google рекомендует отдельный URL для каждого языка ([Managing multilingual sites](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)). (См. [Как настроить SEO для многоязычного приложения Next.js?](/kb/multilingual-nextjs-seo))
* **Сами переводы.** От этих затрат не избавит никакая вспомогательная функция: кто-то должен написать «plików» и все остальные строки на каждом языке — и делать это заново при каждом изменении английского текста.

Когда вспомогательная функция научится обрабатывать категории множественного числа, резервные варианты и форматирование чисел, окажется, что вы по сути написали ядро библиотеки интернационализации — а переводы всё равно понадобятся.

## Что General Translation предлагает взамен

General Translation сохраняет сильные стороны самописного подхода (читаемые тексты и форматирование средствами платформы) и берёт на себя то, что со временем разрастается. С `gt-react` (или `gt-next` для Next.js) тексты остаются прямо в компоненте внутри [`<T>`](/docs/react/reference/components/t), поэтому не нужно поддерживать ни словарь, ни вспомогательную функцию:

```tsx title="Inbox.tsx"
import { T, Plural, Num, Var } from 'gt-react';

export function Inbox({ name, count }: { name: string; count: number }) {
  return (
    <T>
      <h1>Welcome back, <Var>{name}</Var></h1>
      <Plural
        n={count}
        singular={<p>You have <Num>{count}</Num> unread message.</p>}
        plural={<p>You have <Num>{count}</Num> unread messages.</p>}
      />
    </T>
  );
}
```

[`<Plural>`](/docs/react/reference/components/plural) выбирает ветку по правилам множественного числа CLDR для каждой локали — тем же правилам, на которых основан `Intl.PluralRules`, поэтому писать проверку `n === 1` и ошибаться в ней не придётся. [`<Num>`](/docs/react/reference/components/num) форматирует число в соответствии с локалью читателя, а значение внутри [`<Var>`](/docs/react/reference/components/var) никогда не отправляется в API General Translation. Ниже показан результат серверного рендеринга компонента с `gt-react` 11.4.12; для наглядности испанский перевод вписан в шаблон [`gt generate`](/docs/cli/reference/commands/generate) вручную (текстовые разделители React удалены):

```html title="Output"
<!-- en, count = 12500 -->
<h1>Welcome back, Ana</h1><p>You have 12,500 unread messages.</p>
<!-- es, count = 12500 -->
<h1>Hola de nuevo, Ana</h1><p>Tienes 12.500 mensajes sin leer.</p>
```

Если для какого-либо блока в локали нет перевода, [`<T>`](/docs/react/reference/components/t) выводит исходное содержимое, а не `undefined` и не ошибку.

Но главное отличие в том, что переводы создаёт сам General Translation:

* **Перевод с учётом контекста.** [`npx gt translate`](/docs/cli/reference/commands/translate) отправляет каждый блок [`<T>`](/docs/react/reference/components/t) вместе с его элементами, переменными, ветвями множественного числа и заметкой [`context`](/docs/react/reference/components/t#context), если она есть, и записывает отдельный файл для каждой локали. Glossary закрепляет термины, а пользовательские промпты задают тон для всех проектов с общей контекстной группой. (См. [Определение контекста для переводов](/docs/platform/dashboard/guides/defining-context-for-translations).)
* **Постоянная синхронизация.** При каждом запуске переводится новое и изменённое содержимое, а для остального повторно используются готовые переводы. Запускайте перевод в CI или поручите [Locadex](/docs/platform/locadex/quickstart) — AI-агенту General Translation — открывать пул-реквесты по выбранным вами триггерам. В приложениях на Next.js и React Locadex также может обернуть существующие тексты в [`<T>`](/docs/react/reference/components/t).
* **Проверка людьми.** Ваша команда редактирует переводы в панели управления. (См. [Проверка и редактирование переводов](/docs/platform/dashboard/guides/reviewing-translations).)
* **Направление письма и маршрутизация.** [`useLocaleDirection`](/docs/react/reference/hooks/use-locale-direction) возвращает `'rtl'` для арабского языка, а `gt-next` с помощью своего [промежуточного ПО](/docs/react/nextjs/app-router-middleware) может отдавать каждую локаль по отдельному URL.

JavaScript-библиотеки распространяются по лицензии MIT и работают без учётной записи General Translation, если вы предоставляете переводы сами. Приложение, которое загружает все переводы из своего бандла, не обращается к General Translation во время выполнения. Для создания переводов используйте облачный сервис с [оплатой по факту использования](https://generaltranslation.com/pricing).

На другом конце шкалы — Profound: с помощью General Translation компания выпускает свою платформу и документацию более чем на 47 локалях. (См. [развёртывания в рабочей среде](https://generaltranslation.com/enterprise).)

## Собственное решение, библиотека или General Translation: краткое сравнение

|                            | Собственный словарь и вспомогательная функция           | Библиотека с открытым исходным кодом, например i18next                                                              | General Translation                                                                                                                                                         |
| -------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Зависимости                | Нет                                                     | Сама библиотека и привязки к фреймворку, например `react-i18next`                                                   | `gt-react` или `gt-next`, а также CLI `gt`                                                                                                                                  |
| Формы множественного числа | Собственный код выбора формы и все формы в каждом файле | Выбор по правилам CLDR; формы предоставляют люди или подключённый сервис перевода                                   | [`<Plural>`](/docs/react/reference/components/plural) выбирает форму по правилам CLDR; при переводе формы для каждого целевого языка генерируются из написанных вами ветвей |
| Числа, даты, валюты        | API `Intl`, которые вы вызываете сами                   | Встроенные средства форматирования на основе `Intl`                                                                 | [`<Num>`](/docs/react/reference/components/num), [`<Currency>`](/docs/react/reference/components/currency) и [`<DateTime>`](/docs/react/reference/components/datetime)      |
| Отсутствующие переводы     | Зависит от вашей вспомогательной функции                | [Используется резервный язык из конфигурации, затем отображается ключ](https://www.i18next.com/principles/fallback) | Рендерится исходное содержимое                                                                                                                                              |
| Синхронизация языков       | Вручную или собственным скриптом                        | Инструменты извлечения и подключённый вами сервис перевода                                                          | Каждый запуск [`npx gt translate`](/docs/cli/reference/commands/translate) переводит новое и изменённое содержимое                                                          |
| Кто переводит              | Люди или интегрированный вами сервис                    | Люди или подключённый сервис перевода                                                                               | ИИ с учётом размеченного контекста JSX, Glossary и пользовательских промптов; ваша команда проверяет результат в панели управления                                          |
| Стоимость                  | Ваше время и стоимость интегрированных сервисов         | Библиотека бесплатна, перевод оплачивается отдельно                                                                 | Бесплатные JavaScript-библиотеки; [оплата перевода по факту использования](https://generaltranslation.com/pricing)                                                          |

## Когда стоит реализовать всё самостоятельно

Реализуйте всё самостоятельно, если вы поддерживаете один или два языка, текстов немного и они редко меняются, множественное число в ваших языках образуется так же, как в английском, а переводы пишет кто-то из команды, — или если это прототип. Подключите библиотеку с открытым исходным кодом, например i18next, если вам нужны правила множественного числа и резервные варианты, а переводчики или система управления переводами у вас уже есть. Выбирайте General Translation, если вы добавляете несколько языков, тексты меняются с каждым релизом или никому в команде не стоит возиться с польскими формами множественного числа: General Translation генерирует переводы с учётом контекста вашего кода и обновляет все языки при каждой сборке. (См. [General Translation в сравнении с i18next, react-intl и next-intl](/kb/general-translation-vs-i18n-libraries).)

## Сохраните свой словарь и доверьте его перевод CLI

Чтобы отказаться от ручного перевода, не нужно переписывать вспомогательную функцию. Перенесите сообщения для каждого языка в отдельный JSON-файл (`locales/en.json`, `locales/es.json`), оставьте свою `t()` и укажите путь к этим файлам в `gt.config.json` с помощью заполнителя `[locale]`:

```json title="gt.config.json"
{
  "defaultLocale": "en",
  "locales": [
    "es"
  ],
  "files": {
    "json": {
      "include": [
        "locales/[locale].json"
      ]
    }
  }
}
```

[`npx gt translate --dry-run`](/docs/cli/reference/commands/translate) показывает `locales/en.json` как источник, а полный запуск записывает `locales/es.json`. В этом примере используются сообщения на английском и испанском с одинаковой структурой ключей и простыми заполнителями, например `{name}`. В сопутствующем файле `locales/en.metadata.json` можно указать контекст или ограничения по количеству символов для каждого ключа. См. [JSON](/docs/cli/reference/formats/json-files) и [Метаданные, привязанные к ключам](/docs/cli/reference/keyed-metadata). Поиск по ключу и выбор формы множественного числа по-прежнему остаются за вашей вспомогательной функцией; проверьте и то и другое на отрендеренном испанском тексте.

Чтобы отказаться от вспомогательной функции, оборачивайте компоненты в [`<T>`](/docs/react/reference/components/t) по одному или сохраните ключи, используя [`useTranslations`](/docs/react/guides/translating-with-dictionaries). Если работу выполняет агент для написания кода, вместо того чтобы просить его написать вспомогательную функцию `t()`, передайте ему [инструкции для агентов](/docs/overview/for-coding-agents) от General Translation. Начните с [Быстрого старта для Next.js](/docs/react/nextjs-quickstart) или [Быстрого старта SPA для React](/docs/react/react-spa-quickstart).

## Ключевые выводы

* Словаря, вспомогательной функции `t()` и встроенных API `Intl` достаточно, если у вас один-два языка, немного текста и формы множественного числа, устроенные как в английском.
* По мере роста приложения вам приходится самостоятельно поддерживать выбор форм множественного числа, резервные варианты, форматирование, синхронизацию файлов, поддержку письма right-to-left, отдельные URL для каждой локали и сам процесс получения переводов.
* Библиотеки General Translation берут на себя работу во время выполнения, General Translation генерирует переводы, используя ваш код в качестве контекста, а если вы хотите сохранить собственный JSON-словарь, CLI может перевести и его.
