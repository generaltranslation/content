Tolgee connects keyed messages in your app to a translation editor. Its SDK can collect context from the running interface, and its platform can automatically translate new keys, including CLI imports. General Translation's inline workflow extracts source copy from marked components and sends their structure for translation. The choice affects how developers write copy and how reviewers work with the results.

## What Tolgee does well

- **Open source you can self-host.** The platform's core is [Apache 2.0](https://tolgee.io/licencing), and features in its `ee` directory (such as SSO, granular permissions, glossaries, tasks, branching, and webhooks) are under the Tolgee EE License and need a license key. The [free self-hosted version](https://tolgee.io/pricing/self-hosted) includes the core features, unlimited keys, up to 10 seats, and machine translation with your own provider keys.
- **In-context editing.** In development, hold ALT (Option on a Mac) and click a string in your running app to edit its translation. The [Tolgee Tools extension](https://docs.tolgee.io/js-sdk/in-context) for Chrome and Firefox adds screenshot capture from the same dialog and turns in-context editing on in production.
- **SDKs for many stacks.** The [JavaScript SDK](https://docs.tolgee.io/js-sdk) covers React, Vue, Angular, Svelte, and plain JavaScript, plus an integration that works with i18next. [iOS](https://docs.tolgee.io/ios-sdk) and Android SDKs update strings from Tolgee's CDN without an app release.
- **A CLI that reads your code.** `@tolgee/cli` [extracts keys and their default values](https://docs.tolgee.io/tolgee-cli/extraction/parsers) from React, Vue, Svelte, and Angular code, and its `push`, `pull`, `sync`, and `compare` commands keep the Tolgee project and your repository in step. It imports and exports many formats, including XLIFF, ARB, and Java properties.
- **AI with context.** [Machine translation](https://docs.tolgee.io/platform/translation_process/machine_translation) comes from DeepL, Google, Amazon, or Azure, and the AI Translator uses Claude or OpenAI models on Tolgee Cloud, or your own OpenAI, Azure OpenAI, Anthropic, Gemini, or OpenAI-compatible provider. It draws on screenshots, key and project descriptions, translation memory, and [key relationships the SDK records](https://docs.tolgee.io/platform/translation_process/ai_translator).
- **Delivery options.** [Content Delivery](https://docs.tolgee.io/platform/projects_and_organizations/content_delivery) publishes translations to Tolgee's CDN or your own S3 or Azure storage, so a web app can pick up changes without a rebuild.

## How does authoring differ?

With Tolgee, every string in the UI is a key with a default value:

```tsx title="src/Inbox.tsx"
import { T, useTranslate } from '@tolgee/react';

export function Inbox({ count }: { count: number }) {
  const { t } = useTranslate();
  return (
    <section>
      <h1>
        <T keyName="inbox_title" defaultValue="Inbox" />
      </h1>
      <p>
        {t('inbox_unread', '{count, plural, one {# unread message} other {# unread messages}}', { count })}
      </p>
    </section>
  );
}
```

Running `npx @tolgee/cli extract print` on this file (CLI 2.21.0) finds the two keys and their English defaults:

```text title="Output"
2 keys found in src/Inbox.tsx:
	line 8: inbox_title
		default: Inbox
	line 11: inbox_unread
		default: {count, plural, one {# unread message} other {# unread messages}}
```

Those keys connect the component to Tolgee's editor and translation workflow:

1. Name a key for each string and write the English as its default value.
2. Create the keys in the Tolgee project with `tolgee push` or [`tolgee sync`](https://docs.tolgee.io/tolgee-cli/extraction/syncing-strings).
3. Let Tolgee's [automatic translation](https://docs.tolgee.io/platform/projects_and_organizations/machine-translation-settings) fill new keys, including keys the CLI pushes, with machine translation or the AI Translator, or wait for your translators, and review the results.
4. Run [`tolgee pull`](https://docs.tolgee.io/tolgee-cli/push-pull-strings) and commit the files, or set up Content Delivery and point the SDK at it, then add each new language to the app.

These steps can run in an automated workflow. Until a translation is available, the SDK uses its configured fallback. Tolgee's AI context includes screenshots, descriptions, and relationships between keys recorded by the SDK.

For a heading, the authoring difference is small but concrete:

```tsx title="Tolgee"
<T keyName="inbox_title" defaultValue="Inbox" />
```

```tsx title="General Translation"
<T>Inbox</T>
```

The first uses [`T`](https://docs.tolgee.io/js-sdk/integrations/react/translating) from `@tolgee/react`; the second uses [`<T>`](/docs/react/reference/components/t) from `gt-react`, with each library's provider configured. In the GT version, developers edit the source text directly and the CLI extracts the marked content. For richer content, one block can include text and nested elements, preserving their relationship during translation.

Tolgee Cloud is priced mainly by hosted words, which count the base language and each translation separately, with machine translation credits per plan and unlimited seats on paid Cloud plans (the free plan has 3). Self-hosted licenses are priced by keys and seats. (See [Tolgee pricing](https://tolgee.io/pricing), checked October 2026.)

## Tolgee vs. General Translation at a glance

| Feature | Tolgee | General Translation |
| --- | --- | --- |
| Where strings live | Keys with default values in your code, synced to a Tolgee project | In your code inside [`<T>`](/docs/react/reference/components/t), or in the resource files you already have |
| How code connects | `@tolgee/cli` `push`, `pull`, and `sync`, or the SDK in development | [`npx gt translate`](/docs/cli/reference/commands/translate) in your build, or [Locadex](/docs/platform/locadex/quickstart) pull requests |
| Who translates | Automatic translation of new keys, batch translation, or your translators | The GT service generates translations; your team reviews in the Dashboard |
| Context for translation | Key and project descriptions, screenshots, translation memory, and key relationships | Inline blocks include marked element structure and explicit context; catalog translation uses file content and supplied metadata. Both use assigned Glossary and Custom Prompts |
| In-app editing | ALT+click editing in the running app, including production with a browser extension | Review and edit in the Dashboard's Translation Editor |
| Hosting | Self-hosted with Docker, or Tolgee Cloud | Hosted platform; open-source libraries and CLI |
| Pricing | Free plan; Cloud plans by hosted words; self-hosted licenses by keys and seats | [Usage-based translation](https://generaltranslation.com/pricing) |
| Native mobile apps | iOS and [Android SDKs](https://docs.tolgee.io/android-sdk) with over-the-air updates | The CLI translates iOS and Android string files; no over-the-air SDK |

## Why teams choose General Translation over Tolgee

General Translation's inline workflow suits developers who want to maintain source copy in components and reviewers who want to edit translations in the Dashboard.

- **Faster source edits.** With inline [`<T>`](/docs/react/reference/components/t) blocks, a copy change is an edit to the component. [`npx gt translate`](/docs/cli/reference/commands/translate) extracts and translates changed content; Locadex can prepare the changes as a pull request.
- **Less key maintenance.** Developers don't need to create a separate key for every sentence. Reviewers edit generated translations in the [Dashboard Translation Editor](/docs/platform/dashboard/guides/reviewing-translations).
- **Context for quality.** Text and elements inside a marked block travel together. Explicit context explains meaning, and assigned Context Groups apply terminology across the app and other projects. This supplies structural context during extraction without requiring an app screenshot.
- **Independent rendering.** The JavaScript libraries and CLI are MIT-licensed. The libraries can render supplied translations without an account, so the app can keep using them if you change how translations are produced.

The tradeoff: General Translation's platform is a hosted service. If your translations must stay on servers you run, Tolgee's self-hosted edition is the option.

Ramp localizes its dashboard, landing page, and iOS app into 11+ locales with General Translation. If you can't self-host, General Translation's [trust center](https://trust.inc/generaltranslation) documents its SOC 2 Type II and ISO 27001 certifications and GDPR compliance.

## When Tolgee is the better fit

Choose Tolgee when you need to self-host the whole platform, when translators or product managers want to edit text by clicking it in the running app, when your frontend is Angular or Svelte, when you exchange [XLIFF, ARB, or CSV files](https://docs.tolgee.io/platform/supported_formats), or when native iOS and Android apps need over-the-air string updates. Choose General Translation when inline authoring and structural context from marked components fit your development workflow, with translation review in the Dashboard.

## Moving from Tolgee to General Translation

Move one feature at a time. Replace each `<T keyName="…" defaultValue="…" />` with General Translation's [`<T>`](/docs/react/reference/components/t) around the English content, and each `t('key', 'default')` with [`useGT`](/docs/react/reference/hooks/use-gt). If your team wants to keep keys, put the English values in a dictionary and read them with [`useTranslations`](/docs/react/reference/hooks/use-translations). Keep loading Tolgee's translations until each feature is migrated. (See [Migrating i18n libraries](/docs/react/guides/migrating-i18n-libraries).) Bring your glossary over too: Context Group imports accept CSV, TSV, JSON, and text files. (See [Defining context for translations](/docs/platform/dashboard/guides/defining-context-for-translations).)
