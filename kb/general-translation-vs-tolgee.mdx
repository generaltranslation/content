Tolgee is an open-source localization platform: you give each string a key, sync the keys to a Tolgee project with its CLI or SDK, translate them there with machine translation, AI, and your team, and load the results back into the app as files or from Tolgee's CDN. You can run it yourself from a Docker image or use Tolgee Cloud. Its standout feature is in-context editing: hold ALT and click any text in your running app to translate it. What Tolgee leaves to engineers is the key-based loop around that editor. General Translation starts from the code instead: content stays in your components, and translation runs as part of the build.

## What Tolgee does well

- **Open source you can self-host.** The platform's core is Apache 2.0, and features in its `ee` directory (such as SSO, granular permissions, glossaries, tasks, branching, and webhooks) are under the Tolgee EE License and need a license key. The free self-hosted version includes the core features, unlimited keys, up to 10 seats, and machine translation with your own provider keys.
- **In-context editing.** In development, hold ALT (Option on a Mac) and click a string in your running app to edit its translation. The Tolgee Tools extension for Chrome and Firefox adds screenshot capture from the same dialog and turns in-context editing on in production.
- **SDKs for many stacks.** The JavaScript SDK covers React, Vue, Angular, Svelte, and plain JavaScript, plus an integration that works with i18next. iOS and Android SDKs update strings from Tolgee's CDN without an app release.
- **A CLI that reads your code.** `@tolgee/cli` extracts keys and their default values from React, Vue, Svelte, and Angular code, and its `push`, `pull`, `sync`, and `compare` commands keep the Tolgee project and your repository in step. It imports and exports dozens of formats, including XLIFF, ARB, CSV, and Java properties.
- **AI with context.** Machine translation comes from DeepL, Google, Amazon, or Azure, and the AI Translator uses Claude or OpenAI models on Tolgee Cloud, or your own OpenAI, Azure OpenAI, Anthropic, Gemini, or OpenAI-compatible provider. It draws on screenshots, key and project descriptions, translation memory, and key relationships the SDK records.
- **Delivery options.** Content Delivery publishes translations to Tolgee's CDN or your own S3 or Azure storage, so a web app can pick up changes without a rebuild.

## What Tolgee still leaves to your engineers

With Tolgee, every string in the UI is a key with a default value:

```tsx title="src/Inbox.tsx"
import { T, useTranslate } from '@tolgee/react';

export function Inbox({ count }: { count: number }) {
  const { t } = useTranslate();
  return (
    <section>
      <h1>
        <T keyName="inbox_title" defaultValue="Inbox" />
      </h1>
      <p>
        {t('inbox_unread', '{count, plural, one {# unread message} other {# unread messages}}', { count })}
      </p>
    </section>
  );
}
```

Running `npx @tolgee/cli extract print` on this file (CLI 2.21.0) finds the two keys and their English defaults:

```text title="Output"
2 keys found in src/Inbox.tsx:
	line 8: inbox_title
		default: Inbox
	line 11: inbox_unread
		default: {count, plural, one {# unread message} other {# unread messages}}
```

Extraction finds the keys, but getting new copy into every language is still a loop:

1. Name a key for each string and write the English as its default value.
2. Create the keys in the Tolgee project with `tolgee push` or `tolgee sync`.
3. Wait while machine translation, the AI Translator, or your translators fill in each language, and review the results.
4. Run `tolgee pull` and commit the files, or set up Content Delivery and point the SDK at it, then add each new language to the app.

Until a key is translated, readers see the fallback language or the English default. And the AI Translator works from screenshots and descriptions that someone attaches, and from which keys appear together on screen, not from the component that renders the string.

Tolgee Cloud is priced mainly by hosted words, which count the base language and each translation separately, with machine translation credits per plan and unlimited seats on current plans. Self-hosted licenses are priced by keys and seats. (See [Tolgee pricing](https://tolgee.io/pricing), checked October 2026.)

## Tolgee vs. General Translation at a glance

| Feature | Tolgee | General Translation |
| --- | --- | --- |
| Where strings live | Keys with default values in your code, synced to a Tolgee project | In your code inside [`<T>`](/docs/react/reference/components/t), or in the resource files you already have |
| How code connects | `@tolgee/cli` `push`, `pull`, and `sync`, or the SDK in development | [`npx gt translate`](/docs/cli/reference/commands/translate) in your build, or [Locadex](/docs/platform/locadex/quickstart) pull requests |
| Who translates | Machine translation, the AI Translator, or your translators | AI with context from your code, Glossary, and Custom Prompts, reviewed by your team in the Dashboard |
| Context for each string | Key and project descriptions, screenshots, translation memory, and key relationships | The component and elements around the string, its variables, context notes, Glossary, and Custom Prompts |
| In-app editing | ALT+click editing in the running app, including production with a browser extension | Review and edit in the Dashboard's Translation Editor |
| Hosting | Self-hosted with Docker, or Tolgee Cloud | Hosted platform; open-source libraries and CLI |
| Pricing | Free plan; Cloud plans by hosted words; self-hosted licenses by keys and seats | Usage-based; $0 platform fee and unlimited users, projects, and languages on Starter |
| Native mobile apps | iOS and Android SDKs with over-the-air updates | The CLI translates iOS and Android string files; no over-the-air SDK |

## Why teams choose General Translation over Tolgee

General Translation starts from the code, so there are no keys to name or sync. Copy stays in your components inside [`<T>`](/docs/react/reference/components/t) (which wraps the content itself, unlike Tolgee's key-based component of the same name), and translation runs with each release.

- **Faster.** [`npx gt translate`](/docs/cli/reference/commands/translate) runs in your build, or Locadex opens a pull request when code changes, so new copy ships translated with the release that adds it. Adding a language is one line in `gt.config.json`, and the next build translates the whole project into it.
- **Cheaper to run.** Engineers don't name keys, write default values, or pull files between systems. General Translation's pricing is usage-based, with a $0 platform fee and unlimited users, projects, and languages on Starter. (See [pricing](https://generaltranslation.com/pricing).)
- **Higher quality.** General Translation sends the context of the code with every translation: the elements around a string, the variables in the sentence, and the branches that choose between versions of it, plus your Glossary and Custom Prompts across every project. Nobody has to attach a screenshot first.
- **Lower risk.** General Translation's libraries and CLI are open source under the MIT license and work without an account, and translations can live as files in your repository, so you can change how translations are produced without rewriting your app.

The tradeoff: General Translation's platform is a hosted service. If your translations must stay on servers you run, Tolgee's self-hosted edition is the option.

## When Tolgee is the better fit

Choose Tolgee when you need to self-host the whole platform, when translators or product managers want to edit text by clicking it in the running app, when your frontend is Angular or Svelte, when you exchange XLIFF, ARB, or CSV files, or when native iOS and Android apps need over-the-air string updates. Choose General Translation when most of your product's text lives in React, Next.js, or Vue code and you want each release to ship in every language without a key-sync step.

## Moving from Tolgee to General Translation

Move one feature at a time. Replace each `<T keyName="…" defaultValue="…" />` with General Translation's [`<T>`](/docs/react/reference/components/t) around the English content, and each `t('key', 'default')` with [`useGT`](/docs/react/reference/hooks/use-gt). If your team wants to keep keys, put the English values in a dictionary and read them with [`useTranslations`](/docs/react/reference/hooks/use-translations). Keep loading Tolgee's translations until each feature is migrated. (See [Migrating i18n libraries](/docs/react/guides/migrating-i18n-libraries).) Bring your glossary over too: Context Group imports accept CSV, TSV, JSON, and text files. (See [Defining context for translations](/docs/platform/dashboard/guides/defining-context-for-translations).)

## Key takeaways

- Tolgee is an open-source, self-hostable localization platform with in-context editing, SDKs for many stacks, and AI that draws on screenshots and descriptions.
- Engineers still name keys, sync them with the CLI, wait for translations, and pull the results back into the app.
- General Translation translates content where it's written, with the context of the code, and ships every language with each release, on MIT-licensed libraries with no lock-in.
