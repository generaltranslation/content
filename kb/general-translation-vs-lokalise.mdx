Lokalise describes itself as an AI localization platform. Its Lokalise Expert workspace, built for apps and software, stores strings as keys in projects, imports and exports them as files for each platform, and translates them with AI, machine translation, or professional translators; a newer Lokalise Vantage workspace covers marketing and long-form content. For a development team, Lokalise still sits beside the code: keys are created and synced, and translated files come back as a pull request. General Translation starts from the code instead.

## What Lokalise does well

- **One key set for every platform.** A project holds keys for web, iOS, and Android and exports each platform's file format.
- **AI with context.** Standard AI and machine translation use Google Translate and DeepL, and Pro AI routes across models from providers such as OpenAI and Anthropic, using your translation memory, glossary, style guide, screenshots, and key metadata. Custom AI Profiles add retrieval from translation memory on the Advanced plan and up.
- **Design workflows.** Figma, Adobe XD, and Sketch plugins, screenshots whose text is matched to keys automatically, and the LiveJS in-context editor for websites.
- **Translator tooling.** Tasks, review steps, automations, branching, and QA checks, with glossary and translation memory from the Growth plan.
- **Professional translation.** Order from Lokalise's translators or Gengo inside a project; Lokalise says mid-size projects are typically delivered within 24 hours.
- **Mobile over-the-air updates.** iOS, Android, and Flutter SDKs update strings without an app release.
- **Security.** SOC 2 Type II, ISO 27001, and ISO 27017, with data hosted in AWS's EU regions.

## What Lokalise still leaves to your engineers

With Lokalise, new copy reaches every language through a round trip:

1. Set up an i18n library and create a key for each string in your resource files.
2. Send the base-language files to Lokalise with `lokalise2 file upload`, the GitHub app (on demand or automatically on push), or Lokalise's push GitHub Action.
3. Wait while Lokalise AI, machine translation, or translators fill in each language.
4. Bring the translations back by triggering a download, which opens a pull request from a new branch, or with the pull GitHub Action. Then merge, wire each new language into the app, and check every screen.

The AI's context is what's attached to each key: translation memory, glossary, style guide, screenshots, and metadata. The component a key renders in, and the variables and branches around it, stay in your code.

Plans run from Explorer to Enterprise, with allowances for projects, languages, processed words, AI-translated words, seats, integrations, and over-the-air calls, and every plan starts with a 14-day trial. (See [Lokalise pricing](https://lokalise.com/pricing/), checked October 2026.)

## Lokalise vs. General Translation at a glance

| Feature | Lokalise | General Translation |
| --- | --- | --- |
| Where strings live | Keys in Lokalise projects, synced with your resource files | In your code inside [`<T>`](/docs/react/reference/components/t), or in the resource files you already have |
| How code connects | `lokalise2` CLI, GitHub app, or GitHub Actions | [`npx gt translate`](/docs/cli/reference/commands/translate) in your build, or [Locadex](/docs/platform/locadex/quickstart) pull requests |
| Who translates | Lokalise AI, machine translation, or professional translators | AI with context from your code, Glossary, and Custom Prompts, reviewed by your team in the Dashboard |
| Context for each string | Translation memory, glossary, style guide, screenshots, and key metadata | The component and elements around the string, its variables, context notes, Glossary, and Custom Prompts |
| Pricing | Plan tiers with usage and seat allowances; 14-day trial | Usage-based; $0 platform fee and unlimited users, projects, and languages on Starter |
| Native mobile apps | Over-the-air SDKs for iOS, Android, and Flutter | The CLI translates iOS and Android string files; no over-the-air SDK |

## Why teams choose General Translation over Lokalise

General Translation starts from the code, so the round trip goes away: copy stays in your components inside [`<T>`](/docs/react/reference/components/t), and translation runs with each release.

- **Faster.** [`npx gt translate`](/docs/cli/reference/commands/translate) runs in your build, or Locadex opens a pull request with translations when code changes, so new copy ships translated with the release that adds it. Adding a language is one line in `gt.config.json`.
- **Cheaper.** With [`<T>`](/docs/react/reference/components/t), engineers don't create keys or move files between systems. Pricing is usage-based, with no word or seat allowances to outgrow, and Starter includes unlimited users, projects, and languages.
- **Higher quality.** Every translation carries the context of the code itself: the component and elements around a string, the variables in the sentence, and the conditions that choose between versions of it, plus your Glossary and Custom Prompts across every project.
- **Lower risk.** General Translation's libraries and CLI are open source under the MIT license and work without an account, and translations can live as files in your repository, so you can change how translations are produced without rewriting your app.

## When Lokalise is the better fit

Choose Lokalise when designers and translators work from Figma or screenshots, when you want professional translation ordered inside the same tool, when native mobile apps need over-the-air updates, when you exchange XLIFF or ARB files, when your data must stay in the EU, or when marketing and long-form content belongs in the same platform through Lokalise Vantage.

## Moving from Lokalise to General Translation

You can keep your file layout. Export your keys in the format your app already loads, point `gt.config.json` at those files, and run [`npx gt upload`](/docs/cli/reference/commands/upload), which sends your sources and existing translations to the platform. Context Group imports accept CSV, TSV, JSON, and text files for your glossary. (See [Defining context for translations](/docs/platform/dashboard/guides/defining-context-for-translations).) For how Lokalise compares with other TMS platforms, see [Why use General Translation instead of a TMS?](/kb/general-translation-vs-tms)

## Key takeaways

- Lokalise is a strong TMS for multi-platform keys, design-led workflows, and mobile over-the-air updates, with AI that draws on translation memory, glossaries, and screenshots.
- Engineers still create keys, sync files, wait for translations, and merge them back, and plans set allowances for words, seats, and integrations.
- General Translation translates content where it's written, with the context of the code, and ships every language with each release, on open-source libraries with no lock-in.
