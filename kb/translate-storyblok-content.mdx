Storyblok is a Dashboard-managed integration, so there is no package to install. General Translation stores each translation per field and per language inside the same story, next to the source value. Your story structure and slugs stay the same, and your app reads the translations through Storyblok's Content Delivery API.

## Requirements

- Your [project](/docs/platform/dashboard/get-started) is on a Starter or Enterprise plan.
- Your role includes `project:write` permission to connect the space and `translations:content:write` permission to run translations.
- You have a Storyblok personal access token, which is a Management API token.

## Translate a story

1. In Storyblok, add each target language to your space's language settings. The Dashboard offers a Storyblok language as a target only when it is configured on the space and maps to a supported General Translation locale.
2. In your Storyblok account, create a personal access token. Note the space's numeric **Space ID** from **Settings > General**. Also note its **Region**, which is EU, US, CA, AP, or CN.
3. In the Dashboard, open **Project > Integrations > Catalog**, find **Storyblok**, and click **Connect**. Enter the **Space ID**, the **Region**, and the **Personal access token**. The credentials are stored in an Organization connection, and the Dashboard opens the integration's management page.
4. Choose one or more stories in the **Story** selector. Set the **Source locale**. It defaults to the project's default locale. Confirm the **Target locales**, which default to the space's languages minus the source locale.
5. Check **Auto-enable supported fields** unless those fields are already translatable in Storyblok.
6. Click **Sync and apply**.

For each story and target locale, General Translation reads the story's draft, extracts the translatable fields, and translates them. It then writes the results back into the story as a draft. Nothing is published automatically. Values translated in an earlier run are reused instead of being translated again. When a run finishes, the management page shows a summary with the succeeded and failed counts, the fields extracted, and any skipped fields grouped by component and reason.

## Translatable fields

Storyblok stores a field-level translation only in a field marked `translatable: true` in its component schema, and General Translation skips supported fields that are not translatable. **Auto-enable supported fields** marks the supported `text`, `textarea`, `markdown`, `richtext`, and `table` fields as translatable before the sync. It writes to every component in the space, including components outside the stories you selected. To enable fields one at a time instead, open each component in Storyblok's Block Library and turn on the field's translatable option.

## Review and publish

Open the story in Storyblok and switch to a target language to review the translated draft. When the translation is ready, publish the story in Storyblok.

## Fetch translated content

Your app requests the story from Storyblok's Content Delivery API and passes the target language in the `language` parameter:

```bash
# Fetch a story in a specific language
curl "https://api.storyblok.com/v2/cdn/stories/home?version=published&language=fr&token=YOUR_DELIVERY_TOKEN"
```

Storyblok returns the story with the requested language's field values in place. A request for the source language, or a request without `language`, returns the default content. Request `version=draft` to preview translations before you publish them.

The `token` parameter takes a Content Delivery API token from Storyblok. The personal access token authenticates the integration against the Management API. Keep it out of delivery requests. The hostname and parameters follow Storyblok's delivery API, so confirm them in Storyblok's documentation for your space's region.
