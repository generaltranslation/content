Multilingual SEO in Next.js means giving each language version of a page its own URL and telling search engines how those URLs relate. A page that picks its language from a cookie or the `Accept-Language` header has a single URL, so search engines usually index it in only one language. Each version also needs an `<html lang>` attribute, a canonical URL, `hreflang` alternates listing every language version (including itself), a translated title and description, and a sitemap entry. Routing, metadata, and the sitemap are written separately but must agree on every language's URLs.

| Approach | What it does well | Language URLs | What it leaves to you |
| --- | --- | --- | --- |
| An internationalization (i18n) library alone (`i18next`, `react-intl`, `next-intl`) | Mature runtimes for rendering translations and formatting values | A `[locale]` segment, with routing from the library or your own middleware | Translating titles and descriptions in message files and keeping them current |
| Google Translate in the visitor's browser | Any visitor can read any page, with no code changes | One URL per page, in the source language | Search traffic in other languages: titles and descriptions stay in the source language |
| A raw AI API (OpenAI API, Claude API) | Fluent translation that follows instructions | Routes you build yourself | A script that translates titles and descriptions and reruns on every copy change |
| General Translation (`gt-next` and the `gt` CLI) | [`<T>`](/docs/react/reference/components/t) translates JSX in place, in server and client components, and [`npx gt translate`](/docs/cli/reference/commands/translate) translates the [`getGT`](/docs/react/nextjs/reference/functions/get-gt) titles and descriptions in `generateMetadata` before `next build` | [`createNextMiddleware`](/docs/react/nextjs/reference/functions/create-next-middleware) serves `/about`, `/es/about`, and translated paths such as `/fr/a-propos` | Returning the canonical URL and `hreflang` alternates from `generateMetadata`, and listing each language in `app/sitemap.ts` |

Use an i18n library alone when you have translators and copy that rarely changes. Use browser translation when the pages need no search traffic in other languages, for example an app behind a login, which search engines can't crawl. A raw AI API script is enough for a one-time translation of a few static pages. Use `gt-next` when the app ships new copy often and every language version needs its own indexed page and translated title.

General Translation's `gt-next` handles the routing and the translations, and your Next.js code publishes the metadata. Create `proxy.ts` (`middleware.ts` on Next.js 15 and earlier), move your pages under `app/[locale]`, and add `getLocale.ts` if you prerender:

```ts title="proxy.ts"
import { createNextMiddleware } from 'gt-next/middleware';

export default createNextMiddleware();

export const config = {
  matcher: ['/((?!api|static|.*\\..*|_next).*)'],
};
```

The `prefixDefaultLocale` option also prefixes the default locale, and `pathConfig` localizes paths. The root layout from the [Next.js App Router Quickstart](/docs/react/nextjs-quickstart) already sets `<html lang={locale}>` with [`useLocale`](/docs/react/reference/hooks/use-locale). In each page's `generateMetadata`, translate the title and description with [`getGT`](/docs/react/nextjs/reference/functions/get-gt) from `gt-next/server`, and return `alternates.canonical` and `alternates.languages`; Next.js turns `alternates.languages` into `hreflang` links. Use the same language-to-URL map in `app/sitemap.ts`. Profound trusts General Translation to translate their main product, built using the Next.js App Router, into 47 languages. The [App Router middleware guide](/docs/react/nextjs/app-router-middleware) has the routing steps, and [Managing locale alias SEO](/docs/react/nextjs/locale-alias-seo) has `generateMetadata` and `app/sitemap.ts` examples.
