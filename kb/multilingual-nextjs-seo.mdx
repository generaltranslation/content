## Why multilingual SEO needs special attention

Most developers who add i18n to their Next.js app focus on translating the UI and call it done.
But if search engines can't find, index, and properly associate your language versions,
all that translation work is invisible.

A multilingual site without proper SEO setup has problems:

- Google may index only one language version and ignore the rest
- Users searching in Spanish get served the English page
- Search engines may treat `/en/about` and `/fr/about` as duplicates and choose the wrong canonical page
- Incorrect language shown in search result snippets

**The good news:** getting multilingual SEO right in Next.js isn't complicated.
There are six things you need to get right, and this guide covers all of them using [`gt-next`](/docs/react/nextjs-quickstart).

---

## 1. Locale-based URL routing

The foundation of multilingual SEO is having distinct URLs for each language.
Search engines need separate, crawlable URLs to index each language version independently.

This means **locale-in-the-URL** — not cookies, not query parameters, not `Accept-Language` detection alone.

```text
✅ generaltranslation.com/about
✅ generaltranslation.com/fr/about
✅ generaltranslation.com/es/about

❌ generaltranslation.com/about?lang=fr
❌ generaltranslation.com/about (with locale in a cookie)
```

### Setting up locale routing with gt-next

First, nest your pages under a `[locale]` dynamic segment:

```text
app/
└── [locale]/
    ├── layout.tsx
    ├── page.tsx
    └── about/
        └── page.tsx
```

Then create middleware in your project root (`proxy.ts` for Next.js 16+, or `middleware.ts` for Next.js 15 and below):

```ts title="proxy.ts"
import { createNextMiddleware } from 'gt-next/middleware';

export default createNextMiddleware();

export const config = {
  matcher: ['/((?!api|static|.*\\..*|_next).*)'],
};
```

This gives you locale-prefixed URLs automatically.
By default, the default locale (e.g., English) doesn't get a prefix — `/about` stays clean,
while Spanish users see `/es/about` and French users see `/fr/about`.

## 2. Setting the HTML `lang` attribute

The `lang` attribute on your `<html>` tag tells browsers and search engines which language the page is in.
It's one of the simplest and most impactful things you can do for accessibility and SEO.

Without it, screen readers guess the language (often wrong), and search engines have less confidence in their language classification.

In an async root layout, read the locale with [`getLocale`](/docs/react/nextjs/reference/functions/get-locale):

```tsx title="app/[locale]/layout.tsx"
import { GTProvider } from 'gt-next';
import { getLocale } from 'gt-next/server';

export default async function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  const locale = await getLocale();

  return (
    <html lang={locale}>
      <body>
        <GTProvider>{children}</GTProvider>
      </body>
    </html>
  );
}
```

[`getLocale`](/docs/react/nextjs/reference/functions/get-locale) returns the BCP 47 locale code (e.g., `en-US`, `ar`, `zh-Hans`). For static generation, configure the root locale function described in the [App Router static site generation guide](/docs/react/nextjs/app-router-static-site-generation).

## 3. Canonical URLs

Canonical tags tell search engines which URL is the "primary" version of a page.
For multilingual sites, each language version should point to itself as the canonical:

```html
<!-- On /fr/about -->
<link rel="canonical" href="https://example.com/fr/about" />
```

This prevents search engines from treating your French page as a duplicate of your English page.

In Next.js, set canonicals through the [metadata API](https://nextjs.org/docs/app/api-reference/functions/generate-metadata).
The default middleware configuration leaves the default locale unprefixed, so account for it when building the URL:

```tsx title="app/[locale]/about/page.tsx"
import { getDefaultLocale } from 'gt-next';
import { getLocale } from 'gt-next/server';

const BASE_URL = 'https://example.com';

export async function generateMetadata() {
  const locale = await getLocale();
  const defaultLocale = getDefaultLocale();
  const path = '/about';

  const prefix = locale === defaultLocale ? '' : `/${locale}`;

  return {
    alternates: {
      canonical: `${BASE_URL}${prefix}${path}`,
    },
  };
}

export default function AboutPage() {
  return <h1>About Us</h1>;
}
```

These examples use locale codes as URL segments. If you configure custom URL aliases, keep the alias in each URL and use its canonical BCP 47 code for `lang` and `hreflang`. (See [Managing locale alias SEO](/docs/react/nextjs/locale-alias-seo)).

## 4. Hreflang tags

Hreflang tags are the most important multilingual SEO signal.
They tell search engines: "this page exists in these other languages, and here are the URLs."

Without hreflang, Google has to guess which language version to show in search results — and it often gets it wrong.

```html
<link rel="alternate" hreflang="en" href="https://example.com/about" />
<link rel="alternate" hreflang="fr" href="https://example.com/fr/about" />
<link rel="alternate" hreflang="es" href="https://example.com/es/about" />
<link rel="alternate" hreflang="x-default" href="https://example.com/about" />
```

The `x-default` tag tells search engines which URL to show when none of the specified languages match the user.

In Next.js, you can add hreflang through the metadata API's `alternates.languages` property.
Here's a reusable helper that works with gt-next:

```tsx title="lib/i18n-metadata.ts"
import { getDefaultLocale, getLocales } from 'gt-next';
import {
  getLocale,
  resolveCanonicalLocale,
} from 'gt-next/server';

const BASE_URL = 'https://example.com';

export async function getI18NMetadata(path: string) {
  const locale = await getLocale();
  const defaultLocale = getDefaultLocale();

  const getUrl = (loc: string) => {
    const prefix = loc === defaultLocale ? '' : `/${loc}`;
    return `${BASE_URL}${prefix}${path}`;
  };

  const languages = Object.fromEntries([
    ...getLocales().map((urlLocale) => [
      resolveCanonicalLocale(urlLocale),
      getUrl(urlLocale),
    ]),
    ['x-default', getUrl(defaultLocale)],
  ]);

  return {
    alternates: {
      canonical: getUrl(locale),
      languages,
    },
  };
}
```

Then use it in any page:

```tsx title="app/[locale]/about/page.tsx"
import { getI18NMetadata } from '@/lib/i18n-metadata';

export async function generateMetadata() {
  return await getI18NMetadata('/about');
}
```

This generates both the canonical and all hreflang tags in one call.

## 5. Translated metadata

Search engines display your page title and description in results.
If these are in English for a French page, users are less likely to click — and Google may demote the result.

Use gt-next's [`getGT`](/docs/react/nextjs/reference/functions/get-gt) function to translate metadata strings:

```tsx title="app/[locale]/about/page.tsx"
import { getGT } from 'gt-next/server';
import { getI18NMetadata } from '@/lib/i18n-metadata';

export async function generateMetadata() {
  const t = await getGT();
  const i18nMeta = await getI18NMetadata('/about');

  return {
    title: t('About Us'),
    description: t('Learn about our mission and team.'),
    ...i18nMeta,
  };
}
```

This gives you localized titles and descriptions in search results,
which significantly improves click-through rates for non-English queries.

## 6. Multilingual sitemaps

A sitemap helps search engines discover all your pages, including every language version.
For multilingual sites, you should include hreflang annotations in your sitemap as well.

Next.js supports [programmatic sitemaps](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/sitemap) through a `sitemap.ts` file:

```ts title="app/sitemap.ts"
import type { MetadataRoute } from 'next';
import { getDefaultLocale, getLocales } from 'gt-next';
import { resolveCanonicalLocale } from 'gt-next/server';

const BASE_URL = 'https://example.com';
const PAGES = ['/', '/about', '/blog', '/contact'];

export default function sitemap(): MetadataRoute.Sitemap {
  const locales = getLocales();
  const defaultLocale = getDefaultLocale();

  return PAGES.flatMap((path) => {
    const getUrl = (locale: string) => {
      const prefix = locale === defaultLocale ? '' : `/${locale}`;
      return `${BASE_URL}${prefix}${path === '/' ? '' : path}`;
    };

    const languages = Object.fromEntries([
      ...locales.map((urlLocale) => [
        resolveCanonicalLocale(urlLocale),
        getUrl(urlLocale),
      ]),
      ['x-default', getUrl(defaultLocale)],
    ]);

    return locales.map((locale) => ({
      url: getUrl(locale),
      lastModified: new Date(),
      alternates: { languages },
    }));
  });
}
```

This generates a sitemap with one entry per page per locale,
and each entry includes hreflang annotations pointing to all language versions.
