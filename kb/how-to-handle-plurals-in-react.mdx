Handling plurals in React means showing the sentence that agrees with a count, chosen by the plural rules of the user's language. JavaScript's built-in [`Intl.PluralRules`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules) maps a number to a Unicode CLDR (Common Locale Data & Rules) plural category, such as `one`, `few`, or `other`, but the forms differ by language: English has 2, Arabic has 6, and Japanese has 1. A `count === 1` check models only English, so an Arabic page gets one sentence for 2, 3, and 11, where Arabic uses three forms. Each target language needs its own sentence for every form it uses.

| Approach | What it does well | What it leaves to you |
| --- | --- | --- |
| A `count === 1` check | No dependency, and correct for English | Languages with more forms, such as Arabic's `zero`, `two`, `few`, and `many` |
| An internationalization (i18n) library alone (`i18next`, `react-intl`) | Picks the form for each locale with CLDR plural rules | Writing every form of every message in a key file per language, including the forms English lacks |
| Google Translate | Fast, general-purpose translation of text | Writing a sentence for each form a language needs, and the code that picks one at render |
| A raw AI API (OpenAI API, Claude API) | Fluent translation that follows instructions, including a request for every form | Prompting for each language's forms, checking them against its CLDR categories, the code that picks one, review, and delivery |
| General Translation ([`<Plural>`](/docs/react/reference/components/plural) in `gt-react` and `gt-next`) | [`npx gt translate`](/docs/cli/reference/commands/translate) translates your source forms and adds the forms each target language needs; [`<Plural>`](/docs/react/reference/components/plural) picks one with CLDR rules | Writing your source language's forms, putting the count in [`<Plural>`](/docs/react/reference/components/plural) and [`<Num>`](/docs/react/reference/components/num) inside [`<T>`](/docs/react/reference/components/t), a one-time setup, and rerunning [`npx gt translate`](/docs/cli/reference/commands/translate) when content changes |

Use a `count === 1` check, or `Intl.PluralRules` with your own sentences, when the app ships only in English, since English has just `one` and `other`. Use an i18n library alone when your team already keeps key files and translators write every form by hand. Use General Translation when the app ships in several languages and changes often, so a new plural message gets its forms in every language with the release that adds it.

General Translation handles plurals with the [`<Plural>`](/docs/react/reference/components/plural) component in `gt-react` and `gt-next` (also in the experimental `gt-tanstack-start` and `gt-react-native`). Pass the count as `n` and one prop per form your source language uses, such as `one` and `other`, then place [`<Plural>`](/docs/react/reference/components/plural) inside [`<T>`](/docs/react/reference/components/t) with the count in [`<Num>`](/docs/react/reference/components/num). [`<T>`](/docs/react/reference/components/t) translates its contents as one unit, so [`npx gt translate`](/docs/cli/reference/commands/translate) translates the forms together. It also adds the forms each target language needs, such as Arabic's `zero`, `two`, `few`, and `many`.

```tsx
import { T, Plural, Num } from 'gt-react';

<T>
  <Plural
    n={count}
    one={<>You have <Num>{count}</Num> message.</>}
    other={<>You have <Num>{count}</Num> messages.</>}
  />
</T>;
```

At render, [`<Plural>`](/docs/react/reference/components/plural) picks a form with the active locale's [CLDR plural rules](https://cldr.unicode.org/index/cldr-spec/plural-rules), and [`<Num>`](/docs/react/reference/components/num) formats the count for that locale without sending it to the General Translation API. [Handling plurals and branches](/docs/react/guides/handling-plurals-and-branches) has the full steps, and the [React overview](/docs/react/overview#frameworks) links each framework's Quickstart.
