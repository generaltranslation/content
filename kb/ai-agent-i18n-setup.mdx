Yes. A coding agent such as Cursor, Claude Code, or Copilot can set up internationalization (i18n), the code changes that let an app show its text in more than one language: it installs a library, marks each string for translation, adds a language switcher, and runs the build. Working from memory, though, it can call APIs and pass CLI flags that have since changed. It can also stall, because an interactive setup command waits at its first question and signing in needs a person. Without browser tools, it can't see the page it reports as done.

| Approach | What it does well | Code changes the agent makes | What it leaves to you |
| --- | --- | --- | --- |
| An i18n library alone (`i18next`, `react-intl`, `next-intl`) | Mature runtimes for rendering translations and formatting values | Replaces each string with a key lookup, such as `t('home.title')`, and creates a message file per language | Translating every file yourself or with translators, keeping every file current as copy changes, and checking that the agent used the library's current API |
| Google Translate | Fast, general-purpose translation of text | The same keyed files, plus a script that sends each string to the API | It translates each string on its own, without the surrounding UI or your tone; plurals, review, and rerunning the script on every copy change are up to you |
| A raw AI API (OpenAI API, Claude API), or the agent itself | Fluent translation that follows instructions | The same keyed files, with translations written into each one | Context beyond what the agent loaded in that session, consistent terms across sessions and releases, translating copy added later, and review |
| General Translation (the start prompt that **Setup for Agents** copies, and the `gt` CLI) | [`npx gt translate`](/docs/cli/reference/commands/translate) translates each [`<T>`](/docs/react/reference/components/t) as a unit and applies the Context Groups (Glossary and Custom Prompts) assigned to the project | In a fresh Next.js App Router app, [`gt init`](/docs/cli/reference/commands/init) adds [`<GTProvider>`](/docs/react/reference/components/gt-provider), `withGTConfig`, and `gt.config.json`; the agent wraps text in [`<T>`](/docs/react/reference/components/t) where it is written and adds a language switcher | Approving the [`gt login`](/docs/cli/reference/commands/login) sign-in, choosing the languages and first page, reviewing the changes, and rerunning [`npx gt translate`](/docs/cli/reference/commands/translate) (locally or in CI) when copy changes, which translates only content whose source changed |

Use an i18n library alone when translators already own the message files; have the agent translate strings itself, or script Google Translate, for a prototype or a page whose copy won't change; use General Translation's start prompt when the app keeps shipping new copy. Use [Locadex](/docs/platform/locadex/quickstart), General Translation's AI agent, when you want localization pull requests opened in a Next.js or React app without driving an agent (requires a Starter or Enterprise plan).

Click **Setup for Agents** on generaltranslation.com to copy General Translation's start prompt, then paste it into your agent. It has the agent read `llms.txt` and your stack's Quickstart, ask you for the languages and first page, and sign in with [`gt login`](/docs/cli/reference/commands/login). For a fresh app, the agent then runs [`gt init`](/docs/cli/reference/commands/init) with `--no-interactive` and a flag for every question, so the command asks nothing. For a Next.js App Router app that keeps translations in the repository and reuses a project:

```bash
npx gt@latest init --no-interactive --json --defaults \
  --default-locale <source-locale> --locales <target-locales> \
  --no-locadex --react-setup --file-formats none \
  --no-dev-credentials --project-id <project-id>
```

The framework setup in [`gt init`](/docs/cli/reference/commands/init) is experimental, so the agent checks it against the Quickstart. Then it wraps the page in [`<T>`](/docs/react/reference/components/t), adds [`<LocaleSelector>`](/docs/react/reference/components/locale-selector), runs [`npx gt translate`](/docs/cli/reference/commands/translate) and the production build, and claims no check it could not run. The [Using coding agents](/docs/overview/for-coding-agents#start-prompt) guide has the full prompt.
