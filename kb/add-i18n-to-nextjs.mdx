The `gt-next` package is the open-source internationalization (i18n) library from General Translation for Next.js, and `gt` is its CLI. The steps below are for the App Router. They take an app written in English, add Spanish, French, and Japanese, and put a language menu on the home page.

You need a Next.js App Router app on Next.js 13.0.0 or later (excluding 15.2.1 and 15.2.2) and Node.js 18 or later. A Pages Router app follows the [Next.js Pages Router Quickstart](/docs/react/nextjs-pages-router-quickstart) instead.

## 1. Install the packages

The `gt-next` package renders translations in your app. The `gt` package is the CLI that prepares translations for production.

```bash
npm i gt-next
npm i -D gt
```

## 2. Wrap your Next.js config

The [`withGTConfig`](/docs/react/nextjs/config) plugin sets up internationalization at build time. It reads your `gt.config.json` and sets up translation loading and request handling. Wrap your existing config with it and keep any options the config already has:

```ts title="next.config.ts"
import { withGTConfig } from 'gt-next/config';

const nextConfig = {};

export default withGTConfig(nextConfig);
```

## 3. List your languages

Create `gt.config.json` in the project root:

```json title="gt.config.json"
{
  "defaultLocale": "en",
  "locales": ["es", "fr", "ja"],
  "files": {
    "gt": {
      "output": "public/_gt/[locale].json"
    }
  }
}
```

The `defaultLocale` field is the language your app is written in. The `locales` field lists the languages to translate into. Pick them from the [supported locales list](/docs/platform/dashboard/reference/supported-locales). The CLI writes one file per language to the `files.gt.output` path and replaces `[locale]` with each code, such as `public/_gt/es.json`. These files are generated, so add `public/_gt/` to `.gitignore`.

## 4. Add a translation loader

Create a [`loadTranslations`](/docs/react/reference/functions/load-translations) file in `src/`:

```ts title="src/loadTranslations.ts"
export default async function loadTranslations(locale: string) {
  const translations = await import(`../public/_gt/${locale}.json`);
  return translations.default;
}
```

The plugin detects a `loadTranslations.[js|ts]` file in `src/` with no other configuration. When it finds one, the translation files are bundled with your app. Without one, `gt-next` fetches translations from the General Translation CDN. The CLI saves translations to local files by default, so the loader is how those files reach the app.

The translation files do not exist until the CLI creates them, and until then `npm run dev` fails to compile. Run [`npx gt generate`](/docs/cli/reference/commands/generate), which needs no API key, or add an empty `{}` file for each language at `public/_gt/[locale].json`.

## 5. Add the provider to the root layout

The [`<GTProvider>`](/docs/react/reference/components/gt-provider) component gives your app access to translations, and it must wrap the app in the root layout. The [`useLocale`](/docs/react/reference/hooks/use-locale) hook returns the active locale, which the layout puts in the `lang` attribute:

```tsx title="app/layout.tsx"
import { GTProvider, useLocale } from 'gt-next';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  const locale = useLocale();
  return (
    <html lang={locale}>
      <body>
        <GTProvider>
          {children}
        </GTProvider>
      </body>
    </html>
  );
}
```

Keep your layout's fonts, metadata, and styles as they are.

## 6. Mark content and add a language menu

Wrap the text you want translated in the [`<T>`](/docs/react/reference/components/t) component. The component translates everything inside it as a unit, including nested elements and formatting. The [`<LocaleSelector>`](/docs/react/reference/components/locale-selector) component renders a dropdown of the languages in `gt.config.json`:

```tsx title="app/page.tsx"
import { T, LocaleSelector } from 'gt-next';

export default function Home() {
  return (
    <main>
      <LocaleSelector />
      <T>
        <h1>Welcome to my app</h1>
        <p>This content will be translated automatically.</p>
      </T>
    </main>
  );
}
```

The [`useGT`](/docs/react/reference/hooks/use-gt) hook translates plain strings, such as `placeholder` attributes, `aria-label` values, and `alt` text. Async server components cannot use hooks, so they call [`getGT`](/docs/react/nextjs/reference/functions/get-gt) from `gt-next/server` instead.

## 7. Preview translations in development

On-demand translation in development needs a [project API key](/docs/platform/dashboard/reference/api-keys#create-project-keys) with the **Runtime translation** permission. Put it and your project ID in `.env.local`:

```bash title=".env.local"
NEXT_PUBLIC_GT_DEV_API_KEY="gtx-api-your-runtime-key"
NEXT_PUBLIC_GT_PROJECT_ID="your-project-id"
```

Start the dev server with `npm run dev`, open `http://localhost:3000`, and switch languages with the dropdown. The first switch to a new language can show a short loading state while it translates. The `NEXT_PUBLIC_` prefix exposes the key to browser code, so remove `NEXT_PUBLIC_GT_DEV_API_KEY` from your production build environment. The `gt-next` package rejects it in production.

## 8. Translate before the build

In production, translations are generated at build time. Add the translate command to the build script:

```json title="package.json"
{
  "scripts": {
    "build": "npx gt translate && next build"
  }
}
```

Set `GT_PROJECT_ID` and `GT_API_KEY` in your hosting provider. The build's [`gt translate`](/docs/cli/reference/commands/translate) needs a project API key with **Files > Write** and **Translation queue > Enabled**. Keep `GT_API_KEY` on the server and never give it the `NEXT_PUBLIC_` prefix.
