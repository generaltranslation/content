Translating a Mintlify docs site means writing a copy of every page in a folder per language and listing each language in the `languages` array of the `docs.json` navigation. Pages mix prose with code blocks, MDX components, frontmatter, and links, so the prose and the `title` and `description` fields need translating, code and components must stay intact, and internal links must point to pages in the reader's language. Every edit to a source page then leaves its translations stale until someone redoes them.

## Ways to translate a Mintlify site

| Approach | What it does well | What it leaves to you |
| --- | --- | --- |
| Mintlify's `languages` navigation, translated by hand | Builds a language switcher and a page tree per language from `docs.json` | Writing every translated page into its language folder, writing a full navigation per language, and tracking which translations each source edit made stale |
| Google Translate | Translates a page you paste in, with no setup | It translates each passage on its own; separating prose from code and components, and writing the folders and the navigation, are up to you |
| A script on an AI API (OpenAI API, Claude API) | Can be told to translate prose and leave code blocks and components alone | A script that protects MDX syntax, holds product terms across pages, writes the folders and navigation, and reruns when pages change |
| General Translation (Locadex) | Opens a pull request with the translated pages, per-language navigation, and localized links, then translates each change on the trigger you choose | Reviewing and merging the setup pull request, then reviewing later pull requests or turning on **Auto-merge** |

Use Mintlify's navigation with hand translation when translators cover a few pages that rarely change; use Google Translate or a one-off AI API script for a single pass over a small, stable site. Use General Translation when the docs change every release and each language has to keep up.

## Translate Mintlify docs with Locadex

General Translation translates Mintlify docs with Locadex, its AI agent, which requires a Starter or Enterprise plan.

1. In the Dashboard, connect GitHub under **Project > Integrations > Catalog**.
2. Under **Project > Automations**, create an automation from **Generate translations and push** with **Mintlify** as the framework.
3. Click **Run setup** and pick your languages.
4. Review and merge the pull request Locadex opens.

The pull request adds a `gt.config.json`, a `docs.json` navigation entry per language, and the translated pages, where code and components keep their structure and links to translated pages stay in the reader's language. The **Run setup** dialog for Mintlify has a **Hide default locale in URL paths** toggle, which is on by default: source pages keep their current paths, and each translated language gets its own locale folder, such as `/es/...`. If you turn the toggle off, the source pages also move into a locale folder (English pages move to `/en/...`), which changes their URLs.

## Keep translations current

After that, Locadex runs when a pull request changes (the default) or when a commit is pushed. Each run applies the project's assigned Context Groups (Glossary and Custom Prompts), which your app can share, so product names match in both. The [Mintlify Quickstart](/docs/integrations/mintlify/quickstart) has the full steps.
