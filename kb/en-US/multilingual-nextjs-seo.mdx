## Why multilingual SEO needs special attention

Translating the UI does not by itself give search engines a URL for each language. This guide connects locale routing, metadata, and discovery in a Next.js App Router app using [`gt-next`](/docs/react/nextjs-quickstart).

Fully translated English and French pages are not duplicates merely because they describe the same product. Google considers localized versions duplicates when the main content remains untranslated. The practical risks are undiscovered language URLs, conflicting canonical signals, and search results that send readers to an unsuitable version. (See Google's [localized-page guidance](https://developers.google.com/search/docs/specialty/international/localized-versions)).

---

## 1. Locale-based URL routing

The foundation of multilingual SEO is having distinct URLs for each language.
Search engines need separate, crawlable URLs to index each language version independently.

Use a stable URL for each language. Cookies and `Accept-Language` can remember or suggest a preference, but they don't create separately crawlable versions. (See [locale routing and SEO](/kb/locale-routing-seo) for which signal should win, and the [URL structure comparison](/kb/multilingual-url-structure) for domains and paths).

```text
✅ example.com/en/about
✅ example.com/fr/about
✅ example.com/es/about
↪ example.com/about       (redirects to one of the above)

Discouraged by Google: example.com/about?lang=fr
❌ example.com/about (serves French or English depending on a cookie)
```

### Setting up locale routing with gt-next

First, nest your pages under a `[locale]` dynamic segment:

```text
app/
└── [locale]/
    ├── layout.tsx
    ├── page.tsx
    └── about/
        └── page.tsx
```

Then create middleware in your project root (`proxy.ts` for Next.js 16+, or `middleware.ts` for Next.js 15 and below):

```ts title="proxy.ts"
import { createNextMiddleware } from 'gt-next/middleware';

export default createNextMiddleware({ prefixDefaultLocale: true });

export const config = {
  matcher: ['/((?!api|static|.*\\..*|_next).*)'],
};
```

`prefixDefaultLocale: true` puts every locale, including English, under a prefix, so each content URL always serves one language. This article uses that configuration throughout. An unprefixed path such as `/about` becomes an entry point: the middleware answers with a temporary `307` redirect to the visitor's saved locale or best `Accept-Language` match, or to `/en/about` when there's neither. A localized URL never moves; `/en/about` returns English even to a browser that prefers French. (See [locale routing and SEO](/kb/locale-routing-seo) for why that matters and what changes if you keep the default locale unprefixed).

## 2. Setting the HTML `lang` attribute

The `lang` attribute on your `<html>` tag identifies the page language for assistive technology and language-aware browser behavior. Google determines language from the [visible content](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites#language), not the HTML `lang` attribute. Keep it accurate for accessibility; do not treat it as a Google language-detection or ranking switch.

{/* useLocale works in both client and server rendered components, just not in async components */}
gt-next provides the [`useLocale`](/docs/react/reference/hooks/use-locale) hook that makes this trivial in your root layout:

```tsx title="app/[locale]/layout.tsx"
import { useLocale, GTProvider } from 'gt-next';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  const locale = useLocale();

  return (
    <html lang={locale}>
      <body>
        <GTProvider>
          {children}
        </GTProvider>
      </body>
    </html>
  );
}
```

[`useLocale`](/docs/react/reference/hooks/use-locale) returns the BCP 47 locale code (e.g., `en-US`, `ar`, `zh-Hans`).

## 3. Canonical URLs

Canonical tags indicate the preferred URL among duplicate or very similar pages. For distinct translated pages, use a canonical pointing to that language version's preferred URL, usually itself:

```html
<!-- On /fr/about -->
<link rel="canonical" href="https://example.com/fr/about" />
```

A canonical is a signal, not a guarantee, and translation does not require a canonical tag to become distinct. Avoid pointing all translated pages at English. When several regional pages in the same language are duplicates, choose a preferred canonical in that language and keep the hreflang annotations consistent. (See [hreflang and canonical tags](/kb/what-is-hreflang#hreflang-and-canonical-tags)).

In Next.js, you set canonicals through the [metadata API](https://nextjs.org/docs/app/api-reference/functions/generate-metadata).
Combine it with gt-next's [`getLocale`](/docs/react/nextjs/reference/functions/get-locale). Because every locale has a prefix, the canonical is always the locale plus the path:

```tsx title="app/[locale]/about/page.tsx"
import { getLocale } from 'gt-next/server';

const BASE_URL = 'https://example.com';

export async function generateMetadata() {
  const locale = await getLocale();

  return {
    alternates: {
      canonical: `${BASE_URL}/${locale}/about`,
    },
  };
}

export default function AboutPage() {
  return <h1>About Us</h1>;
}
```

The next section folds this into a helper that also writes hreflang.

## 4. Hreflang tags

Hreflang annotations tell search engines which URLs are language or regional versions of the same page. The examples here generate them as HTML links from Next.js metadata. (See [What is hreflang](/kb/what-is-hreflang) for the rules).

In Next.js, you add hreflang through the metadata API's `alternates.languages` property. A translation can lag behind its page, so drive the canonical, the alternates, and the sitemap from one record of which locales each page is published in. This helper builds the canonical and the alternates from that record, and marks a version that isn't published yet `noindex`:

```ts title="lib/i18n-metadata.ts"
import type { Metadata } from 'next';
import { getLocale } from 'gt-next/server';

export const BASE_URL = 'https://example.com';

// The locales each page is published in. Add a locale once its translation is reviewed.
export const PUBLISHED: Record<string, string[]> = {
  '/': ['en', 'fr', 'es'],
  '/about': ['en', 'fr', 'es'],
  '/pricing': ['en', 'fr'], // Spanish isn't translated yet
};

export const localeUrl = (locale: string, path: string) =>
  `${BASE_URL}/${locale}${path === '/' ? '' : path}`;

export async function getI18NMetadata(path: string): Promise<Metadata> {
  const locale = await getLocale();
  const published = PUBLISHED[path] ?? [];

  // Keep an unpublished version out of the index.
  if (!published.includes(locale)) return { robots: { index: false } };

  const languages: Record<string, string> = {};
  for (const loc of published) languages[loc] = localeUrl(loc, path);
  languages['x-default'] = localeUrl('en', path);

  return { alternates: { canonical: localeUrl(locale, path), languages } };
}
```

Then call it from each page:

```tsx title="app/[locale]/pricing/page.tsx"
import { getI18NMetadata } from '@/lib/i18n-metadata';

export async function generateMetadata() {
  return getI18NMetadata('/pricing');
}
```

Built with Next.js 16.4.2 and `gt-next` 11.4.14, `/fr/about`, which is published in all three languages, rendered this `<head>`:

```html title="/fr/about"
<html lang="fr">
<link rel="canonical" href="https://example.com/fr/about"/>
<link rel="alternate" hrefLang="en" href="https://example.com/en/about"/>
<link rel="alternate" hrefLang="fr" href="https://example.com/fr/about"/>
<link rel="alternate" hrefLang="es" href="https://example.com/es/about"/>
<link rel="alternate" hrefLang="x-default" href="https://example.com/en/about"/>
```

`/fr/pricing` lists no Spanish alternate, because Spanish pricing isn't published:

```html title="/fr/pricing"
<html lang="fr">
<link rel="canonical" href="https://example.com/fr/pricing"/>
<link rel="alternate" hrefLang="en" href="https://example.com/en/pricing"/>
<link rel="alternate" hrefLang="fr" href="https://example.com/fr/pricing"/>
<link rel="alternate" hrefLang="x-default" href="https://example.com/en/pricing"/>
```

The route still answers at `/es/pricing`, but its `<head>` carries only `<meta name="robots" content="noindex"/>` and no canonical or alternates, so search engines skip it until you add `es` to the record. `x-default` points at the English version of each page, a URL that always returns English. The helper assumes the same path in every locale; if you use localized slugs or route aliases, build URLs from that route map instead.

Also provide a [language switcher](/kb/language-switcher) with ordinary links to equivalent pages. Hreflang does not replace a visible navigation choice.

## 5. Translated metadata

Write the title and description in the page's language so readers can understand the result. Search engines can generate or rewrite displayed titles and snippets, so the supplied metadata is not a promise of exact presentation or ranking.

Use gt-next's [`getGT`](/docs/react/nextjs/reference/functions/get-gt) function to translate metadata strings:

```tsx title="app/[locale]/about/page.tsx"
import { getGT } from 'gt-next/server';
import { getI18NMetadata } from '@/lib/i18n-metadata';

export async function generateMetadata() {
  const t = await getGT();
  const i18nMeta = await getI18NMetadata('/about');

  return {
    title: t('About Us'),
    description: t('Learn about our mission and team.'),
    ...i18nMeta,
  };
}
```

This supplies localized titles and descriptions. Measure actual impressions, clicks, and conversions after publication rather than assuming a fixed click-through improvement.

## 6. Multilingual sitemaps

A sitemap helps search engines discover your published language URLs. Because the earlier example declares hreflang in HTML, this sitemap only lists the URLs. You can instead declare hreflang in a sitemap, but Google says maintaining both methods provides no additional Search benefit.

Next.js supports [programmatic sitemaps](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/sitemap) through a `sitemap.ts` file. Read the same `PUBLISHED` record so the sitemap and hreflang never disagree:

```ts title="app/sitemap.ts"
import type { MetadataRoute } from 'next';
import { PUBLISHED, localeUrl } from '@/lib/i18n-metadata';

export default function sitemap(): MetadataRoute.Sitemap {
  return Object.entries(PUBLISHED).flatMap(([path, locales]) =>
    locales.map((locale) => ({ url: localeUrl(locale, path) })),
  );
}
```

The generated `/sitemap.xml` listed eight URLs: `/en`, `/fr`, `/es`, the three `/about` versions, `/en/pricing`, and `/fr/pricing`. `/es/pricing` stays out until it's published. If you add `lastModified`, use the date of the page's actual substantive update, not the time the sitemap was generated. (See Google's [sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)).
