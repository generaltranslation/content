Keeping translations up to date on every deploy is called continuous localization: translation runs as a pipeline step before each release is built, so every change ships in every language with the deploy that adds it. It's hard because the step runs in CI (continuous integration): it needs a credential that works without anyone signing in, it should translate only what changed so builds stay short, and it has to finish before the build command, or new copy ships untranslated.

## Ways to keep translations current

| Approach | What it does well | When translation happens | What it leaves to you |
| --- | --- | --- | --- |
| An internationalization (i18n) library alone (`i18next`, `react-intl`, `next-intl`) | Mature runtimes for rendering translations and formatting values | Whenever someone updates the files, often in a batch between releases | Extracting new strings into key files, adding each translation to one file per language, and getting every file translated before the release |
| A [translation management system](/kb/general-translation-vs-tms) sync ([Crowdin](/kb/general-translation-vs-crowdin), [Lokalise](/kb/general-translation-vs-lokalise)) | A CLI or GitHub integration uploads new source strings and downloads finished translations | When translators finish, often after the deploy that added the copy | Key files for every string, the sync configuration, and either holding the release or shipping untranslated copy until translations land |
| A custom script on a machine translation or AI API (DeepL, OpenAI API, Claude API) | Translates inside the pipeline, at whatever volume you send | In a CI step you write and maintain | Finding new and changed strings, context and consistent terms for each request, writing the results back, and review |
| General Translation (the `gt` CLI) | [`npx gt translate`](/docs/cli/reference/commands/translate) scans [`<T>`](/docs/react/reference/components/t) components, `useGT` calls, and the files in `gt.config.json`, and translates only content whose source changed | In CI, before the build command | Wrapping new UI copy in [`<T>`](/docs/react/reference/components/t) or passing it to the `gt` function from `useGT`, storing a project API key and the project ID as CI secrets, and reviewing translations in the Dashboard when you want a person to check them |

Use an i18n library alone when translators own the language files and each release can wait for them, and a translation management system sync when translators must approve every string before it ships. Use a custom script for a one-time pass over copy that won't change. Use a translate step in CI when most releases change copy. If copy changes only now and then, a simpler setup is enough: run [`npx gt translate`](/docs/cli/reference/commands/translate) locally after [`gt login`](/docs/cli/reference/commands/login), with `projectId` set in `gt.config.json`, and commit the files it writes.

## Add a translate step to CI

General Translation's `gt` CLI runs this step with [`npx gt translate`](/docs/cli/reference/commands/translate). Because [`gt login`](/docs/cli/reference/commands/login) needs a person to approve it, CI uses a project key instead:

1. Create a key under **Project > API Keys** with **Custom** permissions: set **Files** to **Write**, **Translation queue** to **Enabled**, and **Context** to **Write** if the pipeline generates context.
2. Store the key as `GT_API_KEY` and the project ID as `GT_PROJECT_ID` in your CI provider's secret settings.
3. Translate before the build:

   ```json title="package.json"
   {
     "scripts": {
       "translate": "npx gt translate",
       "build": "npm run translate && <your build command>"
     }
   }
   ```

## What each run does

With General Translation, each run translates only content whose source changed, applies the Context Groups (Glossary and Custom Prompts) assigned to the project so terms stay the same across releases, and saves the results to your codebase for the build to ship (or publishes them to General Translation's CDN with `--publish`, for the app to load at run time). The [Generating translations](/docs/cli/guides/generating-translations) guide has the full steps.
