Translating a React app takes two jobs: internationalization (i18n), which makes components render in the user's language, and translation of every string into each language you support. The work is hard because the text lives inside JSX, mixed with markup, variables, and plurals whose rules differ by language (English has 2 forms, Arabic has 6). The usual setup moves each string behind a key, such as `t('home.welcome')`, with one JSON file per language to keep in sync. Translated without the UI around it, a "Save" button can come back in German as *sparen* (save money) instead of *speichern* (save a file).

| Approach | What it does well | What it leaves to you |
| --- | --- | --- |
| An i18n library alone (`i18next` with `react-i18next`, or `react-intl`) | Mature runtime for rendering translations and formatting values | Replacing strings with keys, keeping a JSON file per language in sync, and producing every translation |
| Google Translate | Fast, general-purpose translation of text | Each string is translated alone, without the component or your tone; the i18n setup, plurals, and review are up to you |
| A raw AI API (OpenAI API, Claude API) | Fluent translation that follows instructions | Collecting context for every string, keeping terms consistent across releases, plurals, review, and loading results into the app |
| General Translation (`gt-react` and the `gt` CLI) | [`<T>`](/docs/react/reference/components/t) translates JSX in place with no keys, and [`npx gt translate`](/docs/cli/reference/commands/translate) writes one file per language, with the surrounding JSX structure as context | Wrapping text in [`<T>`](/docs/react/reference/components/t), a one-time setup (languages in `gt.config.json`, a loader, an entry file, sign-in, and a project ID), and rerunning [`npx gt translate`](/docs/cli/reference/commands/translate) (locally or in CI) when content changes |

Use an i18n library alone, with hand-written JSON files, when the app has a few strings that rarely change. Use Google Translate or a raw AI API for one-off text, such as a page you translate once. Use General Translation when the app keeps changing and every release has to ship in every language.

General Translation's open-source `gt-react` library and `gt` CLI translate a React single-page app (SPA), such as a Vite or webpack project. Install both, list your languages in `gt.config.json`, add a [`loadTranslations`](/docs/react/reference/functions/load-translations) function, and call [`initializeGTSPA`](/docs/react/reference/config#initialize-spa) in a small entry file so translations load before the app renders. The `npx gt@latest` setup wizard can configure the Vite entry and translation loading for you (an experimental step). Wrap your text in the [`<T>`](/docs/react/reference/components/t) component, sign in with [`npx gt login`](/docs/cli/reference/commands/login), set your project ID, and run [`npx gt translate`](/docs/cli/reference/commands/translate).

```tsx title="src/components/Welcome.tsx"
import { T } from 'gt-react';

export default function Welcome() {
  return (
    <main>
      <T>
        <h1>Welcome to my app</h1>
        <p>This content will be translated automatically.</p>
      </T>
    </main>
  );
}
```

The `context` prop on [`<T>`](/docs/react/reference/components/t) resolves an ambiguous word, such as "Save," and a Glossary and Custom Prompts in the Dashboard keep terms and tone consistent. [Server-rendered React](/docs/react/react-quickstart), [React Router framework](/docs/react/react-router-quickstart), and [Next.js](/docs/react/nextjs-quickstart) (with `gt-next`) apps have their own Quickstarts; for an SPA, the [React SPA Quickstart](/docs/react/react-spa-quickstart) has the full steps.
