Translating a React app takes two jobs: internationalization (i18n), which makes components render in the user's language, and translation of every string into each language you support. The work is hard because the text lives inside JSX, mixed with markup, variables, and plurals whose rules differ by language (English has 2 forms, Arabic has 6). The usual setup moves each string behind a key, such as `t('home.welcome')`, with one JSON file per language to keep in sync. Translated without the UI around it, a "Save" button can come back in German as *sparen* (save money) instead of *speichern* (save a file).

## Ways to translate a React app

| Approach | What it does well | What it leaves to you |
| --- | --- | --- |
| A key-based i18n library ([`i18next`](/kb/general-translation-vs-i18next) with `react-i18next`, or [`react-intl`](/kb/general-translation-vs-react-intl)) | Mature runtime for rendering translations, selecting plural forms, and formatting values | Replacing strings with keys, keeping a JSON file per language in sync, and producing every translation |
| [Lingui](/kb/general-translation-vs-lingui) | Keeps copy inline with its `<Trans>` macro, and `lingui extract` writes a catalog per language | Translating each catalog, by hand or through a connected service, and rerunning extract and compile as copy changes |
| A translation management system ([Crowdin](/kb/general-translation-vs-crowdin), [Lokalise](/kb/general-translation-vs-lokalise)) | A web editor where translators work with screenshots, a glossary, and translation memory, synced with your repository | The i18n library and key files in your code, the sync setup, and waiting on translators before each release |
| General Translation (`gt-react` and the `gt` CLI) | [`<T>`](/docs/react/reference/components/t) translates JSX in place with no keys, and [`npx gt translate`](/docs/cli/reference/commands/translate) writes one file per language, with the surrounding JSX structure as context | Wrapping text in [`<T>`](/docs/react/reference/components/t), a one-time setup (languages in `gt.config.json`, a loader, an entry file, sign-in, and a project ID), and rerunning [`npx gt translate`](/docs/cli/reference/commands/translate) (locally or in CI) when content changes |

Use a key-based library alone, with hand-written JSON files, when the app has a few strings that rarely change. Use Lingui when you want copy inline and have translators to fill its catalogs, and a translation management system when a localization team translates every release by hand. Use General Translation when the app keeps changing and every release has to ship in every language.

## Translate a React app with General Translation

General Translation's open-source `gt-react` library and `gt` CLI translate a React single-page app (SPA), such as a Vite or webpack project. The `npx gt@latest` setup wizard can configure the Vite entry and translation loading for you (an experimental step). To set it up yourself:

1. Install `gt-react` and the `gt` CLI.
2. List your languages in `gt.config.json`.
3. Add a [`loadTranslations`](/docs/react/reference/functions/load-translations) function, and call [`initializeGTSPA`](/docs/react/reference/config#initialize-spa) in a small entry file so translations load before the app renders.
4. Wrap your text in the [`<T>`](/docs/react/reference/components/t) component:

   ```tsx title="src/components/Welcome.tsx"
   import { T } from 'gt-react';

   export default function Welcome() {
     return (
       <main>
         <T>
           <h1>Welcome to my app</h1>
           <p>This content will be translated automatically.</p>
         </T>
       </main>
     );
   }
   ```

5. Sign in with [`npx gt login`](/docs/cli/reference/commands/login) and set your project ID.
6. Run [`npx gt translate`](/docs/cli/reference/commands/translate) to write one translation file per language.

The `context` prop on [`<T>`](/docs/react/reference/components/t) resolves an ambiguous word, such as "Save," and a Glossary and Custom Prompts in the Dashboard keep terms and tone consistent. [Server-rendered React](/docs/react/react-quickstart), [React Router framework](/docs/react/react-router-quickstart), and [Next.js](/docs/react/nextjs-quickstart) (with `gt-next`) apps have their own Quickstarts; for an SPA, the [React SPA Quickstart](/docs/react/react-spa-quickstart) has the full steps.
