Storyblok stores translations at the field level once you add languages to a space: each field marked translatable in its component schema holds one value per language in the same story, and your app requests a language with the Content Delivery API's `language` parameter. Filling those values is hard: a story is a tree of nested blocks, rich text has marks such as bold and links that must survive translation, and each result must go back into the same field and language. A field that isn't marked translatable stores no translation, and a source edit leaves the other languages out of date.

## Ways to translate Storyblok content

| Approach | What it does well | How translations get into the story | What it leaves to you |
| --- | --- | --- | --- |
| Translating by hand in Storyblok's editor | A translator sees each field in its story | A person types each value while viewing that language | Every translation, and finding the fields that changed after each source edit |
| Google Translate | Translates a field's text when you paste it in, with no setup | A person pastes each translated value back into its field | Context (each field is translated alone, without the block around it), rich text marks, consistent terms, and redoing changed fields |
| A script on an AI API (OpenAI API, Claude API) | Translates many stories in one scripted run, with your tone and terms in the prompt | A script you write reads and updates stories through Storyblok's Management API | Walking nested blocks, keeping rich text marks, context for each field, consistent terms, and rerunning after edits |
| General Translation (Storyblok integration) | Translates `text`, `textarea`, `markdown`, `richtext`, and `table` fields, nested blocks included; keeps rich text marks; sends each field with context from its location, type, and story | **Sync and apply** writes each target language into the story as a draft | Adding languages in Storyblok, rerunning **Sync and apply** after source edits, and reviewing and publishing each draft |

Translate by hand in Storyblok's editor when you have a few stories and a translator for each language; nothing more is needed. Use Google Translate or an AI API script when someone checks a one-off batch by hand; use General Translation when stories change often or span many blocks and languages.

## Translate stories with General Translation

General Translation's Storyblok integration runs from the Dashboard, with nothing to install, and requires a Starter or Enterprise plan.

1. In Storyblok, add your target languages under **Settings > Internationalization**.
2. Create a personal access token under **My account > Account settings > Personal access tokens**.
3. In the Dashboard, open **Project > Integrations > Catalog**, click **Connect** on **Storyblok**, and enter the **Space ID**, **Region**, and token.
4. Choose stories and target locales. Check **Auto-enable supported fields** if supported fields aren't translatable yet (it updates every component in the space).
5. Click **Sync and apply**.

## Review, publish, and update drafts

The run writes each language into the story as a draft and publishes nothing: review and publish the draft in Storyblok, and request it with `language` (add `version=draft` to preview). Each rerun reuses the translations in the story, including values you edited in Storyblok, and translates new or changed fields. The [Storyblok Quickstart](/docs/integrations/storyblok/quickstart) has the full steps.
