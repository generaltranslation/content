Smartling sells end-to-end localization: a translation management system (TMS) with a CAT (computer-assisted translation) tool and translation memory, AI translation through its AI Hub, human translation from Smartling Language Services, and a Global Delivery Network (GDN) that translates websites as a proxy. For software, the code side runs through files: resource files in your repository become files in Smartling, their strings are parsed out and translated, and translations come back through the GitHub Connector, a self-hosted Repository Connector, or the CLI. General Translation starts from the code instead.

## What Smartling does well

- **AI and human translation from one vendor.** Smartling's translation services page lists machine and AI translation with instant turnaround, AI-assisted human translation at 1 day, and expert human translation at 2 days, from a language services team of more than 4,000 linguists.
- **AI Hub.** LLMs and machine translation engines such as DeepL, Google, and Microsoft, with your glossary and translation memory pulled into prompts.
- **Websites without code changes.** The GDN serves translated pages as a translation proxy.
- **Visual context.** HTML captured with a Chrome extension or JavaScript library, screenshots matched to strings with OCR, PDFs, and video.
- **Quality tooling.** A CAT tool, quality checks, and an LQA Agent that scores jobs against the MQM framework.
- **Compliance and connectors.** PCI Level 1, SOC 2, HIPAA, HITRUST, ISO 27001, and ISO 42001, plus 50+ connectors for CMSs and marketing tools such as AEM, Contentful, and Salesforce.

## What Smartling still leaves to your engineers

With Smartling, new copy reaches every language through a round trip:

1. Set up an i18n library and keep each string in a resource file under a key. Smartling's SDKs are API clients, not an i18n library.
2. Connect the repository. The hosted GitHub Connector watches pull requests or commits, the self-hosted Repository Connector serves GitHub Enterprise, GitLab, Bitbucket, and SVN, or you push files with `smartling-cli files push`.
3. Wait for the translation job. In the GitHub Connector's pull request mode, Smartling's docs say a pull request shouldn't be merged or deleted until its translations are delivered, so a feature pull request waits on translation.
4. Merge the delivery pull request (the Repository Connector commits to the branch instead), wire each new language into the app, and check every screen.

App strings also start without visual context: the GitHub Connector doesn't capture it automatically, and Smartling's [supported file types](https://help.smartling.com/hc/en-us/articles/360007998893--Supported-File-Types) table lists none by default for JSON, iOS, and Android files, so it comes from screenshots or captures your team adds.

Smartling has a free-to-start Core plan and an Enterprise plan through sales, and it publishes per-word starting rates for each kind of translation. (See [Smartling plans](https://www.smartling.com/plans), checked October 2026.)

## Smartling vs. General Translation at a glance

| Feature | Smartling | General Translation |
| --- | --- | --- |
| Where strings live | Resource files whose strings Smartling parses and stores | In your code inside [`<T>`](/docs/react/reference/components/t), or in the resource files you already have |
| How code connects | GitHub Connector, Repository Connector, CLI, or API | [`npx gt translate`](/docs/cli/reference/commands/translate) in your build, or [Locadex](/docs/platform/locadex/quickstart) pull requests |
| Who translates | AI Hub engines, Smartling AI Translation, or Smartling's linguists | AI with context from your code, Glossary, and Custom Prompts, reviewed by your team in the Dashboard |
| Context for each string | Visual context capture, screenshots with OCR, glossary, translation memory, and style guides | The component and elements around the string, its variables, context notes, Glossary, and Custom Prompts |
| Websites | The GDN translation proxy | Translates the content in your code, with locale routing in `gt-next` |
| Pricing | Core and Enterprise plans, plus per-word translation rates | Usage-based; $0 platform fee and unlimited users, projects, and languages on Starter |

## Why teams choose General Translation over Smartling

General Translation starts from the code, so the round trip goes away: copy stays in your components inside [`<T>`](/docs/react/reference/components/t), and translation runs with each release.

- **Faster.** [`npx gt translate`](/docs/cli/reference/commands/translate) runs in your build, or Locadex opens a pull request with translations when code changes, so no feature pull request waits on a translation job. Adding a language is one line in `gt.config.json`.
- **Cheaper.** Engineers skip the translation chores: no keys to create with [`<T>`](/docs/react/reference/components/t), no files to send out or merge by hand. Pricing is usage-based, and Starter includes unlimited users, projects, and languages.
- **Higher quality.** Every translation carries the context of the code itself: the component and elements around a string, the variables in the sentence, and the conditions that choose between versions of it, plus your Glossary and Custom Prompts across every project.
- **Lower risk.** General Translation's libraries and CLI are open source under the MIT license and work without an account, and translations can live as files in your repository, so you can change how translations are produced without rewriting your app.

General Translation is SOC 2 Type II and ISO 27001 certified and GDPR compliant, and Enterprise plans add SSO, SCIM provisioning, audit logs, custom roles, and forward-deployed engineers.

## When Smartling is the better fit

Choose Smartling when you want AI and human translation bought from one vendor with a quality guarantee, when marketing sites need translating through a proxy without code changes, when your industry requires certifications such as PCI or HIPAA, when content lives in many enterprise CMS and marketing tools, or when you exchange XLIFF, TMX, or Office files with vendors.

## Moving from Smartling to General Translation

You can keep your file layout. Point `gt.config.json` at the resource files your Smartling configuration uses and run [`npx gt upload`](/docs/cli/reference/commands/upload), which sends your sources and existing translations to the platform. Context Group imports accept CSV, TSV, JSON, and text files for your glossary. (See [Defining context for translations](/docs/platform/dashboard/guides/defining-context-for-translations).) For how Smartling compares with other TMS platforms, see [Why use General Translation instead of a TMS?](/kb/general-translation-vs-tms)

## Key takeaways

- Smartling is a full-service enterprise platform, strongest when you want AI and human translation, a website proxy, and broad compliance from one vendor.
- Engineers still keep keyed resource files, and in pull request mode a feature pull request waits until its translations are delivered.
- General Translation translates content where it's written, with the context of the code, and ships every language with each release, on open-source libraries with no lock-in.
