Phrase calls itself a Language Intelligence Platform. For software teams it offers Phrase Strings, which stores keys and syncs them with your repository, and Phrase TMS (formerly Memsource), a translation management system (TMS) and CAT (computer-assisted translation) tool for documents, vendors, and large translation programs. Language AI connects both to machine translation and LLM engines. For a development team, Phrase still sits beside the code: keys are pushed and pulled, and translations come back as a pull request. General Translation starts from the code instead.

## What Phrase does well

- **Two tools in one platform.** Phrase Strings for developers' keys and Phrase TMS for documents, vendor management, and CAT-based translation.
- **Language AI.** 30+ machine translation and LLM engines with automatic engine selection, Next GenMT that uses translation memory matches, and quality evaluation that flags the lowest-scoring segments for review.
- **Repository automation.** Repo Sync for GitHub, GitLab, and Bitbucket imports files from a monitored branch and exports translations as a pull request, and a GitHub Action runs the CLI in CI.
- **Mobile and web over-the-air updates.** SDKs for iOS, Android, React Native, Flutter, i18next, and Rails fetch new translations without a release, falling back to the last cached or bundled files.
- **Context for translators.** Screenshots whose text is matched to keys, key descriptions and character limits, and a Figma plugin.
- **Human translation.** Order from Gengo or TextMaster inside Phrase Strings; Phrase says most translations are delivered within 24 hours.
- **Hosting choice.** Data hosted in the EU or the US.

## What Phrase still leaves to your engineers

With Phrase, new copy reaches every language through a round trip:

1. Set up an i18n library and keep each string in a resource file under a key.
2. Describe your files in `.phrase.yml` and send them with `phrase push`, or let Repo Sync import them from the monitored branch.
3. Wait while Language AI or translators fill in each language.
4. Bring the translations back with `phrase pull` or a Repo Sync export, which opens a pull request. Then merge, wire each new language into the app, and check every screen.

The AI's context is your translation memory, term base, and style guide, and translators see key descriptions and screenshots. The component a key renders in, and the variables and branches around it, stay in your code.

Plans are built around Strings seats and managed words, plus machine translation and AI units, and every plan starts with a 14-day free trial. (See [Phrase pricing](https://phrase.com/pricing/), checked October 2026.)

## Phrase vs. General Translation at a glance

| Feature | Phrase | General Translation |
| --- | --- | --- |
| Where strings live | Keys in Phrase Strings, synced with your resource files | In your code inside [`<T>`](/docs/react/reference/components/t), or in the resource files you already have |
| How code connects | `phrase` CLI, Repo Sync, or a GitHub Action | [`npx gt translate`](/docs/cli/reference/commands/translate) in your build, or [Locadex](/docs/platform/locadex/quickstart) pull requests |
| Who translates | Language AI engines, or vendors such as Gengo and TextMaster | AI with context from your code, Glossary, and Custom Prompts, reviewed by your team in the Dashboard |
| Context for each string | Translation memory, term base, style guide, key descriptions, and screenshots | The component and elements around the string, its variables, context notes, Glossary, and Custom Prompts |
| Pricing | Plans built on Strings seats, managed words, and machine translation and AI units | Usage-based; $0 platform fee and unlimited users, projects, and languages on Starter |
| Native mobile apps | Over-the-air SDKs for iOS, Android, React Native, and Flutter | The CLI translates iOS and Android string files; no over-the-air SDK |

## Why teams choose General Translation over Phrase

General Translation starts from the code, so the round trip goes away: copy stays in your components inside [`<T>`](/docs/react/reference/components/t), and translation runs with each release.

- **Faster.** [`npx gt translate`](/docs/cli/reference/commands/translate) runs in your build, or Locadex opens a pull request with translations when code changes, so new copy ships translated with the release that adds it. Adding a language is one line in `gt.config.json`.
- **Cheaper to run.** With [`<T>`](/docs/react/reference/components/t), engineers don't create keys or move files between systems. Pricing is usage-based with no seat charges, so everyone who reviews translations can have access, and Starter includes unlimited users, projects, and languages.
- **Higher quality.** Every translation carries the context of the code itself: the component and elements around a string, the variables in the sentence, and the conditions that choose between versions of it, plus your Glossary and Custom Prompts across every project.
- **Lower risk.** General Translation's libraries and CLI are open source under the MIT license and work without an account, and translations can live as files in your repository, so you can change how translations are produced without rewriting your app.

## When Phrase is the better fit

Choose Phrase when one platform must serve both software strings and a document-heavy translation program run in a CAT tool with vendors, when you want to route translation across many machine translation and LLM engines, when native and React Native apps need over-the-air updates, when you exchange XLIFF or Office files with vendors, or when you need a choice of EU or US hosting.

## Moving from Phrase to General Translation

You can keep your file layout. Point `gt.config.json` at the resource files your `.phrase.yml` lists and run [`npx gt upload`](/docs/cli/reference/commands/upload), which sends your sources and existing translations to the platform. Context Group imports accept CSV, TSV, JSON, and text files for your glossary. (See [Defining context for translations](/docs/platform/dashboard/guides/defining-context-for-translations).) For how Phrase compares with other TMS platforms, see [Why use General Translation instead of a TMS?](/kb/general-translation-vs-tms)

## Key takeaways

- Phrase is a strong choice when software strings and a large, document-heavy translation program share one platform, with broad engine choice and over-the-air SDKs.
- Engineers still keep keyed resource files, push them, wait for translations, and merge them back, and plans are built around seats and managed words.
- General Translation translates content where it's written, with the context of the code, and ships every language with each release, on open-source libraries with no lock-in.
