A translation management system (TMS) is where strings go to be translated. You sync resource files or keys from your repository into the TMS, translators and AI translate them there with translation memory and glossaries, and the results come back as files or a pull request. Smartling, Lokalise, Phrase, Crowdin, and Transifex all work this way, and the model suits large translation programs run by localization managers and language vendors. For a development team, the cost is the hand-off: the code and the TMS each hold a copy of every string, and the context a string had in the code has to be rebuilt after it leaves.

## What a TMS does well

A TMS is built to coordinate people and content at scale:

- **Translation tooling.** Editors with translation memory, glossaries, and QA checks for placeholders, length, and terminology, plus workflows that chain translation, review, and proofreading steps.
- **Human translation.** Smartling has its own language services team of more than 4,000 linguists, Lokalise and Phrase let you order professional translation per word, and Crowdin runs a vendor marketplace.
- **File formats.** Each platform reads the common app formats plus XLIFF, the format translation vendors exchange, and ARB.
- **Context for translators.** Screenshots matched to strings, Figma plugins, key descriptions with character limits, and in-context editors for websites.
- **AI translation.** Every vendor now offers it, and their AI features can draw on your glossary, translation memory, and style guide.
- **Mobile delivery.** Lokalise, Phrase, Crowdin, and Transifex ship SDKs that update strings in native mobile apps without an app release.

## Where the hand-off costs a development team

- **Every string exists twice.** The code holds keys, and the TMS holds the strings and their translations. A CLI or Git integration keeps the two in sync: Lokalise and Phrase return translations as a pull request, and Crowdin's GitHub integration syncs hourly by default. New copy is untranslated until that round trip finishes.
- **Context has to be rebuilt.** A TMS attaches screenshots, Figma frames, and key descriptions to each string, supplied by people or plugins. What a string list can't carry is the code itself: the component a string sits in, the variables around it, and the conditions that choose between sentences. Smartling's [supported file types](https://help.smartling.com/hc/en-us/articles/360007998893--Supported-File-Types) table, for example, lists no visual context by default for JSON, iOS, and Android files and recommends adding it by manual upload or an integration.
- **Internationalizing the code is still your job.** A TMS manages strings, not the code that renders them. You still set up an i18n library in each app, mark or key every string, and handle plurals and formatting in the code.
- **Cost tracks what you store or who logs in.** Crowdin prices mainly by hosted words (source words times target languages), Phrase by Strings seats and managed words, and Lokalise by plan tier, with allowances for processed words, seats, and integrations. ([Crowdin pricing](https://crowdin.com/pricing), [Phrase pricing](https://phrase.com/pricing/), and [Lokalise pricing](https://lokalise.com/pricing/), checked October 2026.)

## When a TMS is the better fit

Choose a TMS when:

- linguists or agencies translate in a CAT (computer-assisted translation) editor with translation memory and multi-step review;
- you exchange XLIFF, ARB, or Office files with vendors (General Translation doesn't support XLIFF, ARB, CSV, or DOCX files);
- you want to buy professional human translation through the same platform;
- native iOS and Android apps need over-the-air string updates through an SDK.

Choose General Translation when most of your product's text lives in code and ships on a release schedule, and you want translation to happen in that release instead of a round trip after it.

## How General Translation replaces the hand-off

- **The code is the source.** In React, Next.js, and Vue, copy stays in your components inside [`<T>`](/docs/react/reference/components/t). For everything else, the CLI translates the files you already have, including JSON, YAML, Markdown and MDX, PO, iOS `.xcstrings` and `.strings`, and Android `strings.xml`.
- **Translation runs with the release.** Add [`npx gt translate`](/docs/cli/reference/commands/translate) to your build, or let [Locadex](/docs/platform/locadex/quickstart), General Translation's AI agent, open a pull request with translations when a pull request changes or a commit lands.
- **Context travels with the content.** Each [`<T>`](/docs/react/reference/components/t) block is translated with its element structure and an optional [`context`](/docs/react/reference/components/t#context) note, and [keyed metadata](/docs/cli/reference/keyed-metadata) adds context to JSON and YAML keys. A Context Group's Glossary and Custom Prompts apply to every project you assign it to, so web, docs, and mobile share terms and tone.
- **Review happens where translations are made.** Reviewers edit translations on the Dashboard's **Translations** page, compare locales side by side, and leave annotations, with unlimited users on every plan. (See [Reviewing and editing translations](/docs/platform/dashboard/guides/reviewing-translations).)
- **Enterprise controls.** Enterprise plans add SSO (SAML and OIDC), SCIM provisioning, audit logs, custom roles, and forward-deployed engineers who build custom workflows. General Translation is SOC 2 Type II and ISO 27001 certified and GDPR compliant.

## Moving from a TMS

You don't have to change your file layout. Point `gt.config.json` at your existing resource files and run [`npx gt upload`](/docs/cli/reference/commands/upload), which sends your source files and any existing translations to the platform. Glossary imports accept CSV, TSV, JSON, and text files, so terms exported from a TMS can go into a Context Group. (See [Defining context for translations](/docs/platform/dashboard/guides/defining-context-for-translations).) Current rates are on the [pricing page](https://generaltranslation.com/pricing).

## Key takeaways

- A TMS manages translation outside your code, which suits large human translation programs and vendor workflows.
- General Translation translates content where it's written, with context from the code, and ships translations with each release through your build or a Locadex pull request.
- Keep a TMS for XLIFF exchange, professional translation services, or native mobile over-the-air updates. Choose General Translation when your product's text lives in code.
