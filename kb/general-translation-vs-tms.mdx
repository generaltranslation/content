A translation management system (TMS) coordinates source content, translation, review, and delivery. Platforms such as Smartling, Lokalise, Phrase, Crowdin, and Transifex connect to repositories or content systems, support AI and human translation, and return translated content through configured integrations. General Translation connects these tasks to inline source code and shared product context. Compare the complete workflow: how authors write copy, how context reaches translation, how reviewers correct it, and how updates reach users.

## What a TMS does well

A TMS is built to coordinate people and content at scale:

- **Translation tooling.** Editors with translation memory, glossaries, and QA checks for placeholders, length, and terminology, plus workflows that chain translation, review, and proofreading steps.
- **Human translation.** Smartling has its own language services team of more than 4,000 linguists, Lokalise and Phrase let you order professional translation per word, and Crowdin runs a vendor marketplace.
- **File formats.** Each platform reads the common app formats plus XLIFF, the format translation vendors exchange, and ARB.
- **Context for translators.** Screenshots matched to strings, Figma plugins, key descriptions with character limits, and in-context editors for websites.
- **AI translation.** Every vendor now offers it, and their AI features can draw on your glossary, translation memory, and style guide.
- **Mobile delivery.** Lokalise, Phrase, Crowdin, and Transifex ship SDKs that update strings in native mobile apps without an app release.

## How catalog workflows connect to releases

An application using a TMS needs a path from source content to a translated release:

1. Author messages using the library's keys, inline messages, or another supported format, and configure extraction where needed.
2. Connect the source files or strings to the translation platform through its CLI, API, or repository integration.
3. Configure translation and review, using AI, people, or a combination that fits the release requirements.
4. Load the translated content in the app and verify the release in each supported locale.

These steps can be automated. Crowdin documents [repository synchronization](https://support.crowdin.com/github-integration/) and [automatic AI translation of new content](https://support.crowdin.com/crowdin-ai/); Phrase documents [GitHub synchronization for Strings](https://support.phrase.com/hc/en-us/articles/5784125562012-GitHub-Strings). Libraries such as next-intl also offer [experimental inline extraction](https://next-intl.dev/docs/usage/extraction). After integration, an automated catalog workflow can update translations as source changes. Release timing depends on the configured generation and review process.

Context is another part of that integration. TMS workflows can provide descriptions, screenshots, and in-context editing; Crowdin's [AI settings](https://support.crowdin.com/crowdin-ai/) can include file and project context and tagged screenshots. GT carries marked JSX structure into translation and applies explicit context, Glossary terms, and Custom Prompts in the same workflow. Compare the context your actual setup supplies, rather than inferring its quality from the catalog format.

Pricing also differs. Crowdin prices mainly by hosted words, Phrase by Strings seats and managed words, and Lokalise by plan tier, with allowances for processed words, seats, and integrations. General Translation charges for translation and agent usage without per-seat fees. Consult [Crowdin pricing](https://crowdin.com/pricing), [Phrase pricing](https://phrase.com/pricing/), [Lokalise pricing](https://lokalise.com/pricing/), and [GT's usage rates](https://generaltranslation.com/pricing/usage) for the current terms.

## Why teams choose General Translation instead

General Translation brings authoring, translation production, review, and delivery into one workflow. Copy can stay in your components inside [`<T>`](/docs/react/reference/components/t), and the CLI or Locadex connects source changes to translations:

- **Translation tied to releases.** Add a target language in `gt.config.json`, then run [`npx gt translate`](/docs/cli/reference/commands/translate) before the build to generate its translations. The incremental workflow reuses matching earlier translations and translates changed content. [Locadex](/docs/platform/locadex/quickstart) can automate repository changes through pull requests, so new copy can ship translated in the release that adds it.
- **Code context and shared terminology.** Marked JSX retains its element and sentence structure, with explicit [`context`](/docs/react/reference/components/t#context) notes, Glossary terms, and Custom Prompts to guide meaning and tone. Assign the same Context Groups across web, docs, and mobile projects, then review and edit output in the Dashboard's **Translations** page.
- **Independent libraries and portable translations.** GT's MIT-licensed libraries can render supplied translations without an account. Store translations in your repository or load them from the CDN, and change how translations are produced without replacing the rendering library.

General Translation is SOC 2 Type II and ISO 27001 certified and GDPR compliant, and Enterprise plans add SSO (SAML and OIDC), SCIM provisioning, audit logs, custom roles, and forward-deployed engineers who build custom workflows. ## When a TMS is the better fit

Choose a TMS when:

- linguists or agencies translate in a CAT (computer-assisted translation) editor with translation memory and multi-step review;
- you exchange XLIFF, ARB, or Office files with vendors (General Translation doesn't support XLIFF, ARB, CSV, or DOCX files, though it translates Google Docs and Slides through its [Google Drive integration](/docs/integrations/google-drive/quickstart));
- you want to buy professional human translation through the same platform;
- native iOS and Android apps need over-the-air string updates through an SDK.

Choose General Translation when most of your product's text lives in code and ships on a release schedule, and you want translation to happen in that release.

## Moving from a TMS

You don't have to change your file layout. The CLI translates the resource files you already have, including JSON, YAML, Markdown and MDX, PO, iOS `.xcstrings` and `.strings`, and Android `strings.xml`. Point `gt.config.json` at them and run [`npx gt upload`](/docs/cli/reference/commands/upload), which sends your source files and any existing translations to the platform. Glossary imports accept CSV, TSV, JSON, and text files, so terms exported from a TMS can go into a Context Group. (See [Defining context for translations](/docs/platform/dashboard/guides/defining-context-for-translations).) Current rates are on the [pricing page](https://generaltranslation.com/pricing).

## Key takeaways

- TMS workflows can automate extraction, synchronization, AI translation, and delivery, with review configured for the team's needs.
- General Translation connects inline source code, translation context, generation, review, and release automation in one workflow. It can also translate existing catalogs.
- Its libraries and CLI are open source, so there's no lock-in. Keep a TMS for XLIFF exchange, professional translation services, or native mobile over-the-air updates.
