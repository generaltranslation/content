Crowdin describes itself as an AI-powered localization platform. You sync resource files from your repository with its CLI or a Git integration, translators and AI translate them in Crowdin's editor, and the translations come back to your repository as a pull request. It's popular with open-source projects, which can qualify for a free license. What Crowdin leaves to engineers is the work around that sync: the i18n library, the keys, the resource files, and wiring each new language into the app. General Translation starts from the code instead.

## What Crowdin does well

- **Free to start.** The Free plan includes 60,000 hosted words, with translations shared into Crowdin's translation memory, and open-source projects that meet its criteria (such as an OSI license and no related commercial product) can get a free license.
- **Developer tooling.** A CLI configured in `crowdin.yml`, Git integrations for GitHub, GitLab, Bitbucket, and Azure Repos, a GitHub Action, an MCP server, and 700+ apps and integrations.
- **AI with context.** You can bring your own OpenAI, Anthropic, Gemini, or other provider keys, or use a Crowdin-managed model. Each request includes the string's context, key, and maximum length, and prompts can add your glossary, translation memory, style guide, neighboring strings, and tagged screenshots.
- **Human translation.** A vendor marketplace on every plan, and Crowdin Language Services ordered inside a project.
- **Context and QA.** Screenshots tagged to strings, an In-Context editor for web apps on the Team plan and up, a Figma plugin, and 50+ QA checks.
- **Mobile over-the-air updates.** iOS, Android, and Flutter SDKs and a JavaScript client update strings from Crowdin's CDN without an app release.

## What Crowdin still leaves to your engineers

With Crowdin, new copy reaches every language through a manual loop:

1. Set up an i18n library, extract each English string into a resource file under a key, and reference the key in the component.
2. Describe the files in `crowdin.yml` and send them to Crowdin with `crowdin upload sources`, or let a Git integration pick them up. Crowdin's GitHub integration syncs hourly by default, and a GitHub Action can run on each push.
3. Wait while AI, machine translation, vendors, or your translators fill in each language.
4. Merge the pull request from Crowdin's `l10n_` service branch, wire each new language into the app, and check every screen.

Crowdin can also collect context from code now: its coding-agent skills and `crowdin context` commands have an agent summarize your codebase and upload that context, replacing its archived Context Harvester. What reaches the translator is still a text summary next to each string, not the component that renders it.

Paid plans are priced mainly by hosted words, which are source words times target languages, plus manager seats, so each new language raises the hosted-word count. (See [Crowdin pricing](https://crowdin.com/pricing), checked October 2026.)

## Crowdin vs. General Translation at a glance

| Feature | Crowdin | General Translation |
| --- | --- | --- |
| Where strings live | Keyed resource files in your repository, synced to Crowdin projects | In your code inside [`<T>`](/docs/react/reference/components/t), or in the resource files you already have |
| How code connects | `crowdin.yml` with the CLI, Git integrations, or a GitHub Action | [`npx gt translate`](/docs/cli/reference/commands/translate) in your build, or [Locadex](/docs/platform/locadex/quickstart) pull requests |
| Who translates | Machine translation or AI providers, vendors, or your translators | AI with context from your code, Glossary, and Custom Prompts, reviewed by your team in the Dashboard |
| Context for each string | Key, maximum length, screenshots, glossary, translation memory, and agent-written summaries | The component and elements around the string, its variables, context notes, Glossary, and Custom Prompts |
| Pricing | Free plan; paid plans by hosted words and manager seats | Usage-based; $0 platform fee and unlimited users, projects, and languages on Starter |
| Native mobile apps | Over-the-air SDKs for iOS, Android, and Flutter | The CLI translates iOS and Android string files; no over-the-air SDK |
| Open source | Free license for qualifying open-source projects | MIT-licensed libraries and CLI |

## Why teams choose General Translation over Crowdin

General Translation starts from the code, so the loop above goes away: copy stays in your components inside [`<T>`](/docs/react/reference/components/t), and translation runs with each release.

- **Faster.** [`npx gt translate`](/docs/cli/reference/commands/translate) runs in your build, or Locadex opens a pull request when code changes, so new copy ships translated with the release that adds it. Adding a language is one line in `gt.config.json`, and the next build translates the whole project into it.
- **Cheaper.** With [`<T>`](/docs/react/reference/components/t), engineers don't create keys or move files between systems. Pricing is usage-based, with no hosted-word tiers or manager seats, and Starter includes unlimited users, projects, and languages.
- **Higher quality.** Every translation carries the context of the code itself: the component and elements around a string, the variables in the sentence, and the conditions that choose between versions of it, plus your Glossary and Custom Prompts across every project.
- **Lower risk.** General Translation's libraries and CLI are open source under the MIT license and work without an account, and translations can live as files in your repository, so you can change how translations are produced without rewriting your app.

## When Crowdin is the better fit

Choose Crowdin when an open-source project qualifies for its free license and wants community translators, when you run a human translation program with vendors and multi-step review, when you exchange XLIFF or Office files, when native mobile apps need over-the-air updates, or when you need its EU data residency option or a HIPAA business associate agreement.

## Moving from Crowdin to General Translation

You can keep your file layout. Point `gt.config.json` at the same source and translation files that `crowdin.yml` lists, and run [`npx gt upload`](/docs/cli/reference/commands/upload) to send your sources and existing translations to the platform. Bring your glossary over too: Context Group imports accept CSV, TSV, JSON, and text files. (See [Defining context for translations](/docs/platform/dashboard/guides/defining-context-for-translations).) For how Crowdin compares with other TMS platforms, see [Why use General Translation instead of a TMS?](/kb/general-translation-vs-tms)

## Key takeaways

- Crowdin is a strong TMS for open-source and human translation programs, with a free plan and AI that draws on keys, screenshots, and glossaries.
- Engineers still maintain keys and resource files, sync them, wait for translations, and merge them back, and paid plans grow with hosted words and manager seats.
- General Translation translates content where it's written, with the context of the code, and ships every language with each release, on open-source libraries with no lock-in.
