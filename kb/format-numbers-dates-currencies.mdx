---
title: How do I format numbers, dates, and currencies for each locale?
summary: Format each value when the page renders, with the reader's locale and JavaScript's Intl API, and keep it out of the translated sentence. General Translation's <Num>, <Currency>, <DateTime>, and <RelativeTime> components do both inside a <T>, so one translation serves every value.
date: 2026-10-13
updated: 2026-10-14
related: [how-to-handle-plurals-in-react, translate-strings-outside-jsx, translate-conditional-jsx, translate-react-app]
---

Format each value at render with the reader's locale and JavaScript's `Intl` API, which applies each locale's digit grouping, decimal mark, currency placement, and date order: 12,450.75 euros is €12,450.75 in English and 12.450,75 € in German, and 4 August 2026 is 8/4/2026 in US English and 4.8.2026 in German. The sentence around the value is harder. It is translated ahead of time, but the value exists only at render, so each translation needs a slot for it. A date also depends on a time zone, so a server in UTC and a browser in Los Angeles can render different days for the same moment.

| Approach | What it does well | What it leaves to you |
| --- | --- | --- |
| JavaScript's `Intl` API alone | Formats numbers, currencies, dates, and relative times by each locale's conventions, built into the language | Translating every sentence that holds a value, in every language, and fitting the formatted value into each one |
| An internationalization (i18n) library alone (`i18next`, `react-intl`, `next-intl`) | Mature runtimes for rendering translations and formatting values, with a placeholder for the value in each message | Writing each message in a keyed file for every language and keeping those files current |
| Google Translate | Fast, general-purpose translation of text | Each string is translated on its own; formatting the value, plurals, and delivery are up to you |
| A raw AI API (OpenAI API, Claude API) | Fluent translation that follows instructions | Locale formatting, plural forms, consistent terms, review, and delivery |
| General Translation ([`<Num>`](/docs/react/reference/components/num), [`<Currency>`](/docs/react/reference/components/currency), [`<DateTime>`](/docs/react/reference/components/datetime), and [`<RelativeTime>`](/docs/react/reference/components/relative-time) inside [`<T>`](/docs/react/reference/components/t)) | Formats each value locally with `Intl` for the active locale; the sentence around it is translated once per language, with a slot for the value | Choosing each amount's currency code and pinning the locale, time zone, and `baseDate` on server-rendered pages |

Use `Intl` alone when a value stands by itself, such as a price column. Use your i18n library's formatters when translators maintain your messages in keyed files. Use Google Translate or a raw AI API when one-off text has no values to format. Use General Translation's components when values sit inside sentences that ship in several languages and change with each release.

General Translation's `gt-next`, `gt-react`, and the experimental `gt-tanstack-start` and `gt-react-native` ship one component per value type: [`<Num>`](/docs/react/reference/components/num) for numbers, percentages, and units; [`<Currency>`](/docs/react/reference/components/currency) for an amount in an ISO 4217 currency (without converting it); [`<DateTime>`](/docs/react/reference/components/datetime) for dates and times; and [`<RelativeTime>`](/docs/react/reference/components/relative-time) for phrases such as "3 days ago." Inside a [`<T>`](/docs/react/reference/components/t), each keeps its value out of the translation, so [`npx gt translate`](/docs/cli/reference/commands/translate) translates the sentence once per language and the component formats the value locally with `Intl`, without sending it to the General Translation API:

```tsx
<T>
  <p>
    Your total is <Currency currency="EUR">{total}</Currency>.
  </p>
</T>;
```

To avoid hydration errors in a server-rendered app, pin the locale and the `timeZone` option on [`<DateTime>`](/docs/react/reference/components/datetime), and the locale and a shared `baseDate` on [`<RelativeTime>`](/docs/react/reference/components/relative-time). [Vue apps](/docs/vue/guides/formatting-variables) get [`<Num>`](/docs/vue/reference/components/num), [`<Currency>`](/docs/vue/reference/components/currency), and [`<DateTime>`](/docs/vue/reference/components/datetime) from `gt-vue`. The [Formatting numbers and dates](/docs/react/guides/formatting-variables) guide has the full steps.
