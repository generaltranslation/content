The [Dashboard](https://dash.generaltranslation.com) is the General Translation web app. Its **Translations** page shows a project's generated translations and compares target locales side by side, so a reviewer can make precise corrections without starting a new translation job.

## Find the content to review

1. Open your project in the Dashboard.
2. Go to the **Translations** page.
3. Choose **Files** or **Components** in the top left. **Files** holds file-based content such as Markdown, JSON, gettext, and Apple String Catalogs. **Components** holds strings from React and JSX projects.
4. Use **Search** to filter the view by file name, component name, key, source text, or translated text.
5. Choose the branch and one or more locales in the top right.

Component, keyed-file, and structured-file views show the selected locales side by side. Raw file views show one target locale at a time. From any project page, press `⌘K` on macOS or `Ctrl+K` on Windows to search across files and components.

## Edit a translation

Click a translation cell and type the change. The edit stays a draft until you click **Save**.

An inline edit updates the current translation and does not create a new entry in version history. A new history entry is created only when source edits are sent for translation.

For JSON, YAML, `.strings`, and `.xcstrings` translations, the **Raw** view is editable too. It is read-only for HTML, PO, POT, and Android files. Editing translations requires the **Edit translations** permission, which the default **Admin** and **Editor** roles have. (See [Roles and permissions](/docs/platform/dashboard/reference/roles-and-permissions)).

## Check earlier versions

The file tools sit under the name of an open file. Click **History** to compare translations across source versions, open a prior version, or confirm when a translated file changed. The same tools download the translated output, show or hide the source content, and filter by annotation label.

## Track the review with annotations

Annotations attach review information to one entry in one locale, so an entry's Spanish translation can carry different annotations than its French translation. The annotation types are labels, notes, and comments:

- **Labels** are colored, project-wide tags for review states such as "Needs review," "Approved," or "Legal."
- A **Note** is a plain-text note for translator guidance and internal context, with one note per entry and locale.
- **Comments** are threaded discussions that your team can reply to, resolve, and reopen.

On the **Translations** page, click the **Tag** icon to add a label to the selected entry, or the **Comment** icon to open the full panel for labels, the note, and comments. To label many entries at once, select the rows and click **Manage labels**. The **Filter** icon in the translation header shows only the entries with a given label, such as everything marked "Needs review."

Annotations require a Starter or Enterprise plan. Adding or changing them also requires the **Review & approve translations** permission (`translations:review:write`).

## Fix a term everywhere

The Glossary of a Context Group defines how key terms are translated, such as a product name that stays untranslated in every locale. Editing a Context Group changes new translations only. To update existing translations, open the project's **Context** page, select the Glossary terms and locales, and click **Apply**. (See [Apply Glossary translations](/docs/platform/dashboard/guides/defining-context-for-translations#apply-glossary)).

## Bring the edits into your repository

[Locadex](/docs/platform/locadex/quickstart) is the General Translation AI agent which works in your GitHub repository. It syncs Dashboard edits back to GitHub by opening pull requests for Dashboard changes, such as manual translation edits and Apply Glossary updates.

To set it up, connect GitHub under **Project > Integrations > Catalog**, create an automation under **Project > Automations**, click **Run setup** on it, and merge the setup pull request that Locadex opens. Open an automation and click **Run now** to run it by hand. Locadex requires a Starter or Enterprise plan. (See the [Locadex Quickstart](/docs/platform/locadex/quickstart)).

The **Translations** page does not run full-file retranslation. For a new translation pass over code or uploaded files, use the [CLI](/docs/cli/quickstart) or Locadex.

Read [Reviewing and editing translations](/docs/platform/dashboard/guides/reviewing-translations) for every view and file type, and [Adding annotations](/docs/platform/dashboard/guides/adding-annotations) for the label catalog and comment threads.
