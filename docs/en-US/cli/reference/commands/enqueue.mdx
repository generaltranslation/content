title: gt enqueue
description: Queue uploaded files for General Translation without downloading results. API reference for the gt enqueue command.

---

Queues previously uploaded files for translation and returns immediately, without waiting for or downloading the results. Pair it with [`gt upload`](/docs/cli/reference/commands/upload) and [`gt download`](/docs/cli/reference/commands/download) to split translation across CI stages. See [Manage translations](/docs/cli/guides/managing-translations#split).

*Note: Requires a project ID and [saved login or explicit tooling key](/docs/cli/guides/configuring#credentials), with permissions for the requested operations.*

```bash
npx gt enqueue
```

## How it works [#how-it-works]

1. Reads `gt.config.json` to determine which files to translate.
2. Identifies the previously uploaded files by their content hashes.
3. Sends them to the General Translation API for translation.
4. Exits immediately without waiting for translations to complete.

To download the results once they are ready, run [`gt download`](/docs/cli/reference/commands/download).

## Flags [#flags]

`enqueue` accepts the shared [`gt translate`](/docs/cli/reference/commands/translate#flags) flags, but not its source-scanning flags (`--src`, `--dictionary`, `--tsconfig`/`--jsconfig`, `--inline`, `--ignore-errors`). Configure source paths with [`src`](/docs/cli/reference/config#src). Shared flags do not make this command upload source files, sync local edits, publish files, create tags, or download translations.

| Parameter | Description | Type | Optional | Default |
| --- | --- | --- | --- | --- |
| `--api-key <key>` | Explicit tooling key override. | `string` | Yes | `GT_API_KEY`, otherwise login |
| `--project-id <id>` | project ID. | `string` | Yes | `GT_PROJECT_ID` |
| `-c, --config <path>` | Path to the config file. | `string` | Yes | `gt.config.json` |
| `--locales <locales...>` | Extra target locales, appended to config locales. | `string[]` | Yes | — |
| `--default-locale <locale>` | Source locale for the project. | `string` | Yes | `en` |
| `--timeout <seconds>` | Accepted but has no effect: this command does not wait for translation jobs. | `number` | Yes | `900` |
| `--dry-run` | Accepted but does not prevent API calls or enqueueing. | `boolean` | Yes | `false` |

<Callout type="warn">
  In `gt` 2.23.1, `enqueue --dry-run` still runs the enqueue workflow and can start billable translation jobs. To collect files without enqueueing them, use [`gt stage --dry-run`](/docs/cli/reference/commands/stage#notes), which still updates the staging configuration. For offline validation of inline content, use [`gt validate`](/docs/cli/reference/commands/validate).
</Callout>

## Example [#example]

```bash
# Stage 1: upload source files
npx gt upload

# Stage 2: enqueue the uploaded files for translation
npx gt enqueue

# Stage 3: download the results once they are ready
npx gt download
```

## Other notes [#notes]

Splitting [`upload`](/docs/cli/reference/commands/upload), `enqueue`, and [`download`](/docs/cli/reference/commands/download) is useful in CI/CD pipelines where each step runs in a separate stage or job. Because `enqueue` returns immediately, the download step can run in a later job once translations complete.
