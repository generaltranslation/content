title: gt project status
description: Check the current state of a Project setup job. API reference for the gt project status command.

---

Use this command when another workflow returns a setup job ID and you need a single status check. It does not wait for the job to finish.

## Overview [#overview]

```bash
npx gt project status <job-id>
```

The command requires a production Project key, or an Organization key with a target Project ID. The key must have `project:files:read`.

## How it works [#how-it-works]

The command calls the [translation job status endpoint](/docs/platform/openapi/reference/translation/job-status) with one job ID. It prints one of:

- `queued`
- `processing`
- `failed`
- `completed`
- `unknown`

## Flags [#flags]

| Parameter | Description | Type | Optional | Default |
| --- | --- | --- | --- | --- |
| `<job-id>` | Setup job ID to inspect. | `string` | No | — |
| `-c, --config <path>` | Read API and Project settings from this config file. | `string` | Yes | Nearest `gt.config.json` |
| `--api-key <key>` | API key used as the bearer token. | `string` | Yes | `GT_API_KEY` |
| `--project-id <id>` | Target Project ID for an Organization key. | `string` | Yes | Config, then `GT_PROJECT_ID` |

Prefer `GT_API_KEY` over `--api-key` so the key does not appear in shell history.

## Example [#example]

```bash
npx gt project status setup-job-id
```

The command exits with status `1` when credentials are missing or the API request fails.
