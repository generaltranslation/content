Use this command to check the account selected by [`gt login`](/docs/cli/reference/commands/login). It checks a user session, not an API key's identity.

## Overview [#overview]

```bash
npx gt whoami
```

| Option | Description |
| --- | --- |
| [Global options](#flags) | Output, compatibility checks, and help; no command-specific flags. |

## How it works [#how-it-works]

The command reads the session for the selected issuer, refreshes it when needed, and fetches authenticated user information. It prints the email, falling back to the name and then the subject identifier. It requires network access; it is not an offline cached-account viewer.

Missing or invalid sessions and failed identity requests fail the command. Use [`gt login`](/docs/cli/reference/commands/login) to sign in again. Issuer selection and credential storage follow the [login settings](/docs/cli/reference/commands/login#storage).

## Flags [#flags]

There are no command-specific flags. The [global options](/docs/cli/reference/global-options) apply; there is no config, project-ID, API-key, or JSON-output flag.

## Example [#example]

```bash
npx gt whoami
```

The output identifies the signed-in account. To remove that session, use [`gt logout`](/docs/cli/reference/commands/logout).
