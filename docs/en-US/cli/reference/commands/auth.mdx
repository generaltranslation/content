---

title: gt auth
description: Generate General Translation API credentials for a project. API reference for the gt auth command.

---

Generates one project API key and a project ID and writes them to your `.env.local` file. If `.env.local` does not exist, the command creates it and adds it to `.gitignore`.

The `--key-type` compatibility option selects which environment-variable slots receive the key. It does not create keys with different capabilities.

```bash
npx gt auth
```

## How it works [#how-it-works]

1. Prompts you to sign in to the General Translation Dashboard.
2. Generates one project API key, which works in any environment, and a project ID.
3. Creates `.env.local` (and adds it to `.gitignore`) if needed.
4. Writes `GT_PROJECT_ID` and the selected key slots to `.env.local`: `GT_API_KEY` for `production`, the framework's `GT_DEV_API_KEY` variable for `development`, or the same key to both slots for `all`.

## Flags [#flags]

| Parameter | Description | Type | Optional | Default |
| --- | --- | --- | --- | --- |
| `-c, --config <path>` | Path to the config file. | `string` | Yes | `gt.config.json` |
| `-t, --key-type <type>` | Credential slots to write: `production`, `development`, or `all`. | `string` | Yes | Prompted |

## Example [#example]

```bash
# Prompt for the credential slots, then write credentials to .env.local
npx gt auth

# Write the generated key to GT_API_KEY without prompting
npx gt auth --key-type production
```

## Other notes [#notes]

- The API key and project ID are not required to use `gt-react` or `gt-next` — they are only needed to call the General Translation API.
- `auth` is the credentials step of the [`gt init`](/docs/cli/reference/commands/init) wizard. Run it on its own to generate credentials for an already-configured project.
