---

title: gt auth
description: Generate General Translation API credentials for a project. API reference for the gt auth command.

---

Generates a project API key and writes it with your project ID to `.env.local`. If `.env.local` does not exist, the command creates it and adds it to `.gitignore`.

All newly generated keys are project keys starting with `gtx-api-`. The `--key-type` option controls which SDK environment variables the CLI writes. When omitted, the CLI prompts for that choice.

```bash
npx gt auth
```

## How it works [#how-it-works]

1. Prompts you to sign in to the General Translation Dashboard.
2. Creates one project API key with the default project permissions and returns your project ID.
3. Creates `.env.local` (and adds it to `.gitignore`) if needed.
4. Writes the project ID and API key to `.env.local`. For supported client-side setups, it adds a public environment-variable prefix so browser code can read the development credentials.

The credential choices are:

- `production`: writes the key to `GT_API_KEY` for CLI and server use.
- `development`: writes the key to `GT_DEV_API_KEY` for SDK development translation. For Next.js Pages Router, the CLI writes `NEXT_PUBLIC_GT_DEV_API_KEY`; for Vite, it writes `VITE_GT_DEV_API_KEY`. These prefixes expose the key to browser code. The project ID gets the same prefix.
- `all`: writes the same project key to both settings.

For client-side development translation, both values must be available to browser code. If the CLI writes unprefixed variables for your setup, use `NEXT_PUBLIC_GT_DEV_API_KEY` and `NEXT_PUBLIC_GT_PROJECT_ID` in Next.js, or `VITE_GT_DEV_API_KEY` and `VITE_GT_PROJECT_ID` in Vite. Keep `GT_API_KEY` unprefixed for server and CLI use.

These choices do not restrict permissions. The generated full-access project key works for local development. To minimize risk, we recommend a separate development key: use **Project > API Keys > Edit key**, choose **Custom** permissions, and enable only **Runtime translation**. Keep a key with file and queue permissions for the CLI. Never include any API key in deployed client bundles. (See [API keys](/docs/platform/dashboard/reference/api-keys)).

## Flags [#flags]

| Parameter | Description | Type | Optional | Default |
| --- | --- | --- | --- | --- |
| `-c, --config <path>` | Path to the config file. | `string` | Yes | `gt.config.json` |
| `-t, --key-type <type>` | Credential settings to write: `production`, `development`, or `all`. All choices create a project key. | `string` | Yes | Prompted |

## Example [#example]

```bash
# Choose credential settings, then write them to .env.local
npx gt auth

# Write a project key to GT_API_KEY without the prompt
npx gt auth --key-type production
```

## Other notes [#notes]

- The API key and project ID are not required to use `gt-react` or `gt-next` — they are only needed to call the General Translation API.
- `auth` is the credentials step of the [`gt init`](/docs/cli/reference/commands/init) wizard. Run it on its own to generate credentials for an already-configured project.
