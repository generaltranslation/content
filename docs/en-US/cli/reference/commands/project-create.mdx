title: gt project create
description: Create a Project from the command line with an Organization API key. API reference for the gt project create command.

---

Use this command when automation must provision a Project before a Project-scoped key or config exists. It calls the [Create a Project endpoint](/docs/platform/openapi/reference/project/create-project).

## Overview [#overview]

```bash
npx gt project create \
  --name <name> \
  --default-locale <locale>
```

The Organization key must have `org:projects:create`. Passing `--cdn-enabled` also requires `project:write`.

## How it works [#how-it-works]

The command creates the Project in the Organization associated with `GT_API_KEY` or `--api-key`. On success, it prints the Project name and ID.

Project creation is Organization-scoped, so it does not require a Project ID. The command does not write the new ID to `gt.config.json`.

## Flags [#flags]

| Parameter | Description | Type | Optional | Default |
| --- | --- | --- | --- | --- |
| `--name <name>` | Name of the new Project. | `string` | No | — |
| `--default-locale <locale>` | Source locale for the new Project. | `string` | No | — |
| `--cdn-enabled` | Enable CDN delivery for the new Project. | `boolean` | Yes | `false` |
| `-c, --config <path>` | Read API settings and locale mappings from this config file. | `string` | Yes | Nearest `gt.config.json` |
| `--api-key <key>` | Organization API key used as the bearer token. | `string` | Yes | `GT_API_KEY` |
| `--project-id <id>` | Shared CLI option; not required for Project creation. | `string` | Yes | Config, then `GT_PROJECT_ID` |

Prefer `GT_API_KEY` over `--api-key` so the key does not appear in shell history.

## Example [#example]

```bash
GT_API_KEY=gtx-org-... npx gt project create \
  --name "Storefront" \
  --default-locale en \
  --cdn-enabled
```

The command exits with status `1` when credentials are missing or the API rejects the request.
