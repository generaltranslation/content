title: gt login
description: Sign in to the CLI with your General Translation account. API reference for the gt login command.

---

Use `gt login` to authenticate interactive CLI commands without creating an API key. An explicit `GT_API_KEY` or `--api-key` still takes precedence when a command supports it.

## Overview [#overview]

```bash
npx gt login [options]
```

## How it works [#how-it-works]

- Opens a browser and completes sign-in through a local callback.
- Uses device authorization automatically in SSH sessions, when the callback cannot bind locally, or when you pass `--no-browser`.
- Requests credentials for the API configured by `baseUrl`. A login for one API origin cannot authenticate requests to another.
- Stores refreshable credentials in `$XDG_STATE_HOME/gt/credentials.json`, or `~/.local/state/gt/credentials.json` when `XDG_STATE_HOME` is unset. The file is readable and writable only by your user.
- Refreshes an expired access token when an authenticated command runs.

## Flags [#flags]

| Parameter | Description | Type | Optional | Default |
| --- | --- | --- | --- | --- |
| `--no-browser` | Show a device sign-in URL instead of opening a browser. | `boolean` | Yes | `false` |

## Example [#example]

```bash
# Open the browser and sign in
npx gt login

# Sign in from SSH or another environment without a browser
npx gt login --no-browser
```

## Other notes [#notes]

- `gt login` authenticates the CLI. It does not write a project ID or development key to `.env.local`; run [`gt init`](/docs/cli/reference/commands/init) to provision those values.
- Run [`gt whoami`](/docs/cli/reference/commands/whoami) to inspect the current account and [`gt logout`](/docs/cli/reference/commands/logout) to remove the stored login.
- `gt login` is available in `gt` 2.22.0 and later.
