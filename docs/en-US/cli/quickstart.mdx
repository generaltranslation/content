The General Translation CLI (`gt`) sets up internationalization and translates your project from the command line.

It works with [`gt-react`, `gt-next`, and `gt-react-native`](/docs/react/overview), with third-party i18n libraries like `next-intl` and `i18next`, and with standalone files such as JSON, YAML, Markdown, and MDX.

## What the CLI does [#what-it-does]

The CLI gives you direct access to:

- **Setup** for installing dependencies, wiring up your framework, and creating a `gt.config.json`.
- **Translation** for sending your source content to the General Translation API and saving the results to your codebase or the CDN.
- **CI building blocks** for uploading, enqueuing, and downloading translations across separate pipeline stages.
- **API access** for authenticated raw requests and bundled OpenAPI discovery with [`gt api`](/docs/cli/reference/commands/api).
- **Validation** for checking your project for translation errors without calling the API.

## When to use the CLI [#when-to-use]

Use the CLI when you want to:

- Set up a new project for translation with a guided wizard.
- Translate your project as part of a build or CI pipeline.
- Translate standalone content files without adding a framework library.
- Keep translations in version control alongside your source content.

## Quickstart [#quickstart]
Install `gt`, configure your project, and run your first translation. You need an existing project with a `package.json` and Node.js 20 or later installed. Prefer a currently supported Node.js LTS release. Hosted setup needs a General Translation account with project access, or permission to create a project in an Organization. Install Git so the wizard can check credential files before writing them.

### 1. Install `gt`

Install the CLI as a dev dependency.

<Tabs items={['npm', 'yarn', 'bun', 'pnpm']}>
  <Tab value="npm">
    ```bash
    npm install gt --save-dev
    ```
  </Tab>

  <Tab value="yarn">
    ```bash
    yarn add --dev gt
    ```
  </Tab>

  <Tab value="bun">
    ```bash
    bun add --dev gt
    ```
  </Tab>

  <Tab value="pnpm">
    ```bash
    pnpm add --save-dev gt
    ```
  </Tab>
</Tabs>

### 2. Configure your project

Run [`gt init`](/docs/cli/reference/commands/init) to detect your framework, create `gt.config.json`, and select or create a project when needed. The wizard starts sign-in if needed; you do not need to log in first.

```bash
npx gt init
```

In a monorepo, run the command from the app you want to localize. The wizard stops without changing files when you run it from the workspace root.

<Callout type="warn">
  [`gt init`](/docs/cli/reference/commands/init) is an interactive wizard and needs a terminal. In CI or another non-interactive shell it may wait for input, fail validation, or exit early without creating `gt.config.json` or writing credentials. For those environments, use [Non-interactive setup for CI](#ci-setup).
</Callout>

The wizard sets your default and target locales and chooses where translations are stored. It can provision a generate-only development runtime key and write it with the project ID to ignored `.env.local`, using framework-specific variable names. It does not provision a tooling key or replace `GT_API_KEY`. See [Configuring the CLI](/docs/cli/guides/configuring#credentials) for authentication and [`gt init`](/docs/cli/reference/commands/init) for provisioning permissions and file protections.

*Note: You should now have a `gt.config.json`. Bundled-local Vite setup makes live development credentials opt-in (default no); declining skips sign-in, project discovery, and key creation.*

### 3. Check your project binding

The [`translate`](/docs/cli/reference/commands/translate) command needs a project ID and either your saved login or an explicit tooling key. If setup did not bind a project, add [`projectId`](/docs/cli/reference/config#project-id) to your existing config or set it in the environment:

```bash title=".env.local"
GT_PROJECT_ID=your-project-id
```

If you have neither a saved login nor a tooling key after setup, run [`gt login`](/docs/cli/reference/commands/login) before translating. Never add API keys to `gt.config.json`. (See [CLI credentials](/docs/cli/guides/configuring#credentials)).

### 4. Translate your project

Run the [`translate`](/docs/cli/reference/commands/translate) command to translate every file configured in `gt.config.json`, along with any inline [`<T>`](/docs/react/reference/components/t) components and dictionary entries in your source code.

```bash
npx gt translate
```

Translations are saved to your codebase, ready to commit. Run this in your CI pipeline before you build for production. See [Generating translations](/docs/cli/guides/generating-translations) for the full workflow.

## Non-interactive setup for CI [#ci-setup]

The setup wizard needs an interactive terminal, so it cannot run in CI or other non-interactive environments. Set those up by hand: commit a `gt.config.json`, provide your credentials as environment variables, and run [`translate`](/docs/cli/reference/commands/translate) against that config.

### 1. Add a `gt.config.json`

Write the file yourself and commit it so the CLI knows what to translate. A minimal config sets the source and target locales and a `files` entry so [`translate`](/docs/cli/reference/commands/translate) has something to work on. The `gt` entry below stores framework translations (from `gt-next`, `gt-react`, or `gt-react-native`) locally at the given path.

```json title="gt.config.json"
{
  "$schema": "https://assets.gtx.dev/config-schema.json",
  "defaultLocale": "en",
  "locales": ["fr", "es"],
  "files": {
    "gt": {
      "output": "public/_gt/[locale].json"
    }
  }
}
```

To translate standalone files instead, add a file type such as `json` or `mdx` with an `include` glob in place of (or alongside) the `gt` entry. See [Configuring the CLI](/docs/cli/guides/configuring) for the file and storage options, and the [configuration reference](/docs/cli/reference/config) for every field.

### 2. Set your credentials

Set your project API key and project ID as environment variables in your CI provider's secret settings, not in a committed file. Create a suitably scoped key in the [Dashboard](/docs/platform/dashboard/reference/api-keys) or with [`gt api-key create`](/docs/cli/reference/commands/api-key-create). Include permissions for the whole workflow, including file reads/writes, translation enqueueing, and context access when used; the wizard's generate-only key is not enough. Neither [`gt login`](/docs/cli/reference/commands/login) nor its device-authorization mode is an unattended CI substitute.

```bash
GT_API_KEY=your-api-key
GT_PROJECT_ID=your-project-id
```

### 3. Run the translate command

Run [`translate`](/docs/cli/reference/commands/translate) before you build for production. Pass `--config` to point at your config file.

```bash
npx gt translate --config gt.config.json
```
