In a React Router storefront, `gt-react` translates the copy in your code and Hydrogen talks to Shopify. The Shopify-specific work is giving Hydrogen's request context the same locale as the page.

*Note: This guide matches `@shopify/hydrogen` 2026.10 on React Router 8, or on React Router 7 with `future.v8_middleware: true` in `react-router.config.ts`.*

<Callout type="info">
  **Changed in Hydrogen 2026.10:** `createHydrogenContext` and the React Router-only template were replaced by the framework-agnostic `createShopifyRequestContext`. It takes the same `i18n` language and country, plus an optional `pathPrefix`. Hydrogen's packaged `migrate-to-hydrogen-2026-10` skill covers the upgrade.
</Callout>

## Before you start [#before-start]

- Set up Hydrogen in your React Router app with `npx @shopify/hydrogen setup`. Your root middleware creates the Shopify request context and Storefront client, and runs `handleShopifyRoutes`.
- Complete the [React Router Quickstart](/docs/react/react-router-quickstart). Your root loader returns a locale and a translations snapshot, and the root `Layout` renders [`GTProvider`](/docs/react/reference/components/gt-provider) and `<html lang>`. This guide replaces the Quickstart's [`<LocaleSelector>`](/docs/react/reference/components/locale-selector) with a switcher that changes the URL.

## Resolve the locale from the URL [#request-locale]

Read the locale from the request path so every locale has its own URL. Use one module for both `gt-react` and Hydrogen:

```ts title="app/lib/i18n.ts"
import gtConfig from '../../gt.config.json';

// "/fr/products/x" -> "fr"; unprefixed paths use the default locale.
export function getRequestLocale(request: Request): string {
  const [, segment] = new URL(request.url).pathname.split('/');
  return gtConfig.locales.includes(segment) ? segment : gtConfig.defaultLocale;
}

// "/products/x" -> "/fr/products/x"; the default locale keeps the unprefixed path.
export function localizePath(pathname: string, locale: string): string {
  if (locale === gtConfig.defaultLocale) return pathname;
  return pathname === '/' ? `/${locale}` : `/${locale}${pathname}`;
}

// "/fr/products/x" -> "/products/x"; unprefixed paths are returned as they are.
export function stripLocale(pathname: string): string {
  const [, segment, ...rest] = pathname.split('/');
  return gtConfig.locales.includes(segment) ? `/${rest.join('/')}` : pathname;
}
```

In the root loader, call `getRequestLocale(request)` instead of `parseLocale(request)`, and pass the result to [`getTranslationsSnapshot`](/docs/react/reference/functions/get-translations-snapshot).

*Note: `parseLocale` reads the locale cookie, then `Accept-Language`. Used on its own, it serves every language from one URL, so search engines index only one language.*

To serve prefixed paths, nest your pages under an optional `:locale?` layout route. Keep Hydrogen's catch-all route last, so unmatched paths still reach its redirects:

```ts title="app/routes.ts"
import {type RouteConfig, index, route} from '@react-router/dev/routes';

export default [
  // Pages render with no prefix or with a target-locale prefix, such as /fr.
  route(':locale?', 'routes/locale.tsx', [
    index('routes/home.tsx'),
    route('products/:handle', 'routes/product.tsx'),
  ]),
  route('*', 'routes/catchall.tsx'),
] satisfies RouteConfig;
```

In the layout route, respond with 404 when the segment is not a configured target locale, so `/en/...` and unknown prefixes don't render a second copy of a page:

```tsx title="app/routes/locale.tsx"
import {Outlet} from 'react-router';
import gtConfig from '../../gt.config.json';

// Only target locales are valid prefixes; the default locale stays unprefixed.
export async function loader({params}: {params: {locale?: string}}) {
  if (params.locale && !gtConfig.locales.includes(params.locale)) {
    throw new Response(null, {status: 404});
  }
  return null;
}

export default function LocaleLayout() {
  return <Outlet />;
}
```

With file-based routes, name the layout `($locale).tsx` and nest page files under it instead.

Hydrogen's own handlers, such as `/api/cart`, `/checkout`, and the Customer Account routes, answer in the root middleware before any page renders, so they stay unprefixed.

## Pass the language to Shopify [#storefront-language]

Map each locale to its Shopify `LanguageCode` and pass it to `createShopifyRequestContext` in your root middleware. The Storefront client then fills `$language` and `$country` in every query that declares `@inContext(country: $country, language: $language)`.

```ts title="app/root.tsx"
import {
  createShopifyRequestContext,
  createStorefrontClient,
  handleShopifyRedirects,
  handleShopifyRoutes,
} from '@shopify/hydrogen';
import gtConfig from '../gt.config.json';
import {getRequestLocale} from '~/lib/i18n';
import type {Route} from './+types/root';

// One entry for every locale in gt.config.json.
const SHOPIFY_LANGUAGES = {en: 'EN', fr: 'FR', ja: 'JA'} as const;

export const middleware: Route.MiddlewareFunction[] = [
  async ({context, request}, next) => {
    const locale = getRequestLocale(request) as keyof typeof SHOPIFY_LANGUAGES;
    const requestContext = createShopifyRequestContext({
      request,
      // The language follows the page; the country stays on the market you sell in.
      // pathPrefix keeps Hydrogen's variant and standard-route redirects in the locale's URLs.
      i18n: {
        language: SHOPIFY_LANGUAGES[locale],
        country: 'US',
        pathPrefix: locale === gtConfig.defaultLocale ? '' : `/${locale}`,
      },
    });
    const storefrontClient = createStorefrontClient({type: 'public', requestContext, config});

    const shopifyRoute = handleShopifyRoutes({request, requestContext, storefrontClient, routeTemplates, handlers});
    if (shopifyRoute) return shopifyRoute;

    context.set(storefrontClientContext, storefrontClient);

    const response = await next();
    if (response.status === 404) {
      const redirect = await handleShopifyRedirects({request, routeTemplates, storefrontClient});
      if (redirect) return redirect;
    }
    storefrontClient.requestContext.applyResponseHeaders(response.headers);
    return response;
  },
];
```

`config`, `routeTemplates`, `handlers`, and `storefrontClientContext` come from your existing Hydrogen setup; only `i18n` changes.

Do not derive the country from the language. A French-speaking shopper can buy in the US market in USD; switching to French must not change the cart's buyer country or currency. If you also sell in several markets, select the country separately and update the cart's buyer identity when it changes. (See [Language and market](/docs/integrations/shopify/reference/locale-handling#language-market)).

## Format prices [#prices]

Format Shopify's amount with the currency code Shopify returns. [`<Currency>`](/docs/react/reference/components/currency) formats for the active locale; it never converts the amount.

```tsx title="app/components/LocalizedMoney.tsx"
import {Currency} from 'gt-react';

/** Format Shopify's price in the active locale without converting currency. */
export function LocalizedMoney({data}: {data: {amount?: string; currencyCode?: string}}) {
  // Optimistic cart responses can temporarily omit their cost fields.
  if (data.amount == null || !data.currencyCode) return null;
  return <Currency currency={data.currencyCode}>{data.amount}</Currency>;
}
```

## Link within the locale [#links]

Keep route paths in your code unprefixed, and add the current locale's prefix when you render a link. Read the active locale with [`useLocale`](/docs/react/reference/hooks/use-locale) and pass `localizePath(to, locale)` to React Router's `Link`.

To switch languages, change the prefix of the current URL. The root loader then reads the new locale, and the cart stays as it is. Don't use [`<LocaleSelector>`](/docs/react/reference/components/locale-selector) here: it saves the locale in a cookie and reloads the same URL, which still resolves to the old locale.

```tsx title="app/components/LanguageSwitcher.tsx"
import {useLocale, useLocales} from 'gt-react';
import {useLocation, useNavigate} from 'react-router';
import {localizePath, stripLocale} from '~/lib/i18n';

/** Switches language by changing the URL prefix; the root loader reads the new locale from the URL. */
export function LanguageSwitcher() {
  const locale = useLocale();
  const locales = useLocales();
  const {pathname, search} = useLocation();
  const navigate = useNavigate();
  return (
    <select
      aria-label="Language"
      value={locale}
      onChange={(event) => navigate(localizePath(stripLocale(pathname), event.target.value) + search)}
    >
      {locales.map((option) => (
        // Name each language in itself, such as "français" or "日本語".
        <option key={option} value={option} lang={option}>
          {new Intl.DisplayNames([option], {type: 'language'}).of(option)}
        </option>
      ))}
    </select>
  );
}
```

Link to Customer Account routes, such as `/account/login`, with a plain `<a>` or `<form>`, not `Link`. Their handlers redirect to Shopify, which client-side navigation cannot follow.

## Generate translations [#generate]

Wrap copy in [`<T>`](/docs/react/reference/components/t), use [`useGT`](/docs/react/reference/hooks/use-gt) for strings such as `aria-label` values, and run [`npx gt translate`](/docs/cli/reference/commands/translate) before `react-router build`. Translations bundled by your loader are available on the first server render, so cached responses include them.

To keep copy wrapped and translated as the storefront changes, connect the repository to [Locadex](/docs/platform/locadex/quickstart). It opens pull requests with new translations for review.
