Hydrogen storefronts are React Router framework apps, so `gt-react` translates their copy. The Hydrogen-specific work is making Shopify's Storefront API context use the same locale as the page.

*Note: This guide matches Hydrogen 2026.4 on React Router 7, the versions used by [kevinwu98/gt-shopify](https://github.com/kevinwu98/gt-shopify).*

## Before you start [#before-start]

Complete the [React Router Quickstart](/docs/react/react-router-quickstart), including its [Shopify Hydrogen](/docs/react/react-router-quickstart#hydrogen) section. Your root loader returns a locale and a translations snapshot, and the root `Layout` renders [`GTProvider`](/docs/react/reference/components/gt-provider) and `<html lang>`.

## Resolve the locale from the URL [#request-locale]

Read the locale from the request path so every locale has its own URL. Use one function for both GT and Hydrogen:

```ts title="app/lib/i18n.ts"
import gtConfig from '../../gt.config.json';

// "/fr/products/x" -> "fr"; unprefixed paths use the default locale.
export function getRequestLocale(request: Request): string {
  const [, segment] = new URL(request.url).pathname.split('/');
  return gtConfig.locales.includes(segment) ? segment : gtConfig.defaultLocale;
}
```

In the root loader, call `getRequestLocale(request)` instead of `parseLocale(request)`, and pass the result to [`getTranslationsSnapshot`](/docs/react/reference/functions/get-translations-snapshot).

To serve prefixed paths, add an optional `($locale)` segment to your route files, as in Shopify's [Hydrogen Markets guide](https://shopify.dev/docs/storefronts/headless/hydrogen/markets). Respond with 404 when the segment is not a configured target locale, so `/en/...` and unknown prefixes don't render a second copy of a page. Leave routes whose URLs are registered with Shopify unprefixed, such as the Customer Account API callback.

*Note: The example storefront uses `parseLocale`, which reads the locale cookie, then `Accept-Language`. That serves every language from one URL, so search engines index only one language.*

<Callout type="info">
  **Upcoming in Hydrogen:** open pull requests propose `defineShopifyI18n`, `getSupportedLocales`, and `getLanguageTag` for declaring locales and matching them from the URL. They are not released, so keep your own locale list and mapping until they ship. (See [Upcoming Hydrogen APIs](/docs/integrations/shopify/reference/locale-handling#upcoming-hydrogen)).
</Callout>

## Pass the language to Shopify [#storefront-language]

Map each locale to its Shopify `LanguageCode` and pass it to `createHydrogenContext`. Hydrogen then fills `$language` in every query that declares `@inContext(language: $language)`.

```ts title="app/lib/context.ts"
import {createHydrogenContext} from '@shopify/hydrogen';
import type {LanguageCode} from '@shopify/hydrogen/storefront-api-types';
import {getRequestLocale} from '~/lib/i18n';

// One entry for every locale in gt.config.json.
const SHOPIFY_LANGUAGES: Record<string, LanguageCode> = {en: 'EN', fr: 'FR', ja: 'JA'};

export async function createHydrogenRouterContext(request: Request, env: Env, executionContext: ExecutionContext) {
  // ...cache and session setup from the Hydrogen template
  const locale = getRequestLocale(request);

  return createHydrogenContext({
    env,
    request,
    cache,
    waitUntil,
    session,
    // The language follows the page; the country stays on the market you sell in.
    i18n: {language: SHOPIFY_LANGUAGES[locale], country: 'US'},
    cart: {queryFragment: CART_QUERY_FRAGMENT},
  });
}
```

Do not derive the country from the language. A French-speaking shopper can buy in the US market in USD; switching to French must not change the cart's buyer country or currency. If you also sell in several markets, select the country separately and update the cart's buyer identity when it changes. (See [Language and market](/docs/integrations/shopify/reference/locale-handling#language-market)).

## Format prices [#prices]

Format Shopify's amount with the currency code Shopify returns. [`<Currency>`](/docs/react/reference/components/currency) formats for the active locale; it never converts the amount.

```tsx title="app/components/LocalizedMoney.tsx"
import {Currency} from 'gt-react';

/** Format Shopify's price in the active GT locale without converting currency. */
export function LocalizedMoney({data}: {data: {amount?: string; currencyCode?: string}}) {
  // Optimistic cart responses can temporarily omit their cost fields.
  if (data.amount == null || !data.currencyCode) return null;
  return <Currency currency={data.currencyCode}>{data.amount}</Currency>;
}
```

## Link within the locale [#links]

Keep route paths in your code unprefixed, and add the current locale's prefix when you render a link. The default locale has no prefix. Switching languages changes only the prefix of the current URL; the cart stays as it is.

## Generate translations [#generate]

Wrap copy in [`<T>`](/docs/react/reference/components/t), use [`useGT`](/docs/react/reference/hooks/use-gt) for strings such as `aria-label` values, and run [`npx gt translate`](/docs/cli/reference/commands/translate) before `shopify hydrogen build`. Translations bundled by your loader are available on the first server render, so cached responses include them.

To keep copy wrapped and translated as the storefront changes, connect the repository to [Locadex](/docs/platform/locadex/quickstart). It opens pull requests with new translations for review.
