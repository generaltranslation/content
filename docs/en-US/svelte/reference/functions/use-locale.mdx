`useLocale` returns an object whose `current` property is the active locale of the nearest [`<GTProvider>`](/docs/svelte/reference/components/gt-provider). Reading `current` in the template or `$derived` updates when the locale changes.

## Overview [#overview]

```ts
function useLocale(): { readonly current: string };
```

```svelte
<script lang="ts">
  import { useLocale } from 'gt-svelte';

  const locale = useLocale();
</script>

<p>Current locale: {locale.current}</p>
```

## How it works [#how-it-works]

- **Reactive getter.** `current` is a getter over the provider's state, so do not destructure it: `const { current } = useLocale()` captures one value.
- **Switching.** After [`useSetLocale()`](/docs/svelte/reference/functions/use-set-locale) is called, `current` changes once the new locale's translations have loaded, not when the call starts.
- **Context.** Call it during component initialization. Outside a [`<GTProvider>`](/docs/svelte/reference/components/gt-provider), `current` is the default locale.

On the server outside a component, such as in hooks and `load` functions, use the locale you resolved with [`resolveLocale()`](/docs/svelte/reference/functions/resolve-locale) instead.

## Parameters [#parameters]

`useLocale` takes no parameters.

## Returns [#returns]

**Type** `{ readonly current: string }`

`current` is the active locale code, as resolved by [`resolveLocale()`](/docs/svelte/reference/functions/resolve-locale).

## Example [#example]

Bind a language selector to the active locale:

```svelte
<script lang="ts">
  import { useLocale, useLocales, useSetLocale } from 'gt-svelte';

  const locale = useLocale();
  const setLocale = useSetLocale();
</script>

<select
  value={locale.current}
  onchange={(event) => setLocale(event.currentTarget.value)}
>
  {#each useLocales() as code (code)}
    <option value={code}>{code}</option>
  {/each}
</select>
```

This example does not save the choice. (See [Managing locales](/docs/svelte/guides/managing-locales) for a switcher that persists it).
