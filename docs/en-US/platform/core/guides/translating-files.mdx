The `generaltranslation` library can translate full source files. This page walks through uploading a file, queueing its translation, waiting for the job, and downloading the result.

## Before you start [#before-start]

Make sure you've completed the [Quickstart](/docs/platform/core/quickstart) to install `generaltranslation` and initialize the [GT](/docs/platform/core/reference/gt-class/constructor) class with your API key and project ID.

## How file translation works [#file-translation-works]

Files are translated as jobs:

1. Upload the source file.
2. Queue the file for translation.
3. Wait for the translation jobs.
4. Download the translated file.

File translation uses multiple calls because projects often translate many files. Separate steps give you more flexibility in using the API: making it easier to batch files, retry failed work, poll jobs, and download output when ready.

Uploading creates source-file records. Calling [`translateFiles`](/docs/platform/core/reference/gt-class-methods/translation/translate-files) then queues one job for each file and target locale that still needs translating. Batch calls report each item separately: an upload resolves with a `summary` and one result per file, so one failed file does not stop the others. (See the [`uploadSourceFiles`](/docs/platform/core/reference/gt-class-methods/files/upload-source-files) and [`queryFilesContent`](/docs/platform/core/reference/gt-class-methods/files/query-files-content) methods for more information).

For SVG files, pass the UTF-8 XML source with `fileFormat: 'SVG'`. Translation updates text nodes while preserving shapes and styles. An asynchronous layout pass can recenter text and shorten overflowing translations while preserving authored font sizes, so wait until the file is complete before downloading it. Malformed XML is rejected.

## 1. Upload the source file [#upload]

As an example, this guide translates this English JSON file:

```json
{
  "hello": "Hello",
  "world": "World"
}
```

Read the file, format contents, and then call [uploadSourceFiles](/docs/platform/core/reference/gt-class-methods/files/upload-source-files) to upload files.

```typescript title="src/index.ts"
import fs from 'fs';
import path from 'path';
import type { FileUpload } from 'generaltranslation/types';

// (i) Read the content of a file
const filePath = path.join(process.cwd(), 'en.json');
const fileContents = fs.readFileSync(filePath, 'utf8');

// (ii) Format the file contents
const fileUpload: FileUpload = {
  content: fileContents,
  fileName: filePath,
  fileFormat: 'JSON',
  locale: 'en',
};
const files = [ { source: fileUpload } ];

// (iii) Upload the file
const { results } = await gt.uploadSourceFiles(
  files,
  {
    sourceLocale: 'en'
  }
);

// (iv) Stop if the file was not saved
const [uploaded] = results;
if (uploaded.status === 'failed') {
  throw new Error(`Upload failed: ${uploaded.error}`);
}
```

The response has a `summary` and one result per file, in request order. Each succeeded result carries the file references you use to queue, check, and download the translation.

```ts title="Output"
{
  summary: { total: 1, succeeded: 1, failed: 0 },
  results: [
    {
      branchId: '123456789',
      fileId: '41726368696562616c64204d6342616c64792074686973206973206a6f6b652e',
      versionId: '427269616e204c6f75206d6f7265206c696b65204c696f6e2042726f20686121',
      fileName: '/Users/demo/en.json',
      fileFormat: 'JSON',
      status: 'succeeded'
    }
  ]
}
```

## 2. Queue the file for translation [#enqueue]

Use [`translateFiles`](/docs/platform/core/reference/gt-class-methods/translation/translate-files) with the uploaded file and target locales. In this example, we will translate to Spanish (`es`).

```typescript title="src/index.ts"
const { fileId, versionId, branchId } = uploaded;

const { jobs } = await gt.translateFiles(
  [{ fileId, versionId, branchId }],
  {
    sourceLocale: 'en',
    targetLocales: ['es'],
  }
);
```

The response lists one job per file and target locale that needs translating:

```ts title="Output"
{
  jobs: [
    {
      id: 'job-123456',
      status: 'queued',
      subject: {
        type: 'file_translation',
        branchId: '123456789',
        fileId: '41726368696562616c64204d6342616c64792074686973206973206a6f6b652e',
        versionId: '427269616e204c6f75206d6f7265206c696b65204c696f6e2042726f20686121',
        locale: 'es'
      }
    }
  ]
}
```

`jobs` is empty when the file is already translated into every target locale.

## 3. Wait for the translation [#status]

Wait for the jobs with [`awaitJobs`](/docs/platform/core/reference/gt-class-methods/jobs/await-jobs). It polls until every job is finished or the timeout is reached.

```typescript title="src/index.ts"
const result = await gt.awaitJobs(
  jobs.map((job) => job.id),
  { timeoutSeconds: 300 }
);
if (!result.complete || result.jobs.some((job) => job.status !== 'completed')) {
  throw new Error('Translation jobs did not complete successfully');
}
```

`complete` is `false` when the timeout is reached, and each job's `status` is `completed`, `failed`, or `not_found` once it finishes.

## 4. Download the translated file [#download]

Finally, download the translated file with the [`queryFilesContent`](/docs/platform/core/reference/gt-class-methods/files/query-files-content) method. It returns one result per requested file, in request order.

```typescript title="src/index.ts"
const {
  results: [translation],
} = await gt.queryFilesContent([
  { fileId, versionId, branchId, locale: 'es' },
]);

if (translation.status !== 'ready') {
  throw new Error(`The translation is ${translation.status}`);
}
console.log(translation.data);
```

A result is `ready` with the content in `data`, `pending` when the translation is stored but not completed yet (for example during a layout pass; request it again later), or `not_found`. A translation is `not_found` until its job stores it, which is why this guide waits for the jobs first. This example prints:

```json title="Output"
{
  "hello": "Hola",
  "world": "Mundo"
}
```
