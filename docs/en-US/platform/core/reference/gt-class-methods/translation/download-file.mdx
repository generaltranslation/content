Downloads a single file as decoded UTF-8 text, or base64 for binary `LOTTIE` data. Depending on whether you pass a locale, it returns either the source file or the corresponding translation.

## Overview [#overview]

Call `downloadFile` with a file descriptor. Include a `locale` to download a translation, or omit it to download the source file.

```typescript
const gt = new GT({ projectId: 'your-project-id', apiKey: 'your-api-key' });

// Download a translation
const translatedContent = await gt.downloadFile({
  fileId: 'file-123',
  branchId: 'branch-456',
  locale: 'es',
  versionId: 'version-789',
});

// Download the source file (no locale specified)
const sourceContent = await gt.downloadFile({
  fileId: 'file-123',
  branchId: 'branch-456',
});
```

Signature:

```typescript
downloadFile(
  file: {
    fileId: string;
    branchId?: string;
    locale?: string;
    versionId?: string;
    useLatestAvailableVersion?: boolean;
  },
  options?: DownloadFileOptions
): Promise<string>
```

*Note: `downloadFile` requires an API key (including the deprecated `devApiKey` alias), plus `projectId` on the GT instance. When downloading translations, it only works with completed translations — verify status with [`queryFileData`](/docs/platform/core/reference/gt-class-methods/translation/query-file-data) first.*

## How it works [#how-it-works]

- **Source vs. translation.** When a `locale` is provided, the file must have a completed translation for the resolved supported locale. When no `locale` is provided, the source file is returned.
- **Locale resolution.** The requested locale is resolved to the supported locale used for storage. For example, `ja-JP` resolves to `ja`; distinct supported locales such as `en-GB` remain unchanged.
- **Format preserved.** The returned string is in the same format as the original source file; for translations, all translatable text is converted to the target locale.
- **Empty result.** The class delegates to batch download and returns `''` if no file is returned. HTTP or transport errors still reject. It does not expose pending-file details.

## Parameters [#parameters]

| Parameter | Description | Type | Optional | Default |
| --- | --- | --- | --- | --- |
| [`file`](#file) | File information specifying which file to download. | `object` | No | — |
| [`options`](#options) | Configuration for the download request. | `DownloadFileOptions` | Yes | — |

### `file` [#file]

**Type** `object` · **Required**

Identifies the file to download:

| Field | Description | Type | Optional | Default |
| --- | --- | --- | --- | --- |
| `fileId` | Unique identifier of the file to download. | `string` | No | — |
| `branchId` | Branch to download from. | `string` | Yes | default branch |
| `locale` | Target locale of the translation to download. Omit to download the source file. | `string` | Yes | — |
| `versionId` | Version ID for the file. | `string` | Yes | latest version |
| `useLatestAvailableVersion` | If `true` and the specified `versionId` is not found, fall back to the latest available version instead of failing. | `boolean` | Yes | `false` |

### `options` [#options]

**Type** `DownloadFileOptions` · **Optional**

| Field | Description | Type | Optional |
| --- | --- | --- | --- |
| `timeout` | Request timeout in milliseconds. | `number` | Yes |

## Returns [#returns]

**Type** `Promise<string>`

Resolves to the first returned file's decoded UTF-8 data, or base64 for binary `LOTTIE` data. Returns `''` if the response contains no file, so an empty string alone does not establish download success. The class method remains supported; it is not the deprecated generated single-file HTTP helper. Use generated `downloadFiles` through the [API client](/docs/platform/core/reference/api-client#endpoint-helpers) when you need pending-file details; that response uses transport/base64-shaped content.

## Examples [#examples]

```typescript title="index.ts"
import { GT } from 'generaltranslation';
import type { FileUpload } from 'generaltranslation/types';

const fileContents = '{"greeting":"Hello"}';
const filePath = 'en.json';

// (1) Create a GT instance
const targetLocales = ['es', 'fr', 'de'];
const gt = new GT({
  projectId: 'your-project-id',
  apiKey: 'your-api-key',
});

// (2) Upload the file
const fileUpload: FileUpload = {
  content: fileContents,
  fileName: filePath,
  fileFormat: 'JSON',
  locale: 'en',
};
const files = [{ source: fileUpload }];
const { uploadedFiles } = await gt.uploadSourceFiles(files, { sourceLocale: 'en' });

// (3) Enqueue the file translation job
const enqueueResult = await gt.enqueueFiles(uploadedFiles, {
  sourceLocale: 'en',
  targetLocales: targetLocales,
});

// (4) Wait for all translations to be completed
const { fileId, versionId, branchId } = uploadedFiles[0];
const result = await gt.awaitJobs(enqueueResult, { timeoutSeconds: 300 });

if (!result.complete || result.jobs.some((job) => job.status !== 'completed')) {
  throw new Error('Translations are not ready to download');
}

// (5) Download a single file
const spanishContent = await gt.downloadFile({
  fileId,
  versionId,
  branchId,
  locale: 'es',
});

console.log('Spanish translation:', spanishContent);
```

## Notes [#notes]

- Returns UTF-8 text, or base64 for binary `LOTTIE` content.
- When a locale is provided, the file must have a completed translation for its resolved supported locale.
- When no locale is provided, the source file is returned.
- An empty successful response returns `''`; HTTP and transport errors reject.
