---

title: GTIntl
description: Format values and work with locale codes for a locale configuration, without an API key. API reference for GTIntl.

---

`GTIntl` holds a [`LocaleConfig`](/docs/platform/core/reference/types/locale-config) and an optional target locale, and provides every formatting and locale method of the Core library. It takes no credentials and sends no requests, so it is safe to use in browser and mobile code.

## Overview [#overview]

```typescript
import { GTIntl } from 'generaltranslation';

const intl = new GTIntl(
  { defaultLocale: 'en', locales: ['en', 'es', 'fr'] },
  { locale: 'es' }
);

intl.formatNum(1234.5); // "1234,5"
intl.formatNum(1234.5, { locale: 'fr' }); // "1 234,5"
intl.getLocaleName('fr'); // "francés"
```

Signature:

```typescript
new GTIntl(localeConfig?: LocaleConfig, options?: { locale?: string }): GTIntl
```

*Note: Import `GTIntl` from `generaltranslation` or `@generaltranslation/format`. For formatting without an instance, `@generaltranslation/format` also exports each method as a standalone function, which takes its locales and custom mapping as arguments instead of from an instance.*

<Callout type="info">
  **Changed in v10:** The formatting and locale methods of `GT` and `GTRuntime` moved to `GTIntl`. A method's target locale is the instance `locale`, overridden per call with `{ locale }`. `generaltranslation` no longer exports the standalone formatting and locale functions; use `GTIntl`, or import them from `@generaltranslation/format`.
</Callout>

## How it works [#how-it-works]

- **Target locale.** Formatting methods, the locale description methods, [`getRegionProperties`](/docs/platform/core/reference/gt-intl-methods/locales/get-region-properties), and [`requiresTranslation`](/docs/platform/core/reference/gt-intl-methods/locales/requires-translation) act for a target locale: the call's `options.locale`, then the instance `locale`, then `defaultLocale`. A target that is a `customMapping` alias is resolved to its code.
- **One signature style.** Every method takes the values it acts on as positional arguments and an optional options object last. The options object holds per-call overrides such as `locale`, `sourceLocale`, and `approvedLocales`.
- **Formatting fallback.** Formatters try the target locale, then `defaultLocale`, then the library default (`en`). Pass `options.locales` to replace that whole list for one call.
- **Locale description methods.** [`getLocaleName`](/docs/platform/core/reference/gt-intl-methods/locales/get-locale-name), [`getLocaleProperties`](/docs/platform/core/reference/gt-intl-methods/locales/get-locale-properties), [`getLocaleEmoji`](/docs/platform/core/reference/gt-intl-methods/locales/get-locale-emoji), and [`getLocaleDirection`](/docs/platform/core/reference/gt-intl-methods/locales/get-locale-direction) take `(locale?, { locale }?)`. Without a code they describe the target locale, and locale, language, and region names are in the target locale.
- **Locale code methods.** [`isValidLocale`](/docs/platform/core/reference/gt-intl-methods/locales/is-valid-locale), [`resolveCanonicalLocale`](/docs/platform/core/reference/gt-intl-methods/locales/resolve-canonical-locale), [`resolveAliasLocale`](/docs/platform/core/reference/gt-intl-methods/locales/resolve-alias-locale), and [`standardizeLocale`](/docs/platform/core/reference/gt-intl-methods/locales/standardize-locale) take the code they check or convert as their first argument.
- **Custom mapping.** The instance [`customMapping`](/docs/platform/core/reference/types/custom-mapping) resolves aliases and overrides locale properties in the formatting, locale description, comparison, and matching methods. [`standardizeLocale`](/docs/platform/core/reference/gt-intl-methods/locales/standardize-locale) only normalizes spelling and does not resolve aliases. No method takes a per-call mapping.
- **Fixed configuration.** The instance copies and freezes `localeConfig` at construction, including the `locales` array and each `customMapping` entry. Later changes to the objects you passed have no effect, and the `defaultLocale`, `locales`, `customMapping`, and `locale` properties are read-only.
- **No credentials.** `GTIntl` accepts no API key and does not include the API client. Translate with [`GT`](/docs/platform/core/reference/gt-class/constructor) or [`GTRuntime`](/docs/platform/core/reference/runtime).

## Parameters [#parameters]

| Parameter | Description | Type | Optional | Default |
| --- | --- | --- | --- | --- |
| [`localeConfig`](#locale-config) | Default locale, supported locales, and custom mapping. | [`LocaleConfig`](/docs/platform/core/reference/types/locale-config) | Yes | `{}` |
| [`options.locale`](#locale) | Default target locale of every call. | `string` | Yes | `localeConfig.defaultLocale` |

### `localeConfig` [#locale-config]

**Type** [`LocaleConfig`](/docs/platform/core/reference/types/locale-config) · **Optional** · **Default** `{}`

`{ defaultLocale?, locales?, customMapping? }`. `defaultLocale` defaults to `en` and is the last fallback before the library default; `locales` defaults to `[]` and is the approved list of [`determineLocale`](/docs/platform/core/reference/gt-intl-methods/locales/determine-locale) and [`requiresTranslation`](/docs/platform/core/reference/gt-intl-methods/locales/requires-translation). For [`requiresTranslation`](/docs/platform/core/reference/gt-intl-methods/locales/requires-translation), omitted `locales` mean no restriction, while `locales: []` approves no locale. Pass the same object you pass to `GT` or `GTRuntime`.

### `options.locale` [#locale]

**Type** `string` · **Optional** · **Default** `localeConfig.defaultLocale`

The target locale used when a call does not pass `{ locale }`, such as the current user's locale. Create one instance per locale, or pass `{ locale }` per call.

## Examples [#examples]

```typescript title="format.ts"
import { GTIntl, type LocaleConfig } from 'generaltranslation';

const localeConfig: LocaleConfig = {
  defaultLocale: 'en',
  locales: ['en', 'de', 'ja'],
};

// One instance per request or user, for that user's locale.
const intl = new GTIntl(localeConfig, { locale: 'de' });

intl.formatCurrency(1234.5, 'EUR'); // "1.234,50 €"
intl.formatDateTime(new Date('2024-03-14'), { dateStyle: 'long', timeZone: 'UTC' }); // "14. März 2024"
intl.requiresTranslation(); // true: de differs from the default locale en
intl.determineLocale(['de-AT', 'en']); // "de"
```

```typescript
// Use `cn` as an alias for Chinese.
const intl = new GTIntl(
  { defaultLocale: 'en', customMapping: { cn: { code: 'zh', name: 'Chinese' } } },
  { locale: 'cn' }
);

intl.getLocaleName('cn'); // "Chinese"
intl.formatNum(1234.5); // "1,234.5"
```

## Notes [#notes]

- `GTIntl` sends no requests and needs no API key.
- `GT` and `GTRuntime` take the same [`LocaleConfig`](/docs/platform/core/reference/types/locale-config) as `localeConfig`, so one object can configure all three.
- Locale codes are not validated at construction; check a code with [`isValidLocale`](/docs/platform/core/reference/gt-intl-methods/locales/is-valid-locale).
