`GT` is the General Translation API client for project, file, job, runtime translation, and Organization operations. The constructor has two forms: pass `projectId` for a project-scoped instance, or omit it for an account-scoped instance.

## Overview [#overview]

Most code works on one project. Pass the project ID and call project methods directly on the instance:

```typescript
import { GT } from 'generaltranslation';

const gt = new GT({
  apiKey: 'your-api-key',
  projectId: 'your-project-id',
  localeConfig: { defaultLocale: 'en' },
});

const result = await gt.translate('Hello, world!', 'es');
```

Without `projectId`, the instance works across an Organization's projects. List Organizations and projects, and scope work with [`account.project()`](/docs/platform/core/reference/gt-class/project) and [`account.org()`](/docs/platform/core/reference/gt-class/org):

```typescript
const account = new GT({ apiKey: 'your-org-api-key' });

const projects = await account.listProjects();
const project = account.project(projects[0].id);
```

Signature:

```typescript
new GT(config: GTProjectConfig): ProjectHandle
new GT(config: GTAccountConfig): GT
```

*Note: `GT` does not format values or resolve locales. Use [`GTIntl`](/docs/platform/core/reference/gt-intl/constructor) for formatting and locale helpers, which need no API key, and [`GTRuntime`](/docs/platform/core/reference/runtime) for runtime translation without the project and file management client.*

<Callout type="info">
  **Changed in v10:** `GT` takes its locales as one [`localeConfig`](#locale-config) object, requires `apiKey`, and no longer reads `GT_API_KEY` or `GT_PROJECT_ID`. Its formatting and locale methods moved to [`GTIntl`](/docs/platform/core/reference/gt-intl/constructor), and `setConfig` is removed.
</Callout>

## How it works [#how-it-works]

- **Two forms.** With `projectId`, the instance is a [`ProjectHandle`](/docs/platform/core/reference/types/project-handle): every project, branch, file, job, and runtime translation method is called on it. Without `projectId`, the instance has [`listOrgs`](/docs/platform/core/reference/gt-class-methods/organizations/list-orgs), [`listProjects`](/docs/platform/core/reference/gt-class-methods/projects/list-projects), [`project()`](/docs/platform/core/reference/gt-class/project), and [`org()`](/docs/platform/core/reference/gt-class/org). Calling a project method on the account-scoped form, or `project()` on the project-scoped form, is a type error.
- **API key required.** `apiKey` is required, and the constructor reads no environment variables. Pass the key yourself, for example `apiKey: process.env.GT_API_KEY!`. Each API operation needs the permission its page lists.
- **Checks at construction.** The constructor throws an `Error` with a diagnostic message in two cases: `projectId` is passed but is not a non-empty string after trimming, or the account-scoped form gets a project API key (one starting with `gtx-api-`), which needs `projectId`. Other problems with the key, such as a missing permission, are reported by the first request as an [`ApiError`](/docs/platform/core/reference/api-client#api-error).
- **Fixed configuration.** The instance keeps a frozen copy of `localeConfig` from construction, including the `locales` array and each `customMapping` entry, so later changes to the objects you passed have no effect, and its properties are read-only. Both forms and their handles are frozen. Construct a new instance for a different configuration.
- **Locale configuration.** `localeConfig.defaultLocale` is the default source locale for runtime translation, and [`customMapping`](/docs/platform/core/reference/types/custom-mapping) resolves aliases before a locale is sent to the API. Locale codes are not validated at construction.
- **Returned locale codes.** Project, file, and job responses, including job `subject.locale`, use the spellings and aliases in `localeConfig` (`locales`, `defaultLocale`, and `customMapping` keys) where possible. If multiple configured codes identify the same locale, the first match is used unless your request distinguishes them. Other dialects are not substituted. Runtime translation results use the API's locale codes.

## Parameters [#parameters]

The constructor takes one object: a [`GTProjectConfig`](/docs/platform/core/reference/types/gt-project-config), with a required `projectId`, for the project-scoped form, or a [`GTAccountConfig`](/docs/platform/core/reference/types/gt-account-config), without `projectId`, for the account-scoped form. A `projectId` typed `string | undefined` matches neither; check it before constructing. The properties are:

| Parameter | Description | Type | Optional | Default |
| --- | --- | --- | --- | --- |
| [`apiKey`](#api-key) | API key for the General Translation API. | `string` | No | — |
| [`projectId`](#project-id) | Project to work on. Selects the project-scoped form. | `string` | Yes | — |
| [`localeConfig`](#locale-config) | Default locale, supported locales, and custom mapping. | [`LocaleConfig`](/docs/platform/core/reference/types/locale-config) | Yes | `{}` |
| [`baseUrl`](#base-url) | API base URL. | `string` | Yes | `https://api.gtx.dev` |

### `apiKey` [#api-key]

**Type** `string` · **Required**

API key for the General Translation API. Use a project API key with the project-scoped form, and an Organization API key with the account-scoped form or to work on several projects. The constructor does not read `GT_API_KEY`; pass it explicitly.

### `projectId` [#project-id]

**Type** `string` · **Required** in [`GTProjectConfig`](/docs/platform/core/reference/types/gt-project-config), absent in [`GTAccountConfig`](/docs/platform/core/reference/types/gt-account-config)

ID of the project to work on, such as the ID shown in the Dashboard or returned by [`listProjects`](/docs/platform/core/reference/gt-class-methods/projects/list-projects). With it, the constructor returns a project-scoped instance; without it, an account-scoped one. An empty or blank string throws. The constructor does not read `GT_PROJECT_ID`.

### `localeConfig` [#locale-config]

**Type** [`LocaleConfig`](/docs/platform/core/reference/types/locale-config) · **Optional** · **Default** `{}`

`{ defaultLocale?, locales?, customMapping? }`. `defaultLocale` is the default source locale of [`translate`](/docs/platform/core/reference/gt-class-methods/translation/translate) and [`translateMany`](/docs/platform/core/reference/gt-class-methods/translation/translate-many), and `en` when omitted. `locales` and the keys of [`customMapping`](/docs/platform/core/reference/types/custom-mapping) are the spellings returned locale codes are restored to, and `customMapping` resolves aliases before requests. Pass the same object to [`GTIntl`](/docs/platform/core/reference/gt-intl/constructor) to format with the same locales.

### `baseUrl` [#base-url]

**Type** `string` · **Optional** · **Default** `https://api.gtx.dev`

API base URL. Override it only when your deployment uses a different endpoint.

## Returns [#returns]

**Type** [`ProjectHandle`](/docs/platform/core/reference/types/project-handle) with `projectId`; `GT` without it

- **Project-scoped:** a frozen [`ProjectHandle`](/docs/platform/core/reference/types/project-handle) with every project method, [`translate`](/docs/platform/core/reference/gt-class-methods/translation/translate), [`translateMany`](/docs/platform/core/reference/gt-class-methods/translation/translate-many), and the read-only `projectId`, `apiKey`, `baseUrl`, and `localeConfig` properties.
- **Account-scoped:** a frozen `GT` instance with [`listOrgs`](/docs/platform/core/reference/gt-class-methods/organizations/list-orgs), [`listProjects`](/docs/platform/core/reference/gt-class-methods/projects/list-projects), [`project()`](/docs/platform/core/reference/gt-class/project), and [`org()`](/docs/platform/core/reference/gt-class/org).

## Examples [#examples]

```typescript title="index.ts"
import { GT } from 'generaltranslation';

// Project-scoped: project, file, job, and translation methods
const gt = new GT({
  apiKey: process.env.GT_API_KEY!,
  projectId: process.env.GT_PROJECT_ID!,
  localeConfig: { defaultLocale: 'en', locales: ['en', 'es', 'fr'] },
});

const { items: branches } = await gt.listBranches();
const result = await gt.translate('Hello, world!', 'fr');
```

```typescript
// Account-scoped: discover projects and work on several of them
const account = new GT({ apiKey: process.env.GT_ORG_API_KEY! });

for (const { id } of await account.listProjects()) {
  const { defaultLocale } = await account.project(id).get();
  console.log(id, defaultLocale);
}
```

```typescript
// Use `cn` as an alias for `zh`. The API does not support `cn`,
// so the custom mapping resolves it before each request.
const gt = new GT({
  apiKey: process.env.GT_API_KEY!,
  projectId: process.env.GT_PROJECT_ID!,
  localeConfig: { customMapping: { cn: { code: 'zh' } } },
});

const result = await gt.translate('Hello, world!', 'cn');
```

## Notes [#notes]

- Only `apiKey` is required. Pass `projectId` for project work; omit it to list Organizations and projects or to work on several projects.
- The constructor reads no environment variables.
- A project API key needs `projectId`; an Organization API key works with both forms.
- Construct a new instance to change the configuration; direct property assignment is not supported.
- Configured locale spellings and aliases are preserved in returned codes, following the rules above.
