title: API reference
description: Find the public General Translation API endpoints, authentication details, and OpenAPI spec.

---

The General Translation API lets you discover accessible projects and create-capable Organizations, create projects and project API keys, update supported project settings, upload source content and translated files, download translations, queue translation jobs, manage branches and tags, and read project and job status.

Most SDK and CLI workflows call these endpoints for you. However, the API allows you to call these endpoints directly if you need:

- Custom automation
- Endpoint schemas
- An interactive request playground
- Machine-readable `openapi.json` spec

Use the [`generaltranslation/api` TypeScript client](/docs/platform/core/reference/api-client) for generated request and response types, or browse the [OpenAPI reference](/docs/platform/openapi/overview) to call endpoints directly.

[Project discovery](/docs/platform/openapi/reference/project/list-projects) returns only projects the caller can read. [Organization discovery](/docs/platform/openapi/reference/project/list-orgs) accepts OAuth user tokens only and returns Organizations where the user can create projects. Both are paginated; follow `nextCursor` until it is `null`.

[Project creation](/docs/platform/openapi/reference/project/create-project) requires `org:projects:create`, even when enabling CDN delivery. Omitted `cdnEnabled` defaults to `false`. Creation returns project identifiers and the default locale, not credentials or CDN state; the Organization's project limit returns `409`. Repeating the request creates another project.

[Project info](/docs/platform/openapi/reference/project/project-info) requires `project:files:read` and returns `id`, `name`, `orgId`, `defaultLocale`, `currentLocales`, and `autoApprove`, not CDN state. [Settings updates](/docs/platform/openapi/reference/project/update-project) use `POST /v2/project/info/{projectId}` with `project:write`, accepting `defaultLocale` and `cdnEnabled`. Omitted fields stay unchanged, an empty update makes no changes, and success returns `{ success: true }`. These endpoints do not expose every Dashboard setting.
