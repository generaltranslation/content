Each project in the Dashboard has its own settings, separate from Organization-wide settings. Use them to rename the project, change its source locale, enable CDN delivery or automatic context updates, copy the project ID, require approval, assign reviewers, and delete the project.

## General settings [#general-settings]

- Update the project **display name**. This changes how the project appears in the Dashboard.
- Update the project **source locale**. This changes the language your content is authored in, but does not update existing translations.
- Enable the **CDN setting** to serve translations from a global CDN for faster load times.
- Enable **Automatic Context Update** to add project context and Glossary terms from your source files during translation runs. (See [Control automatic updates](/docs/platform/dashboard/guides/defining-context-for-translations#automatic-updates)).

## Project ID [#project-id]

The project ID is read-only and can be copied from Settings. 

Use it in SDK, CLI, and CI configuration when a workflow needs to target a specific project.

```bash
GT_PROJECT_ID=...
```

## Review [#review]

Translation approval requires an Enterprise plan. Open **Project > Settings > Review**. On that plan, anyone in the project can open the page. Only members who can update the project (`project:write`) can change it.

**Auto approve translations** approves future translations as they complete. It is on for a new project. Turning it on or off does not change approvals that already exist, and reviews that are already open stay on **Project > Reviews** until they are finished. These settings, and **Assign automatically**, appear only while it is off:

- **Deadline** is how many hours reviewers have after a translation is ready. Enter a whole number from 1 to 8760, or leave it empty for no deadline.
- **Branches** lists the branches whose translations need review. Separate names with commas and use `*` to match several, such as `main, release/*`. Leave it empty to review only the default branch. The list can be up to 255 characters.
- **Reviewer groups** assign reviewers to locales, integrations, or file formats. Choose **Add group** to create one, or open a group's actions to **Edit** or **Remove** it. A group with no locales or content selected covers all of them. Until the project has a group, every reviewer can review any translation. Once a group exists, reviewers can review only what their groups cover, and members who can update the project can still review anything. A project can have up to 50 groups, and each name can be up to 255 characters.

**Assign automatically** is off until you turn it on. Click **Save** after changing it. When it is on, each new open review goes to the reviewer with the fewest open reviews they can still review on that branch. Members who can update the project are never assigned this way. If no reviewer qualifies, the review stays unassigned. When a finished review opens again, a reviewer who can still review that translation keeps it.

Open reviews are listed on **Project > Reviews**. Members who can update the project choose the **Assignee** there, including **Unassigned**. (See [Assign open reviews](/docs/platform/dashboard/guides/reviewing-translations#assign-reviews)).

## Danger zone [#danger-zone]

Permanently delete a project, all its translations, API keys, and data. This cannot be undone.
