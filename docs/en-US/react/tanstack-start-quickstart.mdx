`gt-tanstack-start` adds automatic internationalization to TanStack Start apps. A Vite plugin reads your `gt.config.json`, and a router integration loads translations during server rendering and provides them to your components.

Use this quickstart for TanStack Start apps. For a plain React SPA use the [React Quickstart](/docs/react/react-quickstart).

<Callout type="warn">
  **Warning:** `gt-tanstack-start` is experimental and may have breaking changes. It is not yet recommended for production use.
</Callout>

Run [`npx gt@latest init`](/docs/cli/reference/commands/init) from the app root to automate the setup. The wizard installs the runtime, adds the Vite plugin and the router integration, and sets the root route's `<html lang>`. It leaves unrecognized files unchanged and lists any manual actions; this guide covers the same setup by hand.

*Note: This setup requires `gt-tanstack-start` 11.5.0 or later, `@tanstack/react-start` 1.159.0 or later, and Vite 6 or later.*

## Quickstart [#quickstart]

Install the packages, create a config file, add the Vite plugin and the router integration, mark content for translation, and generate translations.

### 1. Install `gt-tanstack-start`

Install `gt-tanstack-start` as a dependency and the [`gt` CLI](/docs/cli/quickstart) as a dev dependency.

<Tabs items={['npm', 'yarn', 'bun', 'pnpm']}>
  <Tab value="npm">
    ```bash
    npm install gt-tanstack-start && npm install gt --save-dev
    ```
  </Tab>

  <Tab value="yarn">
    ```bash
    yarn add gt-tanstack-start && yarn add --dev gt
    ```
  </Tab>

  <Tab value="bun">
    ```bash
    bun add gt-tanstack-start && bun add --dev gt
    ```
  </Tab>

  <Tab value="pnpm">
    ```bash
    pnpm add gt-tanstack-start && pnpm add --save-dev gt
    ```
  </Tab>
</Tabs>

`gt-tanstack-start` is ESM-only. Use `import` syntax rather than CommonJS `require()`.

### 2. Create `gt.config.json`

Create a `gt.config.json` file in your project root. It declares your source language, your target locales, and where translation files are written.

```json title="gt.config.json"
{
  "defaultLocale": "en",
  "locales": ["es", "ja"],
  "files": {
    "gt": {
      "output": "src/_gt/[locale].json"
    }
  }
}
```

- `defaultLocale` — the language your app is written in.
- `locales` — the languages to translate into. Pick from the [supported locales](/docs/platform/dashboard/reference/supported-locales).
- `files.gt.output` — where the CLI writes translation files and where the app loads them from. Keep them under `src/` so Vite can bundle them; files in `public/` will not resolve.

### 3. Add the Vite plugin

Add [`gtTanstackStart`](/docs/react/tanstack-start/config) to the plugins in your Vite config.

```ts title="vite.config.ts"
import { tanstackStart } from '@tanstack/react-start/plugin/vite';
import react from '@vitejs/plugin-react';
import { gtTanstackStart } from 'gt-tanstack-start/plugin/vite'; // [!code ++]
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [tanstackStart(), react(), gtTanstackStart()], // [!code highlight]
});
```

The plugin reads `gt.config.json` and loads translations from the `files.gt.output` path, so you do not write a translation loader.

### 4. Set up the router integration

Call [`setupRouterGTIntegration`](/docs/react/tanstack-start/reference/functions/setup-router-gt-integration) in `getRouter()` in your existing `src/router.tsx` file.

```tsx title="src/router.tsx"
import { createRouter } from '@tanstack/react-router';
import { setupRouterGTIntegration } from 'gt-tanstack-start'; // [!code ++]
import { routeTree } from './routeTree.gen';

export function getRouter() {
  const router = createRouter({ routeTree });
  setupRouterGTIntegration({ router }); // [!code ++]
  return router;
}
```

The integration resolves each request's locale, loads its translations before the page renders, hydrates them in the browser, and wraps your app in [`<GTProvider>`](/docs/react/reference/components/gt-provider).

### 5. Set the document language

Because the integration wraps the root route, the root document can read the active locale with [`useLocale`](/docs/react/reference/hooks/use-locale). Set it on the `<html>` element in `src/routes/__root.tsx`.

```tsx title="src/routes/__root.tsx"
import { HeadContent, Scripts } from '@tanstack/react-router';
import { LocaleSelector, useLocale } from 'gt-tanstack-start';

function RootDocument({ children }: { children: React.ReactNode }) {
  return (
    <html lang={useLocale()}>
      <head>
        <HeadContent />
      </head>
      <body>
        <LocaleSelector />
        {children}
        <Scripts />
      </body>
    </html>
  );
}
```

[`<LocaleSelector>`](/docs/react/reference/components/locale-selector) adds a language switcher so you can test each locale.

### 6. Mark content for translation

Wrap JSX in the [`<T>`](/docs/react/reference/components/t) component to translate it in place, and translate strings with [`useGT`](/docs/react/reference/hooks/use-gt).

```tsx title="src/routes/index.tsx"
import { createFileRoute } from '@tanstack/react-router';
import { T, useGT } from 'gt-tanstack-start';

export const Route = createFileRoute('/')({ component: Home });

function Home() {
  const gt = useGT();

  return (
    <main>
      <T>
        <h1>Welcome to my app</h1>
        <p>This content is translated automatically.</p>
      </T>
      <input aria-label={gt('Email input field')} />
    </main>
  );
}
```

[`useGT()`](/docs/react/reference/hooks/use-gt) returns the translation function directly, so call it as `const gt = useGT();`.

### 7. Generate translations

Sign in with [`gt login`](/docs/cli/reference/commands/login), set your existing project's [`projectId`](/docs/cli/reference/config#project-id) in `gt.config.json` or `GT_PROJECT_ID` in the environment, and translate:

```bash
npx gt login
GT_PROJECT_ID=your-project-id npx gt translate
```

Until a locale's translation file exists, that locale renders your source content.

Add the command to your build script so production builds always have up-to-date translations:

```json title="package.json"
{
  "scripts": {
    "build": "npx gt translate && vite build"
  }
}
```

<Callout type="info">
  **Note:** For CI, provide a separately scoped `GT_API_KEY` and the same project ID through your secret settings. Use [`gt init`](/docs/cli/reference/commands/init) separately if you need guided project selection or creation. (See [CLI credentials](/docs/cli/guides/configuring#credentials)).
</Callout>
