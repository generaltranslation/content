The `msg` function marks a string for translation at module scope. It returns input unchanged when no options are passed and encodes strings that carry options. Resolve registered values at runtime with [`useMessages`](/docs/react/reference/hooks/use-messages).

*Available in `gt-react`, `gt-next`, `gt-tanstack-start`, and `gt-react-native`.*

## Overview [#overview]

Call `msg` with a string or array. Pass the registered value to [`useMessages`](/docs/react/reference/hooks/use-messages) to retrieve the translation.

```tsx
const registered = msg('Hello, world!');
```

```ts
msg<T extends string | string[]>(message: T): T;
msg<T extends string | string[]>(
  message: T,
  options?: GTTranslationOptions
): T extends string ? string : string[];
```

*Note: when options are passed, `msg` returns opaque encoded metadata and the result should not be rendered directly. Recover its source text with [`decodeMsg`](/docs/node/reference/functions/decode-msg).*

## How it works [#how-it-works]

- **Registration for extraction.** `msg` marks the string so the CLI can extract it for translation and [`useMessages`](/docs/react/reference/hooks/use-messages) can resolve it at runtime. Without options it returns the string unchanged; with options it returns an encoded string carrying those options.
- **Message format.** The default `ICU` format interpolates variables before encoding. Set `$format: 'STRING'` to preserve braces and source text literally. User variables remain in the encoded options but are not substituted into STRING source.
- **Build-time translation.** In production, registered strings are translated during the build. Missing translations fall back to the original. In development, translation happens on demand with a slight delay.
- **Decoding.** `decodeMsg` extracts the content prefix from an encoded message: interpolated content for `ICU`, or literal source for `STRING`. [`decodeOptions`](/docs/node/reference/functions/decode-options) extracts the options.
- **Arrays.** `msg` also accepts an array of strings; when an `$id` is provided, each entry is given a unique id of `${id}.${index}`.

*Examples import from `gt-react`; import from your framework's package instead.*

```tsx
import { msg, decodeMsg } from 'gt-react';

const encoded = msg('Hello, world!');
const decoded = decodeMsg(encoded);
console.log(decoded); // "Hello, world!"
```

## Parameters [#parameters]

| Parameter | Description | Type | Optional | Default |
| --- | --- | --- | --- | --- |
| [`message`](#message) | The string (or array of strings) to register. | `string \| string[]` | No | — |
| [`options`](#options) | Interpolation variables and options such as `$context` and `$id`. | [`InlineTranslationOptions`](/docs/react/reference/types/inline-translation-options) | Yes | — |

### `message` [#message]

**Type** `string | string[]` · **Required**

The string content to register and encode. An array registers multiple strings at once.

### `options` [#options]

**Type** [`InlineTranslationOptions`](/docs/react/reference/types/inline-translation-options) · **Optional**

Interpolation variables plus options such as `$context`, `$id`, `$format`, and `$maxChars`. Variables are inserted into the string for `ICU` messages. With `$format: 'STRING'`, the source is encoded literally; variables remain in the encoded options but are not substituted.

## Returns [#returns]

**Type** `string | string[]`

The original input when no options are passed, or encoded content when options are passed. `ICU` messages include interpolated variables; `STRING` messages preserve source text literally. Arrays return an array of the same shape. Resolve the result with [`useMessages`](/docs/react/reference/hooks/use-messages).

## Examples [#examples]

```tsx
import { msg, useMessages } from 'gt-react';

const encodedString = msg('Hello, world!');

export default function TranslateGreeting() {
  const m = useMessages();
  return <p>{m(encodedString)}</p>;
}
```

```tsx
import { msg, useMessages } from 'gt-react';

const encodedString = msg('Hello, {name}!', { name: 'Alice' });

export default function TranslateGreeting() {
  const m = useMessages();
  return <p>{m(encodedString)}</p>;
}
// "Alice" is a variable and is not translated.
```

```tsx
import { msg } from 'gt-react';

// Disambiguate with $context
const LABEL = msg('Bank', { $context: 'a bank of a river' });
```

```tsx
import { msg } from 'gt-react';

// Preserve braces as literal source text instead of interpolating them.
const TEMPLATE = msg('Use {name} in your template', {
  $format: 'STRING',
  name: 'Ada', // Encoded as metadata, but not substituted into the source.
});
```

`gt-react` supports [ICU message format](https://unicode-org.github.io/icu/userguide/format_parse/messages/) for formatting variables inside registered strings.

## Notes [#notes]

- `msg` marks strings for translation; translation happens at build time (or on demand in development).
- Resolve encoded strings with [`useMessages`](/docs/react/reference/hooks/use-messages).
