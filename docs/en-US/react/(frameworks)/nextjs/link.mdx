The `<Link>` component from `gt-next/link` wraps Next.js's `<Link>` and adds the locale prefix to internal App Router URLs before navigation. This avoids an extra middleware redirect when changing locales. (See the [App Router middleware setup](/docs/react/nextjs/app-router-middleware)).

*Note: Pages Router apps should use `next/link` or `next/router` with Next.js's `locale` option. (See [Pages Router locale routing](/docs/react/nextjs/pages-router-middleware)).*

## Overview [#overview]

Import the default export from `gt-next/link` and use it like `next/link` inside [`<GTProvider>`](/docs/react/reference/components/gt-provider). It accepts the same props and forwards refs.

```tsx title="app/nav.tsx"
import Link from 'gt-next/link';

export function Navigation() {
  return <Link href="/home">Home</Link>; // /fr/home for a French visitor
}
```

## The `locale` prop [#locale-prop]

**Type** `string | false | undefined`

`locale` selects the prefix. It is not forwarded to `next/link`.

- **Omitted.** Use the current locale from [`useLocale`](/docs/react/reference/hooks/use-locale). The default locale is not prefixed unless [`prefixDefaultLocale`](/docs/react/nextjs/reference/functions/create-next-middleware#prefix-default-locale) is `true`.
- **Locale string.** Link directly to that locale, such as from a language switcher. An explicit default locale is prefixed when `prefixDefaultLocale` is `true`. When `prefixDefaultLocale` is `false`, it is prefixed only while [`enableSmartRouting`](/docs/react/nextjs/reference/functions/create-next-middleware#smart-routing) is `true` (the default), so the middleware keeps that visit on the default locale instead of the locale cookie. Set `enableSmartRouting` to `false` to leave that link unprefixed.
- **`false`.** Leave the href unchanged.

```tsx
import Link from 'gt-next/link';

// Current locale (default): /fr/home, or /home for the default locale
<Link href="/home">Home</Link>;

// Explicit locale: /fr/home
<Link href="/home" locale="fr">French</Link>;

// Explicit default locale with smart routing on: /en/home
<Link href="/home" locale="en">English</Link>;

// No prefix: /legal
<Link href="/legal" locale={false}>Legal</Link>;
```

<Callout type="info">
  **Changed in v11.4.13:** `<Link>` no longer prefixes the current default locale when `prefixDefaultLocale` is `false`. An explicit default-locale `locale` stays prefixed while `enableSmartRouting` is `true`, and stays unprefixed when both options are `false`. `prefixDefaultLocale: true` still prefixes every default-locale link.
</Callout>

Pass unlocalized paths. An href that already starts with a locale is prefixed again. External URLs, including protocol-relative URLs, stay unchanged. Query strings and hashes are preserved. For object hrefs, `<Link>` localizes only a string `pathname` and preserves the other fields.

`<Link>` reads `prefixDefaultLocale` and `enableSmartRouting` from [`withGTConfig`](/docs/react/nextjs/config#routing). Set them there, not only on [`createNextMiddleware`](/docs/react/nextjs/reference/functions/create-next-middleware), or the middleware can redirect the link. To localize a path without rendering a link, such as for `router.push()`, use [`useLocalizeHref`](/docs/react/nextjs/reference/hooks/use-localize-href).
