---

title: Set up TanStack Start
description: Add the gtTanstackStart Vite plugin and router integration to a TanStack Start app, set the document language, and enable locale routing.

---

The setup has two parts. The [`gtTanstackStart`](/docs/react/tanstack-start/config) Vite plugin supplies your `gt.config.json` and translation files to the app, and [`setupRouterGTIntegration`](/docs/react/tanstack-start/reference/functions/setup-router-gt-integration) resolves each request's locale and provides translations to your components.

This page covers the TanStack Start-specific setup. For the full path including installation and the CLI, follow the [TanStack Start Quickstart](/docs/react/tanstack-start-quickstart).

<Callout type="warn">
  **Warning:** `gt-tanstack-start` is experimental and may have breaking changes.
</Callout>

*Note: `gt-tanstack-start` is ESM-only. Use `import` syntax rather than CommonJS `require()`. This setup requires `gt-tanstack-start` 11.5.0 or later.*

## Add the Vite plugin [#vite-plugin]

Add [`gtTanstackStart`](/docs/react/tanstack-start/config) to the plugins in your Vite config:

```ts title="vite.config.ts"
import { tanstackStart } from '@tanstack/react-start/plugin/vite';
import react from '@vitejs/plugin-react';
import { gtTanstackStart } from 'gt-tanstack-start/plugin/vite';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [tanstackStart(), react(), gtTanstackStart()],
});
```

The plugin reads `gt.config.json` from the working directory and loads translation files from its `files.gt.output` path. Without a local output path, translations load from the General Translation CDN. Pass options for settings that `gt.config.json` cannot hold, such as cookie names and dictionary files (see [Configuration](/docs/react/tanstack-start/config#options)).

## Integrate the router [#router]

Call [`setupRouterGTIntegration`](/docs/react/tanstack-start/reference/functions/setup-router-gt-integration) in `getRouter()`, after you create the router:

```tsx title="src/router.tsx"
import { createRouter } from '@tanstack/react-router';
import { setupRouterGTIntegration } from 'gt-tanstack-start';
import { routeTree } from './routeTree.gen';

export function getRouter() {
  const router = createRouter({ routeTree });
  setupRouterGTIntegration({ router });
  return router;
}
```

On each server request, the integration:

- Resolves the locale from the locale cookie, then the `Accept-Language` header, then `defaultLocale`. With [locale routing](#locale-routing), a supported path prefix comes first.
- Persists the resolved locale in the locale cookie.
- Loads the locale's translations and dictionary before the page renders, and sends them to the browser with the page.
- Wraps your app, including the root route, in [`<GTProvider>`](/docs/react/reference/components/gt-provider).

In the browser, the integration hydrates the same locale and translations before the first render, so translated content does not flash. Do not render [`<GTProvider>`](/docs/react/reference/components/gt-provider) yourself.

Loaders, server functions, and server routes can read the request's locale and translate with the [isomorphic runtime functions](/docs/react/tanstack-start/using-server-functions).

## Set the document language [#document-language]

Components in the root route, including the root document, can use the shared hooks. Set the `<html>` element's `lang` attribute with [`useLocale`](/docs/react/reference/hooks/use-locale):

```tsx title="src/routes/__root.tsx"
import { HeadContent, Scripts } from '@tanstack/react-router';
import { useLocale } from 'gt-tanstack-start';

function RootDocument({ children }: { children: React.ReactNode }) {
  return (
    <html lang={useLocale()}>
      <head>
        <HeadContent />
      </head>
      <body>
        {children}
        <Scripts />
      </body>
    </html>
  );
}
```

## Enable locale routing [#locale-routing]

Locale routing keeps non-default locales in the URL, such as `/es/about`, while the default locale stays unprefixed, such as `/about`. It is opt-in. Set `localeRouting` to `true` in `gt.config.json`:

```json title="gt.config.json"
{
  "defaultLocale": "en",
  "locales": ["es", "ja"],
  "localeRouting": true
}
```

The router integration then rewrites URLs for you, so your route files and links stay locale-free:

- An incoming `/es/about` matches your `/about` route, with `es` as the request locale.
- `<Link to="/about">` renders `/es/about` while the active locale is `es`, and `/about` for the default locale.
- Changing the locale reloads the same page under the new locale's prefix, and keeps the query string and hash.
- Your router's own `rewrite` keeps working and receives locale-free URLs.

TanStack Router's base path is respected through `TSS_ROUTER_BASEPATH`. Restart the dev server after you change `gt.config.json`.

### Handle locale prefixes yourself [#own-prefixes]

If your routes already declare an [optional `/{-$locale}` segment](https://tanstack.com/router/v1/docs/guide/internationalization-i18n#i18n-with-optional-path-parameters), pass `localeRewrite: false` so the integration does not strip the prefix before your routes see it:

```tsx title="src/router.tsx"
setupRouterGTIntegration({ router, localeRewrite: false });
```

With `localeRewrite: false`, the request locale still comes from the path prefix, and locale changes still reload at the matching pathname. Your routes and links must accept and produce both the unprefixed and the prefixed URLs.
